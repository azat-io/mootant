# Фикстуры прототипов ускорения (раздел 4)

Исходники маленьких проектов для проверки эквивалентности вердиктов
прототипов (`analysis/experiments/prototypes.md`). Зависимости здесь не
ставятся: `analysis/tools/perf-proto/setup-fixture.sh <имя> <каталог> <tgz>`
копирует фикстуру в `<каталог>` (вне `analysis/`) и ставит Vitest 5 и указанный
tarball Mootant.

| фикстура | раннер | зачем |
|---|---|---|
| `vitest-units` | Vitest 5 | много юнитов одного тест-файла (P1), выжившие с несколькими покрывающими файлами (раунды), обычная эквивалентность P2/P3 |
| `shared-resource` | Vitest 5 | стресс для P1: тесты делят фиксированный файл и порт — почему параллельные юниты только opt-in |
| `prefix-boundary` | Vitest 5 | граница P2: мутант меняет состояние модуля, которое читают поздние непокрывающие тесты (база убивает, P2 — нет), и P2' «только покрывающие» (ложное убийство) |
| `node-units` | `node --test` | P1 и P3 для адаптера node:test |
