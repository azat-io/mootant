# Замечания верификаторов к BUG-402

Источник: data/verification/batch3.json

## Пробелы промпта (воспроизводящий агент)

1) Главное: в реальном Vite 8 у виртуального узла поле file НЕ null. В графе стоит file = cleanUrl(id) = '\0virtual:limits' (vite node.js:36905; на живом графе это подтверждено). При этом поддельные узлы в unit-тесте промпта (`file: id.startsWith('/') ? id : null`) и JSDoc GraphNode (collect-dependencies.ts:23-26) изображают виртуальный модуль как file: null, а подсказка к исправлению звучит как «обходить узлы без файла». Если исправить по условию `file === null`, unit-тест проходит, а интеграционный остаётся красным (проверено). Надо прямо написать: обходить узлы, у которых `file ?? id` не абсолютный путь (и не node_modules), не добавляя их в список. Ещё стоит добавить unit-узел с file: '\0virtual:limits', как в реальном Vite, и поправить JSDoc GraphNode.file.
2) Код воспроизведения не проходит ESLint проекта (11 ошибок, начиная с unicorn/filename-case для BUG-402.test.ts). Промпт не говорит, что test/repros/BUG-402.test.ts нужно удалить и переписать в стиле проекта, хотя критерий готовности требует зелёного `pnpm test` (test:js). Сессия, которая скопирует код дословно или оставит файл, получит красный test:js.
3) Про CACHE_VERSION сказано условно. По факту ключ — это дайджест по списку зависимостей и их хешам (core/cache/get-test-file-keys.ts), а dry run выполняется при каждом запуске. Поэтому после исправления старые записи просто не совпадут, и подъём версии для этой правки не обязателен. Лучше сказать это явно.
4) Мелочи по отладке и окружению. Vitest 5 скрывает console-вывод прошедших тестов, нужен `--silent=false`. В этой среде `pnpm install` сработал как `--frozen-lockfile --offline`. Вариант с id без `\0` ('virtual:limits') тоже воспроизводит дефект, его стоит включить в тесты. Для критерия производительности: после исправления обход дойдёт до узлов файлов, объявленных через addWatchFile; если такой узел ни разу не трансформировался (transformResult null), visit() вызовет для него transformRequest. Это лишняя работа, её стоит иметь в виду при замере.

Нужна правка данных без правки мутируемого файла или тестов при сохранившемся локальном кэше. Плагины без addWatchFile останутся непокрытыми и после исправления.

Уточнения к промпту (это не опровержения):
1. В реальном Vite у виртуального узла `file` не null: `mod.file = cleanUrl(resolvedId)` даёт '\0virtual:limits' (chunks/node.js:36905). Комментарий collect-dependencies.ts:24 и фейковый узел в unit-тесте промпта здесь неточны. Условием обхода должно быть «id не абсолютный путь вне node_modules», а не `file === null`. Иначе правка пройдёт unit-тест, но не интеграционный.
2. Виртуальные id, подходящие под /\.(?:map|json)(?:$|\?)/, например '\0virtual:data.json', пропускают import-analysis (chunks/node.js:26448-26449). Их watch-файлы в граф не попадут, и исправление их не покроет. Это стоит добавить в документацию рядом с оговоркой про плагины без addWatchFile.
