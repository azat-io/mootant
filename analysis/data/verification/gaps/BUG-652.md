# Замечания верификаторов к BUG-652

Источник: data/verification/batch5.json

## Пробелы промпта (воспроизводящий агент)

1) Нет шага сборки пакета: /path/to/mootant-0.1.0.tgz — заглушка. Нужно указать, как получить tarball из репозитория (pnpm build, затем pnpm pack).
2) Нет проверки предусловия: mootant не должен лежать в PATH (command -v mootant). Иначе при глобальной установке баг не проявится.
3) Промпт противоречит сам себе в случае без user agent. «Ожидаемое поведение» требует голое mootant, а раздел про определение запускателя предлагает запасной вариант по lockfile. В критериях есть тест «отсутствие user agent», но ожидаемый результат не указан.
4) По user agent не отличить pnpm exec от pnpm dlx (и yarn dlx). Проверено: `pnpm --package=<tgz> dlx mootant` даёт тот же "pnpm/12.16.1 npm/? node/? linux x64", а предложенная подсказка `pnpm exec mootant` без локальной установки падает с 'Command "mootant" not found'.
5) Подсказка на обзоре HTML (render-overview.ts:154) берёт meta.command, то есть то же поле, что заголовок HTML (render-frame.ts:61). Промпт запрещает менять command, но требует исправить эту подсказку. Не сказано, что для этого нужно новое поле в meta или отдельное решение.
6) Воркеры vitest наследуют npm_config_user_agent от запускателя: при `pnpm test` это pnpm/12.16.1..., при npm test — npm/..., при прямом запуске — null. Поэтому тесты обязаны подменять окружение (vi.stubEnv), иначе результат зависит от способа запуска.
7) Промпт не перечисляет всех тестов и хелперов с голым mootant, которые придётся менять: e2e test/cli/run-mutation.test.ts:149-153, 203-208, 273, 289, 342; test/helpers/create-run-report.ts:15; test/helpers/create-html-report.ts:33-35; test/cli/html/build-html-report.test.ts; render-frame.test.ts:22; render-mutant-panel.test.ts:61; render-overview.test.ts:59.
8) «Новый файл теста рядом с format-command.ts» не соответствует структуре проекта: тесты лежат в test/cli/report/*.test.ts.
9) Пункт «отметить в changelog» неприменим: на 170ec52 нет changelog.md. Его генерирует changelogen из Conventional Commits при релизе (release:version), так что изменение отмечается сообщением коммита fix(cli): ...
10) Не охвачены другие примеры команд с голым mootant в сообщениях об ошибках: cli/parse-arguments.ts:292 ('mootant --help'), :407 ('mootant list src'), core/run-mutants.ts:184 ("mootant run src"). В skill-session.ansi первый вызов агента на :3 (`$ mootant run src --json`) тоже голый.
11) Промпт цитирует системный pnpm 10.28.0, а в инструментах проекта стоит pnpm 12.16.1, который пишет `node/?`. Разбирать стоит только первый токен user agent.
12) Предупреждение для окружения: в /home/user/mootant нет node_modules, и `pnpm exec` (pnpm 12) ставит его автоматически. Тесты лучше запускать в /home/user/wt/base.

## Скептик (refuted=false, severity=low)

Итог: находка не опровергается, но её серьёзность завышена (предлагаю low вместо medium). Из этого следует, что по analysis/TASK.md:249-251 отдельный bug-prompt ей не положен: промпты пишутся только для medium и выше.

ПОЧЕМУ НЕ ОПРОВЕРГНУТО
(в) Код прочитан верно, все номера строк совпадают:
- cli/report/format-command.ts:77 жёстко задаёт `['mootant', command, …]`.
- В cli/ и core/ нет ни определения запускателя, ни npm_config_user_agent. `npx` встречается только в adapters/node-test/resolve-command.ts, а там разбираются скрипты тестов.
- recheck собирается в cli/run-mutation.ts:52-58, command — в :67 и :78.
- Где подсказка выводится: текст — format-run-text-report.ts:173; JSON — build-run-report.ts:101-104; HTML — unpack-run-report.ts:68-71, render-mutant-panel.ts:197 и render-overview.ts:154. Во всех трёх HTML-местах команда выводится через render-command.ts:12-25 с кнопкой «Copy command», то есть страница прямо предлагает её скопировать.

(б) Это не артефакт окружения. Результат детерминирован и не зависит от root, TERM или нагрузки. Опыт в /home/user/projects/verify-skeptic/BUG-652/npm-proj (npm 10.9.9, vitest 5.1.0, tgz 170ec52; глобального mootant нет, `command -v mootant` ничего не находит):
- `npx mootant run src` печатает последней строкой `re-check one: mootant run src --mutant 69kd`.
- Эта строка в `bash -c` даёт `mootant: command not found`, exit 127.
- Поле JSON `recheck` = `mootant run src --mutant 69kd92dczrne` даёт тот же exit 127.
- `npx mootant run src --mutant 69kd` отрабатывает с exit 0.
- В HTML-отчёт встроены строки `mootant run src` (recheck) и `mootant run src --html` (command).

(а) Это не задокументированное и не задуманное поведение. Проект сам обещает, что команда запускается:
