## Пробелы промпта (воспроизводящий агент)

1) Не сказано, откуда взять CLI `mootant`: в командах просто `mootant list`. Нужно либо `pnpm build && node bin/mootant.js`, либо tgz. Скрипт switch-size.mjs по умолчанию берёт MOOTANT_ROOT=/home/user/wt/instrument — это локальный путь, в чистой сессии его нет.
2) Svelte не закреплён на коммите (клон --depth 1 HEAD). Нужно указать коммит (у меня 628098d, размеры совпали) и предупредить, что размер JSON зависит от длины пути: эталонное 418 754 527 получено с другим путём.
3) Нет фикстуры для случая recommended «1000 вызовов fnN()». Я восстановил её: 1000 `function fnN(){ return N }` плюс однострочный `export let calls = [fn0(), ...]`. Цифры совпали, фикстуру стоит вписать в промпт.
4) Не указано, к какому процессу относится «3,9 ГБ RSS» (это скрипт замера). Не сказано, что transform делался под именем .ts.
5) Среди подозреваемых мест нет отчётной стороны. В обычном --json before/after строит cli/diff/get-diff-lines.ts: он режет только внешний контекст до 80 символов (MAX_CONTEXT_LENGTH), а неизменные строки внутри литерала оставляет. Если править только instrument и мутаторы, критерий «list --json ≤ нескольких МБ» не выполнить.
6) Конфликт двух требований не разобран. id хеширует полные original и replacement (create-mutant-id.ts:61-72). Если сузить мутант до элемента, id сменятся (кэш, --mutant). Если сохранить id, весь литерал останется в отчёте. Нужно явно разрешить один из вариантов: смену id или изменение формата отчёта.
7) Не упомянут `--skipped`: отброшенные кандидаты печатаются с полными текстами (entities.js под recommended с --json --verbose --skipped — 205,5 МБ). Поэтому вариант (2) «skip с причиной» без обрезки текстов не уменьшит такой отчёт.
8) Требование «осторожно с дырами» и «дифтест включая дыры» сейчас пустое: array-element не мутирует массивы с дырами (array-element.ts:32-34). Не сказано, надо ли менять это поведение.
9) Для `mootant run` нет сценария замера. Эффект в Vite и V8 подтверждается только чтением кода; бюджет времени и памяти для run не задан.
10) Ветки experiment/bug-repros нет в origin, но код теста приведён в промпте полностью, а его хелпер есть на 170ec52, так что это не блокер.

## Скептик (refuted=false, severity=medium)

ВЫВОД: опровергнуть не удалось. Механизм подтверждён в коде и на опыте. Влияние на `run` даже сильнее описанного, но реалистичный триггер почти всегда требует включённого вручную `strict`. Серьёзность medium подтверждаю.

(в) Код прочитан верно:
- Replacement у `object-property` и `array-element` — это `removeListElement(node, index)`, то есть весь литерал без одного элемента: core/mutators/object-property.ts:17-24, core/mutators/array-element.ts:55-59, core/text/remove-list-element.ts:51-54. Диапазон мутанта — весь узел.
- Мутанты с одинаковым `kind:start:end` попадают в одну группу (core/instrument/group-mutant-ranges.ts:17-30). Группа рендерится как `(c1 ? (r1) : c2 ? (r2) : … (original))`, каждый ri вставляется целиком (core/instrument/render-mutant-range.ts:91-95). Итог: N копий литерала.
- Бюджета размера нет: instrument-file.ts:51-76, create-switched-files.ts:63-107.
- Хостятся все pending-мутанты файлов прогона, «selected or not» (core/run-mutants.ts:341). Поэтому даже `--mutant`, включая «re-check one», платит полную цену.
- Repro в /home/user/wt/bug-repros падает ровно так, как заявлено: `expected 3359222 to be less than 415400`.

(а) Поведение не задокументировано и не задумано:
- В docs/content/mutators/object-property.md, array-element.md, guide/configuration.mdx (presets, coarseMutants) и compatibility.mdx нет ни слова о размере или памяти.
- Единственный намёк — строка описания в core/presets/strict.ts:32 («noisier or more expensive»). Она про число мутантов, а не про O(N²)-модуль и отказ прогона.
- Против «задумано» говорят несколько мест в коде:
  - cli/diff/get-diff-lines.ts:16-20, `MAX_CONTEXT_LENGTH = 80`, с пояснением «so a long line … does not repeat in every mutant»: авторы сознательно избегают дублирования в отчёте.
  - Бюджет `MAX_STEPS` в core/generate/get-mutant-regions.ts:18.
  - Прецедент skip для больших списков: `large-alternation` в core/regex/collect-pattern-changes.ts:20,110-122.
- Частичный контраргумент: под `recommended` правило solitary отбрасывает `object-property` у записей вида `'x;': 123` (generate-file-mutants.ts:258; object-property.md:37). Значит, для таблиц данных триггер — `strict`/`coarseMutants` (strict.ts:33).
- Но для элементов без вложенных мутантов (идентификаторы, вызовы, shorthand) квадрат есть и под `recommended`:
  - 1600 элементов → `--json` 53–64 МБ, switched 21–27 МБ;
  - 1000 вызовов `fN()` (40,7 КБ) → switched 10,0 МБ (в находке 9,0 МБ).

(б) Это не артефакт окружения:
- Размеры детерминированы. Реальный svelte `entities.js` (41 289 байт, с main):
  - 4462 мутанта (2231 `object-property` + 2231 `number-literal`);
  - switched 92 100 466 байт — байт в байт как в находке;
  - `list --json --verbose` — 418,8 МБ, `--json` — 214 МБ, под `recommended` — 830 КБ.
- На синтетике N=100/200/400/800 размер растёт ×4 при каждом удвоении N.
- Тайминги зависят от нагрузки (в находке 56 с и 13 с, у меня 44 с и 7 с).
- «Пик RSS 3,9 ГБ» — это RSS измерительного скрипта switch-size.mjs: он держит в памяти JSON 418 МБ, switched-текст и вывод oxc. У самого `mootant list` пик 1,4–1,9 ГБ, но `mootant run` доходил до 3,2 ГБ, так что порядок верный.
- Жёсткие пределы от машины не зависят:
  - cli/report/format-report.ts:20 сериализует весь отчёт одним `JSON.stringify`. Таблица из 2600 записей (58 КБ) под strict → `list --json --verbose` падает с «Error: Invalid string length», exit 1, вывод пустой.

Почему не high:
- Ложных killed/survived нет: отказ виден как Error, диагностика и exit 1. Недостаток в том, что диагностика ошибочно винит все файлы.
- Для типичных таблиц данных нужен включённый вручную `strict`. Под `recommended` нужны литералы примерно из 2000+ элементов без вложенных мутантов — в рукописном коде это редкость.
- Есть задокументированные обходы: `mootant-ignore-file`, `mootant-ignore-start/end` (docs/content/mutators.md:109-110), выключение мутатора, сужение paths.
- Сопоставимые исходы (все мутанты файла → Error) в самом анализе оценены как medium: BUG-106, BUG-100.

Почему не low: под strict одна таблица примерно из 1500+ записей обнуляет весь Vitest-прогон проекта (пример — сам компилятор Svelte) и ломает `list --json --verbose`. А `--json` — интерфейс для агентов — становится непригодным: 214–419 МБ на файл в 41 КБ.
