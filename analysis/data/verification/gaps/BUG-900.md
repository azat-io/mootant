# Замечания верификаторов к BUG-900

Источник: data/verification/batch1.json

## Пробелы промпта (воспроизводящий агент)

1) Команды сквозного сценария из промпта не работают как написаны. `npx mootant run --no-cache --verbose` и `npx mootant run --no-cache --mutant y1rm` без путей падают с «mootant run needs paths, such as "mootant run src"». Нужно `npx mootant run src ...` или run.paths в конфиге, а конфиг в промпте не описан.
2) Фикстура описана только словами. Не дано полное содержимое test/a.test.js и test/b.test.js, package.json (скрипт test: `vitest run` или `node --test`, по нему адаптер определяется автоматически) и устройство счётчика .runs (путь, чтение-инкремент при загрузке файла). Не сказано, как ставить пакет (tgz) и Vitest. Через npm `vitest@5` разрешается в 5.1.0, а 5.0.5 приходится ставить через pnpm. Воспроизводится на обеих версиях.
3) Описание node:test неточно (см. citation_notes): факты дают hookError с общим текстом и tests: [], а не «упавшие тесты без hookError». Версия Node не указана (проверено на 22.23.4). Сессия, которая будет чинить «упавшие тесты», пойдёт по ложному следу.
4) «Error с диагностикой» неоднозначно. Существующий путь юнита без фактов даёт Error с сообщением вердикта 'The test runner did not report this mutant.' и без записи в state.diagnostics. Не задано, какое сообщение или код (warning) ожидаются для неполного юнита и нужна ли запись в diagnostics.
5) Для исправления в Vitest не упомянуто, что флаг abandoned уже есть в end-записи (adapters/vitest/runner.ts:932) и что batch его использует (adapters/vitest/run-batch.ts:83-90). Это более прямой сигнал, чем сравнение с fileTests. Для сравнения facts.tests с fileTests не разобраны крайние случаи: повторы и retry (несколько tries на один id), тесты, пропущенные в рантайме (ctx.skip даёт skipped-try), id в node:test.
6) Мелочь: код теста в промпте — сжатая версия файла из ветки (другие названия describe/it, hookError 'listen EADDRINUSE' без хвоста). На результат это не влияет, но в промпте сказано, что файл лежит в ветке, без оговорки, что текст сокращён.

Опровергнуть не удалось. Находка подтверждена по коду и сквозными прогонами, в том числе в вариантах, которых не было в исходном анализе.

(г) Серьёзность: high, но на нижней границе. Аргументы за high:
- Ошибка молчаливая и сидит на основном (default) пути, который по контракту и есть «надёжный».
- Затронуты оба адаптера, подтверждены четыре разных триггера.
- Видимый в обычном прогоне флейк mootant превращает в невидимый уверенный вердикт.
- Отчёт сам себе противоречит: предлагает расширить файл, где убивающий тест уже есть.
- Возможен ложный `NoCoverage`.
- `--threshold` в CI становится недетерминированным, агенты пишут лишние тесты.
- Каждый тест-файл выполняется по разу на каждый покрытый мутант, поэтому редкий флейк набора почти наверняка случится за прогон.

Аргументы за medium (почему граница нижняя):
- Нужен посторонний сбой до достижения мутанта в «убивающем» файле.
- Без флейков одна нагрузка его не вызвала: 2 прогона, 36+ юнитов при load average около 30 на 4 CPU (фикстура `natural`), результат 15 Killed и 3 Survived, все три эквивалентные, ровно как в эталоне.
- В кэш ложный вердикт не попадает: следующий прогон дал `Killed`. `--mutant` исправляет.
- Ошибка ведёт к ложной тревоге, а не скрывает пробел в тестах.
- `retry` в Vitest смягчает таймауты тестов, но не падения хуков.

Поправки к исходному анализу:
- Довод `static-review.md:105-108`, что параллельные юниты делают сбои вероятнее, частично неверен. `wait-for-turn.ts:14-21` сериализует юниты одного файла, поэтому конфликтов порта или БД внутри файла нет. Вероятнее сбой только за счёт числа запусков.
- Предложенный в промпте способ исправления (сравнивать `facts.tests` с `fileTests`) не поймает `node:test`: там тесты после упавшего хука приходят как упавшие, а не как отсутствующие.
- Калибровка расходится с BUG-901 (ложный `Killed`, причём кэшируемый, оценён как medium): эти две находки стоит оценивать вместе.
