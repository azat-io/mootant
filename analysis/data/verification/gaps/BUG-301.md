== Почему НЕ опровергнуто ==
1. (в) Код прочитан верно (вне analysis/ рабочая копия совпадает с 170ec52, git diff пуст):
   - core/mutators/return-value.ts:170-171: solitary = [target, ...getLocalRanges(...)];
   - :349-365 getLocalRanges: инициализатор и все записи в той же функции, другие чтения переменной не проверяются;
   - :378-391 getLocalBinding;
   - core/generate/apply-solitary-rule.ts:60-115: грубый кандидат выбрасывается по первому засчитанному тонкому;
   - Binding.references существует (types/syntax/binding.d.ts:23-27).
2. (б) Это не артефакт окружения: генерация мутантов статическая, от таймингов не зависит.
   - /home/user/wt/bug-repros/test/repros/BUG-301.test.ts падает ровно с 'count -> 0 (subsumed solitary)'.
   - Сквозная проверка в /home/user/projects/verify-skeptic/BUG-301/e2e (npm, vitest 5.1.0, load ~4): `list --skipped` → `7:10 return-value count -> 0 subsumed solitary` (by number-literal). `run --no-cache` → killed 3, score 100%. После ручной замены на `return 0` тест проходит.
3. Класс шире игрушечного примера: e2e/src/users.ts (`let user = {...}; store.save(user); return user` и `onLabel(label); return label`). В recommended score 100%, в `--preset strict` 75%: выжили 2 мутанта return-value.
4. Посылка правила ложна для этого подкласса. Причина пропуска звучит как «killing that mutant needs a test that observes this code», а здесь тест наблюдает значение через другой канал. Проект уже делает аналогичное исключение для простого присваивания: core/mutators/statement-removal.ts:458-462 («a mutant of the assigned value only shows that the value is observed»). Значит, по логике самих авторов это пробел, а не замысел.
   - Тестов, закрепляющих пропуск при чтении переменной в другом месте, нет: test/core/mutators/return-value.test.ts:92, 205-215, 740-880 проверяют только ограничение функцией и runtime-деревом.
5. `run` (и текст, и `--json --all`) вообще не упоминает пропущенные или эвристические мутанты. Без `list --skipped` пользователь дыру не увидит.

   - не считать чтением записи, в том числе составные, и вызовы мутирующих методов самой переменной;
   - считать утечкой передачу в вызов, захват замыканием, запись в другое хранилище и другой return.
