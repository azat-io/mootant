# Замечания верификаторов к BUG-905

Источник: data/verification/batch1.json

## Пробелы промпта (воспроизводящий агент)

1) Главное: тест 2 (`does not blame a switched file…`) невыполним при исправлении, которое предписывает промпт, а критерий готовности разрешает менять форму только тесту 1. Причин две, обе подтверждены на копии 170ec52:
   (а) в мире фейкового адаптера нет cacheInputs и files[].dependencies, поэтому у DryFile нет dependencies (create-fake-adapter.ts:319-324). По собственному правилу промпта («все файлы — когда зависимости неизвестны») src/b.ts всё равно обвиняется.
   (б) onDry роняет /t/a.test.ts при ЛЮБОМ instrumented-прогоне. Поэтому после правильного сужения до a.ts повторный dry run бросает «Tests still fail with mootant's switched files after the files that broke them were dropped».
   Тест нужно поправить: добавить `cacheInputs: { settings: null, files: [] }` и `files: [{ file: '/t/a.test.ts', dependencies: ['/t/a.test.ts', '/src/a.ts'] }, …]`, а в onDry проверять `request.related.includes('/src/a.ts')`. Такой вариант падает на 170ec52 с тем же сообщением и проходит с исправлением.
2) «Подозреваемое место» group-replacement.ts:233-236 уводит в сторону. Отвергать текст только там бесполезно: такая проверка не поймает ни сквозной сценарий (`return a + b` выходит на 230-231), ни замены-операторы (`if (a {` попадает в список как Pending). Промпт должен прямо сказать, что текст нужно разбирать в addReplacement (как выражение или как оператор, в зависимости от kind) или разбирать переключённый файл целиком.
3) Для варианта «проверка при переключении» не сказано, чем и для каких расширений разбирать. Например, oxc parseSync для js/ts/jsx/tsx/mjs/cjs/mts/cts; .astro тоже никак не проверяется. Не сказано и о цене такой проверки.
4) В сквозной фикстуре не хватает шагов:
   - как получить CLI: bin/mootant.js импортирует ../dist/cli/index.js, а dist в репозитории нет, нужен `pnpm build` (и pack или install в фикстуру);
   - содержимое тестов и package.json (не критично: работает и без "type": "module");
   - что 3 из 4 мутантов дают встроенные мутаторы пресета recommended;
   - что под npm 10.9.9 vitest 5.0.5 не ставится, а vitest@5 (5.1.0) воспроизводит баг так же.
5) Для исправления по dependencies не сказано, что findBrokenFiles получает только failures. У DryTest нет dependencies, поэтому для упавших тестов (не только незагрузившихся файлов) нужно передавать dry.files.
6) У критерия «не замедляет mootant list заметно (замер на core)» нет ни базовой цифры, ни методики, ни порога.

## Цитаты кода (воспроизводящий агент)

Все диапазоны строк точные (проверено в /home/user/mootant на 170ec52):
- validate-replacement.ts:49-84 — функция validateReplacement целиком.
- group-replacement.ts:233-236 — `let readings = readText(...)` и `if (readings.length === 0) return true`.
- collect-candidates.ts:266-367 — функция addReplacement целиком.

Для замен-операторов (kind 'block') groupReplacement выходит ещё раньше, на 178-184. Строки 233-236 отвечают за случай `(a +)` в аргументе вызова или инициализаторе, но не за описанный сценарий.
2) dependencies заполняет не только адаптер Vitest (adapters/vitest/run-dry.ts:200), но и node-test (adapters/node-test/run-dry.ts:131).
3) Блок теста в промпте — сокращённая копия файла: describe называется 'BUG-905' вместо полного имени, комментарии убраны. По смыслу тест тот же.
