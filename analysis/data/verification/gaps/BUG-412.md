## Пробелы промпта (воспроизводящий агент)

1) Окружение. Промпт говорит просто «pnpm install» без версии. Системный pnpm 10.28.0 на этом репозитории падает (configDependencies без integrity), нужен pnpm 12 (/home/user/tools/bin). Каталога test/repros на 170ec52 нет, его нужно создать (мелочь).
2) Существующий тест не упомянут. Промпт не говорит, что в ветке experiment/bug-repros уже есть test/repros/BUG-412.test.ts с общим хелпером BUG-400-cache-project.ts. Тест из промпта даёт 9 ошибок ESLint; если оставить его в test/repros, `pnpm test` не будет зелёным. Не сказано, что после переноса в test/adapters/vitest/index.test.ts этот файл надо удалить.
3) Обоснование для define неверно. Vitest 5 (node) убирает define из конфига Vite (deleteDefineConfig) и присваивает globalThis[key] в каждом воркере (setupDefines). Ключи с точками и не-JSON значения идут через скрипт _scriptDefines. Поиск идентификатора в тексте зависимостей — лишь эвристика: она пропустит globalThis[вычисляемое имя] или перебор globalThis. Надёжнее записывать чтения через геттеры на globalThis, по аналогии с trackEnvironment, либо явно принять эвристику как компромисс.
4) Детали inject не описаны. inject(key) — это getWorkerState().providedContext[key]; обернуть ESM-экспорт непрактично, реальная точка — Proxy на workerState.providedContext в runner. При этом надо исключить собственное чтение mootant (this.injectValue('mootant'), runner.ts:476).
5) Не названы места, где строится ключ тестового файла: core/cache/get-test-file-keys.ts (variables/file.environment, строки ~39-60), core/cache/prepare-run-cache.ts и types/adapter/cache-inputs.d.ts (куда класть хеши значений provide по проектам).
6) Не сказано, что существующий unit-тест test/adapters/vitest/get-cache-inputs.test.ts (ожидания values около строк 136-137 и 157-158) фиксирует текущее поведение со значениями provide и define целиком. Его придётся переписать.
7) В «Ожидаемом поведении» требуется, чтобы отчёт сообщал о смене ключа из-за provide, но в критериях готовности нет ни теста на это, ни указания, куда писать (RunResult.diagnostics или stderr).
8) Для define нет готового кода воспроизведения. Есть только ссылка на скрипт в ветке analysis/2026-11, которой в чистом клоне azat-io/mootant нет. Хватило бы варианта vitest.config: `{ define: { __BUILD_TIME__: JSON.stringify(new Date().toISOString()) }, test: {...} }` без globalSetup — он даёт 0/3.
9) Не упомянуто, что --incremental тоже не помогает (0/8). Не сказано, как увидеть симптом через CLI: во втором прогоне нет строки «Reused cached verdicts for N of M mutants», а поле cached и summary.totalCached есть только в выводе --json --verbose.
