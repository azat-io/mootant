2. КОНТРАРГУМЕНТЫ. Они снижают серьёзность, но не опровергают находку.

(а) Поведение задокументировано и задумано.
- docs/content/guide/compatibility.mdx:56-57: «Tests that load a mutated file only through a computed import() may not be selected».
- Автор внёс эту оговорку ещё в коммите 9c27d69 (2026-10-18, readme); в 170ec52 её перенесли в гайд.
- docs/content/guide/cli.mdx:29: «Mootant selects test files related to the mutated code».
- Контракт: types/adapter/dry-run-request.d.ts:26-32.
- Следствие «тест не запущен → его убийства не засчитаны» прямо вытекает из «not selected». Это то же ограничение, что у самого `vitest related`/`--changed`.

(б) Обход существует, хотя в документации Mootant не описан.
- Штатная опция Vitest `test.experimental.recordDependencies: true` («...instead of the static module graph. A test file without a record always runs»).
- Mootant форсирует `cache: false` (adapters/vitest/start-vitest-session.ts:106). Поэтому `DependenciesCache.path` равен null (5.0.5 :6125), записей нет, и `RecordedModulesResolver` возвращает все спецификации (`if (!dependencies) return specs`, 5.0.5 :10276, 5.1.0 :6905).
- Проверено в .../recdeps (5.1.0) и .../pnpm505rd (5.0.5): `dry run 2 tests`, `killed 1`.
- То есть «опция запуска всех тест-файлов в dry run», которую предлагает промпт, де-факто уже есть. Но она держится на побочном эффекте `cache: false` и нигде не описана.

(в) Неточности в промпте.
- «Предупреждений нет» верно для обычного вывода и `--json`. Но с `--verbose`, как в команде из промпта, печатается предупреждение Vite: `invalid import "../src/${name}" ... File: test/dynamic.test.js` (только для шаблонной формы).
- «Ядро уже разбирает import() в тест-файлах» — только в файлах из dry run (core/run-mutants.ts:465-467). Невыбранный файл ядро не разбирает. Для предупреждения нужно разбирать весь `listTestFiles()` (core/run-mutants.ts:378).
- `npm i -D vitest@5.0.5` упирается в баг arborist в npm 10.9.9. На 5.1.0 через npm и на 5.0.5 через pnpm результат одинаковый.

(г) Серьёзность завышена.
- Ошибка консервативная: занижает оценку тестов (ложный Survived/NoCoverage). Ложного Killed и ложной уверенности она не даёт; с `--threshold` скорее вызовет лишнее падение, чем скроет слабые тесты.
- Узкий триггер. Нужен неразбираемый спецификатор: самый частый шаблон «по имени» `${name}.js` выбирается. Кроме того, нужен второй тест, который статически достаёт модуль и не проверяет результат. Иначе будет NoCoverage с `never-served`.
- Для калибровки: BUG-205 (`createRequire`, не задокументирован) оценён как low.
- Реальный вред: потерянное время и вводящая в заблуждение подсказка «test: test/static.test.js».

ВЫВОД: refuted=false. Документация не называет следствия и обхода, диагностики нет, вердикт тихо расходится с оракулом. Но это задокументированное и осознанное ограничение механизма Vitest, с консервативным направлением ошибки и рабочим обходом. По сути это доработка диагностики и документации, а не дефект корректности уровня medium, поэтому severity=low.
