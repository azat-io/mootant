ЧТО ЧАСТИЧНО ОСЛАБЛЯЕТ НАХОДКУ
(а) Для O19 — основной пример промпта и большинство затронутых строк (166/357 и 205/268) — сохранение пропуска задокументировано и задумано:
- mutators.md:64: «`owned` changes stay skipped»;
- statement-removal.md:227 и return-value.md:187: «The other changes stay skipped»;
- create-static-run-context.ts:4-8: «never depends on the preset or on comments».
Поэтому требование промпта выдать `statement-removal: ;` и его фраза «так уже устроен `context.runs` для ignore-комментариев» к O19 не подходят: O19 ignore-комментарии сознательно не учитывает. Решение, согласованное с документацией: при `--since` добавлять в отбор владельца (`by`) пропуска, стоящего на изменённой строке. Id при этом не меняются.
(в) Мелкие неточности:
- В фикстуре без `--since` выживает 1 мутант, а не 2: `user.isAdmin -> true` убивается TypeError, потому что у тестовой двери нет метода `open`. Итог 5 убито, 1 выжил.
- «Правка вызова внутри if не тестируется» — это обобщение: эффект есть только для if без else, где ветка состоит из одного оператора, и на строке нет других кандидатов.
