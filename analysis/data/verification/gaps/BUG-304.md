## Пробелы промпта (воспроизводящий агент)

1) Сквозная проверка опирается на фикстуру analysis/data/skips/fx1. Её нет в upstream azat-io/mootant, а содержимое теста в промпт не вставлено, есть только фраза «шесть входов, проверяются только вызовы report». Теста хватило восстановить по описанию, но текст лучше вставить. Кроме того, package.json фикстуры пинит vitest 5.0.5 (с npm 10.9.9 ловит баг arborist) и ссылается на file:../../../artifacts/...tgz, а этот путь от её каталога не резолвится (analysis/artifacts нет). Не сказано, как поставить mootant (tgz или сборка) и что конфиг не нужен: vitest определяется автоматически.
2) В «Воспроизведении» нет команды, которая показывает пропуск: npx mootant list src/validate.js --skipped, а для поля by ещё --json. Блок «Фактическое поведение» оформлен не так, как реальный вывод CLI («6:10 return-value ok -> true subsumed R6» плюс строка причины).
3) Контрольный пример в критерии готовности, `let ok = a > 0 && b; return ok`, без типов не булев: в .js или в .ts без аннотаций он даёт `ok -> undefined (subsumed solitary)`, и R6 нет даже на 170ec52. Нужно `b: boolean` (хелперы по умолчанию работают с example.ts) или `b > 0`.
4) «Только отключение мутатора-владельца» — упрощение. В примере после выключения comparison-operator R6 переходит к logical-operator, и константы возвращаются только при выключенных обоих.
5) Для исправления: Binding.references содержит и чтения, и цели записи. Предикат «единственное чтение — этот return» должен исключать цели простого `=` (существующий тест return-value.test.ts:671 `let ok = check(); if (a) ok = a > 2; return ok` обязан сохранить R6), считать чтением составные записи (`||=`, тест :680) и учитывать чтения в замыканиях. В промпте этого нет.
6) Repro покрывает только чтение в ветке и источник-инициализатор. Тот же ложный R6 я получил при чтении через вызов (`log(ok)`) и при источнике-записи (`ok = a > 2; if (!ok) ...`). Эти случаи стоит добавить в тест исправления.
7) Полезно было бы сказать, что существующие тесты 170ec52 ошибочное поведение не закрепляют: там локальные переменные читаются только в return, и все 164 теста зелёные.

- core/skips/skip-rules.ts:322-325: у R6 `heuristic: false`.
- Сильный довод против версии «так задумано»: core/mutators/missing-await.ts:152-179 (`isReturnedLocal`). Там при аналогичном переносе свойства с инициализатора локальной переменной на `return` автор явно требует `binding.references.length !== 1` (строка 162). Значит, условие «единственное чтение» ему известно, и в R6 его нет по упущению, а не по замыслу. JSDoc return-value.ts:191-195 подтверждает, что расширение на локальные переменные задумано, но без этого условия.
