## Скептик (refuted=false, severity=medium)

Итог: опровергнуть не удалось. Серьёзность medium, на нижней границе. Это задокументированный компромисс, который противоречит контракту категории `equivalent` (дефект дизайна), а не ошибка реализации.

(в) Код прочитан верно.
- core/mutators/shared/get-logical-drops.ts:80-84: keepsFalsyDefault = hasDefinedFalsyValue && !mayBeNullish && isCanonicalFalsy.
- :158-160: для `||` возвращается falsyDefaultNote (:89-93) с безусловным reason «…so the result is the same»; :119-121 делает то же для `&&`.
- get-canonical-falsy.ts:5-17 («`0` for a number (`NaN` ignored)»), is-canonical-falsy.ts:19-22.
- skip-rules.ts:10-13: equivalent, heuristic:true.
- Тип выводится синтаксически: well-known-calls.ts:57,77,95,96 (parseFloat, parseInt, Number, Math.* → number); `/` и унарный `+` тоже дают number.

(б) Это не артефакт окружения: поведение детерминировано, тайминги не влияют.
- test/repros/BUG-307.test.ts в /home/user/wt/bug-repros упал в 3 прогонах из 3: выдаётся только `done / total || 0 -> 0`.
- Сквозная проверка: пакет tgz + vitest 5.1.0 (npm), каталог /home/user/projects/verify-skeptic/BUG-307/e2e. `mootant list --skipped` помечает как `equivalent canonical-falsy-default` случаи `Number(text) || 0`, `done / total || 0`, а также `+text || 0`, `sum / values.length || 0` и TS `count: number` → `count`. `mootant run`: все мутанты toCount, ratio, avg и plusParse убиты.
- Физическая замена, каталог /home/user/projects/verify-skeptic/BUG-307/phys: тесты проходят 6 из 6. При этом ratio(0,0), toCount('abc'), plusParse('x') и avg([]) возвращают NaN вместо 0.

(а) Поведение действительно задокументировано и задумано. Это главный контраргумент:
- logical-operator.md:205 и assignment-operator.md:180: «Default is the type's only falsy value, `NaN` aside» (добавлено коммитом 885d614);
- флаг heuristic:true;
- mutators.md:46-48: «A category is Mootant's decision, not a proof»;
- readme.md:58: «likely equivalent».

Но это не делает поведение согласованным:
1. Определение категории в mutators.md:38 — «Can't alter what the code does, apart from details such as `undefined` for `null`». NaN→0 — не «деталь». Для number `x || 0` отличается от `x` только при NaN и -0, то есть правило скрывает единственное, что этот код делает.
2. В текстовом выводе CLI причина безусловна, флаг heuristic виден только в --json. Пример в документации строковый (`note || ''`).
3. Ровно то же NaN-различие в `nullish-swap` отнесено к `noise` и возвращается через `nullishSwap:'always'`/strict (logical-operator.md:162-166 и 206, assignment-operator.md:150-152). `canonical-falsy-default` не возвращается ничем: проверено с `--preset strict --json`, пропуск остаётся (logical-operator.md:227 «The other changes stay skipped»).
4. Результат зависит от того, насколько хорошо выведен тип. `Number.parseInt(text, 10) || 0` нет в well-known-calls, поэтому он получает свап `?? 0`, и этот мутант выжил в моём прогоне именно из-за отсутствия NaN-теста. Для `Number(text)`, `parseInt(...)`, `a / b` и `+s` такого мутанта нет.

(г) Серьёзность: medium оправдана.
- Ложное `equivalent` исключает мутант из знаменателя: получается 100% при непроверенной защите от NaN.
- Пропуск нельзя вернуть ни пресетом strict, ни опцией.
- Идиома распространена: grep по зависимостям bug-repros дал 22 вхождения `Number/parseInt/parseFloat(...) || 0` в 12 пакетах.
- Оценка согласуется с соседними находками: BUG-302 (не возвращается strict) — medium; BUG-312 — low, потому что `null`→`undefined` прямо названо «деталью» в определении категории.

Доводы за понижение:
