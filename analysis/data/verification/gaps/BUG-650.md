## Пробелы промпта (воспроизводящий агент)

2. Не сказано, во что обходится `pnpm docs:build`. Нужен предварительный `pnpm install`. Сборка шла ~2 мин 20 с под нагрузкой: хук `astro:build:start` интеграции report-demo (docs/plugins/report-demo.ts) запускает `vite build` CLI и `mootant run --html` на docs/demo. Это важно, если проверку ссылок захотят делать по собранному сайту внутри тестов.

3. В промпте для grep ожидается одно совпадение, а выводится две строки. Вторая — keyword `'agent-skills'` в docs/pages/index.astro:12.

4. Сказано «рядом с другими тестами документации, если они есть», но не сказано, что их нет. В test/ только adapters/cli/core/fixtures/helpers, а docs/demo/test — тесты демо-проекта, исключённые в vitest.config.ts. Не упомянуто:
   - пороги покрытия 100% действуют только для adapters/cli/core;
   - `test:astro` — это `astro check` (проверка типов), поэтому «скрипт в test:astro» означает менять этот скрипт;
   - сопоставлять href с маршрутами статически непросто: `/guide/getting-started` идёт через динамический `guide/[slug]` и id коллекции, `/mutators` — через `mutators/index.astro`. При `build.format: 'file'` страницы выходят как `x.html`.

5. Нет однозначного решения, что делать. Выбор «страница или временный якорь» зависит от BUG-651, которого отдельная сессия не видит. Стоило прямо написать, что в 170ec52 нет ни SKILL.md, ни каталога skill, поэтому по разделу «Ограничения» сейчас ожидается запасной вариант `/guide/getting-started#let-an-agent-fix-them`. Этот якорь я проверил: он существует.

6. Команда `--skill mootant` расходится с текущими доками, и это никак не объяснено.

7. Полезный факт для объёма работы: `/agent-skill` — единственная битая внутренняя ссылка на всём собранном сайте (27 страниц), а 404.html и report/demo.html меню не содержат.

8. Мелочь по окружению: mootant.org из песочницы недоступен (прокси 403), поэтому прод-поведение проверяется только локально через `astro preview`.
