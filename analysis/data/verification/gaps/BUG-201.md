## Пробелы промпта (воспроизводящий агент)

## Скептик (refuted=false, severity=low)

Итог: находку опровергнуть не удалось. Поведение реальное и детерминированное, код прочитан верно. Но серьёзность medium завышена: я ставлю low. Причины: корень частично задокументирован, триггер через vi.mock намного уже, чем описано, а ошибка всегда пессимистичная.

1. Это не артефакт окружения, поведение воспроизводится.
- Эксперимент в /home/user/projects/verify-skeptic/BUG-201/base: тарбол 170ec52, vitest 5.1.0 через npm, CLI.
- `run src`: мутант jnhjhh9w (`user${id}` → '') получает Killed.
- `run src --mutant jnhjhh9w`: NoCoverage, 2 из 2 запусков.
- `run src/api.js`: NoCoverage, 2 из 2.
- `--since HEAD` после правки строки 2 src/api.js: оба мутанта строки NoCoverage, score 0. С `--threshold 50` код выхода 1, у полного прогона с тем же порогом — 0 (/home/user/projects/verify-skeptic/BUG-201/since-check).
- То же показывает oracle на vitest 5.0.5 через pnpm (results/mocks: iso-mocks-A, only-api, since — NoCoverage; default — Killed).
- Отбор тестов делает статический анализ, поэтому нагрузка, root, TERM и npm на результат не влияют.
- Сам Vitest ведёт себя так же: `vitest related src/api.js` выдаёт «No affected test files found», а `related src/service.js` тест находит.

2. Код прочитан верно, с одной натяжкой.
- Ссылки подтверждаются:
  - core/run-mutants.ts:658-663: остаются только файлы с выбранными мутантами;
  - core/run-mutants.ts:202-210 и :379-394: switched = hosting;
  - core/run/run-dry-phase.ts:156;
  - adapters/vitest/run-dry.ts:225-236;
  - adapters/node-test/run-dry.ts:75-80 и :127-129.
- Натяжка: JSDoc core/run-mutants.ts:340-342 появился в коммите 2e203ef «perf: rank test files by covering tests». Вместе с ним добавлен тест «hosts the other pending mutants of the files of the selected mutants in the dry run».
- То есть комментарий говорит о хостинге мутантов внутри файла, а не о том, что вердикт не зависит от состава файлов прогона. «Комментарий утверждает обратное» — пережатое прочтение, хотя общая формулировка комментария действительно неточна.

3. Корень частично задокументирован.
- docs/content/guide/compatibility.mdx:56: «Tests that load a mutated file only through a computed `import()` may not be selected».
- Вариант v4 (вычисляемый `import()`, без vi.mock) даёт ту же картину: полный прогон Killed, `--mutant` и узкий путь NoCoverage.
- Значит, несогласованность — проявление задокументированного ограничения. Узкий прогон ведёт себя ровно как в документации, а полный прогон верен по случайности: тест попадает в него через другой переключаемый файл.
- Не задокументированы случай с фабрикой vi.mock и то, что вердикт зависит от состава прогона.

4. Триггер через vi.mock уже, чем описано.
- В @vitest/mocker (chunk-hoistMocks.js:549) правило такое: `factoryLoadsOriginal = factory.params.length > 0 || code.slice(factory).includes("importActual")`.
- В vitest (index.1TqnEahn.js:862, resolveStaticMocks) модуль помечается как подменённый (replaced) только если это правило не сработало. Фабрика, переданная не inline-функцией, получает hasFactory=false и ничего не подменяет.
- Эксперименты, во всех трёх прогонах (полный, `--mutant`, узкий путь) стабильно Killed:
  - v1: идиоматичная фабрика `async importOriginal => …`;
  - v2: прямой `vi.importActual` в фабрике;
  - v3: тот же хелпер, но с именем `importActualModule`.
- Хелпер `loadActual` в фикстуре (и в oracle) обходит именно эту проверку подстроки.
- Реальный триггер: inline-фабрика без параметров, которая грузит оригинал через хелпер, в имени которого нет `importActual`, либо вычисляемый `import()`. Плюс тест должен статически импортировать другой мутируемый файл, иначе NoCoverage стабилен и это уже задокументированный случай.

5. Ошибка всегда пессимистичная, поэтому вред ограничен.
- Неверный вердикт — только NoCoverage или Survived вместо Killed. Ложного Killed нет, score не завышается, реальные пробелы в тестах не скрываются.
- Кэш не портится. В /home/user/projects/verify-skeptic/BUG-201/cache-check после `--mutant` (NoCoverage) полный прогон с кэшем снова даёт Killed: NoCoverage не кэшируется (core/cache/apply-cached-units.ts:18-49).
- В фикстуре с одним тестом узкие прогоны выдают предупреждение never-served для src/api.js (core/run/run-dry-phase.ts:360-366). Правда, его текст «no test imports it» вводит в заблуждение. В oracle, где есть другие тесты, предупреждения нет.

6. Сценарий с recheck узже, чем в находке.
- По умолчанию отчёт показывает recheck только для NoCoverage, Survived и Error (cli/report/build-run-report.ts:19-23, :89, :101-104). Показанный случай «Killed в полном прогоне → NoCoverage при перепроверке» требует `--all`.
- Реально вредный случай уже: новый тест с таким экзотическим паттерном не засчитывается при перепроверке или в `--since`.

7. Почему low, а не medium.
- Аргументы против понижения:
  - вред реальный: в CI `--since` вместе с `--threshold` (это основной CI-сценарий из cli.mdx:104-108) может ложно упасть;
  - цикл агента с перепроверкой даёт противоречивые вердикты.
- Аргументы за low:
  - триггер узкий и частично задокументирован;
  - вердикт ошибается только в пессимистичную сторону;
  - полный прогон верен;
  - корень в AffectedModulesResolver самого Vitest.
- Предложенное минимальное исправление (related = listing.files) сделает dry run при `--mutant` и `--since` таким же тяжёлым, как полный, а случай с узким путём (`run src/api.js`) им не исправить в принципе.
