# Промпты по ускорению Mootant

Самодостаточные промпты для отдельных сессий Claude Code в репозитории
azat-io/mootant, по одному на каждый ранг списка ускорений
[`04-performance.md` §4.4](../04-performance.md#44-ранжированный-список-ускорений).
Числа сняты на коммите 170ec52 (окно 2026-11-04: 4 vCPU, Node 22.23.4, Vitest
5.0.5, 3 прогона, `--concurrency 3`). Ссылки на код сверены с `main` на bd7af11
(2026-11-22). На bd7af11 ни одно из ускорений ещё не сделано.

Промпты опираются на опубликованную ветку `analysis/2026-11`: diff прототипов,
стенд и скрипт сравнения вердиктов берутся командами из самих промптов
(`git fetch origin analysis/2026-11`). Общее правило: ускорение не меняет
вердиктов, и любое расхождение с базой блокирует слияние.

## С чего начать

- Быстро и безопасно: PERF-06 (готовый diff накладывается на `main` без
  конфликтов), PERF-03 и PERF-05.
- Самый крупный измеренный выигрыш — PERF-01. От него зависят PERF-04 и
  PERF-07: префорк посчитан поверх PERF-01, а выигрыш PERF-07 после PERF-01
  падает с −80…−140 с до примерно 5 %, так что о нём лучше решать после
  PERF-01.
- PERF-02 и PERF-08 пересекаются по кэшу `hit-limit`-тайм-аутов: тот, кто
  вливается вторым, переиспользует запись первого.
- PERF-09–PERF-12 — исследования: сначала замер, затем решение по критерию из
  промпта. PERF-09 к тому же идёт против решения автора: с 2e203ef порядок
  тест-файлов намеренно не зависит от длительностей
  (`core/run/rank-mutant-files.ts:19-22`), чтобы план был одинаковым на каждом
  прогоне. Анализ это упустил, поэтому без согласия автора его не делать.

## Чего не делать

Отрицательные результаты анализа (`04-performance.md` §4.4). Промптов на них
нет:

- обрезка isolated-юнита до покрывающих тестов (прототип P2) дала ложные
  Survived;
- кэш трансформаций Vite между прогонами сэкономит не больше 0,4–2,0 с CPU за
  прогон;
- «ускорить dry run»: он уже стоит ×1,0–1,2 обычного прогона тестов. Беда в
  том, что он идёт всегда, и это закрывает PERF-02;
- сортировка юнитов раунда по стоимости (LPT): секвенсор Vitest уже ставит
  большие файлы первыми;
- `--fast` как средство для больших проектов: на perfectionist ×1,00.

## Как проверены

PERF-01–PERF-06 подробные, 500–730 строк. Автор каждого сверил код с `main`,
проверил наложение diff (`git apply --check`) и пути в ветке анализа.
PERF-07–PERF-12 короче, около 250 строк, и оформляют только то, что анализ уже
нашёл. Независимой перепроверки, как у bug-prompts, не было. Автоматически
проверены все относительные ссылки и все ссылки `path:строка`: без пометки — на
`main` bd7af11, с пометкой — на 170ec52.

Шаблон — [`_TEMPLATE.md`](_TEMPLATE.md). Список промптов печатает
`node analysis/tools/list-perf-prompts.mjs`.
