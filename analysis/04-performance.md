Кратко (подробно — `analysis/bench/README.md`):

- **Инструменты**: Mootant `170ec52` (devDependency проекта из tarball, как

- **Честность сравнения**: одинаковые файлы (конфиг Stryker генерируется из того

  `analysis/bench/lib/make-stryker-config.mjs`), одинаковая конкурентность

- **Метрики** (определения — README стенда, «Метрики»): wall (медиана, min–max,

### Что именно меряют фазы Mootant (по коду)

`core/run-mutants.ts:533-540`:

| поле | интервал | что внутри |
|---|---|---|
| `startup` | `started` (`:171`) → `dryStarted` (`:410`) | загрузка конфига, поиск файлов, парсинг, генерация мутантов, эвристики (`listFileMutants`, `:192`), чтение изменённых строк git (`--since`), выбор адаптера, **запуск Vitest** (`adapter.start`, `:275`), список тест-файлов, инструментирование (`createSwitchedFiles`, `:390`) |
| `dryRun` | `dryStarted` → `batchStarted` (`:491`) | dry run (`runDryPhase`, `:411`), разбор (`readDryRun`), **подготовка кэша** (`prepareRunCache`, `:442-459`: хэши входов), `createRunState`, `readTestImports`, применение кэша (`reuseCachedVerdicts`, `:489`) |
| `batch` | `batchStarted` → `isolatedStarted` | только в `--fast` |
| `isolated` | `isolatedStarted` → `finished` (`:531`) | раунды isolated, **сохранение кэша** (`saveRunCache`, `:516`) |
| `total` | `started` → `finished` | не включает закрытие Vitest (`session.close`, `:321`), удаление рабочего каталога (`:324`), построение и печать отчёта (`cli/run-mutation.ts:59-72`), запуск самого node и загрузку модулей CLI |

Поэтому в сводке есть колонка «вне total» = wall − total. Поиск файлов,
парсинг, генерация, эвристики и инструментирование внутри `startup` отдельных
полей не имеют; их делит CPU-профиль главного процесса (`analysis/bench/profile.sh
<project> list run`: инклюзивное время модулей `core/files/expand-paths.js`,
`core/generate/generate-file-mutants.js` (внутри — парсинг oxc),
`core/generate/collect-candidates.js` (мутаторы и эвристики),
`core/generate/deduplicate-candidates.js`, `core/generate/get-mutant-regions.js`,
`core/instrument/create-switched-files.js`, `adapters/vitest/start-vitest-session.js`
— dist минифицирован, но в каждом файле одна функция; self-время по группам
`mootant/core/hints`, `mootant/core/skips`, `oxc-parser` и т.д.).

### Что видно о стоимости юнита (по коду)

Юнит isolated = (мутант, тест-файл) в свежем форк-процессе: Mootant
принудительно ставит `isolate: true` и свой пул форков
(`adapters/vitest/configure-project.ts:46-48`), отключает кэш трансформаций на
диске (`:54`, `adapters/vitest/start-vitest-session.ts:104`). В записях воркера
есть всё для разбивки (`adapters/vitest/runner.ts:924-941`):

- `startup` юнита = `booted − spawned`: от `fork` до `onBeforeCollect` — старт
  node, инициализация воркера Vitest и окружения
  (`adapters/vitest/build-isolated-facts.ts:48`, время spawn пишет пул:
  `adapters/vitest/create-forks-pool.ts:63-69`); в отчёт попадает только в сумме
  `summary.staticCost[].duration` (`core/run/compute-static-cost.ts:32`,
  `core/run/apply-isolated-result.ts:67`), а `mutants[].duration` — без него
  (`:66`), так что Σ startup = Σ staticCost.duration − Σ mutants.duration;
- ожидание очереди = от `claim` до открытия out-файла: юнит ждёт, пока процесс
  предыдущего юнита того же тест-файла не завершится
  (`adapters/vitest/worker/wait-for-turn.ts:11`, `:32-49`: опрос раз в 20 мс, пока
  жив процесс предыдущего юнита; `adapters/vitest/runner.ts:534-541`);
- `loadDuration` = сбор тест-файла (импорт теста и всего, что он тянет, вместе с
  запросами трансформаций к Vite главного процесса; `runner.ts:585`);
- время тестов = сумма `tries[].duration`; остальное в `duration` — хуки и
  teardown.

Скрипт `lib/units-report.mjs` собирает эти величины по трассе и даёт по
каждому раунду занятость слотов, долю ожидания очереди файла, хвост и самую
длинную последовательную цепочку одного тест-файла.

Подмножества подобраны так, чтобы полный прогон Mootant в обычном режиме

- perfectionist — правило со своим тест-файлом плюс общие компараторы, до
  которых доходит почти каждый тест-файл правил.

догфудинга про `core/text` относится к модулю, который импортируют почти все

perfectionist с ним останется на обычном пути.

**`--mutant <id>`** — перепроверка одного мутанта, цикл агента: 2,1–7,4 с.
perfectionist: 7,4 с = startup 0,8 + dry run тестов, связанных с файлом
мутанта, 4,9 + isolated 1,1 + ~0,5 с вне `total`. Почти всё здесь — dry run,
его закрыл бы частичный снимок (P3, «частичный повтор»).

**`--incremental` после правки** — одна функция без смены поведения
(`edit.patch` проекта), 3 прогона на проект:

| проект | правка | wall, с | из кэша | прогнано заново | фазы: dry run / isolated, с |
|---|---|---|---|---|---|
| perfectionist | `statementIsBreakOrReturn` в `rules/sort-switch-case.ts` | 276,6 ± 4,3 (×3,4) | 146 из 314 | 160 из 187 мутантов изменённого файла + 8 некэшируемых (6 NoCoverage, 2 Timeout) | 44–47 / 226–231 |

Что видно:

- **Регион мутанта крупный.** Он включает то, что мутант использует в своём
  файле. Если правка задевает функцию, которую вызывает тело правила
  (perfectionist) или класс `Serializer` (fast-json-stringify), заново идёт
  большая часть файла.
- **Остаток стоит как маленький холодный прогон.** На perfectionist первый
  раунд — снова цепочка `sort-switch-case.test.ts`: 160 юнитов, 209 с из 225 с
  isolated-фазы. Ускорения 1 и 3 из 4.4 сократили бы и её.
- **Timeout повторяются и здесь**, как в тёплом прогоне.
- **Вердикты те же**, что у холодного прогона. Статусы совпали по всем общим
  id: 311, 341, 493 и 297 мутантов (perfectionist, path-to-regexp, cheerio,
  fast-json-stringify). Остальные мутанты стоят на изменённых строках и
  получили новые id. Тёплый прогон тоже дал 0 расхождений с холодным на всех
  четырёх проектах. Правка поведения не меняет, так что устаревших вердиктов
  здесь и не ждали. Проверка кэша на правках, меняющих поведение, — раздел 2.

**`--since bench/base`** — синтетический коммит с той же правкой, без кэша:

| проект | wall, с | мутантов на изменённых строках | фазы: startup / dry run / isolated, с |

`--since` на маленьком диффе — это пол «старт + dry run тестов изменённых
файлов + несколько мутантов». Всё, что сверх, — выжившие. На

юнитов, 33 с. Это ровно сценарий PR в CI, и здесь же видна цена раундов
(ускорение 3 из 4.4).
