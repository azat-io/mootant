# BUG-603: node:test — честно долгий тест со своим `timeout` обрывает прогон как «зависший»

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Dry run запускает тесты без мутантов под сторожем: бюджет попытки — 60 с
плюс собственные таймауты раннера, потому что таймауты раннера не прерывают
синхронный цикл (`core/run/run-dry-phase.ts:106-114`). Зависание в dry run
останавливает весь `mootant run` (`core/run/run-dry-phase.ts:477-493`).
Vitest-адаптер добавляет к бюджету таймаут самого теста и таймауты его
хуков (`adapters/vitest/runner.ts:989-998`,
`adapters/vitest/worker/get-hook-budget.ts`). node-test-адаптер добавляет
только `--test-timeout` из флагов (`adapters/node-test/get-dry-deadline.ts:17-28`,
`adapters/node-test/read-test-timeout.ts`), но не `timeout` из опций
`test()`/`it()`/`describe()`/хуков. Поэтому тест, которому разрешено идти
дольше 60 с (интеграционный, с `{ timeout: 120_000 }`), — и который
`node --test` проходит — убивается, и прогон падает с сообщением ядра,
утверждающим обратное: «did not finish within 60 s plus its own timeout and
the timeouts of its hooks» (`core/run/run-dry-phase.ts:489`). То же для
`before`/`after`-хука дольше 60 с (бюджет вне попыток —
`DRY_TIMEOUTS.file` + `--test-timeout`).

## Воспроизведение

```bash
mkdir -p /tmp/bug603/{src,test} && cd /tmp/bug603
cat > package.json <<'EOF'
{ "name": "bug603", "private": true, "type": "module", "scripts": { "test": "node --test" } }
EOF
cat > src/price.js <<'EOF'
export function isFree(price) {
  return price <= 0
}
EOF
cat > test/slow.test.js <<'EOF'
import { it } from 'node:test'
import assert from 'node:assert/strict'

import { isFree } from '../src/price.js'

it('waits 65 s, then checks', { timeout: 120_000 }, async () => {
  await new Promise(resolve => setTimeout(resolve, 65_000))
  assert.equal(isFree(0), true)
})
EOF
echo "export default { run: { paths: ['src'], runner: 'node-test', cache: false } }" > mootant.config.js
npm i -D <path-to>/mootant.tgz

node --test; echo "plain exit=$?"          # exit 0 за ~65 с
npx mootant run; echo "mootant exit=$?"    # exit 1 за ~63 с
```

## Ожидаемое поведение

Тест, который проходит в обычном `node --test` за время меньше своего
`timeout`, проходит dry run; сторож срабатывает не раньше «60 с + собственный
таймаут теста (и его хуков)». Сообщение о зависании называет фактически
применённый бюджет.

## Фактическое поведение

```
plain exit=0   (65,7 с)
Error: Tests hang without mutants: "waits 65 s, then checks" in test/slow.test.js did not finish within 60 s plus its own timeout and the timeouts of its hooks, and its worker was stopped.
mootant exit=1 (63 с)
```

Тот же тест на Vitest (`it(…, 120_000)`) проходит dry run (66 с) и получает
вердикт.

## Подозреваемые места в коде

- `adapters/node-test/get-dry-deadline.ts:17-28` — бюджет без собственного
  таймаута попытки.
- `adapters/node-test/preload/create-try-tracker.ts:233-276` (`open`) — здесь
  удобно записать в `open`-запись собственный таймаут попытки, но
  `TestContext` его не отдаёт. Реалистичные источники: (а) обёртка
  `test`/`it`/`describe`/`before`/`after`/`beforeEach`/`afterEach` модуля
  `node:test` в preload, запоминающая `options.timeout` по полному имени;
  (б) события репортёра (`adapters/node-test/preload/create-report-reader.ts`),
  если в используемых версиях Node они несут таймаут. Проверить на Node
  20.19, 22 и 24.
- `core/run/run-dry-phase.ts:486-490` — текст сообщения не должен обещать
  то, чего адаптер не учитывает (например, брать формулировку из
  `DryRunResult.hung` или из возможностей адаптера).

## Критерий готовности

- node-test учитывает собственный таймаут теста, набора и хука в бюджете dry
  run (или, если он недоступен, использует безопасный верхний предел и пишет
  предупреждение), а сообщение ядра соответствует реальному бюджету.
- Новый тест `test/adapters/node-test/get-dry-deadline.test.ts` (бюджет с
  собственным таймаутом попытки) и интеграционный тест в
  `test/adapters/node-test/index.test.ts` с уменьшенным для теста бюджетом
  (например, через внедряемые `DRY_TIMEOUTS`), где тест со своим большим
  `timeout` идёт дольше бюджета mootant и **не** считается зависшим; падает до
  исправления, проходит после.
- Тот же сценарий для Vitest остаётся зелёным (контрольный тест).
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
