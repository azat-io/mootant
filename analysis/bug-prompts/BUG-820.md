# BUG-820: yarn PnP + `node:test` — прогон молча бесполезен (все мутанты NoCoverage, exit 0)

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён (эксперимент M10
> агента раздела 7, `analysis/data/compat-experiments.md`). Найдено на коммите
> 170ec52.

## Контекст

Адаптер `node:test` переключает мутируемые модули своими module hooks
(`adapters/node-test/preload/install-module-hooks.ts`). Yarn PnP подключается
через `NODE_OPTIONS` с устаревшим `--experimental-loader .pnp.loader.mjs`.
Такой загрузчик срабатывает раньше хуков Mootant. Адаптер это замечает и
выдаёт только предупреждение `config-overridden`
(`adapters/node-test/start-node-test-session.ts:123-132`): «The loader … runs
before mootant's module hooks, so mootant cannot switch the modules it
changes.» Прогон при этом продолжается. Ни один мутант не переключается,
все получают `NoCoverage`, score 0%, а процесс завершается с кодом 0.
Пользователь видит «тесты ничего не покрывают», хотя тесты есть и рабочие.

## Воспроизведение

```bash
mkdir -p /tmp/bug-820 && cd /tmp/bug-820
corepack enable && yarn init -2 -y   # yarn 4, nodeLinker: pnp по умолчанию
yarn add -D mootant                   # или tarball этой сборки
mkdir -p src test
cat > src/sum.js <<'JS'
export function sum(a, b) { return a + b }
JS
cat > test/sum.test.js <<'JS'
import { test } from 'node:test'
import assert from 'node:assert/strict'
import { sum } from '../src/sum.js'
test('sum', () => { assert.equal(sum(2, 3), 5) })
JS
npm pkg set type=module scripts.test="node --test"
yarn mootant run src; echo "exit=$?"
```

## Ожидаемое поведение

Одно из двух:

1. Mootant переключает модули и под PnP-загрузчиком. Например, регистрирует
   свои хуки так, чтобы они срабатывали раньше устаревшего загрузчика, или
   оборачивает его.
2. Если переключение невозможно, прогон завершается ошибкой с понятным
   сообщением и exit 1: «yarn PnP loader … prevents switching; use
   nodeLinker: node-modules or Vitest». Нельзя выдавать отчёт с 0% и exit 0.

## Фактическое поведение

```
… 0 killed, 0 survived, 12 no coverage …   (на фикстуре эксперимента M10)
warning [config-overridden] The loader …/.pnp.loader.mjs runs before mootant's module hooks…
exit=0
```

## Подозреваемые места в коде

- `adapters/node-test/start-node-test-session.ts:123-132`: устаревший
  загрузчик понижается до предупреждения.
- `core/run/run-dry-phase.ts`: диагностика `never-served` для файлов, которые
  так и не были поданы переключёнными. Проверь, почему она не подняла ошибку
  в этом сценарии.

## Критерий готовности

- Тест в `test/adapters/node-test/start-node-test-session.test.ts` (или
  интеграционный в `test/adapters/node-test/index.test.ts`): при устаревшем
  загрузчике в `NODE_OPTIONS`, который мешает переключению, прогон либо
  переключает модули (вердикты совпадают с прогоном без загрузчика), либо
  завершается ошибкой с понятным текстом.
- `docs/content/guide/compatibility.mdx` упоминает Yarn PnP с `node:test`.
- `pnpm test` полностью зелёный, включая 100% coverage. Учти, что покрытие
  веток с `NODE_OPTIONS` зависит от окружения (см.
  `analysis/00-baseline.md`).

## Ограничения

- Стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc, `let`,
  строгий ESLint, cspell, knip.
- Не ломай поддержку других загрузчиков (`--import tsx` и т.п.), для которых
  переключение работает.
- Сообщения коммитов — Conventional Commits.
