# BUG-651: `npx skills add azat-io/mootant` не находит skill — в репозитории нет `SKILL.md`

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: high. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Mootant позиционируется как «mutation testing tool that ships with an agent
skill» (`package.json:4`). Документация предлагает поставить skill командой
`npx skills add azat-io/mootant` (`docs/content/guide/getting-started.mdx:136-145`,
`docs/components/Skill.astro:22-41`, сессия агента —
`docs/components/skill-session.ansi`). CLI `skills` (vercel-labs/skills)
клонирует репозиторий и ищет `SKILL.md` с YAML-frontmatter: в корне, в
`skills/<name>/` (до трёх уровней), в каталогах агентов (`.agents/skills`,
`.claude/skills`, …), а если ничего не нашлось — рекурсивно до глубины 5.
Файл принимается, если во frontmatter есть строковые непустые `name` и
`description`. В репозитории нет ни одного `SKILL.md` и каталога `skills/`;
нет их и в истории git, и в npm-пакете. Поэтому ключевая функция проекта
недоступна.

Образец раскладки, которую автор уже использует, — `azat-io/ghostwriter`:
`skills/ghostwriter/SKILL.md` и проверка skill в CI
(`scripts/lib/skill-validation.js`: frontmatter, `name` совпадает с именем
каталога, меньше 500 строк, ссылки внутри skill ведут на существующие файлы).

## Воспроизведение

```bash
mkdir /tmp/skill-check && cd /tmp/skill-check
npx -y skills@1.7.6 add azat-io/mootant; echo "exit=$?"
npx -y skills@1.7.6 add azat-io/mootant --list --full-depth; echo "exit=$?"
```

## Ожидаемое поведение

Команда находит skill `mootant` и ставит его (например, в
`./.agents/skills/mootant/SKILL.md` с симлинком `.claude/skills/mootant`).

## Фактическое поведение

```text
o  Source: https://github.com/azat-io/mootant.git
o  No skills found
—  No valid skills found. Skills require a SKILL.md with name and description.
exit=1
```

## Подозреваемые места в коде

- Нет файла `skills/mootant/SKILL.md` (и `skills/mootant/references/`).
- `package.json` (`files`) — если skill должен попадать и в npm-пакет.
- `docs/content/guide/getting-started.mdx:136-145` — после появления skill
  стоит писать `npx skills add azat-io/mootant --skill mootant`.

## Что положить

`skills/mootant/SKILL.md` по формату Agent Skills: `name: mootant` (совпадает с
каталогом), `description` до 1024 символов в третьем лице (что делает и когда
применять), `license: MIT`, `compatibility` (Node.js и раннеры), тело короче
500 строк. Черновик, проверенный CLI `skills` (находится `--list`, ставится
`-y`), лежит в ветке `analysis/2026-11`: `analysis/ux/SKILL.draft.md`. Его
опорные пункты, если черновик недоступен:

1. Подготовка: `npx mootant --version`; тесты зелёные; маленькая область
   (пути пользователя, `--since <base>`, один каталог); `.mootant/` в
   `.gitignore`.
2. Поиск: `mkdir -p .mootant && npx mootant run <paths> --json >
   .mootant/mutants.json`; stdout — только JSON; exit 1 с пустым stdout —
   прогон остановился (читать stderr); exit 1 с JSON — порог или `Error`.
   Поля мутанта: `id`, `file`, `line`, `column`, `mutator`, `scope`,
   `before`/`after`, `testFiles`, `test`, `recheck`, `message`. Большой отчёт
   читать по файлу.
3. Решение по каждому мутанту: эквивалентный (нет входа, на котором caller
   увидит разницу) — теста не писать, предложить
   `// mootant-ignore-next-line <mutator>: <reason>` и предупредить, что
   комментарий выключает все мутанты этого мутатора на строке; `Survived` —
   слабая проверка или нет границы; `NoCoverage` — тест, который вызывает
   код; `Error` — не дыра в тестах, сообщить `message`.
4. Тест: в `testFiles[0]`, в стиле файла, от `test`; точные значения, для
   ошибок — тип или форма (`toThrow('text')` проходит и при `throw undefined`);
   без снапшотов (Mootant их не пишет); исходники и существующие тесты не
   трогать.
5. Подтверждение: тест проходит обычным раннером; затем `recheck` (с `npx`,
   пока BUG-652 не исправлен), несколько `--mutant` за раз; никогда `--fast`.
6. Отчёт пользователю: убитые, эквивалентные с причиной, оставшиеся, score до
   и после.

`references/mutators/<id>.md` — разделы «Kill a surviving mutant» из
`docs/content/mutators/*.md` (по 220–360 токенов); лучше генерировать их
скриптом из документации, а не копировать руками.

## Критерий готовности

- `npx -y skills add <путь к репозиторию> --list` показывает `mootant`
  (проверить на локальном клоне до пуша).
- Появляется тест (например, `test/skills/skill.test.ts`), который читает
  `skills/mootant/SKILL.md` и проверяет: frontmatter парсится, `name ===
  'mootant'` и совпадает с каталогом, `description` — непустая строка до 1024
  символов, файл короче 500 строк, все относительные ссылки ведут на
  существующие файлы; если `references/` генерируется — что он не устарел
  относительно `docs/content/mutators/*.md`.
- Команды и флаги в SKILL.md существуют в `cli/parse-arguments.ts`
  (тест может проверять, что каждый `--флаг` из SKILL.md есть в
  `parserOptions`).
- `pnpm test` полностью зелёный (включая `test:format`, `test:spelling` —
  cspell проверяет и Markdown, `test:usage`).
- Ссылка «Agent skill» в шапке сайта ведёт на существующую страницу (см.
  BUG-650).

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip, Prettier для
  Markdown.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига).
- Текст skill — на английском, коротко, без обещаний сверх того, что делает
  CLI.
- Сообщения коммитов — Conventional Commits (commitlint).
