# BUG-900: прерванный isolated-юнит считается файлом «без улик» → ложный Survived

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: high. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

В режиме по умолчанию каждый покрытый мутант решается на isolated-пути: юнит —
один тест-файл целиком с активным мутантом, файлы мутанта идут в порядке
`rankMutantFiles`, вердикт — первая улика по `decideEvidence`
(`core/run/decide-evidence.ts:17-35`). Контракт `RunStatus`
(`types/run/run-status.d.ts:7-8`): `Survived` — «every test of the test files
that cover it passed … and one of them reached it».

`readIsolatedUnit` (`core/run/read-isolated-unit.ts:22-107`) возвращает `null`
(файл «done without evidence», `core/run/get-unit-evidence.ts:19-21`), когда
юнит **не выполнил тесты, которые достигают мутанта**, по причине, не связанной
с мутантом:

- тест, не достигший мутанта, превысил таймаут — `classifyTry` даёт `doubtful`
  (`core/run/classify-try.ts:29-33`), а раннер Vitest после любого таймаута
  бросает юнит (`adapters/vitest/runner.ts:886-888`) и пропускает оставшиеся
  тесты (`adapters/vitest/runner.ts:630-637`); флаг `abandoned` в
  isolated-режиме ядру не передаётся (`adapters/vitest/build-isolated-facts.ts:46-59`);
- упал suite-хук без достижения мутанта (`read-isolated-unit.ts:84` требует
  `facts.reached`), тесты не выполнялись; так же в адаптере `node:test`
  (`adapters/node-test/build-isolated-facts.ts:65-82`);
- suite-хук превысил таймаут без достижения (`read-isolated-unit.ts:64-74`).

Тогда решение переходит к следующему файлу, и при любом достигнутом проходе
мутант становится `Survived` без диагностики. Batch-путь те же события
обрабатывает консервативно (повтор в recovery, `core/run/run-batch-phases.ts:109-138`;
перевод на isolated, `core/run/apply-batch-result.ts:272-289`).

## Воспроизведение

Юнит-тест (ветка `experiment/bug-repros`, `test/repros/BUG-900.test.ts`):

```ts
import { describe, expect, it } from 'vitest'

import type { IsolatedResult } from '../../types/adapter/isolated-result'
import type { IsolatedPlan } from '../../types/adapter/isolated-plan'
import type { FakeWorld } from '../helpers/create-fake-adapter'

import { runIsolatedRounds } from '../../core/run/run-isolated-rounds'
import { getFinalStatus } from '../../core/run/get-final-status'
import { createTestRun } from '../helpers/create-test-run'

let tests: FakeWorld['tests'] = [
  { file: '/t/a.test.ts', id: 'a1' },
  { kills: { m: 'expected 2 to be 5' }, file: '/t/a.test.ts', covers: ['m'], id: 'a2' },
  { file: '/t/b.test.ts', covers: ['m'], id: 'b1' },
]

function spoilFirstRun(
  change: (facts: IsolatedResult['units'][number]) => IsolatedResult['units'][number],
): NonNullable<FakeWorld['onIsolated']> {
  return (result: IsolatedResult, plan: IsolatedPlan, call: number) =>
    call === 1 ?
      { units: result.units.map(facts => plan.units[facts.unit]!.file === '/t/a.test.ts' ? change(facts) : facts) }
    : result
}

async function runMutant(onIsolated: NonNullable<FakeWorld['onIsolated']>) {
  let { session, state } = await createTestRun({ onIsolated, tests }, { mutants: ['m'], isolate: true })
  await runIsolatedRounds(session, state)
  return getFinalStatus(state.mutants.get('m')!)
}

describe('BUG-900', () => {
  it('does not make the mutant Survived after an unreached test timed out and the rest of the file was skipped', async () => {
    let status = await runMutant(
      spoilFirstRun(facts => ({
        ...facts,
        tests: [{ ...facts.tests[0]!, message: 'Test timed out in 1000ms.', timedOut: true, reached: false, failed: true }],
        reached: false,
      })),
    )
    expect(status).not.toBe('Survived')
    expect(status).not.toBe('NoCoverage')
  })

  it('does not make the mutant Survived after an unreached suite hook failed and no test ran', async () => {
    let status = await runMutant(
      spoilFirstRun(facts => ({ ...facts, hookError: 'listen EADDRINUSE', reached: false, tests: [] })),
    )
    expect(status).not.toBe('Survived')
    expect(status).not.toBe('NoCoverage')
  })
})
```

```bash
pnpm exec vitest run test/repros/BUG-900.test.ts
# 2 failed: expected 'Survived' not to be 'Survived'
```

Сквозная фикстура на реальном Vitest 5.0.5: `src/math.js` с
`export function add(a, b) { return a + b }`; `test/a.test.js` — тест
`slow once` (не вызывает `add`; во 2-м запуске файла ждёт 1500 мс при
`timeout` 1000 мс, счётчик запусков в файле `.runs`) и тест `add`
(`expect(add(2, 3)).toBe(5)`); `test/b.test.js` — `add(1, 1)` без проверок.

```bash
rm -f .runs && npx mootant run --no-cache --verbose   # survived 1 (y1rm: a + b -> a)
npx mootant run --no-cache --mutant y1rm              # killed 1
```

Вариант с `beforeAll`, бросающим `EADDRINUSE` во 2-м запуске, даёт тот же
`survived 1` и под Vitest, и под `node:test` (`before()`).

## Ожидаемое поведение

Юнит, который не выполнил тесты файла не из-за мутанта (таймаут теста или
падение/таймаут suite-хука до достижения мутанта), не считается файлом без
улик: он повторяется (как юнит без фактов, `core/run/apply-isolated-result.ts:93-113`),
а при повторной неудаче мутант получает `Error` с диагностикой. В сценарии
выше повтор проходит, и мутант `Killed` тестом `add`/`a2`.

## Фактическое поведение

`Survived` (покрыт `test/a.test.js:18`, чей тест так и не был запущен), без
предупреждений; повтор с `--mutant` даёт `Killed`.

## Подозреваемые места в коде

- `core/run/read-isolated-unit.ts:46-106` — `doubtful` теста и `null` в конце
  не отличают «тесты прошли» от «тесты не выполнялись».
- `adapters/vitest/runner.ts:886-888,630-637` — abandon после таймаута теста,
  не достигшего мутанта; `adapters/vitest/build-isolated-facts.ts:46-59` — не
  сообщает об этом ядру.
- `adapters/node-test/build-isolated-facts.ts:65-82` — упавший хук превращается
  в упавшие тесты без `hookError`.
- Возможная точка исправления: сравнивать `facts.tests` с
  `state.analysis.fileTests.get(request.file)` — для улики `'none'`/
  `'survived'` все тесты файла должны выполниться (или юнит остановлен bail-ом
  после убийства).

## Критерий готовности

- `test/repros/BUG-900.test.ts` (оба кейса) переносится в `test/core/run/`
  (например, в `apply-isolated-result.test.ts`/`run-isolated-rounds.test.ts`) и
  проходит.
- Есть тест, что юнит, неполный дважды подряд, даёт `Error` с диагностикой, а
  bail после убийства (`read-isolated-unit.ts:54-62`) по-прежнему считается
  полным юнитом.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
