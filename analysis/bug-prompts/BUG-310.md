# BUG-310: выход из бесконечного цикла с несколькими выходами пропускается как timeout

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Без настройки `timeouts` (выключена в `recommended`) Mootant не выдаёт
мутанта, который даёт узлу его «running value» — значение, держащее цикл
(`core/mutators/shared/get-running-value.ts:34-66`, правило `loop-running`,
категория `timeout`, `heuristic: false`). Для теста `if`, который выходит из
бесконечного цикла (`for (;;)`, `while (true)`), running value — `false`
(`core/mutators/shared/get-running-value.ts:56-59`,
`core/syntax/get-exited-loops.ts:33-87`). Это верно для цикла с одним выходом
(пример документации — `if (done) break` в `while (true)`,
`docs/content/mutators/condition.md`, раздел Changes), но не для цикла с
несколькими выходами: принудительное `false` для одного выхода оставляет
остальные, и цикл заканчивается (или падает с исключением). Типичный шаблон —
обход вверх по дереву с несколькими проверками; в `core/` Mootant так
пропущено 30 из 131 `loop-running` (`core/generate/group-replacement.ts:356-372`,
`core/mutators/shared/is-tail-position.ts:28-48`,
`core/syntax/is-timer-delay.ts`, `core/cache/find-lockfile.ts`). Такие мутанты —
единственная проверка, что каждый выход нужен и покрыт тестом. Поскольку есть
`hitLimit` (настоящая бесконечность обнаруживается быстро,
`docs/content/guide/configuration.mdx`, раздел `hitLimit`), цена ошибки в
обратную сторону невелика.

## Воспроизведение

Падающий тест — `test/repros/BUG-310.test.ts` в ветке `experiment/bug-repros`:

```ts
import { describe, expect, it } from 'vitest'

import { listMutantTexts } from '../helpers/list-mutant-texts'

let findRoot = [
  'export function findRoot(node) {',
  '  let current = node',
  '  for (;;) {',
  '    if (current.isRoot) {',
  '      break',
  '    }',
  '    if (current.parent === null) {',
  '      break',
  '    }',
  '    current = current.parent',
  '  }',
  '  return current',
  '}',
]

describe('BUG-310: one exit test of an endless loop with other exits is taken for a timeout', () => {
  it('keeps condition false for an exit test that other exits back up', () => {
    expect(
      listMutantTexts('condition', findRoot, { file: 'example.js' }),
    ).toContain('current.isRoot -> false')
  })

  it('keeps comparison-operator false for an exit test that other exits back up', () => {
    expect(
      listMutantTexts('comparison-operator', findRoot, { file: 'example.js' }),
    ).toContain('current.parent === null -> false')
  })
})
```

Сквозная проверка (фикстура `analysis/data/skips/fx1`, `src/root.js`,
`test/root.test.js`: цепочка `leaf → child → root` с `isRoot: true`):

```bash
npx mootant run src/root.js --no-cache   # killed 3, score 100%
# физически заменить `current.parent === null` на `false` (и отдельно `current.isRoot` на `false`):
npx vitest --run test/root.test.js        # оба раза завершается за ~2.5 с и проходит
```

## Ожидаемое поведение

Running value выхода из бесконечного цикла пропускается как `loop-running`,
только если у цикла нет других выходов (других `break`/`return`/`throw`,
покидающих этот цикл, вне вложенных функций). Иначе мутант выдаётся: если
он всё-таки зациклит, его поймает `hitLimit`/таймаут и он будет `Timeout`
(то есть убит).

## Фактическое поведение

```
condition 'current.isRoot' -> 'false' [loop-running/timeout]  false may keep the loop running forever
comparison-operator 'current.parent === null' -> 'false' [loop-running/timeout]
```

## Подозреваемые места в коде

- `core/mutators/shared/get-running-value.ts:56-59` — для теста `if` с
  выходом из цикла возвращает running value без учёта других выходов.
- `core/syntax/get-exited-loops.ts:33-87` — здесь же можно посчитать выходы
  цикла.
- Потребители: `core/mutators/shared/get-comparison-plan.ts:307, 543-546`,
  `core/mutators/shared/get-condition-constants.ts:160-161, 303-305`,
  `core/mutators/shared/get-group-constant.ts`, `get-literal-skip.ts:98-107`.

## Критерий готовности

- Тест `test/repros/BUG-310.test.ts` (перенести в
  `test/core/mutators/shared/get-running-value.test.ts` и тесты мутаторов)
  падает до исправления и проходит после.
- Для цикла с единственным выходом (`while (true) { if (done) break; … }`)
  `false` по-прежнему пропускается как `loop-running`.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- Абзац про `timeouts` в `docs/content/mutators/condition.md` уточняет условие
  «единственный выход».
