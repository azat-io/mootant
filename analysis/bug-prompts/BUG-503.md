# BUG-503: сигнал процессу mootant оставляет воркер Vitest с зависшим мутантом сиротой

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён. Найдено на
> коммите 170ec52.

## Контекст

Мутанты, вешающие тест бесконечным синхронным циклом, — обычное дело. Пока
такой мутант выполняется в воркере Vitest, mootant может получить SIGTERM,
SIGINT или SIGHUP адресно, только свой PID: `kill <pid>`, кнопка Stop в IDE,
`child.kill()` харнесса агента, который запустил `npx mootant run` и
прерывает его по таймауту, менеджер процессов. Обработчики сигналов есть
только у спиннера в интерактивном терминале (`cli/terminal/create-spinner.ts:144-161`,
`process.exit(130/143)`) и у node:test на время жизни тестовых процессов
(`adapters/node-test/track-process-group.ts:7,18-22`). Для Vitest остановка
воркеров при сигнале не предусмотрена: процесс выходит (через обработчик
логгера Vitest или спиннера), воркер в синхронном цикле не замечает закрытия
IPC и остаётся навсегда (ppid 1, 100% CPU). Ctrl+C в терминале этот случай не
показывает: SIGINT получает вся группа, и воркер умирает сам.

## Воспроизведение

Фикстура в ветке `experiment/bug-repros`: `test/repros/BUG-503/` со скриптом
`run.sh` (собирает `dist`, если его нет).

```js
// src/step.js
export function getStep(size) {
  return size - 9
}

// test/step.check.js
import { expect, it } from 'vitest'

import { getStep } from '../src/step.js'

it('counts to ten', () => {
  let step = getStep(10)
  let n = 0
  // the mutant 9 -> 10 makes the step 0: an endless synchronous loop
  for (let i = 0; i < 10; i += step) {
    n++
  }
  expect(n).toBe(10)
})

// vitest.config.js
export default { test: { include: ['test/**/*.check.js'] } }

// mootant.config.js — зависание длится ~30 с, есть окно для сигнала
export default { run: { timeout: { constant: 30000 } } }
```

```bash
#!/bin/bash
# test/repros/BUG-503/run.sh (сокращённо)
node "$REPO/bin/mootant.js" run src --no-cache </dev/null >/dev/null 2>&1 &
MOOTANT=$!
# ждём воркер, который живёт ≥ 3 с — он выполняет зависший мутант
WORKER=$(ps -o pid=,etimes= --ppid "$MOOTANT" | awk '$2 >= 3 {print $1; exit}')
kill -TERM "$MOOTANT"; wait "$MOOTANT"
sleep 2; kill -0 "$WORKER" && echo "REPRODUCED"
```

## Ожидаемое поведение

После SIGINT/SIGTERM/SIGHUP, адресованного только mootant, не остаётся ни
одного воркера; код выхода 130/143/129; рабочий каталог `mootant-XXXXXX` в
TMPDIR удалён (сейчас он тоже остаётся при любом прерывании — BUG-505).

## Фактическое поведение

```
mootant exit code: 143
REPRODUCED: worker 13634 outlived mootant: 13634     1 Rl   22.8
```

Матрица (`analysis/data/cli/sig-vt-hang-*.txt`): SIGINT pid без TTY — 130 и
сирота; SIGTERM pid без TTY — 143 и сирота; SIGTERM pid под pty, где сессию
ведёт shell, — 143 и сирота; SIGHUP pid — 129 и сирота; в dry run воркер живёт,
пока не закончится его тест. Ctrl+C (SIGINT всей группе) — 130, процессов нет.

## Подозреваемые места в коде

- `adapters/vitest/start-vitest-session.ts:142-185` — сессия не регистрирует
  остановку воркеров при сигналах (ср. `adapters/node-test/track-process-group.ts`).
- `adapters/vitest/create-forks-pool.ts:63-76` — пул знает процессы воркеров
  (`state.spawns`), их можно убить `SIGKILL` при сигнале.
- `cli/terminal/create-spinner.ts:144-161` — `process.exit` в обработчике
  обходит `finally` в `core/run-mutants.ts:301-325` (`session.close()`,
  `work.remove()`).

## Критерий готовности

- Тест (unit на новый модуль отслеживания воркеров по образцу
  `test/adapters/node-test/track-process-group.test.ts` и/или интеграционный,
  который запускает сессию Vitest с зависшим мутантом и шлёт сигнал): после
  SIGTERM, SIGINT и SIGHUP процессу mootant нет живых воркеров; падает до
  исправления, проходит после. `test/repros/BUG-503/run.sh` завершается с
  кодом 0.
- Код выхода по-прежнему 130/143 (129 для SIGHUP), как у оболочки.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
