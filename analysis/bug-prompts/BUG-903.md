# BUG-903: тест с вычисляемым `import()` не выбирается, мутант молча Survived

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Dry run адаптера Vitest запускает только тест-файлы, которые Vitest считает
связанными с переключёнными файлами: `vitest.config.related = request.related`
и `getRelevantTestSpecifications()` (`adapters/vitest/run-dry.ts:225-247`). В
Vitest 5.0.5 это `AffectedModulesResolver` — обход графа по `deps` и
`dynamicDeps` трансформаций: статические импорты и `import()` с литералом.
Isolated-путь потом запускает мутанта только в файлах, которые достигли его в
dry run (`core/run/rank-mutant-files.ts:33-37`). Тест-файл, который загружает
модуль вычисляемым спецификатором (``import(`../src/${name}`)``,
`import(path.join(dir, file))` — частый приём в тестах плагинов, правил,
фикстур «по списку»), в dry run не попадает. Если тот же модуль статически
импортирует другой, слабый тест, мутант получает `Survived` без диагностики
(предупреждение `never-served` не выдаётся — файл ведь отдан).

Документация говорит только «Tests that load a mutated file only through a
computed `import()` may not be selected» (`docs/content/guide/compatibility.mdx:56-57`)
— без следствия и без обхода. При этом ядро уже разбирает `import()` в
тест-файлах и отбрасывает нелитеральные (`core/run/read-test-imports.ts:57-62`).

## Воспроизведение

```bash
mkdir -p repro/src repro/test && cd repro
cat > package.json << 'EOF'
{ "name": "repro", "private": true, "type": "module", "scripts": { "test": "vitest run" } }
EOF
printf 'export function add(a, b) {\n  return a + b\n}\n' > src/math.js
cat > test/static.test.js << 'EOF'
import { test } from 'vitest'
import { add } from '../src/math.js'
test('add runs', () => {
  add(1, 1)
})
EOF
cat > test/dynamic.test.js << 'EOF'
import { test, expect } from 'vitest'
let name = ['math', 'js'].join('.')
test('add', async () => {
  let { add } = await import(`../src/${name}`)
  expect(add(2, 3)).toBe(5)
})
EOF
npm i -D vitest@5.0.5 vite mootant          # или локальный пакет mootant
npx vitest run                                # 2 passed
npx mootant run src --no-cache --verbose
# dry run 1 test …, survived 1: src/math.js 2:10 a + b -> a,
# covered by add runs (test/static.test.js:6)
# С физической мутацией `return a` тест test/dynamic.test.js падает.
```

## Ожидаемое поведение

Мутант `Killed` тестом `test/dynamic.test.js` — либо потому, что тест-файлы с
вычисляемым `import()` (и любые, которые нельзя связать статически) попадают в
dry run, либо потому, что запуск хотя бы предупреждает: «test/dynamic.test.js
loads modules through a computed import() and was not run; verdicts of the
modules it may load can be Survived falsely» с подсказкой, как включить его
(например, опция запуска всех тест-файлов в dry run).

## Фактическое поведение

`dry run 1 test`, `survived 1`, предупреждений нет.

## Подозреваемые места в коде

- `adapters/vitest/run-dry.ts:225-247` — выбор спецификаций только через
  `related`.
- `core/run/run-dry-phase.ts:156-158,195-199` — запрос dry run с
  `files: null, related`.
- `core/run/read-test-imports.ts:57-62` — уже знает о нелитеральных
  `import()`; можно вернуть их наличие.
- `types/adapter/dry-run-request.d.ts:4-10` — контракт `files: null` («runs
  the test files related to `related`, or more»).

## Критерий готовности

- Есть тест (адаптера Vitest или ядра с фейковым адаптером), в котором
  тест-файл с вычисляемым `import()` переключённого модуля участвует в dry run
  либо порождает предупреждение; сценарий выше даёт `Killed` или явное
  предупреждение в выводе и в `--json`.
- Документация (`docs/content/guide/compatibility.mdx`) описывает следствие и
  обход.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига) без явной необходимости; новая опция конфига — только если без неё
  нельзя, с валидацией в `core/config/validate-config.ts`.
- Запуск всех тест-файлов в dry run дорог на больших проектах: не делай его
  поведением по умолчанию без замеров.
- Сообщения коммитов — Conventional Commits (commitlint).
