# BUG-903: тест с вычисляемым `import()` не выбирается, мутант молча Survived

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: low (заявлялась medium). Статус: подтверждён.
> Найдено на коммите 170ec52.
>
> Перепроверено независимо: воспроизведено обоими верификаторами на фикстурах
> с нуля с упакованным mootant 170ec52 (Vitest 5.1.0 через npm и 5.0.5 через
> pnpm, все прогоны одинаковы, `--fast` тоже: `dry run 1 test`, `survived 1`, в
> `--json` `diagnostics: []`; тот же мутант, вписанный руками, валит
> `test/dynamic.test.js`); скептик: не опроверг, но снизил до low — оговорка о
> вычисляемом `import()` уже есть в документации, ошибка только пессимистичная
> (ложных `Killed` нет), триггер узкий, а штатная опция Vitest
> `test.experimental.recordDependencies` баг обходит. Координатор принял low:
> не задокументировано только следствие — тихий `Survived`, когда тот же модуль
> статически импортирует другой, слабый тест.

## Контекст

Под Vitest тест-файлы для dry run выбирает сам Vitest. Ядро просит dry run с
`files: null` и всеми переключёнными файлами в `related`
(`core/run/run-dry-phase.ts:156-158`, `:195-199`). Адаптер записывает их в
`vitest.config.related` и вызывает `vitest.getRelevantTestSpecifications()`
(`findSpecifications`, `adapters/vitest/run-dry.ts:225-247`, вызов на
`:231-233`). В Vitest 5.0.5 из lockfile проекта это `AffectedModulesResolver`
(«Finds test specifications that statically depend on any of the changed
files», `node_modules/vitest/dist/chunks/cli-api.De07GUeT.js:9927-9930`). Он
обходит граф по `deps` и `dynamicDeps` результатов трансформации (`:10136`),
то есть видит статические импорты и те `import()`, спецификатор которых Vite
смог разрешить. Isolated-юниты потом запускают мутанта только в тест-файлах,
которые достигли его в dry run (`core/run/rank-mutant-files.ts:33-37`), а
batch-юниты в `--fast` — только в тестах dry run
(`core/run/plan-batch.ts:47-48`). Спецификации юнитов строятся прямо из
плана (`adapters/vitest/run-plan.ts:63-65`), повторного отбора нет. Значит,
тест-файл, не выбранный в dry run, с мутантом не запускается никогда.

Не выбирается тест-файл, который грузит модуль вычисляемым спецификатором:
``import(`../src/${name}`)`` без статического расширения (Vite при этом
печатает `invalid import … A file extension must be included in the static part
of the import` из плагина `vite:dynamic-import-vars`) или
`import(path.join(dir, file))` (тут Vite молчит вовсе). Это частый приём в
тестах плагинов, правил и фикстур «по списку». Шаблон со статическим
расширением (``import(`../src/${name}.js`)``) Vite превращает в glob, и такой
тест выбирается. Адаптер node:test не затронут: его первый dry run запускает
все тест-файлы, модули которых ещё неизвестны
(`adapters/node-test/run-dry.ts:75-80`), и эквивалентная фикстура даёт
`Killed`.

Последствия. Если тот же модуль статически импортирует другой, слабый тест,
мутант получает `Survived` без диагностики. `never-served` выдаётся только для
файла, который ни разу не отдан (`core/run/run-dry-phase.ts:337-370`, условие
на `:360`), а этот файл отдан слабому тесту. Отчёт к тому же советует дописать
проверку в слабый тест (`test: test/static.test.js`). Если других тестов у
модуля нет, все его мутанты получают `NoCoverage` с `never-served`, и причина
«no test imports it, or tests import a built copy, an external or a pre-bundled
dependency» (`:365`) настоящую не называет. Режим `--fast` затронут так же.
Ошибка только пессимистичная: ложных `Killed` нет.

Документация говорит только «Tests that load a mutated file only through a
computed `import()` may not be selected»
(`docs/content/guide/compatibility.mdx:56-57`), без следствия и без обхода. А
обход есть, хотя нигде не описан: штатная опция Vitest
`test.experimental.recordDependencies: true` («Record the modules that every
test file loads in the cache and use the records with `--changed` and
`--related` instead of walking the module graph statically. A test file without
a record always runs.», `node_modules/vitest/dist/chunks/plugin.d.C8mmycim.d.ts:4214-4221`).
Mootant всегда запускает Vitest с `cache: false`
(`adapters/vitest/start-vitest-session.ts:106`), поэтому с этой опцией записей
у Vitest не бывает, и dry run запускает все тест-файлы (механизм — в
«Подозреваемых местах»). Оба верификатора проверили: с этой опцией `dry run 2
tests`, `killed 1`.

Ядро уже разбирает `import()` тест-файлов и отбрасывает нелитеральные
(`core/run/read-test-imports.ts:57-62`), но только у тест-файлов, которые уже
попали в dry run (`core/run-mutants.ts:465-467`), и только для ранжирования.
`test/dynamic.test.js` оно не видит.

## Воспроизведение

Ветки `experiment/bug-repros` в публичном репозитории нет, а готового
падающего теста для BUG-903 не было и в ней. Все файлы ниже создайте сами.
Нужны Node.js 22.12 или новее (Vitest 5 требует `^22.12.0 || ^24.0.0 ||
>=26.0.0`, `docs/content/guide/compatibility.mdx:22-24`) и pnpm 12. В CI стоит
`latest-12` (`.github/actions/install-tools/action.yml`). pnpm 10 не читает
`configDependencies` из `pnpm-workspace.yaml`, и даже `pnpm --version` внутри
репозитория у него зависает. Команды шагов 2–4 рассчитаны на одну сессию shell:
они используют переменные `PACK`, `TGZ` и `FIX`.

### Шаг 1. Временный падающий тест на исходниках (сборка не нужна)

Это набросок по образцу проверенных репро-тестов соседних багов: `runMutants`
с `createBuiltIns` и `vitestAdapter` на фикстуре в `test/repros/<ID>/`.
**Запуском он не проверялся.** Сначала убедитесь, что до исправления он падает
именно потому, что мутант `Survived` и диагностики про `dynamic.check.js` нет.
Исходник и тела тестов дословно те же, на которых верификаторы воспроизвели
баг через CLI (шаг 2); отличаются только имена тест-файлов и конфиг фикстуры.
Тест-файлы названы `*.check.js`, чтобы их не подхватывал корневой Vitest
репозитория. Всё это временное и в коммит не входит (см.
«Ограничения»).

```bash
# в корне клона azat-io/mootant
pnpm install
mkdir -p test/repros/BUG-903/src test/repros/BUG-903/test

cat > test/repros/BUG-903/package.json <<'EOF'
{
  "name": "bug-903-fixture",
  "private": true,
  "type": "module",
  "scripts": {
    "test": "vitest --run"
  }
}
EOF

cat > test/repros/BUG-903/vitest.config.ts <<'EOF'
export default {
  test: {
    include: ['test/**/*.check.js'],
  },
}
EOF

printf 'export function add(a, b) {\n  return a + b\n}\n' > test/repros/BUG-903/src/math.js

cat > test/repros/BUG-903/test/static.check.js <<'EOF'
import { test } from 'vitest'
import { add } from '../src/math.js'
test('add runs', () => {
  add(1, 1)
})
EOF

cat > test/repros/BUG-903/test/dynamic.check.js <<'EOF'
import { test, expect } from 'vitest'
let name = ['math', 'js'].join('.')
test('add', async () => {
  let { add } = await import(`../src/${name}`)
  expect(add(2, 3)).toBe(5)
})
EOF

cat > test/repros/BUG-903.test.ts <<'EOF'
import { describe, expect, it } from 'vitest'
import path from 'node:path'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

/**
 * Project where `test/static.check.js` imports `src/math.js` statically and
 * calls `add` without checking the result, and `test/dynamic.check.js` checks
 * `add` but loads `src/math.js` through `import()` with a computed specifier.
 */
let root = path.resolve(import.meta.dirname, 'BUG-903')

describe('BUG-903: Vitest and a test that loads a module through a computed import()', () => {
  it('kills the mutant, or warns about the test file left out of the dry run', async () => {
    let result = await runMutants({
      builtIns: createBuiltIns('vitest', vitestAdapter()),
      paths: ['src'],
      concurrency: 1,
      cache: false,
      cwd: root,
    })
    let verdicts = result.results
      .filter(verdict => verdict.mutant.file === 'src/math.js')
      .map(verdict => verdict.status)
    let warned = result.diagnostics.some(diagnostic =>
      `${diagnostic.file} ${diagnostic.message}`.includes('dynamic.check.js'),
    )

    /*
     * With `a + b` -> `a` applied to `src/math.js` by hand,
     * `test/dynamic.check.js` fails: `expected 2 to be 5`. Vitest selects for
     * the dry run only the test files that reach `src/math.js` through static
     * imports, so the mutant runs only against `test/static.check.js`,
     * survives, and no diagnostic names the test file that was left out.
     */
    expect(verdicts).toHaveLength(1)
    expect(
      verdicts[0] === 'Killed' || warned,
      `${verdicts[0]}, diagnostics: ${JSON.stringify(result.diagnostics)}`,
    ).toBe(true)
  }, 60_000)
})
EOF

pnpm exec vitest --run test/repros/BUG-903.test.ts
```

Тест принимает оба допустимых исправления (см. «Ожидаемое поведение»):
`Killed` или предупреждение, которое называет `dynamic.check.js`. Мутант в
фикстуре ровно один (в CLI `mutants 1 in 1 file`).

### Шаг 2. CLI на упакованном mootant (так воспроизводили верификаторы)

`bin/mootant.js` импортирует `../dist/cli/index.js`, поэтому для CLI нужна
сборка. Пакет `mootant` из реестра npm не подходит: там только заглушки `0.0.0`
и `0.0.0-stage` без `bin`. Ставьте `vitest@5` (на момент проверки 5.1.0), а не
`vitest@5.0.5`: в npm 10.9.9 установка 5.0.5 падает с `Cannot read properties
of null (reading 'edgesOut')`. Это баг arborist при разборе
peer-зависимости `@vitest/browser-playwright@5.1.0`, а не mootant. Vitest 5.0.5
верификаторы ставили через pnpm, результат тот же.

### Шаг 4. Варианты

Каждый вариант — копия фикстуры шага 2 с общей `node_modules`, как делали
верификаторы. Результаты в комментариях получены ими на этих же файлах.

```bash
variant() {
  V="$(mktemp -d)"
  cp -R "$FIX/package.json" "$FIX/src" "$FIX/test" "$V/"
  ln -s "$FIX/node_modules" "$V/node_modules"
  cd "$V"
}

# А. path.join: тот же тихий Survived, причём Vite не предупреждает даже в vitest run
variant
cat > test/dynamic.test.js <<'EOF'
import { test, expect } from 'vitest'
import path from 'node:path'
let dir = path.join(import.meta.dirname, '..', 'src')
let file = 'math.js'
test('add', async () => {
  let { add } = await import(path.join(dir, file))
  expect(add(2, 3)).toBe(5)
})
EOF
npx mootant run src --no-cache --verbose    # dry run 1 test, survived 1, ни одного предупреждения

# Б. Статическое расширение в шаблоне: Vite делает из него glob, тест выбирается
variant
cat > test/dynamic.test.js <<'EOF'
import { test, expect } from 'vitest'
let name = ['m', 'a', 't', 'h'].join('')
test('add', async () => {
  let { add } = await import(`../src/${name}.js`)
  expect(add(2, 3)).toBe(5)
})
EOF
npx mootant run src --no-cache              # dry run 2 tests, killed 1

# В. Без слабого статического теста
variant
rm test/static.test.js
npx mootant run src --no-cache              # dry run 0 tests, never-served, NoCoverage

# Д. Обход через recordDependencies
variant
cat > vitest.config.js <<'EOF'
import { defineConfig } from 'vitest/config'
export default defineConfig({ test: { experimental: { recordDependencies: true } } })
EOF
npx mootant run src --no-cache              # dry run 2 tests, killed 1
```

Вариант Г — node:test, контроль на ложные предупреждения после исправления.
Верификатор ставил пакет через pnpm; установка через npm, как ниже, не
проверялась.

```bash
NT="$(mktemp -d)"
mkdir -p "$NT/src" "$NT/test"
cd "$NT"
cat > package.json <<'EOF'
{ "name": "repro-node", "private": true, "type": "module", "scripts": { "test": "node --test" } }
EOF

cat > test/static.test.js <<'EOF'

  add(1, 1)
})

cat > test/dynamic.test.js <<'EOF'

  let { add } = await import(`../src/${name}`)

npm i -D "$TGZ"
npx mootant run src --no-cache              # dry run 2 tests, killed 1
```

## Ожидаемое поведение

- В идеале мутант `a + b` → `a` получает `Killed` от `test/dynamic.test.js`
  (и в варианте А тоже). Тест-файлы, которые Vitest не может связать с
  модулем статически, всё равно попадают в dry run, как под node:test.
  Контракт это разрешает: при `files: null` адаптер запускает связанные
  тест-файлы «or more» (`types/adapter/dry-run-request.d.ts:5-9`, `:26-32`).
- Минимум, допустимый при серьёзности low: вердикт может остаться `Survived`,
  но прогон явно предупреждает, в текстовом отчёте и в `diagnostics` вывода
  `--json`. Например: «test/dynamic.test.js loads modules through a computed
  import() and was not run; verdicts of the modules it may load can be Survived
  or NoCoverage falsely». С подсказкой, как включить файл: статическое
  расширение в шаблоне или `test.experimental.recordDependencies: true`.
- Ложных предупреждений нет: тест со статическим расширением в шаблоне
  (вариант Б) Vitest уже выбирает, а под node:test (вариант Г) dry run
  запускает все файлы.
- Документация описывает следствие и обход.

## Подозреваемые места в коде

Где теряется тест:

- `adapters/vitest/run-dry.ts:225-247` — `findSpecifications`. Отбор только
  через `related` (`:231-233`). При `files !== null` выбранные файлы не
  добавляются, а пересекаются с тем же связанным набором (`:238-246`). Тест
  `test/adapters/vitest/run-dry.test.ts:347-397` это закрепляет:
  `/test/d.test.ts`, которого нет среди связанных, отбрасывается.
- Vitest 5.0.5, `node_modules/vitest/dist/chunks/cli-api.De07GUeT.js`:
  `filterTestsBySource` (`:10373-10402`) выбирает резолвер на `:10396`;
  `AffectedModulesResolver` (`:9930`) берёт рёбра из `deps` и `dynamicDeps`
  (`:10136`). В 5.1.0 поведение то же по прогонам верификаторов; номера строк
  для 5.1.0 здесь не перепроверялись.
- `core/run/run-dry-phase.ts:156-158`, `:195-199` — первый dry run всегда
  `files: null` со всеми переключёнными файлами в `related`. Повторы с `files`:
  `:209-213` (в `--fast`) и `:398-407` (`checkRealFailures`).
- `core/run/rank-mutant-files.ts:33-37` — план isolated-юнитов строится только
  из покрытия dry run.
- `core/run/run-dry-phase.ts:337-370` — `diagnoseServedFiles`: `never-served`
  только для неотданного файла (`:360`), с общей причиной (`:365`).
- `types/adapter/dry-run-request.d.ts:5-9`, `:26-32` — контракт: при
  `files: null` адаптер может запускать больше, «such as every test file when
  it does not know yet what each one imports». Расширение набора контракт не
  нарушает.

Что в одиночку не поможет (уточнения верификаторов и чтение кода):

## Критерий готовности

- **Обязательно, документация.** `docs/content/guide/compatibility.mdx` рядом с
  `:56-57` говорит, что тест, который грузит мутируемый файл только через
  вычисляемый `import()`, в dry run не запускается и его убийства не
  засчитываются. Мутант тогда получает `Survived`, если код достигает другой
  тест (и отчёт называет этот тест в `test:`), или `NoCoverage` с
  `never-served`, если других тестов нет. Там же описан обход: статическое
  расширение в шаблоне (``import(`./${name}.js`)``) и/или
  `test.experimental.recordDependencies: true` в конфиге Vitest (dry run тогда
  запускает все тест-файлы, это медленнее). Если документация рекомендует
  `recordDependencies`, зависимость обхода от `cache: false` должна быть явной:
  в JSDoc `startVitestSession` или в тесте на настоящем Vitest, который
  проверяет вариант Д.
- **Обязательно, поведение.** Одно из двух; какое выбрано, напишите в описании
  PR.
