# BUG-602: процесс юнита, убитый извне, даёт мутанту ложный Killed

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

На isolated-пути каждый юнит — один мутант в одном тестовом файле в свежем
процессе. Если процесс не дошёл до записи `end`, адаптер сообщает
`IsolatedFacts.incomplete: 'crash'` (`adapters/vitest/build-isolated-facts.ts:31-45`,
`adapters/node-test/build-isolated-facts.ts:58-64`), а ядро превращает это в
`Killed` с причиной `crash` **без повтора, без проверки и без диагностики**
(`core/run/read-isolated-unit.ts:42-44`). Это верно, когда процесс уронил
сам мутант (`process.exit`, переполнение стека), но ложно, когда процесс
убила инфраструктура: OOM killer при параллельных воркерах, лимит памяти
контейнера в CI, внешний `kill -9`. Такой мутант засчитывается как
обнаруженный и завышает score — молча. Для таймаутов ядро уже применяет
подтверждение повтором с удвоенными границами
(`core/run/get-unit-evidence.ts:22-28`); для crash аналога нет.

## Воспроизведение

Фикстура (одинаково для Vitest 5 и `node:test`; показан Vitest):

```bash
mkdir -p /tmp/bug602/{src,test} && cd /tmp/bug602
cat > package.json <<'EOF'
{ "name": "bug602", "private": true, "type": "module" }
EOF
cat > src/price.js <<'EOF'
export function applyDiscount(price, percent) {
  if (percent > 100) {
    throw new RangeError('percent must be at most 100')
  }
  return price - (price * percent) / 100
}
EOF
cat > test/price.test.js <<'EOF'
import { expect, it } from 'vitest'

import { applyDiscount } from '../src/price.js'

it('takes a percent off', () => {
  expect(applyDiscount(200, 25)).toBe(150)
})

it('rejects more than 100 percent', () => {
  expect(() => applyDiscount(10, 101)).toThrow(RangeError)
})

it('waits', async () => {
  await new Promise(resolve => setTimeout(resolve, 3000))
})
EOF
cat > vitest.config.js <<'EOF'
import { defineConfig } from 'vitest/config'

export default defineConfig({ test: { include: ['test/**/*.test.js'] } })
EOF
echo "export default { run: { paths: ['src'], runner: 'vitest', cache: false } }" > mootant.config.js
npm i -D --legacy-peer-deps <path-to>/mootant.tgz vitest@5.0.5 vite@8
npx mootant list src --json      # мутант «percent >= 100» — id вида xdbc5hrb56qe

# 1) Без вмешательства — мутант выживает:
npx mootant run --mutant <id> --json --all | grep -o '"status":"[A-Za-z]*"'   # "Survived"

# 2) Имитация OOM killer: убить воркер юнита во время теста 'waits':
npx mootant run --mutant <id> --json --all > out.json &
sleep 4   # dry run (~3 с) уже прошёл, идёт isolated-юнит
pkill -KILL -f 'vitest/dist/workers/forks'
wait; grep -o '"status":"[A-Za-z]*"' out.json        # "Killed", диагностик нет
```

Для `node:test` то же с `pkill -KILL -f 'test/price.test.js'` (процесс
юнита — `node --import …/preload.js … test/price.test.js`).

## Ожидаемое поведение

Смерть процесса юнита, которую нельзя приписать мутанту, не даёт `Killed`:
юнит повторяется (как подтверждение таймаута), и `Killed (crash)` ставится,
только если процесс снова умер; если повтор прошёл — его факты решают
(здесь `Survived`). Каждая смерть процесса, не вызванная сторожем, даёт
предупреждение `worker-crash` с сигналом/кодом выхода.

## Подозреваемые места в коде

- `core/run/read-isolated-unit.ts:42-44` — `crash` → `Killed` безусловно.
- `core/run/get-unit-evidence.ts:15-30` — подтверждение есть только для
  `time-limit`/`hang`; сюда естественно добавить `crash`.
- `types/adapter/isolated-result.d.ts:8-11` — у фактов нет кода выхода/сигнала;
  адаптеры их знают (`adapters/node-test/types/test-process-outcome.d.ts`:
  `signal`, `code`; у Vitest — событие `exit` воркера в
  `adapters/vitest/create-forks-pool.ts:70-75`).

## Критерий готовности

- `crash` подтверждается повтором юнита (тот же механизм, что `confirming`);
  `Killed (crash)` — только при повторной смерти; иначе решают факты повтора.
  Повтор не удваивает стоимость обычных прогонов: crash редок.
- (Желательно) `IsolatedFacts` получает необязательное `exit?: { code:
  number | null; signal: string | null }`, и смерть от `SIGKILL`/`SIGTERM`,
  которые не посылал сторож mootant, сразу считается сбоем инфраструктуры.
- Тесты: новый `test/core/run/read-isolated-unit.test.ts` (сейчас его нет;
  правило покрыто через `test/core/run/apply-isolated-result.test.ts`) и
  `test/core/run/apply-isolated-result.test.ts` — crash ведёт к повтору, а
  повтор с проходом даёт `Survived`; интеграционный тест в
  `test/adapters/vitest/index.test.ts` и `test/adapters/node-test/index.test.ts`
  с убийством процесса юнита (например, тест, который во время ожидания
  делает `process.kill(process.pid, 'SIGKILL')` только при первом запуске,
  отмечая это файлом-флагом) — вердикт `Survived` и предупреждение
  `worker-crash`. Тесты падают до исправления и проходят после.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
