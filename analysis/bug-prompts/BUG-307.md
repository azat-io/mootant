# BUG-307: `x || 0` для числа считается эквивалентным `x`, хотя он защищает от `NaN`

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

`logical-operator` не выдаёт удаление правого операнда `||`, если правый
операнд — «единственное ложное значение типа» левого
(`core/mutators/shared/get-logical-drops.ts:81-84`, `:158-160`, правило
`canonical-falsy-default`, категория `equivalent`, `heuristic: true`;
значения — `core/mutators/shared/get-canonical-falsy.ts`: `0` для числа,
«`NaN` ignored»). Для строк, булевых и BigInt это верно, для чисел — нет:
`NaN || 0` — `0`, а без `|| 0` — `NaN`. Именно ради этого пишут
`done / total || 0` (деление 0/0) и `Number(text) || 0` (нечисловой ввод), то
есть мутант отличается от оригинала ровно на входе, ради которого существует
код. Документация (`docs/content/mutators/logical-operator.md:205`) называет
правило `equivalent` с оговоркой «`NaN` aside», а категория `equivalent` по
`docs/content/mutators.md:38` — «Can't alter what the code does».

Для `Number(text) || 0` других мутантов этой защиты нет: перестановка `??`
не рассматривается (левая часть не может быть `null`), удаление левого
операнда (`0`) убивается любым числовым тестом. Тест без случая `NaN` даёт
100 %, хотя защита не проверена.

import { listMutantTexts } from '../helpers/list-mutant-texts'

describe('BUG-307: a numeric || 0 that guards against NaN is taken for an equivalent default', () => {
  it.each([
    ['done / total || 0', 'done / total'],
    ['Number(text) || 0', 'Number(text)'],

## Ожидаемое поведение

Для числового левого операнда `|| 0` не считается эквивалентным, если левая
часть может быть `NaN`: деление, `%`, `Number()`, `parseInt`/`parseFloat`,
`Math.*`, унарный `+`, арифметика с неизвестным операндом. Пропуск остаётся
для чисел, которые `NaN` быть не могут (`.length`, `indexOf`, счётчики с
известной нижней границей — их уже умеет `getValueBound`), и для строк,
булевых, BigInt. Удаление `|| 0` в примерах выдаётся как мутант.

## Фактическое поведение

```
logical-operator 'done / total || 0' -> 'done / total' [canonical-falsy-default/equivalent/H]
  the right operand is the only falsy value of the left operand's type, so the result is the same
```

## Подозреваемые места в коде

- `core/mutators/shared/get-logical-drops.ts:81-84` — `keepsFalsyDefault` не
  различает числа, которые могут быть `NaN`.
- `core/mutators/shared/get-canonical-falsy.ts` — «`0` for a number (`NaN`
  ignored)».
- `core/mutators/shared/get-nullish-swap-skip.ts` и
  `docs/content/mutators/logical-operator.md:165` — та же оговорка про `NaN`
  для `nullish-swap` (там это `noise`, что честнее).
