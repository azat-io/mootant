# BUG-902: нестабильный тест в dry run выдаётся за поломку инструментирования

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Dry run (`core/run/run-dry-phase.ts`) запускает тесты с переключёнными
(инструментированными) файлами без активного мутанта. Если что-то упало, вне
`--fast` код сразу переходит к `recoverFromFailures`
(`run-dry-phase.ts:161-170`): `checkRealFailures` перезапускает упавшие файлы
**без** переключённых файлов (`run-dry-phase.ts:385-421`), и если там они
проходят, файлы, чьи сайты задел упавший тест (`findBrokenFiles`,
`run-dry-phase.ts:505-517`), объявляются сломавшими тесты: диагностика
`instrumentation-break` (`run-dry-phase.ts:286-296`), все их мутанты — `Error`.
Повторного инструментированного прогона, который отличил бы нестабильный тест
от реальной поломки, нет; в `--fast` такой повтор есть
(`run-dry-phase.ts:195-213`). Итог: один «флак» в первом прогоне обвиняет
mootant, выбрасывает целые файлы, даёт exit code 1 (`cli/report/build-run-report.ts:151-156`
требует `counts.Error === 0`) и отменяет сохранение кэша
(`core/run-mutants.ts:515-526`).

## Воспроизведение

Юнит-тест (ветка `experiment/bug-repros`, `test/repros/BUG-902.test.ts`):

```ts
import { describe, expect, it } from 'vitest'

import type { DryRunResult } from '../../types/adapter/dry-run-result'
import type { SwitchedFile } from '../../types/adapter/switched-file'
import type { FakeWorld } from '../helpers/create-fake-adapter'

import { createFakeAdapter } from '../helpers/create-fake-adapter'
import { runDryPhase } from '../../core/run/run-dry-phase'

describe('BUG-902', () => {
  it('does not drop a switched file whose test failed once and passes when run again with the same switched file', async () => {
    let instrumented = 0
    let world: FakeWorld = {
      onDry: (result: DryRunResult, request) => {
        if (!request.instrumented) return result
        instrumented += 1
        if (instrumented > 1) return result
        return {
          ...result,
          tests: result.tests.map(test => ({
            ...test,
            tries: test.tries.map(facts => ({ ...facts, message: 'expected 0 not to be 0', failed: true })),
          })),
        }
      },
      tests: [{ file: '/t/a.test.ts', covers: ['a1'], id: 't1' }],
    }
    let fake = createFakeAdapter(world)
    let switched: SwitchedFile[] = [{ switched: 'hit("a1")', file: '/src/a.ts', original: '' }]
    let session = await fake.adapter.start({ workDirectory: '/work', concurrency: null, files: switched, root: '/' })
    let phase = await runDryPhase(session, {
      displays: new Map([['/src/a.ts', 'src/a.ts']]),
      mutantFiles: new Map([['a1', '/src/a.ts']]),
      report: () => {},
      repeat: false,
      root: '/',
      switched,
    })
    expect(phase.diagnostics.map(diagnostic => diagnostic.code)).not.toContain('instrumentation-break')
    expect(phase.errors.size).toBe(0)
    expect(switched.map(entry => entry.file)).toStrictEqual(['/src/a.ts'])
  })
})
```

```bash
pnpm exec vitest run test/repros/BUG-902.test.ts
# 1 failed: expected [ 'instrumentation-break' ] to not include 'instrumentation-break'
```

Сквозная фикстура (Vitest 5.0.5): тест вызывает `add` и падает только в
первом запуске своего файла (счётчик в `.runs`).

```bash
rm -f .runs && npx mootant run --no-cache
# x src/math.js: Tests fail with the switched src/math.js and pass without it;
#   its mutants are not run. [instrumentation-break]
# error 1, score none, exit code 1
```

## Ожидаемое поведение

Перед тем как обвинить инструментирование, упавшие тест-файлы перезапускаются с
теми же переключёнными файлами. Если они проходят, это нестабильный тест: его
мутанты идут дальше (как сейчас в `--fast` для `unrepeatable`-файлов, с
предупреждением `unrepeatable-test` или аналогичным), без
`instrumentation-break` и без `Error`. `instrumentation-break` остаётся только
для падений, которые повторяются с инструментированием и исчезают без него.

## Фактическое поведение

Файл выбрасывается с `instrumentation-break`, его мутанты `Error`, exit 1,
кэш не сохраняется.

## Подозреваемые места в коде

- `core/run/run-dry-phase.ts:161-170` — вне `repeat` нет инструментированного
  повтора перед `recoverFromFailures`.
- `core/run/run-dry-phase.ts:190-251` — `runCheckedDry`, где повтор есть только
  при `input.repeat`.
- `core/run/run-dry-phase.ts:385-421` — `checkRealFailures`.

## Критерий готовности

- Тест из `test/repros/BUG-902.test.ts` перенесён в
  `test/core/run/run-dry-phase.test.ts` и проходит; существующие кейсы
  `broken`/`failing` (`test/helpers/create-fake-adapter.ts`, `dry`) продолжают
  давать `instrumentation-break` и «Tests fail without mutants».
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
