# BUG-902: нестабильный тест в dry run выдаётся за поломку инструментирования

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.
>
> Перепроверено независимо: воспроизведено (юнит-тест падает с заявленным
> assert; сквозные фикстуры с упакованным mootant — Vitest 5.1.0 через npm,
> 5.0.5 через pnpm и node:test — дают `instrumentation-break` и `Error`, exit 1,
> а повторный запуск того же кода — `killed`, exit 0); скептик: не опроверг,
> medium — нужен нестабильный тест (документация требует проходящих тестов),
> отказ громкий и Killed/Survived не искажает, но mootant ложно винит себя,
> `--fast` тот же флак переживает, а флак до первого сайта мутанта или в
> `beforeAll` (его `retry` Vitest не повторяет) выбрасывает все переключённые
> файлы.

## Контекст

Dry run (`runDryPhase`, `core/run/run-dry-phase.ts:141-173`) запускает тесты,
связанные с переключёнными (инструментированными) файлами, без активного
мутанта. Вне `--fast` (`repeat: false`, `core/run-mutants.ts:417`)
`runCheckedDry` возвращается сразу после первого прогона (`:201-202`), и любое
падение уходит в `recoverFromFailures` (`:161-170`, сама функция `:275-321`):

1. `checkRealFailures` (`:385-421`) перезапускает упавшие тест-файлы **без**
   переключённых файлов (`instrumented: false`, `:402`). Падения, которые
   остались, останавливают прогон с «Tests fail without mutants; fix them
   first» (`:411-420`).
2. Если без инструментирования всё прошло, `findBrokenFiles` (`:505-517`)
   объявляет сломанными исходные файлы мутантов, чьи сайты задели упавшие
   тесты и незагрузившиеся тест-файлы. Если не задет ни один сайт, сломанными
   считаются **все** переключённые файлы (`:516`).
3. Каждый такой файл получает диагностику `instrumentation-break` с
   `severity: 'error'` и удаляется из `input.switched` (`:286-296`,
   `createDiagnostic` `:528-541`).
4. Повторный инструментированный dry run (`:300-308`) идёт только по
   оставшимся файлам и выброшенный файл не реабилитирует; если не осталось ни
   одного, повтора нет (`:297-299`). Его сообщение «Running the dry run again
   without 1 file that broke tests.» при флаке сбивает с толку.

Инструментированного повтора, который отличил бы нестабильный тест от реальной
поломки, вне `--fast` нет. В `--fast` он есть (`:195-213`): первый прогон идёт
с `repeat: true`, упавшие тест-файлы прогоняются ещё раз с
`instrumented: true, repeat: false`, а прошедшие в повторе сохраняются как
`unrepeatable`. JSDoc `runDryPhase` (`:124-127`) прямо закладывает эвристику
«падает с переключёнными файлами и проходит без них — виновато
инструментирование».

Итог: один флак в первом прогоне обвиняет mootant и выбрасывает целые файлы.
Их мутанты получают `Error` (`core/run/create-run-state.ts:113-120`), даже если
в кэше для них есть вердикты (скептик: после тёплого прогона «Reused cached
verdicts for 4 of 4 mutants» флак дал `error 4`, exit 1). `passed` требует
`totalErrors === 0` и `counts.Error === 0`
(`cli/report/build-run-report.ts:151-156`), поэтому код выхода 1
(`cli/run-mutation.ts:73-75`). С кэшем (он включён по умолчанию) так:

- если хотя бы один переключённый файл остался, сохранение отменяется с
  предупреждением `cache-skipped` (`core/run-mutants.ts:515-526` →
  `core/cache/save-run-cache.ts:64-69`);
- если выброшены все файлы, dry run пуст и `prepareRunCache` возвращает `null`
  (`core/cache/prepare-run-cache.ts:184-186`): предупреждения нет, файл кэша не
  трогается (скептик проверил по mtime). Поэтому в однофайловой фикстуре шага 2
  `cache-skipped` не будет; он виден в варианте 3a.

Почему флак — реальный сценарий:

- Адаптер Vitest сохраняет `retry` теста (`adapters/vitest/runner.ts:226-228`,
  `:618-619`): с `test: { retry: 1 }` флак внутри теста поглощается (у
  скептика `killed 4`, exit 0). Но `retry` не повторяет suite-хуки: флак в
  `beforeAll` (порт, БД, таймаут setup) при `retry: 2` даёт тот же
  `instrumentation-break` (вариант 3c).
- У адаптера node:test нет batch-режима (`adapters/node-test/index.ts:24`), а
  `fast = requestedFast && adapter.batch` (`core/run-mutants.ts:234`). Под
  node:test `--fast` не включает повтор, и страховки от флака нет совсем.
- Документация требует проходящих тестов
  (`docs/content/guide/getting-started.mdx:39-40`,
  `docs/content/guide/cli.mdx:29-30`, `readme.md:70`) и обещает exit 1 при
  ошибках (`docs/content/guide/cli.mdx:66`). Нарушенное предусловие оправдывает
  отказ выдавать вердикты, но не ложную причину. Понятия «нестабильный тест»
  вне `--fast` нет ни в коде, ни в документации, а `instrumentation-break` с
  `severity: 'error'` попадает в JSON-отчёт и может привести CI и агентов к
  ложному баг-репорту на mootant или к исключению файла из проверки.

## Воспроизведение

Ветки `experiment/bug-repros` в публичном репозитории нет, файлы ниже создай
сам. Нужны Node.js 22.12 или новее (Vitest 5 требует
`^22.12.0 || ^24.0.0 || >=26.0.0`,
`docs/content/guide/compatibility.mdx:22-24`; у скептика была Node 22.23.4) и
pnpm 12 (в CI стоит `latest-12`, `.github/actions/install-tools/action.yml:14`).
Шаги 2–3 рассчитаны на одну сессию shell: они используют переменную `TGZ`.

### Шаг 1. Падающий юнит-тест (fake-адаптер, сборка не нужна)

Сценарий: тест `t1` в `/t/a.test.ts` достигает мутанта `a1` файла `/src/a.ts`.
Хук `onDry` fake-адаптера (`test/helpers/create-fake-adapter.ts:37-40`, вызов
на `:379`; есть в 170ec52) портит только первый инструментированный dry run:
все попытки помечаются упавшими. Все следующие прогоны, с переключёнными
файлами и без них, проходят — как у нестабильного теста. Файл временный, в
коммит не входит (см. «Ограничения»).

```bash
# в корне клона azat-io/mootant
pnpm install
mkdir -p test/repros
cat > test/repros/BUG-902.test.ts <<'EOF'
import { describe, expect, it } from 'vitest'

import type { DryRunResult } from '../../types/adapter/dry-run-result'
import type { SwitchedFile } from '../../types/adapter/switched-file'
import type { FakeWorld } from '../helpers/create-fake-adapter'

import { createFakeAdapter } from '../helpers/create-fake-adapter'
import { runDryPhase } from '../../core/run/run-dry-phase'

describe('BUG-902: one flaky failure in the dry run is blamed on the instrumentation', () => {
  it('does not drop a switched file whose test failed once and passes when run again with the same switched file', async () => {
    let instrumented = 0
    /**
     * `t1` reaches mutant `a1` and fails in the first dry run only, as a flaky
     * test does once in a while; every later run passes, with or without the
     * switched files.
     */
    let world: FakeWorld = {
      onDry: (result: DryRunResult, request) => {
        if (!request.instrumented) {
          return result
        }
        instrumented += 1
        if (instrumented > 1) {
          return result
        }
        return {
          ...result,
          tests: result.tests.map(test => ({
            ...test,
            tries: test.tries.map(facts => ({
              ...facts,
              message: 'expected 0 not to be 0',
              failed: true,
            })),
          })),
        }
      },
      tests: [{ file: '/t/a.test.ts', covers: ['a1'], id: 't1' }],
    }
    let fake = createFakeAdapter(world)
    let switched: SwitchedFile[] = [
      { switched: 'hit("a1")', file: '/src/a.ts', original: '' },
    ]
    let session = await fake.adapter.start({
      workDirectory: '/work',
      concurrency: null,
      files: switched,
      root: '/',
    })
    let phase = await runDryPhase(session, {
      displays: new Map([['/src/a.ts', 'src/a.ts']]),
      mutantFiles: new Map([['a1', '/src/a.ts']]),
      report: () => {},
      repeat: false,
      root: '/',
      switched,
    })

    // The switched file did not break the test: the test passes with it when
    // it runs again. Blaming the instrumentation drops every mutant of the file
    // with `Error`, fails the run and keeps the cache from being saved.
    expect(phase.diagnostics.map(diagnostic => diagnostic.code)).not.toContain(
      'instrumentation-break',
    )
    expect(phase.errors.size).toBe(0)
    expect(switched.map(entry => entry.file)).toStrictEqual(['/src/a.ts'])
  })
})
EOF
pnpm exec vitest run test/repros/BUG-902.test.ts
```

### Шаг 2. Сквозной сценарий на упакованном mootant (Vitest, один файл)

`bin/mootant.js` импортирует `../dist/cli/index.js`, поэтому для CLI нужна
сборка. Ставь `vitest@5` (у верификаторов это была 5.1.0), а не
`vitest@5.0.5`: в npm 10.9.9 установка 5.0.5 ломается в arborist (ошибка про
`edgesOut`). Это баг npm, не mootant; BUG-902 воспроизводится на обеих версиях
(5.0.5 верификатор ставил через pnpm). `mootant run` без путей падает с
«mootant run needs paths, such as "mootant run src".»
(`core/run-mutants.ts:181-185`), поэтому путь `src` указан явно.

`.runs` — счётчик загрузок `test/math.test.js`: он читается и увеличивается
при загрузке модуля. 1-я загрузка — инструментированный dry run: `runs === 0`,
и тест `adds` падает на первой же проверке, ещё до вызова `add`. Значит,
упавшая попытка не задела ни одного сайта, и `src/math.js` объявляется
сломанным через запасной путь `:516` (с одним файлом разницы нет). 2-я загрузка
— проверка без инструментирования, там тест проходит. Поэтому перед прогоном,
который воспроизводит баг, `.runs` удаляется. Фикстура — скептика.

```bash
# в корне клона, после шага 1
pnpm build
pnpm pack                        # пишет mootant-0.1.0.tgz в корень клона
PACK="$(mktemp -d)"
mv mootant-0.1.0.tgz "$PACK/"    # *.tgz нет в .gitignore, не оставляй его в дереве
TGZ="$PACK/mootant-0.1.0.tgz"

FIX="$(mktemp -d)"
mkdir -p "$FIX/src" "$FIX/test"
cd "$FIX"
cat > package.json <<'EOF'
{
  "name": "bug-902-vitest",
  "private": true,
  "type": "module",
  "scripts": {
    "test": "vitest run"
  }
}
EOF
cat > src/math.js <<'EOF'
export function add(a, b) {
  return a + b
}

export function isPositive(value) {
  return value > 0
}
EOF
cat > test/math.test.js <<'EOF'
import { readFileSync, writeFileSync } from 'node:fs'
import { expect, it } from 'vitest'

import { add, isPositive } from '../src/math.js'

let counterFile = new URL('../.runs', import.meta.url)
let runs = 0
try {
  runs = Number(readFileSync(counterFile, 'utf8')) || 0
} catch {}
writeFileSync(counterFile, String(runs + 1))

it('adds', () => {
  // Fails only in the first run of this file: a stand-in for a flaky test.
  expect(runs).not.toBe(0)
  expect(add(2, 3)).toBe(5)
  expect(add(-2, 2)).toBe(0)
})

it('tells positive numbers', () => {
  expect(isPositive(1)).toBe(true)
  expect(isPositive(0)).toBe(false)
  expect(isPositive(-1)).toBe(false)
})
EOF
npm i -D vitest@5 "$TGZ"

rm -f .runs && npx mootant run src --no-cache; echo "exit=$?"         # instrumentation-break, error 4, exit=1
cat .runs                                                             # 2: dry run и проверка без мутантов
npx mootant run src --no-cache; echo "exit=$?"                        # .runs не сброшен: killed 4, exit=0
rm -f .runs && npx mootant run src --no-cache --fast; echo "exit=$?"  # killed 4, 2 × unrepeatable-test, exit 0
```

Второй прогон — оракул: тот же код с тем же инструментированием проходит, то
есть диагноз «поломка инструментирования» ложный.

### Шаг 3. Варианты (каждый — в своей свежей фикстуре)

**3a. Два файла, флак задевает сайт** (фикстура верификатора-воспроизводителя).
Счётчик увеличивается в теле теста, а тест вызывает `add` до проверки, поэтому
выбрасывается только `src/math.js`. `src/other.js` остаётся, по нему идёт
повторный dry run, и становится видна отмена сохранения кэша. Прогон идёт
**с** кэшем, без `--no-cache`. Верификатор задавал путь через
`"mootant": { "run": { "paths": ["src"] } }` в `package.json` и запускал
`npx mootant run`; по `core/run-mutants.ts:181-182` это то же, что
`npx mootant run src`.

```bash
E2="$(mktemp -d)"
mkdir -p "$E2/src" "$E2/test"
cd "$E2"
cat > package.json <<'EOF'
{
  "name": "bug-902-flaky-two-files",
  "private": true,
  "type": "module",
  "scripts": {
    "test": "vitest run"
  }
}
EOF
cat > src/math.js <<'EOF'
export function add(a, b) {
  return a + b
}
EOF
cat > src/other.js <<'EOF'
export function double(x) {
  return x * 2
}
EOF
cat > test/math.test.js <<'EOF'
import { readFileSync, writeFileSync } from 'node:fs'
import { expect, it } from 'vitest'

import { add } from '../src/math.js'

let runsFile = new URL('../.runs', import.meta.url)

it('adds two numbers', () => {
  let runs = 0
  try {
    runs = Number(readFileSync(runsFile, 'utf8'))
  } catch {}
  runs += 1
  writeFileSync(runsFile, String(runs))
  // Flaky: fails on the very first run only, passes on every later run.
  expect(add(2, 3)).toBe(runs === 1 ? 6 : 5)
})
EOF
cat > test/other.test.js <<'EOF'
import { expect, it } from 'vitest'

import { double } from '../src/other.js'

it('doubles a number', () => {
  expect(double(3)).toBe(6)
})
EOF
npm i -D vitest@5 "$TGZ"
rm -f .runs && npx mootant run src; echo "exit=$?"   # cache-skipped, instrumentation-break, killed 2, error 1
npx mootant run src; echo "exit=$?"                  # .runs не сброшен: killed 3
```

**3b. Два файла, флак до первого сайта** (фикстура скептика). Тест падает
раньше, чем вызывает `add`, и `findBrokenFiles` (`:516`) выбрасывает оба файла,
в том числе `src/text.js`, тест которого прошёл. У воспроизводителя тот же итог
дал вариант 3a с тестом, который вообще не вызывает `add`

**3c. Флак в `beforeAll` при `retry: 2`** (по фикстуре скептика, в каталоге
3b). У скептика счётчик лежал вне проекта (абсолютный путь, читался через
`sh`); здесь он заменён на `.runs` в корне фикстуры, и в таком виде вариант
**не запускался**.

```bash
cd "$E3"
cat > vitest.config.js <<'EOF'
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: { retry: 2 },
})
EOF
cat > test/math.test.js <<'EOF'
import { readFileSync, writeFileSync } from 'node:fs'
import { beforeAll, expect, it } from 'vitest'

import { add } from '../src/math.js'

let counterFile = new URL('../.runs', import.meta.url)

beforeAll(() => {
  // A suite hook that fails only in the first run of this file, as a flaky
  // server start or database connection would; retry does not repeat it.
  let runs = 0
  try {
    runs = Number(readFileSync(counterFile, 'utf8')) || 0
  } catch {}
  writeFileSync(counterFile, String(runs + 1))
  if (runs === 0) {
    throw new Error('EADDRINUSE: address already in use')
  }
})

it('adds', () => {
  expect(add(2, 3)).toBe(5)
})
EOF
rm -f .runs && npx mootant run src --no-cache; echo "exit=$?"   # у скептика: оба файла instrumentation-break, error 3
```

**3d. node:test** (по фикстуре скептика; счётчик заменён так же, как в 3c, в
таком виде **не запускался**). Адаптер node:test выбирается, когда скрипт
`test` запускает node:test или тест-файлы импортируют `node:test`
(`cli/built-in-adapters.ts:6-13`).

Контроли скептика без кода: с `test: { retry: 1 }` в `vitest.config.js` флак
внутри теста (счётчик попыток в памяти процесса, падает 1-я попытка)
поглощается — `killed 4`, exit 0; при тёплом кэше (4 из 4 вердиктов взяты из
кэша) флак в dry run всё равно даёт `error 4`, exit 1.

## Ожидаемое поведение

- Вне `--fast`, прежде чем винить инструментирование, упавшие и
  незагрузившиеся тест-файлы запускаются ещё раз с теми же переключёнными
  файлами, каждый тест один раз (`instrumented: true, repeat: false,
  files: <их тест-файлы>`) — до `checkRealFailures`.
- Тест-файлы, прошедшие в этом повторе, — нестабильные. Переключённые файлы не
  выбрасываются, `instrumentation-break` и `Error` нет. Результаты этих
  тест-файлов берутся из повтора, как в ветке `repeat` (`:228-245`). Тогда
  `dry` из `runDryPhase` по-прежнему не содержит упавших первых попыток и
  незагрузившихся файлов: сейчас это гарантировано тем, что оставшиеся падения
  бросают ошибку (`:309-318`, `:411-420`).
- Тихо продолжать нельзя. Отдельное предупреждение (`severity: 'warning'`)
  называет тест-файл (и тест со строкой, как `unrepeatable-test` в
  `core/run-mutants.ts:599-613`). Оно говорит, что тест упал с переключёнными
  файлами и прошёл при повторе с ними же, то есть нестабилен. Стоит добавить,
  что вердикты мутантов, которых он достигает, могут быть ненадёжны: в фазе
  мутантов флаки не обрабатываются и могут дать ложный `Killed` (замечание
  скептика).
- Тексты `--fast` сюда не подходят: «failed with each test run twice» (`:206`)
  и «fails when each test runs twice» (`core/run-mutants.ts:605`). К тому же
  `unrepeatable-test` выдаёт только `reportFastLimits`, а он вызывается лишь
  при `fast` (`core/run-mutants.ts:431-440`). Одного попадания файла в
  `unrepeatableFiles` вне `--fast` недостаточно: предупреждения не будет, а на
  маршрут мутантов это вне fast не влияет
  (`core/run/classify-mutants.ts:104-106`). Код предупреждения — существующий
  `unrepeatable-test` с новым текстом или новый (тогда расширь union
  `types/mutant/diagnostic.d.ts:10-33`); выбор опиши.
- Падения, которые повторились с инструментированием, идут по текущему пути:
  `checkRealFailures` → «Tests fail without mutants» или
  `instrumentation-break`, включая запасной путь `:516` для реальной поломки
  без задетых сайтов.
- Флак, не задевший ни одного сайта, тоже ничего не выбрасывает — ни свой
  файл, ни чужие (варианты 3b, 3c).
- Прогон, где был только флак, даёт код выхода 0 (если нет других ошибок и
  порог не нарушен): `totalErrors` считает только диагностики с
  `severity: 'error'` (`cli/report/build-list-report.ts:92-97`). Кэш
  сохраняется по обычным правилам: `failed` в `core/run-mutants.ts:517-520`
  тоже смотрит только на `error`.
- `--fast` не меняется: повтор там уже есть (`:195-213`). Дополнительный dry
  run — только при падениях, успешный путь не меняется.

### Направление исправления

- Не годится:
  - только убрать `!input.repeat ||` из условия на `:201`. Верификатор
