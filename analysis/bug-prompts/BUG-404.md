# BUG-404: кэш молча выключается из-за `mtime` не раньше старта прогона

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Чтобы не сохранить вердикт, полученный на старом тексте файла, кэш считает
«изменённым во время прогона» файл, у которого `mtimeMs >= start`
(`core/cache/find-changed-files.ts:20-33`). `prepareRunCache` применяет это
правило **без сравнения содержимого**: если так «изменился» любой файл
окружения (конфиг Vitest и его импорты, `package.json`, lockfile, `.env*`,
`tsconfig*.json`), функция возвращает `null`
(`core/cache/prepare-run-cache.ts:137-141`), а тест с такой зависимостью не
получает ключа (`:171-175`; если ключей нет совсем — тоже `null`, `:184-186`).
`runMutants` при `null` просто работает без кэша (`core/run-mutants.ts:442-459`):
нет ни диагностики, ни строки в отчёте (`summary.totalCached: null`).

Это срабатывает не только на настоящие правки во время прогона:

- часы файловой системы впереди часов процесса — WSL2 с файлами на `/mnt/c`,
  NFS/SMB, общие папки VM, распакованный архив с «будущими» датами: тогда кэш
  не работает **ни одного** прогона, пока часы не догонят;
- тест перезаписывает файл окружения тем же содержимым (например,
  `package.json` в тестах CLI, которые правят и восстанавливают его).

`saveRunCache` в той же ситуации сравнивает содержимое и, если файл
действительно изменился, пишет предупреждение `cache-skipped`
(`core/cache/save-run-cache.ts:79-93`) — `prepareRunCache` с ним
несогласован. Собственные тесты проекта обходят правило паузой
`await setTimeout(5)` после записи фикстуры
(`test/adapters/vitest/index.test.ts:359-360`).

## Воспроизведение

Создай `test/repros/BUG-404.test.ts` и запусти
`pnpm vitest run test/repros/BUG-404.test.ts --coverage.enabled=false` (оба
теста падают на 170ec52):

```ts
import { writeFile, realpath, mkdtemp, symlink, utimes, mkdir, rm } from 'node:fs/promises'
import { afterEach, expect, it } from 'vitest'
import { setTimeout } from 'node:timers/promises'
import { tmpdir } from 'node:os'
import path from 'node:path'

import type { RunResult } from '../../types/run/run-result'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

let roots: string[] = []

async function createProject(files: Record<string, string>): Promise<string> {
  let root = await realpath(await mkdtemp(path.join(tmpdir(), 'mootant-bug-')))
  roots.push(root)
  await mkdir(path.join(root, 'node_modules'))
  await symlink(
    await realpath(path.resolve(import.meta.dirname, '../../node_modules/vitest')),
    path.join(root, 'node_modules/vitest'),
  )
  for (let [file, text] of Object.entries({ 'package.json': '{ "type": "module" }', ...files })) {
    await mkdir(path.dirname(path.join(root, file)), { recursive: true })
    await writeFile(path.join(root, file), text)
  }
  await setTimeout(5)
  return root
}

function run(root: string): Promise<RunResult> {
  return runMutants({
    builtIns: createBuiltIns('vitest', vitestAdapter()),
    paths: ['src'],
    concurrency: 1,
    cwd: root,
  })
}

let files = {
  'vitest.config.ts': "export default { test: { include: ['test/**/*.test.ts'] } }\n",
  'src/math.ts': 'export function isAdult(age: number): boolean {\n  return age >= 18\n}\n',
  'test/math.test.ts': [
    "import { expect, it } from 'vitest'",
    "import { isAdult } from '../src/math'",
    "it('isAdult', () => {",
    '  expect(isAdult(30)).toBe(true)',
    '  expect(isAdult(5)).toBe(false)',
    '})',
  ].join('\n'),
}

afterEach(async () => {
  await Promise.all(roots.splice(0).map(root => rm(root, { recursive: true, force: true })))
})

it('reuses verdicts, or says why not, when the configuration has a future modification time', async () => {
  let root = await createProject(files)
  let future = new Date(Date.now() + 2 * 60 * 60 * 1000)
  await utimes(path.join(root, 'vitest.config.ts'), future, future)
  await run(root)

  let second = await run(root)

  let reused = second.results.some(entry => entry.cached)
  let explained = second.diagnostics.some(entry => entry.code === 'cache-skipped')
  expect(reused || explained).toBe(true)
}, 120_000)

it('reuses verdicts when a test writes package.json back unchanged', async () => {
  let root = await createProject({
    ...files,
    'test/math.test.ts': [
      "import { readFileSync, writeFileSync } from 'node:fs'",
      "import { expect, it } from 'vitest'",
      "import { isAdult } from '../src/math'",
      "it('isAdult', () => {",
      "  let file = new URL('../package.json', import.meta.url)",
      '  writeFileSync(file, readFileSync(file))',
      '  expect(isAdult(30)).toBe(true)',
      '  expect(isAdult(5)).toBe(false)',
      '})',
    ].join('\n'),
  })
  await run(root)

  let second = await run(root)

  expect(second.cache).toBe(true)
  expect(second.results.some(entry => entry.cached)).toBe(true)
}, 120_000)
```

Тот же эффект для зависимости теста: `touch -d '+2 hours' src/math.ts` — тест
навсегда без ключа, кэш-файл даже не создаётся (сценарий
`future_mtime_dependency` в `analysis/tools/cache/s-inputs.sh` ветки
`analysis/2026-11`).

## Ожидаемое поведение

Если содержимое файлов окружения и зависимостей не изменилось, второй прогон
переиспользует вердикты. Если mootant всё-таки отказывается от кэша, отчёт
говорит почему: диагностика `cache-skipped` с путём файла, как в `saveRunCache`.

## Фактическое поведение

Первый тест: `expected false to be true` — `second.cache === false`, ни один
вердикт не из кэша, `second.diagnostics` пуст. Второй тест:
`expected false to be true` на `second.cache`. В CLI: `--json --verbose` даёт
`"totalCached": null`, текстовый отчёт о кэше молчит.

## Подозреваемые места в коде

- `core/cache/prepare-run-cache.ts:137-141` — `files.some(file =>
  changed.has(file))` по одному `mtime`. Файлов окружения немного: их можно
  захэшировать в начале прогона (до dry run) и сравнить содержимое после, как
  делает `saveRunCache`.
- `core/cache/prepare-run-cache.ts:142-144` — исключение есть только для
  `DryFile.modified`; файлы окружения, которые перезаписал сам тест, туда не
  попадают.
- `core/cache/prepare-run-cache.ts:171-175` и `core/cache/find-changed-files.ts:20-33`
  — `mtime` в будущем относительно текущего момента не может означать правку
  во время прогона (если часы не шли назад); такой файл стоит проверять по
  содержимому, а не исключать навсегда.
- `core/run-mutants.ts:442-459` — `null` от `prepareRunCache` нигде не
  объясняется; нужна причина (например, `prepareRunCache` возвращает
  `{ cache: null, reason }` или диагностику).

## Критерий готовности

- Появляются тесты в `test/core/cache/prepare-run-cache.test.ts` (будущий
  `mtime` файла окружения при неизменном содержимом не выключает кэш либо даёт
  причину; настоящая правка файла окружения во время прогона по-прежнему
  выключает кэш) и интеграционный в `test/adapters/vitest/index.test.ts` по
  образцу тестов выше. Они падают до исправления и проходят после.
- Существующий тест «gives no key to what depends on a file changed during the
  run» (`test/core/cache/prepare-run-cache.test.ts:249`) остаётся осмысленным:
  настоящая правка во время прогона не даёт сохранить вердикт.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
