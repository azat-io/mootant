# BUG-905: неразбираемый текст замены из плагина не проверяется и превращает прогон в Error

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: low (заявлялась medium). Статус: подтверждён.
> Найдено на коммите 170ec52.
>
> Перепроверено независимо: воспроизведено (юнит-тест — 2 failed с заявленными
> сообщениями, 3 запуска из 3; сквозная фикстура на упакованном mootant:
> `mootant list` показывает `acme/broken a + b -> a +` как обычный мутант без
> диагностики, а `mootant run` даёт `error 4`, в том числе `instrumentation-break`
> у невиновного `src/other.js`, exit 1 — 3 прогона из 3 на Vitest 5.1.0 и 2 из
> 2 на 5.0.5); скептик: не опроверг, но снизил до low — нужен плагин-мутатор,
> нарушающий контракт `Replacement.text`, встроенные мутаторы таких текстов не
> дают, ложных Killed/Survived нет, сбой виден сразу на dry run, а выброс всех
> файлов прогона — общий механизм BUG-100 (та же строка
> `core/run/run-dry-phase.ts:516`); уникальная часть BUG-905 — текст замены не
> проверяется ни при генерации, ни при переключении.

## Контекст

Мутаторы — ESLint-подобные правила, в том числе из плагинов: конфиг подключает
плагин под пространством имён, и его мутаторы получают id вида `acme/broken`
(`types/config/plugin.d.ts:4-18`, `docs/content/guide/configuration.mdx:280-296`).
Публичный контракт `Replacement` (тип экспортируется из пакета,
`core/index.ts:25`) требует: «An expression must parse inside parentheses, a
statement list inside braces» (`types/mutator/replacement.d.ts:33-35`).
Проверяется только узел замены (`validateReplacement`,
`core/generate/validate-replacement.ts:49-84`), текст не проверяет никто:

- `groupReplacement` (`core/generate/group-replacement.ts:170-196`) лишь решает,
  нужны ли тексту скобки. Для операторов (kind `block`) он выходит сразу
  (`:178-184`). Для выражения в слоте, который принимает любое выражение и не
  стоит под оператором (аргумент `return`, выражение-оператор, условие `if` и
  т. п., `expressionParents`, `:77-92`), `needsParentheses` возвращает false на
  `:230-232` и текст не читает. Это и есть сценарий ниже: `return a + b` →
  `return a +`. Текст читается (`readText`, `:294-316`) только в узких слотах
  (аргумент вызова, инициализатор, операнд), и если он не разбирается ни в
  одном контексте, его лишь берут в скобки (`:233-236`): `Math.abs(a + b)` →
  `Math.abs((a +))`. Обёртка задумана и закреплена тестом
  `test/core/generate/group-replacement.test.ts:244-249` (`'c +'` → `'(c +)'`).
- `addReplacement` (`core/generate/collect-candidates.ts:266-367`) принимает
  такой кандидат, и `mootant list` показывает его как обычный мутант без
  диагностики. Оператор `if (a {` вместо `IfStatement` тоже становится
  `Pending` (проверил верификатор). При этом JSDoc `collectCandidates` обещает:
  «an invalid replacement become mutator errors and cost only that mutator,
  visit or replacement» (`:172-174`).
- `createSwitchedFiles` (`core/instrument/create-switched-files.ts:74-94`) не
  разбирает переключённый текст: проверка компиляции есть только для
  Svelte/Vue (`:78-93`). `instrumentFile` разбирает только исходник
  (`findStatementStarts`, `core/instrument/instrument-file.ts:57`,
  `core/instrument/find-statement-starts.ts:68-74`). На 170ec52 переключённый
  `src/math.js` из теста 1 ниже содержит
  `return (globalThis.__mootant?.hit("m1") ? (a +) : (a + b))`, и oxc находит в
  нём ошибку «Unexpected token» (верификатор).

В dry run тест-файл, импортирующий такой файл, падает при загрузке раньше
любого сайта (Vite: `Parse failure: Parse failed with 1 error:`), то есть с
`covers: []`. `findBrokenFiles` (`core/run/run-dry-phase.ts:505-517`) при
пустых уликах объявляет сломанными все переключённые файлы (`:516`). Мутанты
всех файлов прогона получают `Error` с сообщением «Tests fail with the switched
`<file>` and pass without it; its mutants are not run.» (`:289`), в том числе
файлы, которые ничего не ломали. Этот запасной вариант задуман (JSDoc
`:495-498`, тест `test/core/run/run-dry-phase.test.ts:466-493`) и разобран
отдельно как BUG-100; здесь он лишь усиливает ущерб. Сведения для сужения у
адаптера есть: по отладочному выводу скептика, `dependencies` упавшего
`test/math.test.js` содержат `src/math.js` и не содержат `src/other.js`
(`types/adapter/dry-file.d.ts:4-13`; поле заполняют Vitest,
`adapters/vitest/run-dry.ts:200`, и node:test,
`adapters/node-test/run-dry.ts:131`).

Но сужение задачу не решает. Вариант скептика (шаг 3b): упавший тест-файл до
ошибки разбора успел пройти сайт верхнего уровня другого файла. Тогда
`findBrokenFiles` обвиняет только этот невиновный файл, а сломанный оставляет.
Повторный dry run падает снова, и прогон аварийно завершается без отчёта:
«Tests still fail with mootant's switched files after the files that broke
them were dropped» (`:304-319`), без имени мутатора и позиции. Поэтому чинить
нужно проверку текста замены (или переключённого файла), а не
`findBrokenFiles`.

Почему low. Нужен плагин-мутатор, нарушающий контракт. Встроенные мутаторы
таких текстов не дают: по данным анализа, 0 неразбираемых переключённых
текстов на 46 567 встроенных мутантах. Экосистемы плагинов на 0.1.0 нет.
Ложных `Killed`/`Survived` нет: `Error` исключается из score
(`docs/content/guide/cli.mdx:61-63`), exit 1 (`:66`), сбой виден сразу на dry
run. Вред — в диагностике: обвиняются невиновные файлы, мутатор не назван,
ошибка разбора в обычном пути не выводится вовсе, и прогон бесполезен, пока
плагин не отключён. Обходы: `'acme/broken': 'off'` в конфиге или
`mootant run src/other.js` (2 killed, 100%).

Связанные находки того же анализа (их промптов в клоне нет, ниже — суть):

- BUG-100 (medium) — `findBrokenFiles` при пустых уликах выбрасывает все
  switched-файлы (`:516`) при любом провале до первого сайта: флак загрузки,
  упавший `beforeAll`, модуль, сломанный инструментированием. Сужение по
  `dependencies`, повтор и пробы исключением разбираются там.
- BUG-106 — переключённый текст берёт исходник и замену в скобки, и
  регулярное выражение, начинающееся с `<!--`, оказывается сразу после `(`.
  Vite 8 (rolldown/oxc с `sourceType: 'unambiguous'`) такой файл не разбирает:
  «HTML comments are not allowed in modules». Это другой, встроенный источник
  неразбираемого переключённого текста; его исправление — отдельно.

## Воспроизведение

Ветки `experiment/bug-repros` в публичном репозитории нет, файлы ниже создай
сам. Нужны Node.js 22.12 или новее (Vitest 5 требует
`^22.12.0 || ^24.0.0 || >=26.0.0`, `docs/content/guide/compatibility.mdx:22-24`)
и pnpm 12 (в CI стоит `latest-12`, `.github/actions/install-tools/action.yml:14`;
по наблюдению анализа, pnpm 10 не читает `configDependencies` из
`pnpm-workspace.yaml` и зависает). Шаги 2–3 рассчитаны на одну сессию shell:
они используют переменные `ROOT`, `TGZ`, `E2E` и функции `listed` и `report`.

`test/repros/BUG-905.test.ts` (файл из анализа целиком):

```ts
import { describe, expect, it } from 'vitest'

import type { DryRunResult } from '../../types/adapter/dry-run-result'
import type { SwitchedFile } from '../../types/adapter/switched-file'
import type { FakeWorld } from '../helpers/create-fake-adapter'

import { createSwitchedFiles } from '../../core/instrument/create-switched-files'
import { createFakeAdapter } from '../helpers/create-fake-adapter'
import { runDryPhase } from '../../core/run/run-dry-phase'
import { createMutant } from '../helpers/create-mutant'

describe('BUG-905: a replacement that does not parse breaks every switched file of the run', () => {
  it('reports the file whose switched text does not parse instead of serving it', () => {
    /**
     * A plugin mutator wrote `a +` in place of `a + b`; nothing checks that the
     * text parses, so the file is switched and served as is.
     */
    let math = 'export function add(a, b) {\n  return a + b\n}\n'
    let other = "export function greet(name) {\n  return 'Hello, ' + name\n}\n"
    let built = createSwitchedFiles([
      {
        mutants: [
          createMutant({
            file: 'src/math.js',
            replacement: 'a +',
            start: 37,
            end: 42,
          }),
        ],
        absolute: '/p/src/math.js',
        file: 'src/math.js',
        source: math,
      },
      {
        mutants: [
          createMutant({
            replacement: "'Hello, '",
            file: 'src/other.js',
            start: 39,
            id: 'm2',
            end: 55,
          }),
        ],
        absolute: '/p/src/other.js',
        file: 'src/other.js',
        source: other,
      },
    ])

    expect(built.diagnostics.map(diagnostic => diagnostic.file)).toStrictEqual([
      'src/math.js',
    ])
    expect(built.switched.map(entry => entry.file)).toStrictEqual([
      '/p/src/other.js',
    ])
  })

  it('does not blame a switched file that no failing test file reached or loaded', async () => {
    /**
     * `/t/a.test.ts` fails to load while the switched files are served, before
     * any site ran, as when a switched `/src/a.ts` does not parse;
     * `/t/b.test.ts` only uses `/src/b.ts` and passes.
     */
    let world: FakeWorld = {
      onDry: (result: DryRunResult, request) =>
        request.instrumented ?
          {
            ...result,
            files: result.files.map(file =>
              file.file === '/t/a.test.ts' ?
                {
                  ...file,
                  errors: ['SyntaxError: Unexpected token'],
                  loadFailed: true,
                  covers: [],
                }
              : file,
            ),
            tests: result.tests.filter(test => test.file !== '/t/a.test.ts'),
          }
        : result,
      tests: [
        { file: '/t/a.test.ts', covers: ['a1'], id: 'ta' },
        { file: '/t/b.test.ts', covers: ['b1'], id: 'tb' },
      ],
    }
    let fake = createFakeAdapter(world)
    let switched: SwitchedFile[] = [
      { switched: 'hit("a1")', file: '/src/a.ts', original: '' },
      { switched: 'hit("b1")', file: '/src/b.ts', original: '' },
    ]
    let session = await fake.adapter.start({
      workDirectory: '/work',
      concurrency: null,
      files: switched,
      root: '/',
    })
    let phase = await runDryPhase(session, {
      displays: new Map([
        ['/src/a.ts', 'src/a.ts'],
        ['/src/b.ts', 'src/b.ts'],
      ]),
      mutantFiles: new Map([
        ['a1', '/src/a.ts'],
        ['b1', '/src/b.ts'],
      ]),
      report: () => {},
      repeat: false,
      root: '/',
      switched,
    })

    // `src/b.ts` broke nothing: its only test passes with it switched.
    expect([...phase.errors.keys()]).not.toContain('src/b.ts')
  })
})
```

Результат на 170ec52 (верификатор, 3 запуска из 3):

```
2 failed
  expected [] to strictly equal [ 'src/math.js' ]                 # строка 50
  expected [ 'src/a.ts', 'src/b.ts' ] to not include 'src/b.ts'  # строка 114
```

Смещения в тесте 1 верные: `math.slice(37, 42)` — `a + b`,
`other.slice(39, 55)` — `'Hello, ' + name`.

- **Тест 1** — суть BUG-905 на уровне переключения: `createSwitchedFiles`
  отдаёт `src/math.js` с неразбираемым текстом (`diagnostics` пуст, в `switched`
  оба файла). Мутанты он строит сам, в обход генерации. Поэтому проверка только
  при генерации его не исправит: тогда его заменяют тесты генерации (см.
  «Критерий готовности»).
- **Тест 2** моделирует механизм BUG-100 и к этому исправлению не обязателен. В
  этой форме его не сделает зелёным даже верное сужение подозреваемых по
  `dependencies`, и причин две (обе верификатор подтвердил на копии 170ec52):
  - (а) мир не задаёт `cacheInputs`, и фейк не заполняет
    `DryFile.dependencies` (`test/helpers/create-fake-adapter.ts:319-324`). По
    правилу «все файлы, если зависимости неизвестны» `src/b.ts` всё равно
    обвиняется;
  - (б) `onDry` роняет `/t/a.test.ts` в любом инструментированном прогоне.
    Поэтому после верного сужения до `src/a.ts` повторный dry run падает снова,
    и `runDryPhase` бросает «Tests still fail with mootant's switched files
    after the files that broke them were dropped»
    (`core/run/run-dry-phase.ts:304-319`).

  Исправленный мир: замени им `world` в тесте 2, остальное без изменений. У
  верификатора на 170ec52 такой тест падал с тем же сообщением, а с патчем
  сужения проходил:

  ```ts
      let world: FakeWorld = {
        onDry: (result: DryRunResult, request) =>
          request.instrumented && request.related.includes('/src/a.ts') ?
            {
              ...result,
              files: result.files.map(file =>
                file.file === '/t/a.test.ts' ?
                  {
                    ...file,
                    errors: ['SyntaxError: Unexpected token'],
                    loadFailed: true,
                    covers: [],
                  }
                : file,
              ),
              tests: result.tests.filter(test => test.file !== '/t/a.test.ts'),
            }
          : result,
        tests: [
          { file: '/t/a.test.ts', covers: ['a1'], id: 'ta' },
          { file: '/t/b.test.ts', covers: ['b1'], id: 'tb' },
        ],
        files: [
          { dependencies: ['/t/a.test.ts', '/src/a.ts'], file: '/t/a.test.ts' },
          { dependencies: ['/t/b.test.ts', '/src/b.ts'], file: '/t/b.test.ts' },
        ],
        cacheInputs: { settings: null, files: [] },
      }
  ```

  `request.instrumented` в условии нужен: проверка без мутантов
  (`checkRealFailures`) идёт с тем же `related` и `instrumented: false`
  (`core/run/run-dry-phase.ts:398-407`). Без него провал сочли бы настоящим
  («Tests fail without mutants»). Разбор BUG-100 советует условие строже — по
  отдаваемым файлам: `request.instrumented && result.served.includes('/src/a.ts')`.
  Фейк строит `served` из `context.files` (`test/helpers/create-fake-adapter.ts:369-371`),
  а это тот же массив `switched`, из которого `recoverFromFailures` удаляет
  файлы (`core/run/run-dry-phase.ts:295-296`). Вариант с `served` не
  запускался.

### Шаг 2. Сборка и упаковка mootant

`bin/mootant.js` импортирует `../dist/cli/index.js`, а `dist/` в репозитории
нет, поэтому для CLI нужна сборка.

```bash
# в корне клона, после шага 1
ROOT="$(pwd)"

    let r = JSON.parse(require('fs').readFileSync('report.json', 'utf8'))
    let s = r.summary
```

### Шаг 3. Сквозные сценарии

Ставь `vitest@5` (у верификаторов — 5.1.0), а не `vitest@5.0.5`: в npm 10.9.9
установка 5.0.5 падает в arborist с `Cannot read properties of null (reading
'edgesOut')`. Это баг npm, не mootant. Воспроизводитель повторил сценарий 3a и
на Vitest 5.0.5 через pnpm, итог тот же. `mootant list` требует путь;
`mootant run` без путей берёт `run.paths` из конфига
(`core/run-mutants.ts:181-185`), но ниже путь `src` указан явно. Фикстуры и
команды mootant те же, что у верификаторов. В таком виде (heredoc,
`npm i -D vitest@5 "$TGZ"`, функции `listed` и `report`, контроль через
`--config`) команды целиком не запускались.

**3a. Основной сценарий.** Плагин `acme/broken` пишет `a +` вместо `a + b` в
`src/math.js`. Остальные 3 мутанта дают встроенные мутаторы пресета
`recommended` (он применяется, когда `extends` не задан):
`arithmetic-operator` в обоих файлах и `string-literal` в `src/other.js`.

```bash
mkdir -p "$E2E/main/src" "$E2E/main/test"
cd "$E2E/main"
cat > package.json <<'EOF'
{ "name": "bug-905", "private": true, "type": "module" }
EOF
cat > mootant.config.js <<'EOF'
// A plugin mutator with a bug: for `a + b` in math.js it writes a text that
// does not parse.
let broken = {
  meta: { description: 'Writes an unfinished expression.' },
  create(context) {
    return {
      BinaryExpression(node) {
        return context.file.endsWith('math.js') && node.operator === '+' ?
            [{ node, text: 'a +' }]
          : []
      },
    }
  },
}

export default {
  plugins: { acme: { mutators: { broken } } },
  mutators: { 'acme/broken': 'on' },
  run: { runner: 'vitest', paths: ['src'] },
}
EOF
cat > vitest.config.js <<'EOF'
import { defineConfig } from 'vitest/config'

export default defineConfig({ test: { include: ['test/**/*.test.js'] } })
EOF
cat > src/math.js <<'EOF'
export function add(a, b) {
  return a + b
}
EOF
cat > src/other.js <<'EOF'
export function greet(name) {
  return 'Hello, ' + name
}
EOF
cat > test/math.test.js <<'EOF'
import { test, expect } from 'vitest'

import { add } from '../src/math.js'

test('add', () => {
  expect(add(2, 3)).toBe(5)
})
EOF
cat > test/other.test.js <<'EOF'
import { test, expect } from 'vitest'

import { greet } from '../src/other.js'

test('greet', () => {
  expect(greet('Ada')).toBe('Hello, Ada')
})
EOF
npm i -D vitest@5 "$TGZ"
npx vitest run                                    # без mootant оба теста проходят
listed                                            # 4 мутанта, у acme/broken after = ["  return a +"], diagnostics []
npx mootant run src --no-cache; echo "exit=$?"    # error 4, exit=1 (вывод — в «Фактическом поведении»)
report                                            # run exit=1, 4 мутанта, 4 Error, два instrumentation-break
npx mootant run src/other.js --no-cache; echo "exit=$?"   # контроль: только other.js — 2 killed, 100%
sed "s|'acme/broken': 'on'|'acme/broken': 'off'|" mootant.config.js > mootant.off.config.js
npx mootant run src --no-cache --config mootant.off.config.js; echo "exit=$?"   # контроль: killed 3, 100%, exit=0
```

Контроль с выключенным плагином верификатор делал правкой самого конфига, а не
через `--config`; итог — killed 3, score 100%, exit 0.

**3b. Вариант: обвиняется только невиновный файл, прогон падает.** У
`src/other.js` есть сайт верхнего уровня, и `test/math.test.js` импортирует его
раньше `src/math.js`. Сужение подозреваемых по `dependencies` этот случай не

### Направление исправления

Выводы сделаны по чтению кода, если не сказано иное.

1. **Проверка текста при генерации (обязательная часть).** В `addReplacement`
   после `validateReplacement` для плагинных мутаторов:
   - kind `expression`: разбери `replacement.text` так же, как это делает
     `readText` (`core/generate/group-replacement.ts:294-316`). Текст к этому
     моменту уже прошёл `groupReplacement` и может быть в скобках. Используй
     `parseExpression` (`core/text/parse-expression.ts:37-70`): сначала контекст
     `method`, затем `script`, сначала язык файла, затем вариант с JSX. Если ни
     одно чтение не удалось, сделай как с нарушением `validateReplacement`:
     ``createMutatorError(parsed, node, `Mutator "${registered.id}" …`)``,
     затем `skip(…)` с правилом и `return`. Правило — `invalid-target`
     (категория `invalid`, `core/skips/skip-rules.ts:182-185`) или новое:
     `SkipRuleId` выводится из ключей реестра

     `core/skips/skip-rules.ts`. Если переиспользуешь чтение из
     `group-replacement.ts`, вынеси его в свой файл («одна функция — один
     файл»).

     `parseExpression` разбирает `this.#count + 1` и `#x in obj` в обоих

     проверялись.

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига, контракт `Mutator`/`Replacement`) без явной необходимости; если без
  этого нельзя — опиши компромисс. Проверка текста лишь исполняет уже
  объявленный контракт `Replacement.text`; форму `Replacement` и `Mutator` не
  меняй.
- Сообщения коммитов — Conventional Commits (commitlint).
- Тест из шага 1 нельзя копировать в `test/repros/` как есть. Этот каталог не
  исключён ни из ESLint, ни из knip, cspell, tsc или Vitest; исключён только
  `test/fixtures/**` (`eslint.config.ts:15`, `knip.config.ts:5`,
  `cspell.config.ts:44`, `tsconfig.json:2`, `vitest.config.ts:18`). На похожем
  файле BUG-100 верификатор видел `vitest/prefer-lowercase-title` (заголовок
  `describe` с «BUG-…») и `unicorn/filename-case` (имя `BUG-….test.ts`). Для
  этого файла ESLint не запускали, но имя и заголовок устроены так же.
  Постоянные тесты перепиши в стиле проекта: имена файлов, `describe`/`it`,
  порядок импортов, JSDoc. Проще всего добавить новые `it` в
  `test/core/generate/collect-candidates.test.ts` (и, при разборе при
  переключении, в `test/core/instrument/create-switched-files.test.ts`).
  Фикстуры, если понадобятся, клади в `test/fixtures/**`.
- `pnpm test` после `pnpm build` даёт ложные ошибки `test:astro`: в базовой
  линии анализа это 14 ошибок `ts(2322)` в `docs/components/*.astro`. Причина:
  `tsconfig.json` включает `**/*.ts` (`:4`) и не исключает `dist/` (`:2`).
  После сборки в программу попадает `dist/types/html/inline-script.d.ts` с
  `/// <reference types="vite/client" />`, и объявления `*.svg` из Vite
  конфликтуют с SVG-компонентами Astro. После шага 2 запускай `test:unit`,
  `test:js`, `test:types` и остальные скрипты по отдельности, а `test:astro` —
  после `rm -rf dist`.
- Известные зависимости `test:unit` от окружения, не связанные с этим багом
  (базовая линия анализа):
  - 4 теста в `test/cli/run-list.test.ts` и `test/cli/run-mutation.test.ts`
    ждут Unicode-символы и падают при `TERM=linux`
    (`cli/terminal/is-unicode-supported.ts:13`); запускай с
    `TERM=xterm-256color`;
  - тест «skips test files it cannot read»
    (`test/adapters/node-test/score-node-test.test.ts:98`) падает под root;
  - при заданном `NODE_OPTIONS` покрытие ветвей
    `adapters/node-test/start-node-test-session.ts:119,167` ниже 100%;
    запускай с `env -u NODE_OPTIONS`.

  Сверяй падения с прогоном на нетронутом коде.
- Границы задачи: запасной вариант «сломаны все» в `findBrokenFiles`
  (`core/run/run-dry-phase.ts:516`) — BUG-100, а `(/<!--` в переключённом
  тексте под Vite 8 — BUG-106; здесь их не чини. Если в твоём дереве BUG-100
  уже исправлен, до правки 3a может обвинить только `src/math.js`. 3c от
  BUG-100 не зависит, 3b, по чтению, воспроизводится всё равно (улики там
  есть, и они указывают на невиновный файл), а главными критериями остаются

  нет ни `mutator-error`, ни контракта `Replacement.text` (проверено поиском
