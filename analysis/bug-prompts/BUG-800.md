# BUG-800: плагинный мутатор со своим правилом пропуска роняет `list --skipped` и `run --html`

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён (воспроизведён
> координатором независимо от нашедшего агента). Найдено на коммите 170ec52.

## Контекст

Плагины Mootant устроены как правила ESLint: мутатор возвращает замены, и
замена может нести `skip: { rule, reason }`. Такая замена не становится
мутантом, но `mootant list --skipped` показывает её с причиной
(`types/mutator/replacement.d.ts:26-30`). Тип `skip.rule` —
`SkipRuleId = keyof typeof skipRules` (`types/mutant/skip-rule-id.d.ts:7`),
то есть закрытое множество встроенных правил (`core/skips/skip-rules.ts`).
Плагин на JavaScript (или TypeScript с приведением типа) может передать своё
имя правила. Ядро его не проверяет, а при выводе пропущенных кандидатов читает
`skipRules[candidate.rule].heuristic` (`core/generate/generate-file-mutants.ts:376-377`).
Для неизвестного правила это `undefined`, и процесс падает с непонятным
`TypeError`. Пропущенных кандидатов перечисляет и `mootant run --html`
(`core/run-mutants.ts:198`, `skipped: html !== null`). Значит, у проекта с
таким плагином падает и запуск с HTML-отчётом.

## Воспроизведение

```bash
mkdir -p /tmp/bug-800/src && cd /tmp/bug-800
npm init -y >/dev/null
npm i -D mootant   # или tarball сборки из этого репозитория: pnpm build && pnpm pack
cat > src/a.js <<'JS'
export function f(a) {
  return a + 1
}
JS
cat > plugin.mjs <<'JS'
export default {
  mutators: {
    'skip-everything': {
      meta: { description: 'Test mutator that skips with a custom rule' },
      create() {
        return {
          BinaryExpression(node) {
            return [{ node, text: 'a - 1', skip: { rule: 'my-own-rule', reason: 'plugin rule' } }]
          },
        }
      },
    },
  },
}
JS
cat > mootant.config.mjs <<'JS'
import acme from './plugin.mjs'
export default {
  plugins: { acme },
  mutators: { 'acme/skip-everything': 'on' },
}
JS
npx mootant list src;           echo "exit=$?"
npx mootant list src --skipped; echo "exit=$?"
```

Исходная фикстура: `analysis/architecture/repro-plugin-skip-rule/` в ветке
`analysis/2026-11`.

## Ожидаемое поведение

Один из двух вариантов, на выбор мейнтейнера:

1. Ядро принимает собственные правила пропуска плагинов. Например, правило
   объявляется в `meta` мутатора или плагина со своими `category` и
   `heuristic`, а `list --skipped` показывает его.
2. Ядро валидирует `skip.rule` при получении замены и выдаёт понятную ошибку
   или диагностику с именем плагина и правила (как `validate-config` для
   неизвестных мутаторов) вместо `TypeError`.

## Фактическое поведение

```
$ npx mootant list src
… mutants 2 in 1 file …            # exit=0, замена плагина молча исчезла
$ npx mootant list src --skipped
Error: Cannot read properties of undefined (reading 'heuristic')
exit=1
```

## Подозреваемые места в коде

- `core/generate/generate-file-mutants.ts:376-377`: чтение
  `skipRules[candidate.rule].heuristic` без проверки.
- `core/generate/validate-replacement.ts`: не проверяет `skip.rule`.
- `types/mutant/skip-rule-id.d.ts:7`: публичный тип закрывает множество
  правил. Если выбран вариант 1, его нужно расширить (`string` с
  регистрацией).
- `core/run-mutants.ts:198`: тот же путь срабатывает в `run --html`.

## Критерий готовности

- Новый тест в `test/core/generate/generate-file-mutants.test.ts`: мутатор
  с неизвестным `skip.rule` даёт либо видимого пропущенного кандидата с
  корректными `category`/`heuristic`, либо понятную ошибку или диагностику,
  но не `TypeError`.
- Интеграционный тест CLI (`test/cli/run-list.test.ts`): `list --skipped` с
  таким плагином не падает (или падает с понятным сообщением и exit 1, если
  выбран вариант 2).
- Документация плагинного API (`docs/content/guide/configuration.mdx`)
  описывает, можно ли плагину заводить свои правила пропуска.
- `pnpm test` полностью зелёный, включая 100% coverage.
