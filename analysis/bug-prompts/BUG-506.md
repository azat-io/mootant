# BUG-506: `mootant run` не завершается, если что-то в его процессе держит event loop

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён. Найдено на
> коммите 170ec52.

## Контекст

С адаптером Vitest в процессе mootant выполняется код проекта: конфиг Vitest,
плагины Vite, `globalSetup`. Частая ошибка — `globalSetup`, который поднимает
сервер или вотчер и не закрывает его. Vitest CLI защищён от этого: после
`teardownTimeout` (10 с) печатает «close timed out after 10000ms» и вызывает
`process.exit()`. mootant после `vitest.close()`
(`adapters/vitest/start-vitest-session.ts:149-157`) просто ждёт естественного
завершения event loop (`bin/mootant.js:5` вызывает `run()` без выхода), поэтому
печатает весь отчёт и висит. В CI это зависший джоб до его лимита (у GitHub
Actions по умолчанию 6 часов), у агента с `--json` — бесконечное ожидание
завершения процесса; код выхода (например, 1 ниже порога) теряется.

## Воспроизведение

Фикстура в ветке `experiment/bug-repros`: `test/repros/BUG-506/` со скриптом
`run.sh` (собирает `dist`, если его нет).

```js
// global-setup.js
import http from 'node:http'

export default function setup() {
  http.createServer((request, response) => response.end('ok')).listen(0)
}

// vitest.config.js
export default {
  test: {
    include: ['test/**/*.check.js'],
    globalSetup: ['./global-setup.js'],
  },
}

// src/add.js
export function add(a, b) {
  return a + b
}

// test/add.check.js
import { expect, it } from 'vitest'

import { add } from '../src/add.js'

it('adds', () => {
  expect(add(2, 3)).toBe(5)
})
```

```bash
test/repros/BUG-506/run.sh   # выход 1 = воспроизведено
```

## Ожидаемое поведение

После того как отчёт напечатан и сессия закрыта, `mootant run` завершается
не позже чем через таймаут закрытия (как `vitest --run`), с предупреждением в
stderr о том, что что-то держит процесс, и с правильным кодом выхода.

## Фактическое поведение

```
vitest --run: exit 0 after 12 s
mootant run: exit 124 after 40 s; report lines: 11
REPRODUCED: mootant printed its report and did not exit within 40 s
```

## Подозреваемые места в коде

- `bin/mootant.js:5`, `cli/index.ts:12-32` — нет принудительного выхода после
  завершения команды.
- `cli/run-mutation.ts:38-95`, `cli/run-list.ts:17-46` — место, где известен
  код выхода; после печати отчёта и HTML можно дать процессу ограниченное
  время (`unref`-таймер) и затем `process.exit(process.exitCode)` с
  предупреждением.
- `adapters/vitest/start-vitest-session.ts:149-157` — закрытие Vitest.
- Правило `unicorn/no-process-exit` в конфиге ESLint разрешает
  `process.exit()` только в обработчике `process.on()` (см. комментарий в
  `cli/terminal/create-spinner.ts:149-152`) — учти это при выборе места.

## Критерий готовности

- Тест (например, в `test/cli/index.test.ts` или `run-mutation.test.ts`):
  при активном хэндле после завершения команды процесс завершается с
  сохранённым кодом выхода после таймаута и печатает предупреждение; падает до
  исправления, проходит после. `test/repros/BUG-506/run.sh` завершается с
  кодом 0.
- Обычный прогон не замедляется (таймер `unref`).
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
