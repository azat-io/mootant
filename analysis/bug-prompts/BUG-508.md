# BUG-508: проекты Vitest со своим `root` (монорепо) не настраиваются — dry run падает

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: high. Статус: подтверждён. Найдено на коммите
> 170ec52.

## Контекст

Для каждого проекта Vitest mootant ставит свой раннер, пул forks, `isolate`,
отключает снапшоты и т. д. (`adapters/vitest/configure-project.ts`) из хука
`configureVitest` своего Vite-плагина (`adapters/vitest/create-mootant-plugin.ts:53`),
а мутанты подменяет в его `transform`-хуке (`:32`). Плагин передаётся в
`createVitest` третьим аргументом — только в корневой Vite-сервер
(`adapters/vitest/start-vitest-session.ts:110`). Для проекта с другим `root`
Vitest создаёт отдельный сервер и вызывает `configureVitest` по плагинам
`project.vite.config` (Vitest 5.0.5:
`node_modules/vitest/dist/chunks/cli-api.De07GUeT.js:12410-12411`), поэтому
такой проект не настроен: свой раннер Vitest, нет out-файлов, нет подмены.
Самая распространённая схема монорепо — `test.projects: ['packages/*']` —
целиком не работает из корня: mootant сообщает, что тесты падают без мутантов,
хотя `vitest --run` зелёный. Заодно для таких проектов не выполняется
`checkProjectConfig` (неподдерживаемый пул не будет отловлен).

## Воспроизведение

Падающий тест в ветке `experiment/bug-repros`: `test/repros/BUG-508.test.ts` и
фикстура `test/repros/BUG-508/`:

```ts
// test/repros/BUG-508/vitest.config.ts
export default {
  test: {
    projects: [
      {
        test: {
          include: ['test/**/*.check.ts'],
          root: './pkg',
          name: 'pkg',
        },
      },
    ],
  },
}

// test/repros/BUG-508/pkg/src/add.ts
export function add(a: number, b: number): number {
  return a + b
}

// test/repros/BUG-508/pkg/test/add.check.ts
import { expect, it } from 'vitest'

import { add } from '../src/add'

it('adds', () => {
  expect(add(2, 3)).toBe(5)
})
```

`package.json` фикстуры: `{ "name": "bug-508-fixture", "private": true,
"type": "module", "scripts": { "test": "vitest --run" } }`.

```ts
// test/repros/BUG-508.test.ts
import { describe, expect, it } from 'vitest'
import path from 'node:path'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

let root = path.resolve(import.meta.dirname, 'BUG-508')

describe('BUG-508: Vitest projects with a root of their own', () => {
  it('runs the mutants of a project whose root is not the root of the run', async () => {
    let result = await runMutants({
      builtIns: createBuiltIns('vitest', vitestAdapter()),
      paths: ['pkg/src'],
      concurrency: 1,
      cache: false,
      cwd: root,
    })

    expect(
      result.results.map(
        verdict => `${verdict.mutant.replacement} ${verdict.status}`,
      ),
    ).toContain('a - b Killed')
  }, 60_000)
})
```

```bash
(cd test/repros/BUG-508 && npx vitest --run)   # 1 passed
pnpm vitest --run test/repros/BUG-508.test.ts  # падает
```

Те же результаты дают `projects: ['packages/*']` (каталоги без своих
конфигов), `extends: true`, конфиги в пакетах (`projects:
['packages/*/vitest.config.js']`). Проекты с общим `root` (только `include`)
работают; запуск mootant из каталога пакета — тоже.

## Ожидаемое поведение

Проект со своим `root` настраивается так же, как корневой: dry run проходит,
мутант `a + b -> a - b` — Killed.

## Фактическое поведение

```
Error: Tests fail without mutants; fix them first (1 test file):
  pkg/test/add.check.ts: fails to load: The test runner did not report this file.
```

Пробник (плагин с `configureVitest`, переданный в `createVitest` так же, как
делает mootant) на проектах `a` (`root: 'packages/a'`) и `b` (общий root):
`configureVitest called for: [ 'b' ]`.

## Подозреваемые места в коде

- `adapters/vitest/start-vitest-session.ts:91-117` — как плагин попадает в
  Vitest; после `createVitest` можно проверить, что каждый проект из
  `vitest.projects` настроен (запоминать настроенные в `state`), и либо
  настроить остальные, либо остановиться с понятной ошибкой.
- `adapters/vitest/create-mootant-plugin.ts:32-55` — `transform` и
  `configureVitest`; плагин должен оказаться в Vite-конфиге каждого проекта
  (например, через хук `config` корневого плагина, дописывающий себя в inline
  проекты, или через `injectTestProjects`), иначе подмена мутантов в проекте
  со своим сервером не работает даже после `configureProject`.
- `adapters/vitest/configure-project.ts` — настройка проекта.

## Критерий готовности

- Тест в `test/adapters/vitest/` с фикстурой из двух проектов со своими `root`
  (и проектом без `root`): dry run проходит, вердикты совпадают с ручным
  применением мутантов; падает до исправления, проходит после.
  Воспроизведение `test/repros/BUG-508.test.ts` проходит.
- Неподдерживаемая настройка в проекте со своим `root` (например, `pool:
  'vmThreads'`) по-прежнему даёт ошибку `checkProjectConfig`.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
