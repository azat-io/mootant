# BUG-100: провал dry run без достигнутых сайтов выбрасывает все switched-файлы

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.
>
> Перепроверено независимо: воспроизведено (юнит-тест падает в обоих кейсах,
> 3 запуска из 3; сквозные фикстуры на упакованном mootant — Vitest 5.0.5 и
> 5.1.0, а также node:test — выбрасывают невиновный `src/price.js` с
> `instrumentation-break`, все мутанты `Error`, exit 1; flaky — только без
> `--fast`); скептик: не опроверг, medium как нижняя граница — фолбэк «все
> файлы» задуман (его закрепляют JSDoc и тест), сбой громкий и ложных
> Killed/Survived не даёт, но в режиме по умолчанию один провал до первого
> сайта (флак загрузки или `beforeAll`, модуль, сломанный инструментированием)
> лишает вердиктов весь прогон, а диагностика обвиняет невиновные файлы и
> молчит о настоящей причине.

## Контекст

Перед прогоном мутантов Mootant делает dry run: тесты, связанные с
переключёнными (switched) файлами, запускаются на их инструментированном
тексте без активного мутанта (`runDryPhase`,
`core/run/run-dry-phase.ts:141-173`). Если тесты падают или тест-файлы не
загружаются, `recoverFromFailures` (`:275-321`) сначала перезапускает упавшие
тест-файлы без switched-файлов (`checkRealFailures`, `:385-421`,
`instrumented: false` на `:402`). Оставшиеся провалы останавливают прогон, а
исчезнувшие считаются вызванными инструментированием: «виновные»
switched-файлы получают диагностику `instrumentation-break` и удаляются из
`input.switched` (`:285-296`, текст на `:289`). Их мутанты получают `Error`
(`core/run/create-run-state.ts:113-120`), и прогон завершается с кодом 1:
`summary.passed` требует `counts.Error === 0`
(`cli/report/build-run-report.ts:151-156`), код выхода ставит
`cli/run-mutation.ts:73-75`.

Виновных выбирает `findBrokenFiles` (`:505-517`) только по уликам покрытия:
это файлы мутантов, чьи сайты задели упавшие тесты (`tries[0].covers`) и
незагрузившиеся тест-файлы (`DryFile.covers`, `:510-515`). Если улик нет,
сломанными объявляются **все** switched-файлы прогона
(`return broken.size === 0 ? new Set(related) : broken`, `:516`). Это
задокументировано в JSDoc (`:495-498`: «When they reached none, every switched
file counts as broken») и закреплено тестом
`test/core/run/run-dry-phase.test.ts:466-493` («drops every switched file when
the breakage reached no site»), то есть это проектное решение. Пользователю
оно не описано: `docs/content/guide/cli.mdx:29-30` и
`docs/content/guide/compatibility.mdx:16-18` лишь требуют, чтобы тесты
проходили без мутантов. А текст `:289` утверждает причинную связь с каждым
файлом, которую код не проверял.

Улик нет, когда тест-файл падает раньше первого сайта: модуль бросает при
загрузке до первой проверки сайта (например, привязка с именем `globalThis`,
BUG-101 ниже), `beforeAll` падает до вызова кода, загрузка тест-файла
нестабильна (порт занят, ресурс не готов). Тогда невиновные файлы получают
ложное «Tests fail with the switched src/price.js and pass without it», и весь
прогон теряет вердикты. Настоящая причина (имя упавшего тест-файла и текст
ошибки) не выводится ни в тексте, даже с `--verbose`, ни в JSON (скептик), хотя
у ядра она есть: `DryFile.errors` и `DryFile.dependencies`.

Вне `--fast` (режим по умолчанию: `fast: false`,
`core/config/resolve-run-settings.ts:38`,
`docs/content/guide/configuration.mdx:318`) инструментированного повтора
упавших тест-файлов нет (`:201-202`), поэтому и разовый провал приписывается
инструментированию. В `--fast` повтор есть (`:204-250`): там нестабильная
загрузка поглощается, но collateral (шаг 3a) воспроизводится в обоих режимах.

Связанные находки того же анализа (их промптов в клоне нет, ниже — суть):

- BUG-101 — проверка сайта `globalThis.__mootant?.hit(id)`
  (`core/instrument/get-site-check.ts:11-13`) разрешает `globalThis`
  лексически. Модульная `const globalThis = …` с сайтами в инициализаторе даёт
  при загрузке switched-текста TDZ `ReferenceError: Cannot access 'globalThis'
  before initialization`. Это триггер фикстуры collateral.
- BUG-902 — вне `--fast` один нестабильный провал, задевший сайт, выбрасывает
  свой файл с `instrumentation-break`: инструментированного повтора нет.
  BUG-100 — его вариант с бо́льшим ущербом: провал без задетых сайтов
  выбрасывает все файлы.
- BUG-905 и BUG-106 — другие триггеры провала до первого сайта: неразбираемая
  замена из плагина и регулярное выражение, начинающееся с `<!--`, в Vite 8.
  Через ту же строку `:516` выбрасываются все файлы.

Обходы для пользователя (скептик): `mootant run src/price.js` (6 Killed,
2 Survived), `--mutant <id>`, при флаке — повторный запуск.

## Воспроизведение

Ветки `experiment/bug-repros` в публичном репозитории нет, файлы ниже создай
сам. Нужны Node.js 22.12 или новее (Vitest 5 требует
`^22.12.0 || ^24.0.0 || >=26.0.0`, `docs/content/guide/compatibility.mdx:22-24`)
и pnpm 12 (в CI стоит `latest-12`, `.github/actions/install-tools/action.yml:14`;
по наблюдению анализа, pnpm 10 не читает `configDependencies` из
`pnpm-workspace.yaml` и зависает). Шаги 2–3 рассчитаны на одну сессию shell:
они используют переменные `ROOT`, `TGZ`, `E2E` и функцию `dropped`.

### Шаг 1. Падающий юнит-тест (fake-адаптер, сборка не нужна)

Два switched-файла: `/src/a.ts` (мутант `a1`, тест `/t/a.test.ts`) и
`/src/b.ts` (мутант `b1`, тест `/t/b.test.ts`). Хук `onDry` fake-адаптера
(`test/helpers/create-fake-adapter.ts:37-40`, вызов на `:379`) заставляет
`/t/b.test.ts` «не загрузиться» с `covers: []`, то есть до первого сайта:

- кейс 1 — в каждом инструментированном dry run, где `/src/b.ts` есть в
  `related`: b ломает свой тест-файл, a ни при чём;
- кейс 2 — только в первом инструментированном dry run (нестабильная загрузка).

`repeat: false` — режим по умолчанию, без `--fast`. Тест — файл ветки
`experiment/bug-repros` без изменений. Верификатор запускал его 3 раза, оба
кейса падали каждый раз. Файл временный, в коммит не входит (см.
«Ограничения»).

```bash
# в корне клона azat-io/mootant
pnpm install
mkdir -p test/repros
cat > test/repros/BUG-100.test.ts <<'EOF'
import { describe, expect, it } from 'vitest'

import type { DryRunResult } from '../../types/adapter/dry-run-result'
import type { SwitchedFile } from '../../types/adapter/switched-file'
import type { FakeWorld } from '../helpers/create-fake-adapter'

import { createFakeAdapter } from '../helpers/create-fake-adapter'
import { runDryPhase } from '../../core/run/run-dry-phase'

/**
 * Runs the dry phase of two switched files, `/src/a.ts` with mutant `a1` and
 * `/src/b.ts` with mutant `b1`, in a world whose `/t/b.test.ts` fails to load
 * before it reaches any site while `failsWithB` says so.
 *
 * @param failsWithB - Tells, from the request of a dry run, whether the test
 *   file of `b` fails to load in it.
 * @returns Switched files left and the diagnostics of the dry phase.
 */
async function runPhase(
  failsWithB: (request: {
    instrumented: boolean
    related: string[]
  }) => boolean,
): Promise<{ diagnostics: string[]; switched: string[] }> {
  let world: FakeWorld = {
    onDry: (result: DryRunResult, request) => {
      if (!failsWithB(request)) {
        return result
      }
      return {
        ...result,
        files: result.files.map(file =>
          file.file === '/t/b.test.ts' ?
            {
              ...file,
              errors: ['ReferenceError: Cannot access before initialization'],
              loadFailed: true,
              covers: [],
            }
          : file,
        ),
        tests: result.tests.filter(test => test.file !== '/t/b.test.ts'),
      }
    },
    tests: [
      { file: '/t/a.test.ts', covers: ['a1'], id: 'ta' },
      { file: '/t/b.test.ts', covers: ['b1'], id: 'tb' },
    ],
  }
  let fake = createFakeAdapter(world)
  let switched: SwitchedFile[] = [
    { switched: 'hit("a1")', file: '/src/a.ts', original: '' },
    { switched: 'hit("b1")', file: '/src/b.ts', original: '' },
  ]
  let session = await fake.adapter.start({
    workDirectory: '/work',
    concurrency: null,
    files: switched,
    root: '/',
  })
  let phase = await runDryPhase(session, {
    displays: new Map([
      ['/src/a.ts', 'src/a.ts'],
      ['/src/b.ts', 'src/b.ts'],
    ]),
    mutantFiles: new Map([
      ['a1', '/src/a.ts'],
      ['b1', '/src/b.ts'],
    ]),
    report: () => {},
    repeat: false,
    root: '/',
    switched,
  })
  return {
    diagnostics: phase.diagnostics.map(
      diagnostic => `${diagnostic.code} ${diagnostic.file}`,
    ),
    switched: switched.map(entry => entry.file),
  }
}

describe('BUG-100: a dry-run failure that reached no mutant site drops every switched file', () => {
  it('keeps a switched file whose tests pass when another file breaks a test file before any site', async () => {
    // `/src/b.ts` breaks the loading of its test file whenever it is switched,
    // as a module whose switched text throws before its first site does (a
    // binding named `globalThis`, a compile-time macro that rejects the
    // switched argument). `/src/a.ts` and its test have nothing to do with it.
    let result = await runPhase(
      request => request.instrumented && request.related.includes('/src/b.ts'),
    )

    expect(result.diagnostics).not.toContain('instrumentation-break src/a.ts')
    expect(result.switched).toContain('/src/a.ts')
  })

  it('drops no file when a test file failed to load once, before any site, and loads when run again', async () => {
    // A transient load failure (a port in use, a resource not ready) in the
    // first instrumented dry run only: no switched file is to blame.
    let runs = 0
    let result = await runPhase(request => {
      if (!request.instrumented) {
        return false
      }
      runs += 1
      return runs === 1
    })

    expect(result.diagnostics).toStrictEqual([])
    expect(result.switched).toStrictEqual(['/src/a.ts', '/src/b.ts'])
  })
})
EOF
pnpm exec vitest run test/repros/BUG-100.test.ts
```

Кейс 1 моделирует «`/src/b.ts` подключён» через `request.related`. Для
воспроизведения этого достаточно, но правку, которая сужает только `related` и
не меняет набор отдаваемых switched-текстов, такой тест не отличит от верной
(см. «Направление исправления», п. 5). В постоянном тесте условие строй иначе.

### Шаг 3. Сквозные сценарии

Фикстуры 3a и 3b — из `test/repros/BUG-100/` ветки. Там тест-файлы хранились
как `*.check.js` и переименовывались скриптом `run.sh`, потому что
`test/repros/` не исключён из сьюта mootant (`vitest.config.ts:18` исключает
только `test/fixtures/**`). Здесь фикстуры создаются во временном каталоге
сразу как `*.test.js`.

Ставь `vitest@5` (у скептика — 5.1.0 с vite 8.3.5), а не `vitest@5.0.5`: в
npm 10.9.9 установка 5.0.5 падает в arborist с `Cannot read properties of null
(reading 'edgesOut')`. Это баг npm, не mootant. Воспроизводитель ставил 5.0.5
через `npm i --legacy-peer-deps`, так тоже работает, итог тот же. `mootant run`
без путей падает с «mootant run needs paths, such as "mootant run src".»
(`core/run-mutants.ts:181-185`), поэтому путь `src` указан явно. Команды ниже —
переложение `run.sh` из ветки. В отличие от него, вывод `npm i` здесь не
заглушён, и ошибка установки видна сразу, а не как непонятная ошибка чтения
`report.json`. В таком виде (heredoc + `npm i -D vitest@5`) команды целиком не
запускались; фикстуры и команды mootant те же, что у верификаторов.

**3a. collateral.** `src/env.js` объявляет `const globalThis = …` (BUG-101):
его switched-текст бросает `ReferenceError` при загрузке, до первого сайта.
`src/price.js` и его тесты ни при чём.

```bash
mkdir -p "$E2E/collateral/src" "$E2E/collateral/test"
cd "$E2E/collateral"
cat > package.json <<'EOF'
{ "name": "collateral", "private": true, "type": "module" }
EOF
cat > src/env.js <<'EOF'
// A module-level binding named globalThis, as in polyfill-style code.
const globalThis = typeof window !== 'undefined' ? window : { platform: 'node' }
export function platform() {
  return globalThis.platform ?? 'browser'
}
EOF
cat > src/price.js <<'EOF'
export function total(items, discount) {
  let sum = 0
  for (let item of items) sum += item.price * item.count
  return discount > 0 ? sum - sum * discount : sum
}
EOF
cat > test/env.test.js <<'EOF'
import { expect, it } from 'vitest'
import { platform } from '../src/env.js'
it('detects node', () => {
  expect(platform()).toBe('node')
})
EOF
cat > test/price.test.js <<'EOF'
import { expect, it } from 'vitest'
import { total } from '../src/price.js'
it('sums', () => {
  expect(total([{ price: 2, count: 3 }, { price: 1, count: 1 }], 0)).toBe(7)
})
it('discounts', () => {
  expect(total([{ price: 10, count: 1 }], 0.5)).toBe(5)
})
EOF
npm i -D vitest@5 "$TGZ"
npx vitest run                                             # без mootant все 3 теста проходят
npx mootant run src --no-cache --json --all > report.json; echo "exit=$?"   # exit=1
dropped                                                    # оба файла, 14 из 14 Error
npx mootant run src --no-cache --verbose; echo "exit=$?"   # текстовый отчёт, см. «Фактическое поведение»
npx mootant run src/price.js --no-cache; echo "exit=$?"    # контроль: только price.js — 6 killed, 2 survived, exit=0
```

## Ожидаемое поведение

- Файл, без которого провал не исчезает (или провал не повторяется), не
  получает `instrumentation-break`; его мутанты прогоняются.

### Направление исправления

Выводы сделаны по чтению кода, если не сказано иное. Единственный патч,
который запускали, описан в п. 3.

1. **Повтор с теми же switched-файлами.** Прежде чем обвинять, перезапусти
   упавшие и незагрузившиеся тест-файлы с инструментированием и тем же
   `input.switched` (`instrumented: true, repeat: false, files: <их
   тест-файлы>`). Если они прошли, провал нестабилен: ничего не выбрасывай,
   предупреди. Это закрывает кейс 2, 3b и 3c и совпадает с исправлением
   BUG-902. Образец — ветка `repeat` в `runCheckedDry` (`:204-250`). Если в
   твоём дереве BUG-902 уже исправлен, проверь, что кейс 2 проходит, и не
   дублируй повтор.
2. **Дешёвое сужение по `dependencies`** (предложение скептика). Если провал
   повторился, кандидаты — switched-файлы из `DryFile.dependencies` упавших
   тест-файлов; для упавшего теста бери `dependencies` его тест-файла из того
   же прогона. Vitest заполняет поле в `adapters/vitest/run-dry.ts:188-191` и
   `:198-202`, node:test — в `adapters/node-test/run-dry.ts:131-137`.
   Дополнительных прогонов и изменения контракта не нужно; в 3a, по
   отладочному выводу скептика, кандидатом окажется только `src/env.js`.
   Ограничения:
   - поле необязательно: null или его нет, когда адаптер не знает
     (`types/adapter/dry-file.d.ts:5-13`);
   - у тест-файла без записи о конце в Vitest его нет (`createFailedFile`,
     `adapters/vitest/run-dry.ts:258-273`);
   - для провала при загрузке под node:test не проверено;
   - тест-файл, импортирующий и виновный, и невиновный модуль (3e), даёт обоих
     кандидатами.

   Ошибиться в сторону «слишком узко» безопасно: после выброса dry run
   повторяется, и оставшиеся провалы останавливают прогон (`:304-319`).
   Ложных вердиктов не будет (скептик).
3. **Пробы исключением файлов** (бисекция или по одному). Воспроизводитель
   проверил на копии дерева патч: при пустых уликах — повтор с теми же
   файлами, затем исключение каждого файла по одному с временной подменой и
   восстановлением `input.switched`. Виновны файлы, без которых провал
   исчезает; если таких нет — все. Оба кейса шага 1 прошли,
   `test/core/run/run-dry-phase.test.ts` — 17 из 17. Но:
   - патч не учитывал дополнительные прогоны в `runs` и не посылал
     `dry-again`, поэтому тест `:466-493` (`phase.runs === 3`) прошёл без
     изменений. Честный учёт его изменит;
   - сквозной прогон с патчем не делали. Контракт `AdapterContext.files`
     (`types/adapter/adapter-context.d.ts:25-33`) разрешает ядру после первого
     `dryRun` только **удалять** файлы. Адаптер Vitest сбрасывает кэш
     трансформаций только у удалённых (`adapters/vitest/run-dry.ts:49-58`,
     обоснование на `:26-29`: «so their switched text is not served from
     Vite's cache»), а текст подменяется в хуке `transform`
     (`adapters/vitest/create-mootant-plugin.ts:32-52`). Поэтому файл,
     возвращённый после пробы, по чтению, может прийти из кэша Vite с
     оригинальным текстом прошлой пробы. Тогда пробы обвинят невиновного (3e),
     а его мутанты в итоговом dry run потеряют покрытие (`never-served`,
     ложный `NoCoverage`). Значит, для проб нужно расширить контракт (возврат
     файлов, сброс кэша у вернувшихся) и адаптер Vitest. Это изменение
     `types/`, опиши компромисс. В node:test план переключения пишется из
     `context.files` на каждый инструментированный dry run, а каждый тест-файл
     идёт в своём процессе (`adapters/node-test/run-dry.ts:212-227`); там
     возврат, по чтению, безопасен.
4. **Если виновного не найти** (провал повторяется, а сужение ничего не дало).
   Так устроен фейковый мир теста `:466-493`: тест падает при любом
   инструментированном прогоне. Выбери политику и опиши её в JSDoc: либо
   выбросить кандидатов, но с честным текстом (не «fail with the switched X and
   pass without it»), либо остановить прогон ошибкой, которая называет упавшие
   тест-файлы и их ошибки (как `formatFailures`, `:434-463`).
5. **Меняй `input.switched`, а не только `related`.** Какие switched-тексты
   отдаются, определяет общий массив `input.switched`. Это тот же объект, что
   `context.files` адаптера (`core/run-mutants.ts:273`, `:298`, `:416`), и
   адаптер Vitest перечитывает его в начале каждого `dryRun`
   (`adapters/vitest/run-dry.ts:49-58`). `related` только выбирает тест-файлы,
   а при заданных `files` дополнительно их фильтрует (`:231-246`). Поэтому
   сужение одного `related` не работает:
   - тест-файл, импортирующий оба модуля, упадёт при любом `related` (3e);
   - тест-файл, не импортирующий ни одного оставшегося файла, просто не
     запустится, и «провал исчез» окажется пустым прогоном.

   Юнит-тест шага 1 задаёт «b подключён» через `request.related` и такую
   правку пропустит. Верификатор считал, что её поймает сквозной прогон, но,
   по чтению, 3a может пройти случайно: `test/env.test.js` при
   `related = [src/price.js]` не запускается. Поэтому есть 3e. В постоянном
   юнит-тесте проверяй отдаваемые файлы: `request.instrumented &&
   result.served.includes('/src/b.ts')`. Фейк строит `served` из текущего
   `context.files` (`test/helpers/create-fake-adapter.ts:369-371`).

Не годится:

- Только убрать фолбэк `:516` (вернуть пустое множество). Без улик ничего не
  выбрасывается, и при устойчивом провале (3a) повтор `:304-319` остановит
  весь прогон ошибкой «Tests still fail with mootant's switched files after
  the files that broke them were dropped», которой предшествует «Running the
  dry run again without 0 files that broke tests.» (`:300-303`).
- Полагаться на `--fast`: 3a воспроизводится и там.
