# BUG-201: вердикт мутанта зависит от того, какие ещё файлы в прогоне (`--mutant`, узкие пути, `--since`)

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Адаптер Vitest выбирает тест-файлы dry run статическим анализом Vitest:
`vitest.config.related = request.related; vitest.getRelevantTestSpecifications()`
(`adapters/vitest/run-dry.ts:225-244`), где `related` — переключаемые файлы
прогона (`core/run/run-dry-phase.ts:156`). Переключаемые файлы — только файлы,
в которых есть *выбранные* мутанты (`core/run-mutants.ts:202-210`,
`:379-395`): при `--mutant <id>`, при узких путях и при `--since` их меньше,
чем при полном прогоне тех же путей. Анализ Vitest
(`AffectedModulesResolver`, `node_modules/vitest/dist/chunks/cli-api.De07GUeT.js:9930-10073`)
неточен: тест, который достаёт модуль через вычисляемый `import()` или через
фабрику `vi.mock`, грузящую оригинал не напрямую (`importOriginal` /
`vi.importActual` внутри самой фабрики), он не считает зависящим от модуля.
Такой тест всё же попадает в dry run, если статически зависит от *другого*
переключаемого файла. Итог: один и тот же мутант в полном прогоне `Killed`, а
при перепроверке `mootant run src --mutant <id>` — команде, которую отчёт сам
предлагает (`recheck`) и на которую опирается рабочий цикл агента, — и в CI с
`--since` получает `NoCoverage`/`Survived`. Комментарий в коде утверждает
обратное: «The dry run hosts every pending mutant of the files of the run,
selected or not, so the plan of a mutant does not depend on the selection»
(`core/run-mutants.ts:340-342`). Адаптер node:test этим не страдает: первый
dry run запускает все тест-файлы и отбирает их по фактически загруженным
модулям (`adapters/node-test/run-dry.ts:75-80`, `:127-129`).

## Воспроизведение

Падающий тест — `test/repros/BUG-201.test.ts` в ветке `experiment/bug-repros`
(фикстура `test/repros/BUG-201/`).

```bash
pnpm vitest run test/repros/BUG-201.test.ts
```

Фикстура:

```js
// test/repros/BUG-201/src/api.js
export async function fetchUser(id) {
  return { id, name: `user${id}` }
}

// test/repros/BUG-201/src/service.js
import { fetchUser } from './api.js'
export async function greet(id) {
  let user = await fetchUser(id)
  return `Hello, ${user.name}!`
}

// test/repros/BUG-201/test/actual.js
import { vi } from 'vitest'
export function loadActual(specifier) {
  return vi.importActual(specifier)
}

// test/repros/BUG-201/test/greet.check.js
import { expect, test, vi } from 'vitest'
import { loadActual } from './actual.js'
import { greet } from '../src/service.js'

vi.mock('../src/api.js', async () => ({
  ...(await loadActual('../src/api.js')),
}))

test('greets the real user', async () => {
  expect(await greet(2)).toBe('Hello, user2!')
})

// test/repros/BUG-201/vitest.config.js
export default { test: { include: ['test/**/*.check.js'] } }
```

Тест делает три прогона `runMutants` (адаптер Vitest): `paths: ['src']`,
`paths: ['src']` + `mutantIds: [<мутант \`user${id}\` → ''>]` и
`paths: ['src/api.js']`, плюс эталон `runReferenceMutants` (`separate: true`).
То же на фикстуре `/home/user/projects/oracle/vt/mocks` (CLI,
`results/mocks/iso-mocks-*.json`).

## Ожидаемое поведение

Мутант `` `user${id}` `` → `''` получает один и тот же вердикт во всех трёх
прогонах — `Killed`, как в полном прогоне и в эталоне (обычный Vitest с
физически применённой мутацией падает).

## Фактическое поведение

```
full run (paths: src)            -> Killed
--mutant <id> (paths: src)       -> NoCoverage
paths: src/api.js                -> NoCoverage
reference (plain Vitest)         -> killed
```

На CLI-фикстуре `vt/mocks`: `--mutant A` → `NoCoverage`,
`--mutant A --mutant B` (B — мутант `src/service.js`) → `Killed`.

## Подозреваемые места в коде

- `core/run-mutants.ts:379-395` — переключаемые файлы (и, значит, `related`
  dry run) строятся из файлов выбранных мутантов, а не из всех файлов путей
  прогона, хотя мутанты выбранных файлов уже хостятся все.
- `core/run/run-dry-phase.ts:156` — `related` = переключаемые файлы.
- `adapters/vitest/run-dry.ts:225-244` — выбор тест-файлов только
  статическим анализом Vitest, без проверки по факту загрузки.

## Критерий готовности

- `test/repros/BUG-201.test.ts` проходит; добавлен регрессионный тест в
  `test/adapters/vitest/index.test.ts` (или в `test/core/run-mutants.test.ts`
  с фейковым адаптером), который проверяет, что `--mutant <id>` даёт тот же
  вердикт, что полный прогон тех же путей.
- Минимальное исправление — `related` первого dry run строится из всех
  перечисленных файлов путей прогона (`listing.files`), а не только из файлов
  выбранных мутантов; лучше — как в адаптере node:test, отбирать тест-файлы по
  фактически загруженным модулям (хотя бы при `--mutant`/`--since`), либо
  явно предупреждать (`diagnostic`), когда тест-файл не выбран статическим
  анализом, но мог бы быть (динамический `import()`, фабрика `vi.mock`).
- Документация (`docs/content/guide/compatibility.mdx`, раздел Vitest)
  описывает оставшееся ограничение.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига) без явной необходимости; если без этого нельзя — опиши компромисс.
- Не делай dry run полного прогона заметно медленнее без замера: на большом
  проекте статический отбор экономит минуты (см. `analysis/00-baseline.md`).
- Сообщения коммитов — Conventional Commits (commitlint).
