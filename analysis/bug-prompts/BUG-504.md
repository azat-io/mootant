# BUG-504: node:test — SIGHUP/SIGQUIT оставляют тестовый процесс зависшего мутанта навсегда

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён. Найдено на
> коммите 170ec52.

## Контекст

Адаптер node:test запускает каждый тест-файл в отдельном процессе
`detached: true` (`adapters/node-test/run-test-process.ts:117-123`): на POSIX
это новая сессия и группа, поэтому сигналы терминала до процесса не доходят,
и mootant обязан останавливать его сам. `trackProcessGroup`
(`adapters/node-test/track-process-group.ts:7,18-22,40-46`) делает это при
выходе процесса mootant и только на SIGINT и SIGTERM. Закрытие терминала или
обрыв SSH (SIGHUP) и Ctrl+\ (SIGQUIT) завершают mootant действием по
умолчанию, событие `exit` не наступает, и тестовый процесс, выполняющий
зависший мутант, остаётся навсегда (ppid 1, 100% CPU). Тот же исход при
`SIGKILL`/OOM-killer — его не обработать, но SIGHUP и SIGQUIT можно.

## Воспроизведение

Фикстура в ветке `experiment/bug-repros`: `test/repros/BUG-504/` со скриптом
`run.sh <SIGNAL>` (собирает `dist`, если его нет).

```js
// src/step.js
export function getStep(size) {
  return size - 9
}

// test/step.check.js
import { it } from 'node:test'
import assert from 'node:assert/strict'

import { getStep } from '../src/step.js'

it('counts to ten', () => {
  let step = getStep(10)
  let n = 0
  // the mutant 9 -> 10 makes the step 0: an endless synchronous loop
  for (let i = 0; i < 10; i += step) {
    n++
  }
  assert.equal(n, 10)
})

// mootant.config.js — зависание длится ~30 с, есть окно для сигнала
export default { run: { runner: 'node-test', timeout: { constant: 30000 } } }
```

`package.json`: `"scripts": { "test": "node --test test/step.check.js" }`,
`"type": "module"`.

```bash
test/repros/BUG-504/run.sh HUP    # выход 1 = воспроизведено
test/repros/BUG-504/run.sh QUIT   # выход 1 = воспроизведено
test/repros/BUG-504/run.sh TERM   # контроль: обрабатывается, выход 0
```

## Ожидаемое поведение

На SIGHUP (и SIGQUIT) mootant останавливает группы своих тестовых процессов
так же, как на SIGINT/SIGTERM, и завершается с кодом сигнала (129/131).

## Подозреваемые места в коде

- `adapters/node-test/track-process-group.ts:7` — список сигналов
  `['SIGINT', 'SIGTERM']`; `onSignal` (`:40-46`) уже переподнимает сигнал, если
  других слушателей нет, поэтому добавление `SIGHUP` (и `SIGQUIT`, с оглядкой
  на core dump) сохраняет код выхода.
- `adapters/node-test/run-test-process.ts:117-123` — `detached: true`.
- На Windows сигналов SIGHUP/SIGQUIT нет; не ломай `process.on` там
  (`SIGHUP` на Windows эмулируется при закрытии консоли).

## Критерий готовности

- Тест в `test/adapters/node-test/track-process-group.test.ts`: на SIGHUP
  отслеживаемые группы останавливаются и сигнал переподнимается; падает до
  исправления, проходит после. `test/repros/BUG-504/run.sh HUP` и `QUIT`
  завершаются с кодом 0.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
