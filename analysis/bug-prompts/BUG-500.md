# BUG-500: `mootant.config.ts` из документации не грузится в CommonJS-пакете на Node ≥ 22.18

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён. Найдено на
> коммите 170ec52.

## Контекст

Гайд по конфигурации предлагает создать `mootant.config.ts` с
`import { defineConfig } from 'mootant'` и `export default …`
(`docs/content/guide/configuration.mdx:77-91`) и говорит, что TS-конфигу нужен
Node 22.18+ или jiti (`:121-122`, `docs/content/guide/compatibility.mdx:26-28`).
`loadTypescriptConfig` при `process.features.typescript` всегда делает
нативный `import()` (`core/config/load-typescript-config.ts:16-17` →
`core/config/import-config.ts:12`), а Node читает `.ts` по полю `type`
ближайшего `package.json`: в пакете `"type": "commonjs"` ESM-синтаксис —
синтаксическая ошибка. jiti, даже установленный, не пробуется. npm 11 (идёт с
Node 24) пишет `"type": "commonjs"` в `npm init -y`, так что новый проект по
гайду падает на первом шаге. На Node 22.12 с jiti тот же проект работает —
обновление Node ломает конфиг. В пакете без поля `type` конфиг грузится, но
каждый запуск печатает предупреждение Node `MODULE_TYPELESS_PACKAGE_JSON`.

## Воспроизведение

Фикстура в ветке `experiment/bug-repros`: `test/repros/BUG-500/` со скриптом
`run.sh` (собирает `dist`, если его нет; ставит `node_modules/mootant` ссылкой
на репозиторий).

```ts
// test/repros/BUG-500/mootant.config.ts — пример из configuration.mdx
import { defineConfig } from 'mootant'

export default defineConfig({
  mutators: {
    'string-literal': 'off',
  },
  run: {
    paths: ['src'],
    threshold: 80,
  },
})
```

```json
// test/repros/BUG-500/package.json
{ "name": "bug-500-fixture", "private": true, "type": "commonjs" }
```

`src/add.js`: `export function add(a, b) { return a + b }`.

```bash
test/repros/BUG-500/run.sh      # Node 22.18+; выход 1 = воспроизведено
# вручную:
cd test/repros/BUG-500 && mkdir -p node_modules && ln -sfn ../../../.. node_modules/mootant
node ../../../bin/mootant.js list src
```

## Ожидаемое поведение

`mootant list src` выводит мутанты `src/add.js` на Node 22.12 (jiti), 22.18+,
24 и 26 одинаково; либо, если загрузить нельзя, понятная ошибка с советом
(«переименуйте в `mootant.config.mts` или добавьте `"type": "module"`»).

## Фактическое поведение

```
node v22.23.4, process.features.typescript=strip
(node:31897) Warning: Failed to load the ES module: …/mootant.config.ts. Make sure to set "type": "module" in the nearest package.json file or use the .mjs extension.
Error: Cannot load mootant.config.ts: Cannot use import statement outside a module
```

То же на Node 24.22.2 и 26.13.0; на 22.12.0 с jiti — список мутантов. Конфиг
с `enum` на 22.23 даёт «TypeScript enum is not supported in strip-only mode».

## Подозреваемые места в коде

- `core/config/load-typescript-config.ts:15-31` — выбор между нативным
  импортом и jiti: нет запасного пути на ошибки формата модуля
  (`SyntaxError` «Cannot use import statement outside a module»,
  `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`) и нет учёта `type` пакета.
- `core/config/load-config.ts:51-60,110-123` — текст ошибки; сюда можно
  добавить совет про `.mts`.
- `docs/content/guide/configuration.mdx:77-122` — упомянуть `.mts` для
  CommonJS-пакетов.

## Критерий готовности

- Тест в `test/core/config/load-typescript-config.test.ts` (или
  `load-config.test.ts`), который грузит `.ts`-конфиг с ESM-синтаксисом из
  временного каталога с `package.json` `"type": "commonjs"` **вне** модульного
  раннера Vitest (например, дочерним процессом `node` на собранном `dist` или
  на исходниках через `--experimental-strip-types`, иначе Vite сам
  транспилирует файл): падает до исправления, проходит после.
  `test/repros/BUG-500/run.sh` завершается с кодом 0.
- Поведение на Node без type stripping (jiti) не меняется.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига) без явной необходимости; если без этого нельзя — опиши компромисс.
- Сообщения коммитов — Conventional Commits (commitlint).
