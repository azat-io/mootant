# BUG-305: `--since` выкидывает мутанта изменённой строки, «владелец» которого стоит на неизменённой строке

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: high. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Правила пропуска решают на этапе генерации, что мутант не нужен, потому что его
поведение покрывает другой мутант («владелец»): `O19` (удаление then-ветки ≡
`if (false)`), `R4`, `R5`, `R6`, `solitary` и др. (`core/generate/generate-file-mutants.ts:231-306`).
С `--since` выбор мутантов по изменённым строкам происходит **после** генерации
(`core/list-mutants.ts:70-90`, `core/files/select-changed-mutants.ts:17-80`):
мутант владельца на неизменённой строке отбрасывается, а пропущенный мутант
изменённой строки не возвращается. Изменённая строка остаётся вообще без
мутантов, хотя кандидат был. Это ровно сценарий PR/CI, ради которого есть
`--since`: правка вызова внутри существующего `if` не тестируется мутациями.

Масштаб (по `mootant list --skipped` на 170ec52): у 726 пропусков в `core/`
Mootant и у 420 в eslint-plugin-perfectionist владелец стоит на строке вне
диапазона пропущенного мутанта (`O19` 413/313, `R4` 191/32, `solitary` 96/46,
`R5` 13/29, `R6` 13/0). Каждый из них теряется, если в PR меняется только его
строка. Строк, на которых изменение одной этой строки даёт `--since` **ноль
мутантов**, хотя на строке есть такие кандидаты: 357 в core и 268 в
perfectionist (`analysis/tools/skips/since_exposure.py`).

## Воспроизведение

Падающий тест — `test/repros/BUG-305.test.ts` в ветке `experiment/bug-repros`:

```ts
import { afterEach, describe, expect, it } from 'vitest'

import type { GitRepository } from '../helpers/create-git-repository'

import { createGitRepository } from '../helpers/create-git-repository'
import { listMutants } from '../../core/list-mutants'

let repository: GitRepository | null = null

function createSource(call: string): string {
  return [
    'export function open(user, door) {',
    '  if (user.isAdmin) {',
    `    ${call}`,
    '  }',
    '}',
    '',
  ].join('\n')
}

describe('BUG-305: --since drops a mutant whose owner lies on an unchanged line', () => {
  afterEach(async () => {
    await repository?.remove()
    repository = null
  })

  it('keeps a mutant of the changed line when the mutant it is left to is not selected', async () => {
    repository = await createGitRepository()
    let { write, root, git } = repository
    await write('src/access.js', createSource('door.unlock(user)'))
    git('add', '.')
    git('commit', '--quiet', '-m', 'base')
    await write('src/access.js', createSource('door.open(user)'))

    let result = await listMutants({
      paths: ['src'],
      since: 'HEAD',
      skipped: true,
      cwd: root,
    })
    let mutants = result.files.flatMap(file =>
      file.mutants.map(
        mutant => `${mutant.mutator}: ${mutant.replacement}`,
      ),
    )

    expect(mutants).toContain('statement-removal: ;')
  })
})
```

Сквозная проверка (фикстура в `analysis/data/skips/fx-since`):

```bash
git init && git add -A && git commit -m base   # src/access.js с door.unlock(user), тест без админа
sed -i 's/door.unlock(user)/door.open(user)/' src/access.js
npx mootant list src --since HEAD --skipped
#   mutants 0 in 1 file; skipped 1: 1 owned
#   3:5 statement-removal door.open(user) -> ; owned O19
npx mootant run src --since HEAD --no-cache
#   score none (no mutants to score)
npx mootant run src --no-cache   # без --since: 2 выживших (user.isAdmin -> true/false)
```

## Ожидаемое поведение

Пропуск по правилу с владельцем действует, только если владелец сам будет
запущен в этом прогоне. С `--since` (и вообще при любом отборе после генерации)
мутант, чей владелец отброшен отбором, возвращается в список (или отбор делается
до правил, а владельцы вне изменённых строк не считаются запущенными — так уже
устроен `context.runs` для ignore-комментариев). В примере `door.open(user) -> ;`
— мутант изменённой строки.

## Фактическое поведение

`mutants 0`, `score none (no mutants to score)`; изменённая строка без мутантов.

## Подозреваемые места в коде

- `core/files/select-changed-mutants.ts:17-80` — фильтрует готовые
  `mutants`/`skipped`, не зная о владельцах.
- `core/list-mutants.ts:70-90` и `core/run-mutants.ts:192` — порядок: генерация,
  затем отбор.
- `core/mutators/shared/create-run-context.ts` / `create-static-run-context.ts`
  — `runs()` учитывает ignore-правила, но не отбор `--since`; `O19`
  (`core/mutators/shared/get-owner-constant.ts:35-41`) вообще статический.
- `core/generate/apply-solitary-rule.ts:124-136` — `countsFor` знает только об
  ignore.

## Критерий готовности

- Тест `test/repros/BUG-305.test.ts` (перенести в `test/core/list-mutants.test.ts`
  или `test/core/files/select-changed-mutants.test.ts`) падает до исправления и
  проходит после.
- Тест на `solitary`: изменена только строка `return count`, инициализатор
  `let count = 0` не изменён — `count -> 0` выводится с `--since`.
- Без `--since` списки мутантов и их id не меняются (существующие тесты
  `test/core/generate/*` зелёные).
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- В `docs/content/guide/cli.mdx` (раздел `--since`) и в `docs/content/mutators.md`
  (Skipped changes) сказано, что пропуск с владельцем вне изменённых строк
  возвращается.
