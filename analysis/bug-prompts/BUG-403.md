# BUG-403: кэш не видит файлы, которые тесты читают вне корня проекта

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён. Найдено на коммите
> 170ec52.
>
> Перепроверено независимо: воспроизведено (тест шага 1 падает 3 из 3 в чистом
> клоне; упакованный mootant на раскладке монорепозитория отдаёт из кэша все 3
> устаревших вердикта без диагностик и под Vitest 5.1.0, и под `node --test`;
> контроли — фикстура внутри root и JSON вне root через `import` —
> инвалидируются верно); скептик: не опроверг, medium — вердикты молча неверны
> в обе стороны при неизменном score и вопреки документации, но триггер узкий
> (root уже дерева, из которого тесты читают через `node:fs`), а обходы простые.

## Контекст

Кэш вердиктов переиспользует вердикт, «while the mutated file and the files and
environment variables its tests read stay the same»
(`docs/content/guide/configuration.mdx:352-355`). Публичный контракт адаптера
говорит то же: в зависимости тест-файла входят «files the test code read»
(`types/adapter/dry-file.d.ts:6-9`, цитата на `:8`).

Чтения через `node:fs` записывает `trackInputs`
(`adapters/shared/track-inputs.ts:21-61`). Его вызывают в двух местах:

- воркер Vitest: `adapters/vitest/runner.ts:1015-1021`, вызов на `:1017`.
  `root` приходит через `provide` из `context.root`
  (`adapters/vitest/run-specifications.ts:35-39`, `root` на `:38`). Прочитанные
  файлы попадают в зависимости через `listDependencies`
  (`adapters/vitest/runner.ts:1176-1187`, `this.inputs!.files` на `:1183`);
- preload node:test: `adapters/node-test/preload/preload.ts:72`. `root` приходит
  в `MOOTANT_UNIT` (`adapters/node-test/run-test-file.ts:39`). Результат уходит
  в запись `end` при выходе процесса (`preload.ts:83-88`), а оттуда — в
  `end.files` в `adapters/node-test/collect-node-dependencies.ts:56-61`.

`trackInputs` записывает только чтения внутри root: условие
`file === root || file.startsWith(root + path.sep)` (`track-inputs.ts:31-37`,
условие на `:32`). Root — каталог конфига mootant или cwd
(`core/config/prepare-run.ts:133`). Конфиг ищется от cwd вверх до домашнего
каталога (`core/config/load-config.ts:62-65`). Модули вне root при этом
учитываются. Vitest отбрасывает только неабсолютные пути и `node_modules`
(`adapters/vitest/get-module-file.ts:17-19`, вызов в
`adapters/vitest/collect-dependencies.ts:93-100`). node:test отбрасывает только
`node_modules` и каталог preload (`collect-node-dependencies.ts:42-55`). Кэш
хранит пути относительно root через `path.relative`
(`core/cache/get-portable-path.ts:13-15`), поэтому пути вида `../…` для модулей
уже работают.

Внутри кода граница задумана. Её описывают JSDoc `track-inputs.ts:14` («only
files in it, outside `node_modules`, count»),
`adapters/vitest/types/vitest-worker.d.ts:217` и
`adapters/node-test/types/node-test-unit.d.ts:42`. Тест
`test/adapters/shared/track-inputs.test.ts:36,46-55` проверяет, что
`/other/c.json` не записывается. Пользователю же о границе не сказано нигде.
Раздел «Project root» (`configuration.mdx:124-130`) про отслеживание молчит.
Оговорка `:357-359` касается только дочерних процессов, workers и сети. Контракт
`dry-file.d.ts` границы тоже не упоминает.

Типичный случай — монорепозиторий, где mootant запускают в пакете без конфига
в корне репозитория, а тесты читают общие фикстуры (`../../fixtures/*.json`)
или файлы по абсолютному пути. После правки такой фикстуры кэш возвращает
старые вердикты в обе стороны: ложный `Survived` и ложный `Killed`. Score при
этом не меняется (33.33 во всех прогонах примеров ниже). Неверно другое: какие
именно мутанты выжили. CLI пишет только «Reused cached verdicts for 3 of 3
mutants.», у каждого мутанта в JSON стоит `cached: true`. Предупреждения об
устаревшем вердикте или пропущенной зависимости нет. Затронуты оба адаптера.
Обходы, по данным верификаторов: удалить `node_modules/.cache/mootant` в root
или положить конфиг mootant в корень репозитория (тогда root — корень
репозитория). `--no-cache` помогает только на один прогон: сохранённые вердикты
он не обновляет (`configuration.mdx:357-359`).

Зачем нужен фильтр, известно конкретно. Preload node:test под трекингом читает
файлы рабочего каталога mootant. Файл `<workDirectory>/switched/<n>.json`
читается при загрузке переключаемого модуля
(`adapters/node-test/preload/create-source-switcher.ts:50-53`). Пишет эти файлы
главный процесс (`adapters/node-test/write-switch-plan.ts:23-27`, каталог
`switched` задан в `adapters/node-test/run-dry.ts:221-224`). Индекс `plan.json`
читается раньше, до начала записи: переключатель создаётся на `preload.ts:65`,
трекинг стартует на `:72`. Рабочий каталог — новый `mkdtemp` в `os.tmpdir()` на
каждый прогон (`core/run/create-work-directory.ts:26-27`). Верификатор временно
логировал чтения вне root. У воркера Vitest это была только общая фикстура, у
preload node:test — фикстура и `/tmp/mootant-XXXX/switched/0.json`. Если просто
снять фильтр, этот файл попадёт в зависимости каждого тест-файла node:test.
Тогда кэш node:test перестанет попадать (вывод по чтению кода). Путь входит в
ключ и меняется на каждом прогоне (`core/cache/get-test-file-keys.ts:45-51`).
Кроме того, файл изменён после старта прогона, и `prepareRunCache` вообще не
даёт такому тест-файлу ключ (`core/cache/prepare-run-cache.ts:137-144,171-175`).

## Воспроизведение

Ветки `experiment/bug-repros` в публичном репозитории нет, файлы ниже создайте
сами. Нужны Node.js 22.12 или новее (этого требует Vitest 5,
`docs/content/guide/compatibility.mdx:22-24`) и pnpm 12. В CI стоит `latest-12`
(`.github/actions/install-tools/action.yml:14`). pnpm 10 не читает
`configDependencies` из `pnpm-workspace.yaml`, и даже `pnpm --version` внутри
репозитория у него зависает.

### Шаг 1. Падающий тест на исходниках (сборка не нужна)

Тест создаёт во временном каталоге проект на Vitest, а в отдельном временном
каталоге — общую фикстуру `limits.json`. Он гоняет мутантов с кэшем, меняет
фикстуру `30` → `18` и сравнивает прогон с кэшем с прогоном без кэша. Файл
временный и в коммит не входит (см. «Ограничения»).

```bash
# в корне клона azat-io/mootant (коммит 170ec52)
pnpm install --frozen-lockfile
mkdir -p test/repros
cat > test/repros/BUG-403.test.ts <<'EOF'
import { writeFile, realpath, mkdtemp, symlink, mkdir, rm } from 'node:fs/promises'
import { afterEach, expect, it } from 'vitest'
import { setTimeout } from 'node:timers/promises'
import { tmpdir } from 'node:os'
import path from 'node:path'

import type { RunResult } from '../../types/run/run-result'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

let roots: string[] = []

async function write(root: string, files: Record<string, string>): Promise<void> {
  for (let [file, text] of Object.entries(files)) {
    await mkdir(path.dirname(path.join(root, file)), { recursive: true })
    await writeFile(path.join(root, file), text)
  }
  // Files modified in the millisecond a run starts count as changed during it.
  await setTimeout(5)
}

async function createDirectory(): Promise<string> {
  let root = await realpath(await mkdtemp(path.join(tmpdir(), 'mootant-bug-')))
  roots.push(root)
  return root
}

function run(root: string, cache = true): Promise<RunResult> {
  return runMutants({
    builtIns: createBuiltIns('vitest', vitestAdapter()),
    paths: ['src'],
    concurrency: 1,
    cwd: root,
    cache,
  })
}

function verdicts(result: RunResult): Record<string, string> {
  return Object.fromEntries(
    result.results.map(entry => [entry.mutant.replacement, entry.status]),
  )
}

afterEach(async () => {
  await Promise.all(roots.splice(0).map(root => rm(root, { recursive: true, force: true })))
})

it('runs the mutants again when a fixture outside the root changes', async () => {
  let shared = await createDirectory()
  let fixture = path.join(shared, 'limits.json')
  await write(shared, { 'limits.json': '{ "age": 30 }' })
  let root = await createDirectory()
  await mkdir(path.join(root, 'node_modules'))
  await symlink(
    await realpath(path.resolve(import.meta.dirname, '../../node_modules/vitest')),
    path.join(root, 'node_modules/vitest'),
  )
  await write(root, {
    'vitest.config.ts': "export default { test: { include: ['test/**/*.test.ts'] } }\n",
    'test/math.test.ts': [
      "import { readFileSync } from 'node:fs'",
      "import { expect, it } from 'vitest'",
      "import { isAdult } from '../src/math'",
      `let limits = JSON.parse(readFileSync(${JSON.stringify(fixture)}, 'utf8'))`,
      "it('isAdult', () => {",
      '  expect(isAdult(limits.age)).toBe(true)',
      '  expect(isAdult(5)).toBe(false)',
      '})',
    ].join('\n'),
    'src/math.ts': 'export function isAdult(age: number): boolean {\n  return age >= 18\n}\n',
    'package.json': '{ "type": "module" }',
  })
  await run(root)
  await write(shared, { 'limits.json': '{ "age": 18 }' })

  let cached = await run(root)
  let fresh = await run(root, false)

  expect(verdicts(cached)).toStrictEqual(verdicts(fresh))
}, 120_000)
EOF

pnpm vitest run test/repros/BUG-403.test.ts --coverage.enabled=false
```

В ветке анализа есть вариант этого теста на общем помощнике
`BUG-400-cache-project.ts` с ключами вида `src/math.ts: age > 18`. Падает он
так же. Код выше самодостаточен, помощник не нужен.

### Шаг 2. Тот же сценарий в раскладке монорепозитория (образец регрессионного теста)

Тест шага 1 кладёт root и общую фикстуру в два независимых каталога `mkdtemp`
внутри `os.tmpdir()`, у которых нет общего родителя с lockfile или `.git`.
Поэтому ни один вариант исправления из раздела «Подозреваемые места» этот тест
не чинит. Оба верификатора проверили прототип, исключающий `os.tmpdir()`.
Фикстура в tmpdir так и осталась вне ключа: тест шага 1 по-прежнему падает, а
его копия с фикстурой вне tmpdir проходит. Над `/tmp` нет ни lockfile, ни
`.git` (проверил скептик), так что граница «корень git или каталог lockfile»
осталась бы равной root.

Для регрессионного теста нужна раскладка монорепозитория:
`<tmp>/<workspace>/{pnpm-lock.yaml, fixtures/limits.json, packages/app/…}`,
root — `packages/app`. Допишите в файл шага 1 второй тест. Он заодно проверяет,
что неизменённый проект целиком берётся из кэша. Эта проверка ловит лишние
записи вроде рабочего каталога mootant.

Этот тест не запускался. По чтению кода на 170ec52 он падает на последнем
`expect`, как тест шага 1: фильтр `trackInputs` — чистая проверка префикса
пути, и чтение вне root отбрасывается при любой раскладке.

```bash
cat >> test/repros/BUG-403.test.ts <<'EOF'

it('runs the mutants again when a shared fixture of the workspace changes', async () => {
  // A monorepo: the lockfile and the shared fixtures at the top, the project of
  // mootant in packages/app.
  let workspace = await createDirectory()
  let fixture = path.join(workspace, 'fixtures/limits.json')
  await write(workspace, {
    'pnpm-lock.yaml': "lockfileVersion: '9.0'\n",
    'fixtures/limits.json': '{ "age": 30 }',
  })
  let root = path.join(workspace, 'packages/app')
  await mkdir(path.join(root, 'node_modules'), { recursive: true })
  await symlink(
    await realpath(path.resolve(import.meta.dirname, '../../node_modules/vitest')),
    path.join(root, 'node_modules/vitest'),
  )
  await write(root, {
    'vitest.config.ts': "export default { test: { include: ['test/**/*.test.ts'] } }\n",
    'test/math.test.ts': [
      "import { readFileSync } from 'node:fs'",
      "import { expect, it } from 'vitest'",
      "import { isAdult } from '../src/math'",
      `let limits = JSON.parse(readFileSync(${JSON.stringify(fixture)}, 'utf8'))`,
      "it('isAdult', () => {",
      '  expect(isAdult(limits.age)).toBe(true)',
      '  expect(isAdult(5)).toBe(false)',
      '})',
    ].join('\n'),
    'src/math.ts': 'export function isAdult(age: number): boolean {\n  return age >= 18\n}\n',
    'package.json': '{ "type": "module" }',
  })
  await run(root)
  let unchanged = await run(root)

  // Nothing changed: every verdict comes from the cache.
  expect(unchanged.results.every(entry => entry.cached)).toBe(true)

  await write(workspace, { 'fixtures/limits.json': '{ "age": 18 }' })
  let cached = await run(root)
  let fresh = await run(root, false)

  expect(verdicts(cached)).toStrictEqual(verdicts(fresh))
}, 180_000)
EOF

pnpm vitest run test/repros/BUG-403.test.ts --coverage.enabled=false
```

### Шаг 3. CLI на упакованном mootant: Vitest и node:test

`bin/mootant.js` импортирует `../dist/cli/index.js`, поэтому для CLI нужна
сборка. В пакет на Vitest ставьте `vitest@5` (сейчас это 5.1.0), а не
`vitest@5.0.5`: в npm 10.9.9 установка 5.0.5 падает с `Cannot read properties
of null (reading 'edgesOut')`. Это баг arborist, не mootant.

Раскладка повторяет сквозную проверку верификаторов: общая фикстура лежит на
два уровня выше пакетов, конфига mootant нет, root — каталог пакета, mootant
стоит в каждом пакете. Каталог `MONO` создаётся вне клона и вне `os.tmpdir()`:
если исправление исключает tmpdir, фикстура в `/tmp` не покажет, работает ли
оно. Адаптер node:test выбирается сам по скрипту `node --test`. Команды
рассчитаны на одну сессию shell (переменные `TGZ` и `MONO`). Скрипт собран по
сценарию верификаторов и в таком виде целиком не запускался. Значения в
«Фактическом поведении» взяты из их отчётов на такой же раскладке.

```bash
# в корне клона, после шага 1
pnpm build
pnpm pack                        # пишет mootant-0.1.0.tgz в корень клона
PACK="$(mktemp -d)"
mv mootant-0.1.0.tgz "$PACK/"    # *.tgz нет в .gitignore, не оставляйте его в дереве
TGZ="$PACK/mootant-0.1.0.tgz"

MONO="$(mktemp -d "$HOME/bug-403-XXXXXX")"
mkdir -p "$MONO/fixtures" "$MONO/packages/vt/src" "$MONO/packages/vt/test" \
  "$MONO/packages/nt/src" "$MONO/packages/nt/test"
echo '{ "name": "mono", "private": true, "type": "module" }' > "$MONO/package.json"
echo '{ "age": 30 }' > "$MONO/fixtures/limits.json"
for pkg in vt nt; do
  cat > "$MONO/packages/$pkg/src/math.js" <<'EOF'
export function isAdult(age) {
  return age >= 18
}
EOF
done

# Пакет на Vitest
cat > "$MONO/packages/vt/package.json" <<'EOF'
{ "name": "vt", "private": true, "type": "module", "scripts": { "test": "vitest run" } }
EOF
cat > "$MONO/packages/vt/vitest.config.js" <<'EOF'
export default { test: { include: ['test/**/*.test.js'] } }
EOF
cat > "$MONO/packages/vt/test/math.test.js" <<'EOF'
import { readFileSync } from 'node:fs'
import path from 'node:path'
import { expect, it } from 'vitest'
import { isAdult } from '../src/math.js'

let limits = JSON.parse(
  readFileSync(path.join(import.meta.dirname, '../../../fixtures/limits.json'), 'utf8'),
)

it('isAdult', () => {
  expect(isAdult(limits.age)).toBe(true)
  expect(isAdult(5)).toBe(false)
})
EOF
(cd "$MONO/packages/vt" && npm i -D vitest@5 "$TGZ")

# Пакет на node:test
cat > "$MONO/packages/nt/package.json" <<'EOF'
{ "name": "nt", "private": true, "type": "module", "scripts": { "test": "node --test" } }
EOF
cat > "$MONO/packages/nt/test/math.test.js" <<'EOF'
import { readFileSync } from 'node:fs'
import assert from 'node:assert/strict'
import { test } from 'node:test'
import { isAdult } from '../src/math.js'

let limits = JSON.parse(
  readFileSync(new URL('../../../fixtures/limits.json', import.meta.url), 'utf8'),
)

test('isAdult', () => {
  assert.equal(isAdult(limits.age), true)
  assert.equal(isAdult(5), false)
})
EOF
(cd "$MONO/packages/nt" && npm i -D "$TGZ")

# Прогоны: r1 — кэш пуст, r2 — с кэшем после правки фикстуры,
# r3 — эталон без кэша, r4 — повтор без изменений.
run() {  # run <пакет> <метка> [флаги mootant]
  local pkg=$1 tag=$2
  shift 2
  (cd "$MONO/packages/$pkg" &&
    npx mootant run src --json --all --verbose --concurrency 1 "$@" \
      > "$MONO/$pkg-$tag.json" 2> "$MONO/$pkg-$tag.err")
}
for pkg in vt nt; do
  rm -rf "$MONO/packages/$pkg/node_modules/.cache/mootant"
  echo '{ "age": 30 }' > "$MONO/fixtures/limits.json"; sleep 1
  run "$pkg" r1
  echo '{ "age": 18 }' > "$MONO/fixtures/limits.json"; sleep 1
  run "$pkg" r2
  run "$pkg" r3 --no-cache
  run "$pkg" r4
done
node -e '
  const fs = require("node:fs")
  const path = require("node:path")
  for (const file of process.argv.slice(1)) {
    const text = fs.readFileSync(file, "utf8")
    const report = JSON.parse(text.slice(text.indexOf("{")))
    const verdicts = report.mutants.map(m => m.replacement + ": " + m.status).join(", ")
    console.log(path.basename(file), report.runner,
      "totalCached=" + report.summary.totalCached,
      "score=" + report.summary.score, "|", verdicts)
  }' "$MONO"/{vt,nt}-r{1,2,3,4}.json
grep -H "Reused" "$MONO"/*.err
```

`summary.totalCached` есть только в полном отчёте `--json --verbose`
(`cli/report/build-run-report.ts:161-164`). Обычный `--json` его не печатает
(`cli/report/slim-run-report.ts:27-51`). Строку «Reused cached verdicts for N of
M mutants.» пишет `core/run-mutants.ts:703-710`.

## Ожидаемое поведение

- Шаги 1 и 2: вердикты прогона с кэшем совпадают с прогоном без кэша. После
  смены `30` на `18`: `age > 18` — `Killed`, `age == 18` — `Survived`,
  `age >= 17` — `Survived`.
- Файл, который код теста прочитал через `node:fs`, входит в зависимости
  тест-файла, где бы он ни лежал. Исключения: рабочий каталог mootant и места,
  исключённые сознательно и описанные в документации.
- Повторный прогон неизменённого проекта по-прежнему берёт из кэша все
  вердикты, в обоих адаптерах.
- Шаг 3: `r2` заново гоняет мутантов (`totalCached=0`) и даёт вердикты `r3`.
  `r4` берёт из кэша все 3 вердикта, уже новые.

## Фактическое поведение

Шаг 1 (3 из 3 прогонов в чистом клоне, одинаково):

```
- Expected
+ Received
  {
-   "age == 18": "Survived",
-   "age > 18": "Killed",
+   "age == 18": "Killed",
+   "age > 18": "Survived",
    "age >= 17": "Survived",
  }
```

Все вердикты второго прогона взяты из кэша (`cached: true` у всех трёх, `runs`
— `{ dry: 1 }`), `diagnostics` пуст.

Шаг 2 не запускался (см. выше).

Шаг 3, по отчётам верификаторов на 170ec52 (Vitest — 3 повтора с одинаковым
итогом):

| Прогон | Фикстура | `totalCached` | `age > 18` | `age == 18` | `age >= 17` | score |
| --- | --- | --- | --- | --- | --- | --- |
| `r1` | 30 | 0 | Survived | Killed | Survived | 33.33 |
| `r2`, с кэшем | 18 | 3 | Survived | Killed | Survived | 33.33 |

## Подозреваемые места в коде

Где теряется чтение:

- `adapters/shared/track-inputs.ts:31-37`. Условие
  `file === root || file.startsWith(root + path.sep)` (`:32`) отбрасывает все
  чтения вне root. Других фильтров по root на пути чтений нет. Дальше Vitest
  проверяет только абсолютность пути и `node_modules`
  (`adapters/vitest/get-module-file.ts:17-19`), node:test — `node_modules` и
  каталог preload (`adapters/node-test/collect-node-dependencies.ts:49-55`).
- Вызовы `trackInputs`: `adapters/vitest/runner.ts:1015-1021` и
  `adapters/node-test/preload/preload.ts:72`. Больше ни для чего `root` в
  воркере и в preload не используется (`runner.ts:1016-1017`, `preload.ts:72`).
  В воркер root приходит из `adapters/vitest/run-specifications.ts:38`, в
  preload — из `adapters/node-test/run-test-file.ts:39`.

Как чинить: что проверено, а что нет.

- Вариант A: записывать чтения вне root, кроме исключённых мест. Оба
  верификатора прототипировали его правкой `trackInputs`. Прототип исключал
  `os.tmpdir()`, `/proc`, `/sys`, `/dev`, каталог установки Node и
  `node_modules`. Результат под Vitest: фикстура вне root и вне tmpdir
  инвалидируется верно (тест с такой фикстурой до правки падает, после
  проходит). Повторный прогон неизменённого проекта берёт из кэша 3 из 3
  вердиктов. Вне root записалась только сама фикстура. Тест шага 1 с этим
  прототипом по-прежнему падает, потому что его фикстура лежит в tmpdir. Под
  node:test прототип не проверялся.
- Обязательное исключение для варианта A — рабочий каталог mootant (см.
  «Контекст»: `switched/<n>.json`, новый путь на каждом прогоне). Исключайте
  именно его, а не весь `os.tmpdir()`. В tmpdir лежат root всех интеграционных
  тестов кэша (`copyFixture`, `test/adapters/vitest/index.test.ts:346-362`) и
  раскладка шага 2. Если tmpdir всё же исключать, то только когда root лежит вне
  него (предложение скептика). Где взять путь:
  - воркер Vitest знает его как `this.options.directory`
    (`adapters/vitest/runner.ts:1016`, поле `directory` в
    `adapters/vitest/types/vitest-worker.d.ts:205-208`);
  - у preload node:test такого поля нет
    (`adapters/node-test/types/node-test-unit.d.ts:5-50`). Его можно добавить
    в unit там, где тот собирается (`adapters/node-test/run-test-file.ts:34-39`,
    рабочий каталог — `context.workDirectory`). Другой путь — отфильтровать
    рабочий каталог в главном процессе, в `collectNodeDependencies` рядом с
    исключением каталога preload (`collect-node-dependencies.ts:42-55`). Её
    вызывают `adapters/node-test/run-dry.ts:131-137` и
    `adapters/node-test/run-isolated.ts:83`, и в обоих местах `context`
    доступен. Какой путь лучше, не проверялось.
- Почему tmpdir вообще хотелось исключать (по чтению кода, запуском не
  проверено). `mkdtemp` не входит в отслеживаемые записи
  (`adapters/shared/track-file-reads.ts:33-47`). Значит, тест, который создаёт
  временный каталог и читает его (`readdir`, `stat`), при варианте A без
  исключения tmpdir добавит в зависимости новый путь на каждом прогоне. Тогда
  вердикты его тест-файла перестанут переиспользоваться. Чтений из `/proc`,
  `/sys`, `/dev` и каталога Node в прогонах верификаторов не было; на других
  проектах это не проверялось.
- Вариант B: расширить границу до корня git или каталога lockfile и передавать
  её в воркер и preload вместо root. Lockfile ищет
  `core/cache/find-lockfile.ts:23-38`, сейчас его вызывает только главный
  процесс (`core/cache/prepare-run-cache.ts:120`). Вариант не прототипировался.
  Его проще описать в документации, но у него есть ограничения:
  - тест шага 1 он не чинит;
  - в раскладке шага 3 npm кладёт `package-lock.json` в каждый пакет, и граница
    совпадёт с root;
  - файлы вне репозитория (абсолютные пути) не учтутся.

  Рабочий каталог (`<tmpdir>/mootant-*`) попадает в такую границу, только если
  она включает сам tmpdir.

Тесты, документация, JSDoc:

- `test/adapters/shared/track-inputs.test.ts:36,46-55` — ожидание, что
  `/other/c.json` не записывается, меняется вместе с решением.
- `docs/content/guide/configuration.mdx:350-359` и раздел «Project root»
  (`:124-130`) — описать, какие чтения учитываются и какие места исключены. Если
  какая-то граница остаётся, её нужно описать рядом с оговоркой про дочерние
  процессы и сеть (`:357-359`).
- JSDoc с прежней границей («project files … read», «only inside it»):
  `adapters/shared/track-inputs.ts:8-14`,
  `adapters/shared/types/input-tracking.d.ts:15-19`,
  `adapters/vitest/types/vitest-worker.d.ts:11-17,216-219`,
  `adapters/node-test/types/node-test-unit.d.ts:41-44`,
  `adapters/node-test/collect-node-dependencies.ts:10-18`,
  `adapters/vitest/runner.ts:1005-1014`.

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига) без явной необходимости; если без этого нельзя — опиши компромисс.
  `NodeTestUnit`, `VitestWorkerOptions` и `InputTracking` — внутренние типы:
  из адаптеров наружу экспортируются только `VitestAdapterOptions` и
  `NodeTestAdapterOptions` (`adapters/vitest/index.ts:7`,
  `adapters/node-test/index.ts:7`). Публичный контракт зависимостей — `DryFile`
  (`core/index.ts:30`, `types/adapter/dry-file.d.ts`).
- Сообщения коммитов — Conventional Commits (commitlint).
- Тесты шагов 1 и 2 нельзя копировать в `test/repros/` как есть. Этот каталог
  не исключён ни из ESLint, ни из knip, cspell или tsc. Исключён только
  `test/fixtures/**` (`eslint.config.ts:15`, `knip.config.ts:5`,
  `cspell.config.ts:44`, `vitest.config.ts:18`, `tsconfig.json:2`). Постоянные
  тесты перепиши в стиле проекта под строгий ESLint (имена файлов,
  `describe`/`it`, порядок импортов, JSDoc), а фикстуры клади в
  `test/fixtures/**`. Каталог `test/repros/`, tarball и временные каталоги
  (`$PACK`, `$MONO`) в коммит не входят.
- `pnpm test` после `pnpm build` даёт ложные ошибки `test:astro`: 14 ошибок
  `ts(2322)` в `docs/components/*.astro`. Причина в том, что `tsconfig.json`
  включает `**/*.ts` (`:4`) и не исключает `dist/` (`:2`). После сборки в
  программу попадает `dist/types/html/inline-script.d.ts` (из
  `types/html/inline-script.d.ts:1`, `/// <reference types="vite/client" />`),
  и объявления `*.svg` из Vite конфликтуют с SVG-компонентами Astro. В CI джоба
  Astro пакет не собирает, поэтому там она зелёная. После шага 3 проверяй
  `test:unit`, `test:js`, `test:types` и остальные скрипты по отдельности, а
  `test:astro` запускай после `rm -rf dist`.
- Известные зависимости `test:unit` от окружения, не связанные с этим багом:
  - 4 теста в `test/cli/run-list.test.ts` и `test/cli/run-mutation.test.ts`
    ждут Unicode-символы и падают при `TERM=linux`
    (`cli/terminal/is-unicode-supported.ts:13`); запускай с
    `TERM=xterm-256color`;
  - тест «skips test files it cannot read»
    (`test/adapters/node-test/score-node-test.test.ts:98`) падает под root;
  - при заданном `NODE_OPTIONS` покрытие ветвей не достигает 100% в
    `adapters/node-test/start-node-test-session.ts:119,167`; запускай с
    `env -u NODE_OPTIONS`.
- Границы задачи. Другие пробелы ключа кэша — отдельные задачи, здесь их не
  трогай: tsconfig из `references`, файлы, которые плагины подключают к
  виртуальным модулям Vite, правки в `node_modules` без смены lockfile. Чтения
  дочерних процессов и workers по-прежнему не отслеживаются. Это
  задокументированное ограничение (`configuration.mdx:357-359`), его не меняй.
