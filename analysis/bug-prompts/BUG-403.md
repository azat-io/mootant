# BUG-403: кэш не видит файлы, которые тесты читают вне корня проекта

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Кэш вердиктов переиспользует вердикт, «while the mutated file and the files and
environment variables its tests read stay the same»
(`docs/content/guide/configuration.mdx:352-355`; контракт
`types/adapter/dry-file.d.ts:6-9`: «files the test code read»). Чтения через
`node:fs` записывает `trackInputs`, но только внутри root проекта mootant
(`adapters/shared/track-inputs.ts:31-37`; root — каталог конфига mootant или
cwd, `core/config/prepare-run.ts:133`). Модули вне root при этом учитываются
(`adapters/vitest/collect-dependencies.ts` root не проверяет), а чтения — нет.
Типичный случай — монорепозиторий, где mootant запускают в пакете, а тесты
читают общие фикстуры репозитория (`../../fixtures/*.json`). После правки
фикстуры кэш возвращает старые вердикты в обе стороны (ложный `Survived` и
ложный `Killed`) без предупреждения. Затрагивает оба адаптера: `node:test`
использует тот же `trackInputs`
(`adapters/node-test/collect-node-dependencies.ts:56-61`, поле `end.files`).

Фильтр по root, судя по коду, нужен, чтобы не записывать системные и временные
файлы; существующий тест `test/adapters/shared/track-inputs.test.ts` прямо
проверяет, что `/other/c.json` не записывается. Это поведение и надо
пересмотреть.

## Воспроизведение

```bash
# в корне репозитория azat-io/mootant на коммите 170ec52
pnpm install
# создать test/repros/BUG-403.test.ts с кодом ниже, затем:
pnpm vitest run test/repros/BUG-403.test.ts --coverage.enabled=false
```

Создай `test/repros/BUG-403.test.ts` и запусти
`pnpm vitest run test/repros/BUG-403.test.ts --coverage.enabled=false` (падает
на 170ec52):

```ts
import { writeFile, realpath, mkdtemp, symlink, mkdir, rm } from 'node:fs/promises'
import { afterEach, expect, it } from 'vitest'
import { setTimeout } from 'node:timers/promises'
import { tmpdir } from 'node:os'
import path from 'node:path'

import type { RunResult } from '../../types/run/run-result'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

let roots: string[] = []

async function write(root: string, files: Record<string, string>): Promise<void> {
  for (let [file, text] of Object.entries(files)) {
    await mkdir(path.dirname(path.join(root, file)), { recursive: true })
    await writeFile(path.join(root, file), text)
  }
  // Files modified in the millisecond a run starts count as changed during it.
  await setTimeout(5)
}

async function createDirectory(): Promise<string> {
  let root = await realpath(await mkdtemp(path.join(tmpdir(), 'mootant-bug-')))
  roots.push(root)
  return root
}

function run(root: string, cache = true): Promise<RunResult> {
  return runMutants({
    builtIns: createBuiltIns('vitest', vitestAdapter()),
    paths: ['src'],
    concurrency: 1,
    cwd: root,
    cache,
  })
}

function verdicts(result: RunResult): Record<string, string> {
  return Object.fromEntries(
    result.results.map(entry => [entry.mutant.replacement, entry.status]),
  )
}

afterEach(async () => {
  await Promise.all(roots.splice(0).map(root => rm(root, { recursive: true, force: true })))
})

it('runs the mutants again when a fixture outside the root changes', async () => {
  let shared = await createDirectory()
  let fixture = path.join(shared, 'limits.json')
  await write(shared, { 'limits.json': '{ "age": 30 }' })
  let root = await createDirectory()
  await mkdir(path.join(root, 'node_modules'))
  await symlink(
    await realpath(path.resolve(import.meta.dirname, '../../node_modules/vitest')),
    path.join(root, 'node_modules/vitest'),
  )
  await write(root, {
    'vitest.config.ts': "export default { test: { include: ['test/**/*.test.ts'] } }\n",
    'test/math.test.ts': [
      "import { readFileSync } from 'node:fs'",
      "import { expect, it } from 'vitest'",
      "import { isAdult } from '../src/math'",
      `let limits = JSON.parse(readFileSync(${JSON.stringify(fixture)}, 'utf8'))`,
      "it('isAdult', () => {",
      '  expect(isAdult(limits.age)).toBe(true)',
      '  expect(isAdult(5)).toBe(false)',
      '})',
    ].join('\n'),
    'src/math.ts': 'export function isAdult(age: number): boolean {\n  return age >= 18\n}\n',
    'package.json': '{ "type": "module" }',
  })
  await run(root)
  await write(shared, { 'limits.json': '{ "age": 18 }' })

  let cached = await run(root)
  let fresh = await run(root, false)

  expect(verdicts(cached)).toStrictEqual(verdicts(fresh))
}, 120_000)
```

То же для `node:test`: тест `node --test`, читающий фикстуру по абсолютному
пути вне root, — вердикты тоже устаревают (сценарий `nt_outside_root` в
`analysis/tools/cache/s-inputs.sh` ветки `analysis/2026-11`).

## Ожидаемое поведение

Вердикты второго прогона совпадают с прогоном без кэша: после смены `30` на
`18` `age > 18` — `Killed`, `age == 18` — `Survived`. Файл, который тест прочитал
через `node:fs`, входит в его зависимости, где бы он ни лежал, кроме заведомо
не относящихся к проекту мест.

## Фактическое поведение

```
- Expected
+ Received
  {
-   "age == 18": "Survived",
-   "age > 18": "Killed",
+   "age == 18": "Killed",
+   "age > 18": "Survived",
    "age >= 17": "Survived",
  }
```

Все вердикты второго прогона взяты из кэша, диагностики нет.

## Подозреваемые места в коде

- `adapters/shared/track-inputs.ts:31-37` — условие
  `file === root || file.startsWith(root + path.sep)` отбрасывает все чтения вне
  root. Варианты исправления: записывать чтения вне root, исключая только
  `os.tmpdir()`, `/proc`, `/sys`, `/dev`, каталог установки Node и
  `node_modules`; либо расширить границу до корня git-репозитория или корня
  workspace (каталог lockfile, `core/cache/find-lockfile.ts:23-38`). Второй
  вариант проще объяснить в документации.
- `test/adapters/shared/track-inputs.test.ts` — ожидание, что
  `/other/c.json` не записывается, придётся изменить вместе с решением.
- `docs/content/guide/configuration.mdx:352-359` — если граница остаётся,
  её нужно описать рядом с оговоркой про дочерние процессы и сеть.

## Критерий готовности

- Появляются тесты: unit в `test/adapters/shared/track-inputs.test.ts`
  (чтение вне root записывается, чтения из исключённых мест — нет) и
  интеграционный в `test/adapters/vitest/index.test.ts` по образцу теста выше;
  для `node:test` — аналогичный в `test/adapters/node-test/index.test.ts`. Они
  падают до исправления и проходят после.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- Повторный прогон неизменённого проекта по-прежнему берёт все вердикты из
  кэша: Vitest и Node при работе не читают вне root файлы, меняющиеся от
  прогона к прогону (проверить на `test/fixtures/cache*` и на самом mootant —
  доля переиспользованных вердиктов не падает).
