# BUG-419: кэш не видит tsconfig, подключённый через `references`

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Vite трансформирует TypeScript по настройкам tsconfig, который находит для
файла: `useDefineForClassFields`, `target`, `jsx*`, `experimentalDecorators`,
`verbatimModuleSyntax`. Если ближайший `tsconfig.json` — solution-style
(`"files": []` и `references`, как в шаблонах `create-vite`), Vite берёт
настройки из того файла `references`, который включает трансформируемый файл.
Кэш mootant учитывает tsconfig двумя способами: в корне проекта — все
`tsconfig*.json` (`core/cache/prepare-run-cache.ts:125-127`), а для каталогов
зависимостей — `tsconfig.json` и цепочку `extends`
(`adapters/shared/list-tsconfig-files.ts:17-42`,
`adapters/shared/read-tsconfig-extends.ts:24-47`). `references` не учитывается
нигде. В пакете монорепозитория (`packages/web/tsconfig.json` →
`packages/web/tsconfig.app.json`) смена такой настройки меняет код, который
выполняют тесты, но не ключ — кэш возвращает старые вердикты без
предупреждения.

## Воспроизведение

Создай `test/repros/BUG-419.test.ts` и запусти
`pnpm vitest run test/repros/BUG-419.test.ts --coverage.enabled=false` (падает
на 170ec52):

```ts
import { writeFile, realpath, mkdtemp, symlink, mkdir, rm } from 'node:fs/promises'
import { afterEach, expect, it } from 'vitest'
import { setTimeout } from 'node:timers/promises'
import { tmpdir } from 'node:os'
import path from 'node:path'

import type { RunResult } from '../../types/run/run-result'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

let roots: string[] = []

async function write(root: string, files: Record<string, string>): Promise<void> {
  for (let [file, text] of Object.entries(files)) {
    await mkdir(path.dirname(path.join(root, file)), { recursive: true })
    await writeFile(path.join(root, file), text)
  }
  // Files modified in the millisecond a run starts count as changed during it.
  await setTimeout(5)
}

function run(root: string, cache = true): Promise<RunResult> {
  return runMutants({
    builtIns: createBuiltIns('vitest', vitestAdapter()),
    paths: ['packages/web/src'],
    concurrency: 1,
    cwd: root,
    cache,
  })
}

function verdicts(result: RunResult): Record<string, string> {
  return Object.fromEntries(
    result.results.map(entry => [entry.mutant.replacement, entry.status]),
  )
}

function appConfig(define: boolean): string {
  return JSON.stringify({
    compilerOptions: { useDefineForClassFields: define, target: 'ES2022' },
    include: ['src', 'test'],
  })
}

afterEach(async () => {
  await Promise.all(roots.splice(0).map(root => rm(root, { recursive: true, force: true })))
})

it('runs the mutants again when a referenced tsconfig changes how classes compile', async () => {
  let root = await realpath(await mkdtemp(path.join(tmpdir(), 'mootant-bug-')))
  roots.push(root)
  await mkdir(path.join(root, 'node_modules'))
  await symlink(
    await realpath(path.resolve(import.meta.dirname, '../../node_modules/vitest')),
    path.join(root, 'node_modules/vitest'),
  )
  await write(root, {
    'package.json': '{ "type": "module" }',
    'vitest.config.ts':
      "export default { test: { include: ['packages/*/test/**/*.test.ts'] } }\n",
    'packages/web/tsconfig.json':
      '{ "files": [], "references": [{ "path": "./tsconfig.app.json" }] }',
    'packages/web/tsconfig.app.json': appConfig(true),
    'packages/web/src/math.ts': [
      'export function double(value: number): number {',
      '  return value * 2',
      '}',
      'class Base {',
      '  stored = 0',
      '  set value(value: number) {',
      '    this.stored = double(value)',
      '  }',
      '  get value(): number {',
      '    return this.stored',
      '  }',
      '}',
      'export class Child extends Base {',
      '  // @ts-expect-error a field over an accessor, as in older code bases',
      '  value = 5',
      '}',
    ].join('\n'),
    'packages/web/test/math.test.ts': [
      "import { expect, it } from 'vitest'",
      "import { Child, double } from '../src/math'",
      "it('child', () => {",
      '  expect([5, 10]).toContain(new Child().value)',
      '  expect(double(0)).toBe(0)',
      '})',
    ].join('\n'),
  })
  await run(root)
  // [[Set]] semantics: the field calls the setter, so `double` runs and
  // `value / 2` is killed.
  await write(root, { 'packages/web/tsconfig.app.json': appConfig(false) })

  let cached = await run(root)
  let fresh = await run(root, false)

  expect(verdicts(cached)).toStrictEqual(verdicts(fresh))
}, 120_000)
```

## Ожидаемое поведение

После смены `useDefineForClassFields` в `tsconfig.app.json` вердикты
пересчитываются: `value / 2` и `3` (замена литерала `2`) — `Killed`, как в
прогоне без кэша.

## Фактическое поведение

```
- Expected
+ Received
-   "3": "Killed",
+   "3": "Survived",
-   "value / 2": "Killed",
+   "value / 2": "Survived",
```

Оба вердикта из кэша. Свежий dry run при этом уже видит новую семантику (два
мутанта, которые были `NoCoverage`, становятся `Killed`), но записи для
`(мутант, тест)` с прежним ключом переиспользуются.

## Подозреваемые места в коде

- `adapters/shared/list-tsconfig-files.ts:17-42` — обходит только `extends`
  (`readTsconfigExtends`). Нужно также следовать `references` найденного
  `tsconfig.json`: каждая ссылка — файл или каталог с `tsconfig.json`, и их
  собственные `extends`. Дешёвая альтернатива с запасом — добавлять все
  `tsconfig*.json` из каталога найденного `tsconfig.json`, как это уже делается
  для корня в `core/cache/prepare-run-cache.ts:125-127`.
- `adapters/shared/read-tsconfig-extends.ts:57-91` — разбор `tsconfig` как
  JS-выражения; сюда естественно добавить чтение `references`.
- Тот же `listTsconfigFiles` использует `node:test` с tsx
  (`adapters/node-test/collect-node-dependencies.ts:67-71`), поведение
  исправится и там.

## Критерий готовности

- Появляются тесты: unit в `test/adapters/shared/list-tsconfig-files.test.ts`
  (ссылки `references` на файл и на каталог, вложенные `extends` у ссылки,
  отсутствующая ссылка, цикл ссылок) и интеграционный в
  `test/adapters/vitest/index.test.ts` по образцу теста выше. Они падают до
  исправления и проходят после.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
