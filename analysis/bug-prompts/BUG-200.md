# BUG-200: лимит срабатываний сайтов превращает «горячий, но конечный» мутант в Timeout

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Mootant считает мутанта `Timeout` (засчитывается в score как обнаруженный),
как только код вычислил больше сайтов мутантов, чем `hitLimit`:
`max(floor, factor × hits dry run)`, по умолчанию `max(100000, 100 × hits)`
(`core/config/resolve-run-settings.ts:25-28`, `core/run/get-try-limits.ts:16-28`).
В isolated-пути это проверяется первым и без подтверждения
(`core/run/read-isolated-unit.ts:31-38`), в batch — тоже окончательно
(`core/run/apply-batch-result.ts:164-171`); в рантайме `hit()` при этом бросает
`MootantHitLimitError` прямо в пользовательский код
(`core/runtime/install-mutant-runtime.ts:40-44`). Комментарии называют это
защитой от бесконечного цикла («only a loop through sites gets there»,
`core/run/classify-try.ts:6-8`), но в реальности лимит ловит любого мутанта,
который увеличивает число вычислений сайтов в 100+ раз: отключённая
мемоизация или кэш, удалённый `break`/ранний `return` в поиске, линейный
обход вместо бинарного. Тесты таких мутантов проходят (часто за
миллисекунды), то есть мутант выжил, а Mootant записывает его как
обнаруженный — завышенный score и спрятанный от пользователя непроверенный
кэш. Затрагивает оба адаптера (Vitest и node:test).

## Воспроизведение

Падающий тест — `test/repros/BUG-200.test.ts` в ветке `experiment/bug-repros`
(фикстура `test/fixtures/repros/BUG-200/`).

```bash
pnpm vitest run test/repros/BUG-200.test.ts
```

Фикстура:

```js
// test/fixtures/repros/BUG-200/src/memo.js
let memo = new Map()

export function fib(n) {
  if (n < 2) {
    return n
  }
  if (memo.has(n)) {
    return memo.get(n)
  }
  let value = fib(n - 1) + fib(n - 2)
  memo.set(n, value)
  return value
}

// test/fixtures/repros/BUG-200/test/memo.check.js
import { expect, test } from 'vitest'
import { fib } from '../src/memo.js'

test('fib', () => {
  expect(fib(25)).toBe(75025)
})

// test/fixtures/repros/BUG-200/vitest.config.js
export default { test: { include: ['test/**/*.check.js'] } }
```

Тест запускает `runMutants` (адаптер Vitest) на фикстуре, затем тот же
мутант, применённый физически, обычным Vitest (`runReferenceMutants`,
`separate: true`) и сравнивает.

## Ожидаемое поведение

Мутанты `memo.has(n)` → `false` и `memo.set(n, value)` → `;` — `Survived`:
обычный прогон тестов с физически применённой мутацией проходит
(`fib(25)` без мемо — около 250 000 вызовов, ~5 мс в Node 22).

## Фактическое поведение

Оба — `Timeout` с `cause: 'hit-limit'`:

```
- [ "Survived", null ], [ "Survived", null ]
+ [ "Timeout", "hit-limit" ], [ "Timeout", "hit-limit" ]
```

То же на эквивалентной фикстуре node:test (`/home/user/projects/oracle/nt/state`,

## Подозреваемые места в коде

- `core/run/read-isolated-unit.ts:31-38` — превышение лимита сразу даёт
  окончательный `Timeout`, независимо от того, сколько длился юнит и прошли
  ли тесты до броска `MootantHitLimitError`.
- `core/run/classify-try.ts:26-28` — то же для отдельной попытки.
- `core/config/resolve-run-settings.ts:25-28` — множитель 100 и пол 100 000
  слишком малы, чтобы отделить бесконечный цикл от «горячего» кода.
- `core/runtime/install-mutant-runtime.ts:40-44` — бросок внутри кода
  пользователя превращает «долго» в «упал», дальнейшие тесты юнита уже
  ничего не доказывают.

## Критерий готовности

- Появляется тест `test/core/run/read-isolated-unit.test.ts` (или
  интеграционный в `test/adapters/vitest/index.test.ts`), который падает до
  исправления и проходит после; `test/repros/BUG-200.test.ts` проходит.
- Вариант исправления (на выбор, с обоснованием в PR): превышение лимита
  сайтов не даёт `Timeout` само по себе, а (а) подтверждается повтором юнита
  с выключенным лимитом и обычным временным бюджетом, как `time-limit`
  (`core/run/get-unit-evidence.ts:15-30`), или (б) лимит считается в
  несколько порядков выше и/или только для сайтов, вычисляемых *после*
  достижения мутанта.
- Мутант, делающий цикл действительно бесконечным (`index++` → `index--`),
  по-прежнему `Timeout` (есть в `test/fixtures/runner`).
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
