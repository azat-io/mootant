# BUG-302: O19 считает удаление then-ветки тем же мутантом, что `if (false)`, хотя условие с эффектом

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

`statement-removal` не выдаёт удаление единственного оператора then-ветки `if`
без `else`, если «владелец» условия выдаёт константу `false`
(`core/mutators/statement-removal.ts:152-188`, правило `O19`, категория
`owned`, `heuristic: false` в `core/skips/skip-rules.ts:354-357`). Обоснование
в `core/mutators/shared/get-owner-constant.ts:19-34`: «A candidate with the
behavior of that decision forced to the value is then the same mutant under
another name and is skipped statically».

Это неверно, когда у условия есть побочный эффект: `if (map.delete(key))
onRemove(key)` → удаление `onRemove(key)` по-прежнему удаляет ключ, а
`if (false)` — нет. Тест «ключ удалён» убивает `if (false)`, но не удаление
уведомления, и дыра «никто не проверяет, что `onRemove` вызывается» остаётся
невидимой. Правило статическое: ни `strict`, ни отключение мутатора-владельца,
ни ignore-комментарий мутанта не возвращают (`docs/content/mutators/condition.md`,
раздел Configuration). Тот же класс у `R4`, когда владелец — константа или
`&&`/`||`-константа группы, которая не вычисляет операнды
(`core/mutators/shared/get-toward-mutant.ts:96-118`), и у `O19`/`R5` для копий
ветки тернарника (`core/mutators/shared/get-branch-copy-skip.ts`).

## Воспроизведение

Падающий тест — `test/repros/BUG-302.test.ts` в ветке `experiment/bug-repros`:

```ts
import { describe, expect, it } from 'vitest'

import { listMutantTexts } from '../helpers/list-mutant-texts'
import { listSkipped } from '../helpers/list-skipped'

let remove = [
  'export function remove(map, key, onRemove) {',
  '  if (map.delete(key)) {',
  '    onRemove(key)',
  '  }',
  '}',
]

describe('BUG-302: O19 takes the removal of a then-branch for a constant test with an effect', () => {
  it('keeps the removal of the then-branch of a test with an effect', () => {
    expect(
      listMutantTexts('statement-removal', remove, { file: 'example.js' }),
    ).toStrictEqual(['onRemove(key) -> ;'])
  })

  it('does not skip the removal as owned', () => {
    expect(
      listSkipped('statement-removal', remove.join('\n'), {
        file: 'example.js',
      }),
    ).toStrictEqual([])
  })
})
```

Сквозная проверка (фикстура `analysis/data/skips/fx1`, `src/remove.js`,
`test/remove.test.js`: «ключ удалён» и «для отсутствующего ключа колбэк не
вызван»):

```bash
npx mootant run src/remove.js --no-cache   # killed 2, score 100%
# физически заменить `onRemove(key)` на `;`:
npx vitest --run test/remove.test.js        # проходит — мутант выжил
```

## Ожидаемое поведение

`O19` (и `R4`/`R5` с владельцем-константой) применяется, только если
вычисление условия не имеет эффекта, который удаление ветки сохраняет, а
владелец убирает: условие без вызовов, `new`, `await`, присваиваний,
инкрементов, `delete` и `yield` (можно переиспользовать
`core/syntax/is-effect-free.ts`). Иначе удаление выдаётся как обычный мутант
(оно не поглощено: тест на эффект условия убивает `if (false)`, но не удаление).

Компромисс: строгое «без вызовов» вернёт много удалений под чистыми
предикатами (`if (isValid(x))`): на исходниках Mootant у 237 из 604 пропусков
`O19`/`R4` удаления then-ветки в условии есть вызов, но ни один не похож на
вызов с эффектом. Разумнее считать чистыми вызовы известных предикатов
(`has`, `includes`, `startsWith`, `test` у регулярки без `g`/`y`, имена
`is*`/`has*`/`can*`/`should*`) и не применять `O19`/`R4` только к остальным
вызовам, `await`, присваиваниям и инкрементам. Выбор зафиксировать в тесте.

## Фактическое поведение

```
statement-removal 'onRemove(key)' -> ';' [O19/owned] by condition@2:7
  removing the whole then-branch forces the test to false, as condition does
```

## Подозреваемые места в коде

- `core/mutators/statement-removal.ts:152-188` (`getForcedThenSkip`) — нет
  проверки эффектов `parent.test`.
- `core/mutators/shared/get-owner-constant.ts:35-41` — утверждение «тот же
  мутант» верно только для условия без эффектов.
- `core/mutators/shared/get-toward-mutant.ts:96-118` — константы группы и
  константы сравнения как «toward»-владельцы для `R4`.
