# BUG-851: тест-сьют падает под нагрузкой CPU (таймауты и лимиты по стене)

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

В тишине `pnpm test:unit` проходит за ≈ 250 с (4 vCPU). На той же машине при
load average ≈ 30 (`vitest --run --coverage`) он идёт 1 382 с, и падают 20
тестов в 10 файлах. Повторный прогон (load 18–42, `--maxWorkers=2`) дал 9
таких падений, из них общих с первым прогоном — 7. Всего разных тестов,
падавших по времени, — 22. Все падения из-за времени, а не из-за логики.
Кроме перечисленных ниже, во втором прогоне упали `cli/index.test.ts` «prints
the same mutants before the skipped section in the text format» (5,6 с) и
`test/core/hints/create-syntactic-type-provider.test.ts:88` «infers a chain
of 20,000 operators» (10,2 с):

1. **Дефолтный `testTimeout` 5 с у CPU-тяжёлых тестов** (время в скобках —
   под нагрузкой):
   - `test/cli/report/format-header.test.ts:21-29` — 300 000 строк (44,8 с);
   - `test/cli/terminal/get-max-display-width.test.ts:17-22` — 200 000
     текстов (13,9 с);
   - `test/core/cache/prune-cache-entries.test.ts:48-60` — 200 002 записи
     (6,5 с);
   - `test/cli/index.test.ts:211-241` — разбор каждого мутанта эталона
     (10,0 с);
   - `test/cli/html/client/start-report.test.ts:476-490` — happy-dom, 1 000
     тестов (6,8 с);
   - `test/core/run-mutants.test.ts:822-840` — загрузка компиляторов
     Svelte/Vue (5,3 с);
   - `test/core/generate/generate-file-mutants.test.ts` — property-тест «keeps
     no weak mutant and covers every fault of if (!((((!(y1 > x1) …» (7,4 с).
2. **Лимиты по стене внутри хелперов-оракулов**:
   - `test/helpers/run-program.ts:8` `TIME_LIMIT = 1000`. Программа в воркере,
     не уложившаяся в 1 с, считается `hung`. Под нагрузкой это ломает
     `generate-file-mutants.test.ts:4825` («observes function f() { return
     new Promise(() => {}) }» → `['hung']`) и
     `test/core/instrument/instrument-file.test.ts:404` («switches … like
     each mutant applied alone»: эталонный прогон исходной программы получил
     `hung`).
   - `test/adapters/node-test/index.test.ts:140` `timeout: 4000` для эталона
     `test/helpers/run-node-test-reference.ts:150-153`. Обычный `node --test`
     **исходной** копии фикстуры не успевает, и падает
     `expect(original).toBe(true)` (`:350`). Вердикты Mootant при этом ни при
     чём.
3. **Явные таймауты вложенных прогонов** в
   `test/adapters/vitest/index.test.ts` (`}, 30_000)` … `}, 180_000)`,
   `:529-1919`): 10 тестов не уложились.

Сьют — это ещё и среда догфудинга. `mootant run cli/terminal` под нагрузкой
обрывается в dry run с «Tests fail without mutants; fix them first»: в
контрольном прогоне без мутантов не уложились в 5 с `test/cli/index.test.ts:211`
и `test/cli/report/format-header.test.ts:21`.

## Воспроизведение

```bash
# 4 vCPU; создать нагрузку ~×7 по числу ядер, например:
for i in $(seq 28); do (while :; do :; done) & done
pnpm exec vitest --run --coverage --coverage.reportOnFailure \
  --reporter=default --reporter=json --outputFile.json=load.json
kill $(jobs -p)
# Ожидаемо: ≈ 20 падений из списка выше («Test timed out in 5000ms»,
# «expected [ 'hung' ] …», «expected false to be true» на
# test/adapters/node-test/index.test.ts:350)
```

Для отдельного механизма нагрузку можно сузить: например, запускать только
`test/core/generate/generate-file-mutants.test.ts -t 'observes'` под той же
искусственной нагрузкой.

## Ожидаемое поведение

Под нагрузкой тесты идут дольше, но не падают. Лимиты, которые отличают
«завис» от «медленно», задаются с запасом или масштабируются.

## Фактическое поведение

20 падений при load average ≈ 30; данные прогона:
`analysis/data/tests/load-1-failures.tsv`, `analysis/data/tests/load-1.summary.json`.

## Подозреваемые места в коде

- `vitest.config.ts` — нет `testTimeout`, действует дефолт 5 000 мс.
- `test/helpers/run-program.ts:8` — `TIME_LIMIT = 1000`.
- `test/adapters/node-test/index.test.ts:140` — `timeout: 4000`.
- Тесты масштаба из п. 1: размер входа (200–300 тыс.) берётся с большим
  запасом над лимитом spread в V8 (≈ 130 000 элементов при стандартном
  стеке).

## Критерий готовности

- Лимиты по стене в хелперах-оракулах (`TIME_LIMIT`, `timeout: 4000`) подняты
  до 5–10 с или умножаются на коэффициент из окружения, например
  `MOOTANT_TEST_TIME_FACTOR`. «Зависание» в этих тестах — бесконечный цикл,
  его поймает любой лимит.
- Тесты масштаба: размер входа снижен до 140–150 тыс. (всё ещё больше лимита
  spread) **или** у них явный таймаут. Проверить, что тест всё ещё ловит
  регрессию: заменить реализацию на `Math.max(...widths)` — тест должен
  упасть.
- `testTimeout` в `vitest.config.ts` поднят до 15–20 с, либо явные таймауты у
  перечисленных тестов.
- Под искусственной нагрузкой (команда выше) `pnpm test:unit` зелёный, а время
  в тишине не выросло больше чем на 5 %.
- `pnpm test` полностью зелёный (включая 100 % coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ослабляй проверки: таймаут в оракулах должен по-прежнему отличать
  бесконечный цикл от завершения, а тесты масштаба — по-прежнему падать на
  spread большого массива.
- Сообщения коммитов — Conventional Commits (commitlint).
