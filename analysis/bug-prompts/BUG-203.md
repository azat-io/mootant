# BUG-203: необработанная ошибка, которую конфигурация Vitest велит игнорировать, всё равно убивает мутанта

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Воркер-раннер Mootant для Vitest сам подписывается на `unhandledRejection` и
`uncaughtException` процесса (`adapters/vitest/runner.ts:1249-1266`) и пишет
каждую такую ошибку как stray-ошибку попытки или юнита (`runner.ts:665-686`).
В isolated-пути stray после достижения мутанта — убийство (`stray-error`,
`core/run/classify-try.ts:34-38`, `core/run/read-isolated-unit.ts:46-63`,
`:93-105`). Настройки Vitest, которые решают, проваливают ли такие ошибки
прогон, — `dangerouslyIgnoreUnhandledErrors` и фильтр `onUnhandledError`
(в Vitest 5: `node_modules/vitest/dist/chunks/cli-api.De07GUeT.js:10868`,
`:13199`), — Mootant не читает (в `adapters/` и `core/` их нет). Обычный
`vitest run` такого проекта с физически применённым мутантом проходит
(exit 0), а Mootant записывает `Killed` — ложное убийство в режиме по
умолчанию, завышающее score. Тестовый эталон самого проекта
(`test/helpers/run-reference-mutants.ts`, `PLAIN_RUN_SCRIPT`) считает
`getUnhandledErrors().length > 0` провалом и потому этот случай не ловит.

## Воспроизведение

Падающий тест — `test/repros/BUG-203.test.ts` в ветке `experiment/bug-repros`
(фикстура `test/fixtures/repros/BUG-203/`).

```bash
pnpm vitest run test/repros/BUG-203.test.ts
```

Фикстура:

```js
// test/fixtures/repros/BUG-203/vitest.config.js
export default {
  test: {
    include: ['test/**/*.check.js'],
    dangerouslyIgnoreUnhandledErrors: true,
  },
}

// test/fixtures/repros/BUG-203/src/events.js
export function emitLater(listener) {
  setTimeout(() => {
    if (listener) {
      listener()
    }
  }, 0)
  return true
}

// test/fixtures/repros/BUG-203/test/events.check.js
import { expect, test } from 'vitest'
import { emitLater } from '../src/events.js'

test('emits without a listener', async () => {
  expect(emitLater(undefined)).toBe(true)
  await new Promise(resolve => {
    setTimeout(resolve, 10)
  })
})
```

Тест запускает `runMutants` (адаптер Vitest), затем обычный `vitest run` на
копии фикстуры с физически применённым мутантом `listener` → `true` и
сравнивает. То же на CLI-фикстурах `/home/user/projects/oracle/vt/unhandled`
(`dangerouslyIgnoreUnhandledErrors: true`) и `vt/unhandled2`
(`onUnhandledError() { return false }`): мутанты `knkyemhs`, `7mkvyn7b` —
`Killed (stray-error)`, эталон (`results/unhandled{,2}/oracle.jsonl`) —
survived.

## Ожидаемое поведение

Мутант `listener` → `true` — `Survived`: Vitest выводит «Uncaught Exception…
TypeError: listener is not a function», но по `dangerouslyIgnoreUnhandledErrors`
завершается с кодом 0 (`Test Files 1 passed`, `Errors 1 error`). Так же для
ошибки, которую отбрасывает `onUnhandledError` (возвращает `false`).

## Фактическое поведение

```
- [ "Survived", null ]
+ [ "Killed", "stray-error" ]
```

## Подозреваемые места в коде

- `adapters/vitest/runner.ts:665-686` (`onStray`) и `:1249-1266`
  (`listenForStrays`) — ошибки записываются без учёта настроек проекта.
- `core/run/read-isolated-unit.ts:46-63`, `:93-105` и
  `core/run/classify-try.ts:34-38` — stray после достижения мутанта всегда
  убивает.
- `adapters/vitest/configure-project.ts:22-56` — место, где Mootant уже
  читает и переопределяет настройки проекта; здесь можно передать воркеру,
  игнорирует ли проект необработанные ошибки (и фильтр `onUnhandledError`
  вызывать в главном процессе на `unhandledErrors` прогона,
  `adapters/vitest/run-specifications.ts:43`).

## Критерий готовности

- `test/repros/BUG-203.test.ts` проходит; добавлен тест для
  `onUnhandledError: () => false` (ошибка отфильтрована → мутант не убит) и

  `test/fixtures/runner`).

  попытку сомнительной.

  `test:types`, `test:usage`, `test:spelling`).
