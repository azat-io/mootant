# BUG-303: вызов метода у элемента коллекции из условия цикла считается «продвижением» цикла (loop-advance)

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Без настройки `timeouts` (выключена в `recommended`) `statement-removal` не
удаляет оператор, который «продвигает цикл» (`core/mutators/statement-removal.ts:253-259`,
правило `loop-advance`, категория `timeout`, `heuristic: false`). Предикат
`advancesLoop` (`core/syntax/advances-loop.ts:47-75`) считает продвижением не
только запись имени, которое читает условие цикла, но и **любой вызов метода, у
которого корень объекта — такое имя** (`callsRootMethod`,
`core/syntax/advances-loop.ts:222-233`). Поэтому `items[i].render()` в
`for (let i = 0; i < items.length; i++)` и
`bytes.push(Number.parseInt(text.slice(index, index + 2), 16))` в
`while (index < text.length)` (вызов `text.slice`) считаются продвижением,
хотя их удаление не может сделать цикл бесконечным. Удаление — часто
единственный мутант тела цикла, и он молча пропадает.

## Воспроизведение

Падающий тест — `test/repros/BUG-303.test.ts` в ветке `experiment/bug-repros`:

```ts
import { describe, expect, it } from 'vitest'

import { listMutantTexts } from '../helpers/list-mutant-texts'
import { listSkipped } from '../helpers/list-skipped'

describe('BUG-303: a call on an element of the loop bound is taken for the loop advance', () => {
  it('keeps the removal of a call on an element of the array a for loop counts', () => {
    expect(
      listMutantTexts(
        'statement-removal',
        [
          'export function renderAll(items) {',
          '  for (let i = 0; i < items.length; i++) {',
          '    items[i].render()',
          '  }',
          '}',
        ],
        { file: 'example.js' },
      ),
    ).toStrictEqual(['items[i].render() -> ;'])
  })

  it('does not take a push that only reads the bound for the loop advance', () => {
    let push = 'bytes.push(Number.parseInt(text.slice(index, index + 2), 16))'
    let skipped = listSkipped(
      'statement-removal',
      [
        'export function decode(text) {',
        '  let bytes = []',
        '  let index = 0',
        '  while (index < text.length) {',
        `    ${push}`,
        '    index += 2',
        '  }',
        '  return bytes',
        '}',
      ].join('\n'),
      { file: 'example.js' },
    )

    /*
     * The push holds finer mutants, so `recommended` may still drop it as
     * solitary; it must not be skipped as a timeout.
     */
    expect(skipped).not.toContain(`${push} -> ; (timeout loop-advance)`)
  })

  it('still skips the removal of a call that shifts the queue the loop tests', () => {
    expect(
      listMutantTexts(
        'statement-removal',
        [
          'export function drain(queue, handle) {',
          '  while (queue.length > 0) {',
          '    handle(queue.shift())',
          '  }',
          '}',
        ],
        { file: 'example.js' },
      ),
    ).toStrictEqual([])
  })
})
```

Сквозная проверка (фикстура `analysis/data/skips/fx1`, `src/render.js`,
`test/render.test.js`, тест проверяет только возвращаемый счётчик):

```bash
npx mootant run src/render.js --no-cache   # killed 5, score 100%
# физически заменить `items[i].render()` на `;`:
npx vitest --run test/render.test.js        # завершается за ~0.8 с и проходит
```

## Ожидаемое поведение

Удаление считается `loop-advance`, только если оно может остановить изменение
имени, которое читает условие: запись этого имени (уже учитывается
`changesRoot`) или вызов метода **на самом имени** (`queue.shift()`,
`this.next()`), но не вызов метода на элементе/члене (`items[i].render()`), не
чистый метод строки (`text.slice`) и не добавление в другую коллекцию.
`items[i].render() -> ;` выводится в `recommended`.

## Фактическое поведение

```
statement-removal 'items[i].render()' -> ';' [loop-advance/timeout]
  it removes the statement that advances a loop, so it may keep the loop running forever
```

На исходниках Mootant 112 таких пропусков удалений, большинство верные
(`current = current.parent`), но, например, `core/git/unquote-git-path.ts:39`
(`bytes.push(Number.parseInt(text.slice(...), 8))`) пропущен только из-за
`text.slice`.

## Подозреваемые места в коде

- `core/syntax/advances-loop.ts:222-233` (`callsRootMethod`) — проверяет только
  корень `callee.object`, а не то, что вызов вызывается на самом имени.
- `core/syntax/advances-loop.ts:67-75` — обход оператора считает любой такой
  вызов.
