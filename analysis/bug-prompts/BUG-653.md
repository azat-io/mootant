# BUG-653: документированная установка `npm install -D mootant` ставит заглушку 0.0.0

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: critical. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Readme (`readme.md:77-78`) и getting-started
(`docs/content/guide/getting-started.mdx:65-77`) велят выполнить `npm install
-D mootant`, затем `npx mootant run src`. На npm опубликованы только
`0.0.0-stage` и `0.0.0` (2026-10-10): пакет-заглушка для настройки OIDC trusted
publishing с README «DO NOT USE THIS PACKAGE», без `bin` и кода. Версия 0.1.0
из `package.json` не опубликована, тегов и релизов на GitHub нет. Установка из
GitHub (`npm install -D github:azat-io/mootant`) тоже не работает: в git нет
`dist/`, а `prepare` в `package.json` нет, поэтому `bin/mootant.js` падает на
`import '../dist/cli/index.js'`. Любой новый пользователь и любой агент
останавливаются на первом шаге. Релизный workflow
(`.github/workflows/release.yml`, по тегу `v*`, OIDC) готов; не хватает
выпуска или честной документации до него.

## Воспроизведение

```bash
npm view mootant                      # latest: 0.0.0, "OIDC trusted publishing setup package"
mkdir /tmp/bug-653 && cd /tmp/bug-653 && npm init -y >/dev/null
npm install -D mootant                # "mootant": "^0.0.0"
npx mootant run src; echo "exit=$?"   # npm error could not determine executable to run, exit=1
npm install -D github:azat-io/mootant
npx mootant --version                 # ERR_MODULE_NOT_FOUND …/mootant/dist/cli/index.js
```

## Ожидаемое поведение

Либо `npm install -D mootant` ставит работающую 0.1.0, либо документация
до выпуска прямо говорит, что пакет ещё не опубликован, и даёт рабочий путь
установки.

## Фактическое поведение

```text
npm error could not determine executable to run
```

## Подозреваемые места в коде

- `readme.md:66-80` — раздел «Getting started» и плашка «Early development».
- `docs/content/guide/getting-started.mdx:63-69` — «Installation».
- `docs/components/DevelopmentBanner.astro` — плашка на сайте («Mootant is in
  early development. Expect breaking changes.»), не говорит, что пакета нет.
- `package.json` — нет `prepare`; `files: ["./bin", "./dist"]`.

## Что сделать

1. Главное исправление — выпуск 0.1.0 (скрипт `release` в `package.json`:
   `release:check` → `release:version` → `release:prepare` → `release:git`;
   тег `v0.1.0` запускает `.github/workflows/release.yml`). Это делает мейнтейнер; в сессии —
   только проверить готовность: `pnpm release:check`, `pnpm pack`, установка
   получившегося `.tgz` в чистый проект с Vitest 5 и `npx mootant run src`.
2. Если выпуск откладывается — до него в readme, getting-started и плашке
   сайта написать, что пакет ещё не на npm, и дать путь из исходников:
   `git clone`, `pnpm install`, `pnpm build`, `pnpm pack`, `npm install -D
   ./mootant-0.1.0.tgz`. После выпуска эти строки убрать.
3. Не добавлять `prepare` ради установки из GitHub: он поставит все
   devDependencies (Astro, ESLint и т. д.) каждому пользователю git-зависимости.

## Критерий готовности

- В чистом каталоге `npm init -y && npm i -D vitest@5 mootant && npx mootant
  --version` печатает `mootant/0.1.0 …` (после выпуска), **или** документация
  (readme, getting-started, плашка) явно говорит, что пакет не опубликован, и
  путь из неё проходит в чистом каталоге.
- Смоук-тест в CI (например, шаг в `.github/workflows/test.yml`): `pnpm pack`,
  установка `.tgz` в `docs/demo` или временный проект, `mootant list src`
  завершается с кодом 0 — чтобы следующий выпуск не сломал установку.
- `pnpm test` полностью зелёный (`test:format`, `test:spelling` проверяют и
  Markdown).

## Ограничения

  Prettier для Markdown и YAML.
- Не публикуй пакет и не создавай теги из сессии без явного разрешения
  мейнтейнера.
- Сообщения коммитов — Conventional Commits (commitlint).
