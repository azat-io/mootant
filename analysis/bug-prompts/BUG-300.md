# BUG-300: опустошённая строка внутри элемента прячет удаление элемента (solitary)

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Правило `solitary` (пайплайн генерации, `core/generate/apply-solitary-rule.ts:60`)
выбрасывает «грубого» мутанта — например, удаление элемента массива
(`core/mutators/array-element.ts:55-59`, `solitary: [element]`) или свойства
объекта (`core/mutators/object-property.ts:22`), — если внутри его диапазона есть
«тонкий» мутант. Обоснование в причине пропуска: «killing that mutant needs a test
that observes this code» (`core/generate/generate-file-mutants.ts:359`).

Для строкового элемента тонкий мутант — `string-literal` `'else'` → `''`
(`core/mutators/string-literal.ts:92-103`). Его убивает любой тест, который
подаёт на вход пустую строку: `''` становится членом множества, хотя тест ничего
не говорит о том, есть ли в множестве `'else'`. Один тест «пустое слово — не
ключевое» убивает все `''`-мутанты элементов, и все удаления элементов исчезают.
Пользователь получает 100 % при реальной дыре: ни один тест не проверяет состав
множества. Это типичный шаблон (множества ключевых слов, расширений файлов,
команд, разрешённых значений). На исходниках самого Mootant так пропущено
2 028 удалений элементов массивов и 980 удалений свойств
(`mootant list core --skipped`, владелец — `string-literal`).

Правило помечено `heuristic: true`, и `docs/content/mutators.md:51-52` говорит
«likely, not certain», но этот класс ломает предположение систематически, а не
изредка.

## Воспроизведение

Падающий тест — `test/repros/BUG-300.test.ts` в ветке `experiment/bug-repros`:

```ts
import { describe, expect, it } from 'vitest'

import { listMutantTexts } from '../helpers/list-mutant-texts'
import { listSkipped } from '../helpers/list-skipped'

let keywords = [
  "const KEYWORDS = new Set(['if', 'else', 'for'])",
  'export function isKeyword(word) {',
  '  return KEYWORDS.has(word)',
  '}',
]

describe('BUG-300: an emptied string element hides the removal of the element', () => {
  it('keeps the removal of each element of a lookup set', () => {
    expect(
      listMutantTexts('array-element', keywords, { file: 'example.js' }),
    ).toStrictEqual([
      "['if', 'else', 'for'] -> ['else', 'for']",
      "['if', 'else', 'for'] -> ['if', 'for']",
      "['if', 'else', 'for'] -> ['if', 'else']",
    ])
  })

  it('does not drop the removals as solitary', () => {
    expect(
      listSkipped('array-element', keywords.join('\n'), { file: 'example.js' }),
    ).toStrictEqual([])
  })
})
```

## Ожидаемое поведение

Удаление элемента, внутри которого единственный тонкий мутант — опустошение
строки (или заполнение пустой строки `'mootant'`), не считается поглощённым:
`''`-мутант убивается тестом с пустой строкой, который не наблюдает удаляемый
элемент. Удаления `'else'` и `'for'` попадают в список мутантов в `recommended`.

## Фактическое поведение

```
$ npx mootant list src --skipped --json   # фрагмент
array-element "['if', 'else', 'for']" -> "['if', 'for']"  rule solitary (subsumed, heuristic)
  by string-literal 1:33: a finer string-literal mutant lies inside the code it removes, ...
```

`mootant run` показывает 100 %, хотя физически применённое удаление выживает.

## Подозреваемые места в коде

- `core/generate/apply-solitary-rule.ts:124-136` (`countsFor`) — любой тонкий
  мутант считается, кроме `countsForSolitary: false`; нет понятия «тонкий мутант,
  который убивается не через удаляемый код».
- `core/mutators/string-literal.ts:92-103` — опустошение строки; кандидат на
  `meta.countsForSolitary: false` *для элементов коллекций* либо на отдельный
  признак в `Replacement`, который апстрим сможет учесть.
- `core/mutators/array-element.ts:55-59`, `core/mutators/object-property.ts:22`
  — где задаются диапазоны `solitary`.

Возможные исправления (выбрать одно, обосновать): (а) строковый мутант не
считается для `solitary` удаления элемента массива/множества, если сам элемент —
строковый литерал целиком; (б) не считать мутанты, чья замена — «пустое
значение того же типа» (`''`, `0`, `[]`), для удаления содержащего их элемента;
(в) оставить правило, но выводить такие удаления как отдельную подкатегорию,
возвращаемую `coarseMutants: 'partial'`. Вариант (а) самый узкий.
