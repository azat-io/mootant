# BUG-407: переустановка той же версии mootant обнуляет кэш вердиктов

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

В ключ окружения кэша входит «штамп сборки» — `mtimeMs` файла самого модуля
`prepare-run-cache` (`core/cache/prepare-run-cache.ts:164`:
`build: (await stat(import.meta.filename)).mtimeMs`), чтобы пересборка
невыпущенной версии не переиспользовала вердикты прежней сборки
(`core/cache/get-environment-key.ts:47-51`, `:76`). Но npm 10 при установке
ставит файлам пакета **текущее** время, а не время из архива. Поэтому любая
переустановка той же версии — `rm -rf node_modules && npm ci` в CI с
восстановленным `node_modules/.cache/mootant`, установка у коллеги, другая
машина CI — меняет ключ, и ни один вердикт не переиспользуется. Это обесценивает
переносимые ключи: пути в кэше намеренно относительные «so the cache file and
its keys do not depend on where the project lives»
(`core/cache/get-portable-path.ts:4-7`). Ключ ломается даже при потере долей
секунды у `mtime` (копирование архивом без наносекунд). У pnpm время файла
берётся из store, поэтому поведение ещё и зависит от пакетного менеджера.

## Воспроизведение

Скрипт (нужны сеть или npm-кэш; путь к `.tgz` — собранный `pnpm pack` пакет):

```bash
#!/usr/bin/env bash
set -eu
tgz=${1:?path to mootant-*.tgz from pnpm pack}
work=$(mktemp -d)
cd "$work"
echo '{ "name": "bug-407", "private": true, "type": "module", "scripts": { "test": "vitest run" } }' >package.json
mkdir -p src test
printf 'export function isAdult(age: number): boolean {\n  return age >= 18\n}\n' >src/math.ts
cat >test/math.test.ts <<'TS'
import { expect, it } from 'vitest'
import { isAdult } from '../src/math'
it('isAdult', () => {
  expect(isAdult(30)).toBe(true)
  expect(isAdult(5)).toBe(false)
})
TS
# npm 10 cannot resolve the peer set of vitest 5.0.5 without --legacy-peer-deps.
npm i -D --legacy-peer-deps --no-audit --no-fund "$tgz" vitest@5.0.5 vite@8.3.5 >/dev/null
count() { node -e 'console.log(JSON.parse(require("fs").readFileSync(0, "utf8")).summary.totalCached ?? 0)'; }

npx mootant run src --json --all --verbose 2>/dev/null >/dev/null
cp node_modules/.cache/mootant/run-v3.json saved.json
echo "same install:   $(npx mootant run src --json --all --verbose 2>/dev/null | count) cached"

stamp=node_modules/mootant/dist/core/cache/prepare-run-cache.js
touch -r "$stamp" reference
rm -rf node_modules/mootant
npm i -D --legacy-peer-deps --no-audit --no-fund --offline "$tgz" >/dev/null
cp saved.json node_modules/.cache/mootant/run-v3.json
echo "reinstalled:    $(npx mootant run src --json --all --verbose 2>/dev/null | count) cached"

touch -r reference "$stamp"
cp saved.json node_modules/.cache/mootant/run-v3.json
echo "old mtime back: $(npx mootant run src --json --all --verbose 2>/dev/null | count) cached"
```

Готовая версия — `test/repros/BUG-407/run.sh` в ветке `experiment/bug-repros`
(код выхода 1, пока баг есть).

## Ожидаемое поведение

Переустановка того же пакета (те же байты) не меняет ключ: второй и третий
прогоны переиспользуют все вердикты. Пересборка с другим кодом — меняет.

## Фактическое поведение

```
same install:   3 cached
reinstalled:    0 cached
old mtime back: 3 cached
```

## Подозреваемые места в коде

- `core/cache/prepare-run-cache.ts:164` — `mtimeMs` как идентификатор сборки.
  Заменить на идентификатор, зависящий от содержимого: константа, которую
  пишет сборка (хэш содержимого `dist/` или коммит + хэш незакоммиченных
  изменений), либо хэш байтов модулей пакета, вычисленный один раз за прогон.
- `core/cache/get-environment-key.ts:47-51`, `:76` — документация поля `build`
  и его место в ключе.
- `test/core/cache/get-environment-key.test.ts`,
  `test/core/cache/prepare-run-cache.test.ts` — где проверяется штамп.

## Критерий готовности

- Появляется тест (unit в `test/core/cache/`), который показывает: другой
  `mtime` модуля при тех же байтах не меняет ключ окружения, другие байты —
  меняют. Он падает до исправления и проходит после. Скрипт выше печатает
  `3 cached` во второй и третьей строке.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- Подготовка ключа не становится заметно дороже (если хэшируются байты
  пакета — один раз за прогон, а не на каждый тестовый файл).
- Поднят `CACHE_VERSION` (`core/cache/cache-version.ts:6`), так как меняется
  рецепт ключа.
