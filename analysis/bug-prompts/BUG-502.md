# BUG-502: без `ps` зависший воркер Vitest не останавливается, прогон висит вечно

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: high. Статус: подтверждён. Найдено на коммите
> 170ec52.

## Контекст

Мутант, который вешает тест (бесконечный синхронный цикл), Vitest-адаптер
останавливает сторожем пульса: `watchHeartbeats` замечает просроченный пульс и
зовёт `stopHungWorker(pid)` (`adapters/vitest/run-plan.ts:74-75`,
`adapters/vitest/run-dry.ts:69-70`, `adapters/vitest/wait-for-workers.ts:113`).
Перед `SIGKILL` `stopHungWorker` проверяет, что PID — потомок mootant, через
`execFile('ps', ['-o', 'ppid=', '-p', pid])`
(`adapters/vitest/stop-hung-worker.ts:20-21,42-46`). Если `ps` нет (образы
`node:*-slim` на Debian slim без `procps`, distroless) или он не понимает `-p`
(BusyBox в `node:*-alpine` — по исходникам BusyBox, не проверено запуском),
проверка всегда даёт `false`, воркер не убивается, сторож больше не
срабатывает (`watch-heartbeats.ts:60-62`), и прогон ждёт вечно вместо
вердикта Timeout. Это типичные CI-образы.

## Воспроизведение

Падающий тест в ветке `experiment/bug-repros`: `test/repros/BUG-502.test.ts`.

```ts
import { afterEach, describe, expect, it } from 'vitest'
import { mkdtemp, symlink, rm } from 'node:fs/promises'
import { spawn } from 'node:child_process'
import { once } from 'node:events'
import { tmpdir } from 'node:os'
import path from 'node:path'

import { stopHungWorker } from '../../adapters/vitest/stop-hung-worker'

let originalPath = process.env['PATH']
let directory: string | null = null

describe('BUG-502: a hung Vitest worker is never stopped without ps', () => {
  afterEach(async () => {
    process.env['PATH'] = originalPath
    if (directory !== null) {
      await rm(directory, { recursive: true, force: true })
      directory = null
    }
  })

  it('stops a live child process when ps is not installed', async () => {
    let child = spawn(process.execPath, ['-e', 'setInterval(() => {}, 1000)'], {
      stdio: 'ignore',
    })
    await once(child, 'spawn')
    let exited = once(child, 'exit')
    directory = await mkdtemp(path.join(tmpdir(), 'mootant-no-ps-'))
    await symlink(process.execPath, path.join(directory, 'node'))
    process.env['PATH'] = directory

    let stopped: boolean
    try {
      stopped = await stopHungWorker(child.pid!)
    } finally {
      process.env['PATH'] = originalPath
      child.kill('SIGKILL')
    }
    await exited

    expect(stopped).toBe(true)
  })
})
```

```bash
pnpm vitest --run test/repros/BUG-502.test.ts
```

Сквозное воспроизведение на фикстуре (Vitest 5, mootant установлен в
проект): `src/step.js` — `export function getStep(size) { return size - 9 }`,
тест — `let step = getStep(10); let n = 0; for (let i = 0; i < 10; i += step)
n++; expect(n).toBe(10)`. Мутант `9 -> 10` делает шаг 0.

```bash
mkdir -p /tmp/nops && ln -s "$(command -v node)" /tmp/nops/node

timeout -s KILL 75 env PATH=/tmp/nops node node_modules/mootant/bin/mootant.js run src --no-cache

```

## Ожидаемое поведение

Зависший воркер останавливается и без `ps`; мутант получает Timeout, прогон
заканчивается за то же время, что и с `ps`.

## Фактическое поведение

```
+ dry run  1 test in 0.2s
(дальше ничего 75 с; ps: node …vitest… Rl 99% CPU)
exit=137
```

Тест: `expect(stopped).toBe(true)` — получено `false`.

## Подозреваемые места в коде

- `adapters/vitest/stop-hung-worker.ts:20-21,42-46` — проверка родителя через
  внешний `ps`; ошибка `ps` трактуется как «не наш процесс».
- `adapters/vitest/create-forks-pool.ts:66-68` — пул уже знает PID всех своих
  воркеров (`state.spawns`); проверка принадлежности этому множеству не
  требует `ps` и работает на Windows (где сейчас проверки нет вовсе).
- `test/adapters/vitest/stop-hung-worker.test.ts` — тест «leaves processes that
  are gone or not its children» с `mockParent(null)` закрепляет нынешнее
  поведение; его придётся поменять.

## Критерий готовности

- Тест `test/adapters/vitest/stop-hung-worker.test.ts` (или новый рядом)
  проверяет остановку живого воркера при отсутствии `ps`; падает до
  исправления и проходит после. Воспроизведение `test/repros/BUG-502.test.ts`
  проходит.
- Защита от переиспользованного PID сохраняется (процесс, не запущенный пулом,
  не убивается) и покрыта тестом.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- Ручная проверка: фикстура выше с `PATH` без `ps` даёт Timeout за ~5 с.
