# BUG-601: после SIGTERM/SIGHUP главного процесса остаются осиротевшие тестовые процессы (и рабочий каталог)

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52. Заодно закрывает BUG-600 (low): рабочий каталог
> `$TMPDIR/mootant-*` остаётся после любого прерывания.

## Контекст

`mootant run` запускает тестовые процессы: Vitest-адаптер — fork-воркеры
Vitest (по одному на юнит «мутант × тестовый файл»), node-test-адаптер — по
процессу `node` на юнит, `detached: true`, лидером своей группы
(`adapters/node-test/run-test-process.ts:117-123`). Если мутант вешает тест
циклом, в котором нет сайтов мутантов (цикл в немутируемом модуле), лимит
вычислений сайтов не срабатывает, и юнит останавливает только сторож
главного процесса (`adapters/vitest/watch-heartbeats.ts`,
`adapters/node-test/run-test-process.ts:133-139`). Когда главный процесс
умирает от сигнала, сторожа нет, и зависший процесс крутится бесконечно.

* Vitest-адаптер не ставит обработчиков сигналов вовсе; воркеры гасятся
  только `vitest.close()` из `finally` (`core/run-mutants.ts:320-325`,
  `adapters/vitest/start-vitest-session.ts:149-157, 175-178`), а `finally`
  при смерти от сигнала не выполняется.
* node-test-адаптер ставит обработчики только на `SIGINT`/`SIGTERM`
  (`adapters/node-test/track-process-group.ts:7, 17-46`); `SIGHUP`
  (закрыли терминал, оборвалась SSH-сессия) убивает главный процесс, а
  `detached`-процессы в своих сессиях его не получают.
* CLI в интерактивном терминале на SIGINT/SIGTERM делает `process.exit(130/143)`
  (`cli/terminal/create-spinner.ts:143-163`), что тоже минует `finally` — поэтому
  рабочий каталог (`core/run/create-work-directory.ts:26-31`) не удаляется ни
  при каком прерывании (BUG-600).

## Воспроизведение

Фикстура (Vitest 5.0.5, mootant из тарбола или `pnpm pack`):

```bash
mkdir -p /tmp/bug601/{src,lib,test} && cd /tmp/bug601
cat > package.json <<'EOF'
{ "name": "bug601", "private": true, "type": "module" }
EOF
cat > src/config.js <<'EOF'
export function getStep(fast) {
  if (fast) {
    return 1
  }
  return 0
}
EOF
cat > lib/walk.js <<'EOF'
import { getStep } from '../src/config.js'

// Not mutated (outside run.paths): no mutant sites inside the loop.
export function walk(n) {
  let step = getStep(true)
  let i = 0
  while (i < n) {
    i += step
  }
  return i
}
EOF
cat > test/walk.test.js <<'EOF'
import { expect, it } from 'vitest'

import { walk } from '../lib/walk.js'

it('walks to n', () => {
  expect(walk(3)).toBe(3)
})
EOF
cat > vitest.config.js <<'EOF'
import { defineConfig } from 'vitest/config'

export default defineConfig({ test: { include: ['test/**/*.test.js'] } })
EOF
cat > mootant.config.js <<'EOF'
export default {
  run: { paths: ['src'], runner: 'vitest', cache: false, timeout: { constant: 20000 } },
}
EOF
npm i -D --legacy-peer-deps <path-to>/mootant.tgz vitest@5.0.5 vite@8
npx mootant list src --json   # мутант «if (false)» — id вида ef33xd3qqj1e

# Запуск без терминала, SIGTERM главному процессу через ~4 с (юнит уже висит):
setsid node node_modules/mootant/bin/mootant.js run --mutant <id> > out.txt 2>&1 < /dev/null &
pid=$!; sleep 6; kill -TERM $pid; wait $pid; echo "exit=$?"
sleep 10
ps -eo pid,ppid,stat,etimes,pcpu,args | grep -F "vitest" | grep -v grep   # воркер жив, ppid 1, R
ls "${TMPDIR:-/tmp}" | grep '^mootant-'                                    # каталог остался
# Убрать сироту вручную: kill -9 <pid>
```

То же для node:test (`test/walk.test.js` на `node:test`/`node:assert`,
`runner: 'node-test'`) с `kill -HUP $pid` вместо `-TERM`: процесс юнита
остаётся сиротой. С `-TERM` у node:test процессы убираются, но каталог
остаётся.

## Ожидаемое поведение

После SIGINT, SIGTERM или SIGHUP главного процесса в любой фазе прогона:
ни одного живого процесса, запущенного прогоном; рабочий каталог удалён;
код выхода 128 + номер сигнала (130/143/129); в терминале курсор восстановлен.

## Фактическое поведение

Наблюдалось на фикстурах анализа (`analysis/bugs/adapters.md`, BUG-600/601):

```
vitest  + SIGTERM: воркер жив через 11 с и через 75 с (R, 30–40 % CPU, ppid 1)
vitest  + SIGHUP : воркер жив через 11 с
node-test + SIGHUP: процесс юнита жив через 11 с
node-test + SIGTERM: процессов нет
все 6 вариантов прерывания (TTY Ctrl+C, SIGINT группе, SIGTERM) — каталог mootant-* остаётся
```

## Подозреваемые места в коде

- `core/run-mutants.ts:271-325` — владелец рабочего каталога и `close()`, но
  отмены как понятия нет.
- `cli/terminal/create-spinner.ts:143-163` — `process.exit()` в обработчике
  сигнала минует очистку.
- `adapters/vitest/start-vitest-session.ts:149-157` — `close()` полагается на
  Vitest; pid воркеров известны (`worker/<pid>` в рабочем каталоге,
  `adapters/vitest/runner.ts:480-482`), но не используются при отмене.
- `adapters/node-test/track-process-group.ts:7` — нет `SIGHUP`.

## Критерий готовности

- Отмена получает одного владельца: CLI ставит обработчики `SIGINT`,
  `SIGTERM`, `SIGHUP` на время `runMutants` (и снимает после), прерывает
  прогон (например, `AbortSignal` в опциях `runMutants`/`AdapterContext`),
  дожидается `session.close()` и `work.remove()` и выходит с 128 + сигнал;
  спиннер только стирает себя.
- `close()` vitest-адаптера гарантированно убивает живые воркеры прогона
  (SIGKILL по pid из `worker/`, с той же проверкой родителя, что в
  `adapters/vitest/stop-hung-worker.ts`); node-test добавляет `SIGHUP`.
- Новый интеграционный тест (например, `test/cli/interrupt.test.ts`) на
  фикстуре с зависающим мутантом для **обоих** адаптеров: запускает CLI,
  посылает каждый из трёх сигналов во время isolated-юнита и проверяет, что
  через 2 с нет процессов с `cwd` фикстуры и нет каталога `mootant-*` в
  приватном `TMPDIR`; тест падает до исправления и проходит после.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
