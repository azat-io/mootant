# BUG-509: `--json` — в stdout попадает чужой вывод, отчёт не парсится как JSON

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён. Найдено на
> коммите 170ec52.

## Контекст

`--json` — интерфейс для скриптов и агентов. JSDoc `runMutation` обещает, что
stdout содержит только отчёт, «pure JSON with --json» (`cli/run-mutation.ts:22-25`),
документация — что прогресс идёт в stderr (`docs/content/guide/cli.mdx:125`).
Отчёт печатается `console.info` в самом конце (`cli/run-mutation.ts:63-72`), а
до этого stdout открыт для любого кода, который выполняется в процессе
mootant: конфиг Vitest, плагины Vite, `globalSetup`, конфиг mootant.
Перехвачены только потоки логгера Vitest
(`adapters/vitest/start-vitest-session.ts:111-116`). Типичные источники:
`import 'dotenv/config'` в `vitest.config.ts` (dotenv 17 печатает баннер
`[dotenv@17.x] injecting env (n) from .env`; поведение dotenv здесь не
проверялось — фикстура печатает такую же строку сама), `@sveltejs/vite-plugin-svelte`
без `svelte.config.js` («no Svelte config found … using default configuration»
и предупреждения компилятора). `JSON.parse(stdout)` у агента падает.

## Воспроизведение

Фикстура в ветке `experiment/bug-repros`: `test/repros/BUG-509/` со скриптом
`run.sh` (собирает `dist`, если его нет).

```js
// vitest.config.js
console.log('[dotenv@17.2.3] injecting env (1) from .env')

export default {
  test: { include: ['test/**/*.check.js'] },
}

// src/add.js
export function add(a, b) {
  return a + b
}

// test/add.check.js
import { expect, it } from 'vitest'

import { add } from '../src/add.js'

it('adds', () => {
  expect(add(2, 3)).toBe(5)
})
```

```bash
test/repros/BUG-509/run.sh   # выход 1 = воспроизведено
node ../../../bin/mootant.js run src --json 2>/dev/null | node -e 'JSON.parse(require("fs").readFileSync(0, "utf8"))'
```

## Ожидаемое поведение

С `--json` stdout содержит ровно один JSON-документ; всё остальное, что
пишется в stdout во время прогона, уходит в stderr (или в вывод тестов,
который показывается с `--verbose`).

## Фактическое поведение

```
mootant exit code: 0; first bytes of stdout: [dotenv@17.2.3] injecting env (1) from .env
{"summary":{"cov
REPRODUCED: stdout of --json is not JSON
```

С `vite-plugin-svelte` без конфига — три строки до JSON
(`analysis/data/cli/svelte-json-stdout.txt`).

## Подозреваемые места в коде

- `cli/run-mutation.ts:38-95` — на время `runMutants` при `json` можно
  перенаправить `process.stdout.write` (и тем самым `console.log/info/debug`) в
  stderr или в `onProgress` как вывод, вернуть перед печатью отчёта.
- `adapters/vitest/start-vitest-session.ts:91-117` — сейчас перехватывается
  только логгер Vitest.
- `cli/run-list.ts:17-46` — `list --json` загружает конфиг mootant, который
  тоже может печатать.

## Критерий готовности

- Тест в `test/cli/run-mutation.test.ts` (и `run-list.test.ts`): код, который
  во время прогона пишет в `process.stdout`, не попадает в stdout при `--json`
  (stdout — один валидный JSON), а его текст виден в stderr; падает до
  исправления, проходит после. `test/repros/BUG-509/run.sh` завершается с
  кодом 0.
- Без `--json` поведение текстового отчёта не меняется.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
