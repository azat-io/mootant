# BUG-104: switched-текст и JSON-отчёт растут квадратично с размером литерала

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.
>
> Перепроверено независимо: воспроизведено (репро-тест падает детерминированно:
> `expected 3359222 to be less than 415400`; switched-текст `entities.js`
> Svelte под `strict` — 92 100 466 символов, байт в байт как в анализе; при
> каждом удвоении литерала размеры растут в 4 раза); скептик: не опровергнуто,
> medium — в `run` последствия тяжелее заявленного (Vite не разбирает такой
> модуль, и Error получают все мутанты прогона), но для таблиц данных нужен
> включённый вручную `strict`, а под `recommended` квадрат дают только литералы
> из элементов без вложенных мутантов.

## Контекст

Mootant хостит мутанты текстом. Мутаторы `object-property` и `array-element`
удаляют один элемент литерала, но их мутант заменяет весь литерал: диапазон —
весь узел, текст замены — литерал без одного элемента
(`core/mutators/object-property.ts:17-24`,
`core/mutators/array-element.ts:55-59`,
`core/text/remove-list-element.ts:51-54`). Все удаления одного литерала
попадают в одну группу с ключом `kind:start:end`
(`core/instrument/group-mutant-ranges.ts:17-30`). Группа рендерится цепочкой
`(c1 ? (r1) : c2 ? (r2) : … (original))`, и каждый `ri` вставлен целиком
(`core/instrument/render-mutant-range.ts:91-95`; хост блока — `:85-89`). Для
литерала из N элементов switched-текст содержит N копий литерала, размер
O(N²). Бюджета размера нет ни в `instrumentFile`
(`core/instrument/instrument-file.ts:51-76`), ни в `createSwitchedFiles`
(`core/instrument/create-switched-files.ts:63-107`).

Тот же квадрат есть в JSON-отчётах, и чинится он отдельно: `mootant list`
switched-текст вообще не строит (`createSwitchedFiles` вызывается только из
`core/run-mutants.ts:390`). Обычный `--json` несёт у каждого мутанта `before` и
`after`, то есть строки, которых касается правка
(`cli/report/build-list-report.ts:76` → `cli/diff/get-diff-lines.ts:39-75`).
Предел в 80 символов (`MAX_CONTEXT_LENGTH`, `cli/diff/get-diff-lines.ts:16-20`)
режет только неизменённый текст снаружи правки на её первой и последней
строке, а строки внутри литерала остаются. Значит, литерал входит в каждый
мутант дважды. Поля `replacement` в обычном `--json` нет. `--verbose` добавляет
`original` и `replacement` (`cli/report/build-list-report.ts:60-61`), и копий
становится четыре. С `--skipped` пропущенные кандидаты печатаются с полными
`original` и `replacement` (`cli/report/build-list-report.ts:159-160`;
slim-форма их сохраняет, `cli/report/slim-list-report.ts:28-33`). Весь отчёт
сериализуется одним `JSON.stringify` (`cli/report/format-report.ts:19-20`), и
на таблице в 58 КБ `list --json --verbose --preset strict` падает с
`Invalid string length`.

В `mootant run` dry run хостит все pending-мутанты файлов прогона, выбранные или
нет (`core/run-mutants.ts:340-342,388-390`). Поэтому и `--mutant` платит полную
цену. Vitest-плагин отдаёт switched-текст как код модуля
(`adapters/vitest/create-mootant-plugin.ts:32-51`), а Vite 8 модуль такого
размера не разбирает. Тест-файлы не загружаются, и провал, не достигший ни
одного сайта, mootant списывает на все переключённые файлы
(`core/run/run-dry-phase.ts:505-517`, строка 516; это отдельная проблема).
Итог: Error у всех мутантов прогона, включая невиновные файлы, и exit 1.

Когда срабатывает. Под `recommended` правило solitary отбрасывает удаление
члена, внутри которого есть другой мутант
(`core/generate/generate-file-mutants.ts:257-259`;
`docs/content/mutators/object-property.md:37-44`,
`docs/content/mutators/array-element.md:42-49`). Поэтому для таблиц данных вида
`'x': 123` триггер — `strict`, где `coarseMutants: true`
(`core/presets/strict.ts:33`). Для элементов без вложенных мутантов
(идентификаторы, вызовы без аргументов, shorthand-свойства) квадрат есть и под
`recommended`. Реальный пример — компилятор Svelte,
`packages/svelte/src/compiler/phases/1-parse/utils/entities.js`: объект из 2231
записи, 41 289 байт. Из них 2125 ключей вида `'amp;': 38` и 106 ключей без `;`,
например `gt: 62`.

Документация о размере и памяти молчит: ни страницы мутаторов, ни раздел про
`coarseMutants` (`docs/content/guide/configuration.mdx:273-278`) об этом не
говорят. Описание `strict` упоминает лишь «noisier or more expensive mutations»
(`core/presets/strict.ts:31-32`). Против версии «так задумано» говорят места,
где авторы сами избегают такого роста:

- комментарий к `MAX_CONTEXT_LENGTH` (`cli/diff/get-diff-lines.ts:16-19`: «so a
  long line … does not repeat in every mutant»);
- `MAX_STEPS` (`core/generate/get-mutant-regions.ts:11-18`);
- skip-правило `large-alternation`
  (`core/regex/collect-pattern-changes.ts:16-20,109-124`);
- ключи-дайджесты в `core/identity/assign-mutant-ids.ts:10-13` («so a large
  literal is not kept once per candidate»).

Ветки `experiment/bug-repros` в публичном репозитории нет, файлы ниже создайте

### Шаг 1. Падающий юнит-тест на исходниках (сборка не нужна)

```bash

pnpm install

cat > test/repros/BUG-104.test.ts <<'EOF'
import { describe, expect, it } from 'vitest'

import { instrumentFile } from '../../core/instrument/instrument-file'
import { generateMutants } from '../helpers/generate-mutants'

describe('BUG-104: the switched text grows with the square of a literal', () => {
  it('keeps the switched text of a lookup table within a linear bound', () => {
    // A table like `packages/svelte/src/compiler/phases/1-parse/utils/entities.js`
    // in the Svelte compiler (2231 entries, 41 KB): under `strict` every
    // object-property mutant copies the whole literal minus one entry, so the
    // switched text of that file is 92 MB and `mootant list --json --verbose`
    // prints 419 MB for it.
    let entries = Array.from(
      { length: 400 },
      (_, index) => `  'entity${index};': ${index + 100},`,

    let mutants = generateMutants(source, { preset: 'strict', file })
    let switched = instrumentFile({ mutants, source, file })

    expect(
      mutants.filter(mutant => mutant.mutator === 'object-property').length,
    ).toBeGreaterThan(0)
    expect(switched.length).toBeLessThan(50 * source.length)
  })
})
EOF
pnpm exec vitest --run test/repros/BUG-104.test.ts
```

### Шаг 3. Таблица сущностей Svelte: отчёт и switched-текст

Файл берётся из Svelte на коммите `628098d2c662fabf4c1f3cf6564c6b20964ad9a8`:
на нём сняты цифры верификатора. Скрипт `switch-size.mjs` строит
switched-текст функцией `instrumentFile` собранного пакета по отчёту
`list --json --verbose`. Это внутренний модуль, он импортируется по пути. Скрипт
— упрощённая версия скрипта верификатора: та же загрузка `instrumentFile` и
тот же отбор pending-мутантов.

```bash
cd "$FIX"
curl -fsSL -o src/entities.js \
  https://raw.githubusercontent.com/sveltejs/svelte/628098d2c662fabf4c1f3cf6564c6b20964ad9a8/packages/svelte/src/compiler/phases/1-parse/utils/entities.js
wc -c src/entities.js            # 41289

cat > switch-size.mjs <<'EOF'
// Размер switched-текста файла по отчёту `mootant list --json --verbose`.
// Запуск из каталога фикстуры: node switch-size.mjs <report.json> <file>
import { readFileSync } from 'node:fs'
import { resolve } from 'node:path'
import { pathToFileURL } from 'node:url'

let dist = resolve(import.meta.dirname, 'node_modules/mootant/dist')
let { instrumentFile } = await import(
  pathToFileURL(`${dist}/core/instrument/instrument-file.js`).href
)
let [reportPath, file] = process.argv.slice(2)
let report = JSON.parse(readFileSync(reportPath, 'utf8'))
let source = readFileSync(file, 'utf8')
let mutants = report.mutants.filter(mutant => mutant.status === 'Pending')
let counts = {}
for (let mutant of mutants) {
  counts[mutant.mutator] = (counts[mutant.mutator] ?? 0) + 1
}
let switched = instrumentFile({ mutants, source, file })
console.log(
  JSON.stringify({
    sourceLength: source.length,
    pending: mutants.length,
    counts,
    switchedLength: switched.length,
    ratio: Number((switched.length / source.length).toFixed(1)),
  }),
)
EOF

npx mootant list src/entities.js --json --preset strict | wc -c
npx mootant list src/entities.js --json --verbose --preset strict > strict.json
wc -c strict.json
node switch-size.mjs strict.json src/entities.js
npx mootant list src/entities.js --json --verbose | wc -c              # recommended
npx mootant list src/entities.js --json --verbose --skipped | wc -c    # recommended
```

### Шаг 4. Тот же рост под `recommended` и падение `--verbose`

`calls.js` — 1000 функций и однострочный массив их вызовов. У вызова `fnN()`
нет вложенных мутантов, поэтому solitary удаления не отбрасывает. Генератор
повторяет генератор верификатора (форма с однострочным массивом), его файл —
40 690 байт. `table-2600.js` — таблица того же вида, что в шаге 1, из 2600
записей.

```bash
cd "$FIX"
cat > gen-calls.mjs <<'EOF'
import { writeFileSync } from 'node:fs'

let names = Array.from({ length: 1000 }, (_, index) => `fn${index}`)
let lines = names.map((name, index) => `function ${name}() { return ${index} }`)
lines.push(`export let calls = [${names.map(name => `${name}()`).join(', ')}]`)
writeFileSync(process.argv[2], lines.join('\n') + '\n')
EOF
cat > gen-table.mjs <<'EOF'
import { writeFileSync } from 'node:fs'

let count = Number(process.argv[2])
let entries = Array.from(
  { length: count },
  (_, index) => `  'entity${index};': ${index + 100},`,
)
writeFileSync(process.argv[3], ['export default {', ...entries, '}', ''].join('\n'))
EOF

node gen-calls.mjs src/calls.js
wc -c src/calls.js                                              # 40690
npx mootant list src/calls.js --json --verbose > calls.json     # recommended
wc -c calls.json
node switch-size.mjs calls.json src/calls.js

node gen-table.mjs 2600 src/table-2600.js                       # около 58 КБ
npx mootant list src/table-2600.js --json --verbose --preset strict > /dev/null
echo "exit $?"
```

### Шаг 5. `mootant run`: Vite не загружает модуль

Проект скептика: `decode.js` читает таблицу, а `price.js` от неё не зависит. В
тесте `nbsp;` ожидается U+00A0 (неразрывный пробел), поэтому ожидание записано
как `String.fromCodePoint(160)`.

```bash
RUN="$(mktemp -d)"
mkdir -p "$RUN/src" "$RUN/test"
cp "$FIX/src/entities.js" "$RUN/src/"
cd "$RUN"
cat > package.json <<'EOF'
{ "name": "bug-104-run", "private": true, "type": "module", "scripts": { "test": "vitest run" } }
EOF
cat > vitest.config.js <<'EOF'
import { defineConfig } from 'vitest/config'
export default defineConfig({ test: { include: ['test/**/*.test.js'] } })
EOF
cat > src/decode.js <<'EOF'
import entities from './entities.js'

export function decode(name) {
  let code = entities[name]
  return code === undefined ? null : String.fromCodePoint(code)
}
EOF
cat > src/price.js <<'EOF'
export function total(items, discount) {
  let sum = 0
  for (let item of items) {
    sum += item.price * item.quantity
  }
  if (sum >= 100) {
    sum -= discount
  }
  return sum
}
EOF
cat > test/decode.test.js <<'EOF'
import { expect, it } from 'vitest'

import { decode } from '../src/decode.js'

it('decodes a few entities', () => {
  expect(decode('amp;')).toBe('&')
  expect(decode('lt;')).toBe('<')
  expect(decode('nbsp;')).toBe(String.fromCodePoint(160))
  expect(decode('nope;')).toBe(null)
})
EOF
cat > test/price.test.js <<'EOF'
import { expect, it } from 'vitest'

import { total } from '../src/price.js'

it('sums items', () => {
  expect(total([{ price: 10, quantity: 2 }], 5)).toBe(20)
})

it('applies the discount from 100', () => {
  expect(total([{ price: 50, quantity: 2 }], 5)).toBe(95)
  expect(total([{ price: 99, quantity: 1 }], 5)).toBe(99)
})
EOF
npm i -D vitest@5 "$TGZ"
npx vitest run                   # 3 passed
```

A/B на двух мутантах: `sum >= 100` → `sum > 100` (`src/price.js:6`) и
`'amp;': 38` → `39` (`src/entities.js:2006`). У скептика у них были id
`dfeha23k21p9` и `45tjb3z83043`. Id детерминированы при тех же путях и текстах
(`core/identity/create-mutant-id.ts:61-72`). Если `--mutant` их не найдёт,
возьмите id из вывода `npx mootant list src/price.js src/entities.js`.

```bash
cd "$RUN"
npx mootant run src --mutant dfeha23k21p9 --mutant 45tjb3z83043; echo "exit $?"
npx mootant run src --preset strict --mutant dfeha23k21p9 --mutant 45tjb3z83043; echo "exit $?"

# strict без object-property: `--preset` заменяет только `extends`, а `mutators`
# конфига действуют (docs/content/guide/configuration.mdx:152-153,161-176).
# Конфиг восстановлен по документации: у скептика его текст не сохранился.
cat > mootant.config.js <<'EOF'
export default {
  mutators: { 'object-property': 'off' },
}
EOF
npx mootant run src --preset strict --mutant dfeha23k21p9 --mutant 45tjb3z83043; echo "exit $?"
rm mootant.config.js

# необязательно, около 3 минут: весь src под strict
npx mootant run src --preset strict; echo "exit $?"
```

## Ожидаемое поведение

- Switched-текст растёт линейно с размером литерала. Для таблицы шага 1 он
  короче `50 × source.length`, для `entities.js` под `strict` — не больше
  2 064 450 символов (50 × 41 289). Vite разбирает такой модуль, `mootant run`
  под `strict` выносит вердикты мутантам этого файла, и невиновные файлы не
  получают Error.
- JSON-отчёты `list` (обычный, `--verbose`, `--skipped`) растут линейно. Мутант
  удаления элемента несёт строки удаляемого элемента, а не весь литерал.
  `list --json --verbose` не падает с `Invalid string length`. Отчёт
  `run --json` строится тем же кодом и должен вести себя так же.
- Если Mootant решает часть таких мутантов не создавать, это skip с правилом и
  причиной, видимый в `list --skipped` (как `large-alternation` у
  regex-pattern), и тексты пропущенных кандидатов тоже ограничены.
- Switched-текст с активным мутантом ведёт себя так же, как физически
  применённый мутант. Сейчас это проверяет дифференциальный тест.

## Фактическое поведение

Шаг 1. Результат детерминирован и от нагрузки не зависит:

```
AssertionError: expected 3359222 to be less than 415400
```

Первая проверка (мутанты `object-property` есть) проходит. Падает граница 50×:
switched-текст в 404 раза длиннее исходника.

Рост на таблице шага 1 (`--preset strict`, упакованный mootant, Vitest 5.1.0).
Размеры JSON зависят от длины пути файла, отношения от неё не зависят:

| N записей | Исходник, байт | Switched, символов | `list --json` | `list --json --verbose` |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 2 008 | 209 822 (×104) | 477 584 | 929 012 |
| 200 | 4 108 | 839 622 (×204) | 1 875 184 | 3 655 312 |
| 400 | 8 308 | 3 359 222 (×404) | 7 430 384 | 14 507 912 |
| 800 | 16 708 | 13 438 422 (×804) | 29 580 786 | 57 814 555 |
| 1600 | 34 808 | 55 837 523 (×1604) | 122 206 689 | 239 154 764 |

Под `recommended` при N = 400 остаются только 400 мутантов `number-literal`, и
рост ×3,7. Время текстового `list --preset strict` тоже квадратично: 6, 25, 109
и 312 с при N = 400, 800, 1600 и 2600.

Шаг 3, `entities.js`:

- `strict`: 4462 мутанта (2231 `object-property` и 2231 `number-literal`).
  Switched-текст — 92 100 466 символов (×2230,6). `list --json` — около
  214 МБ. `list --json --verbose` — 418 959 825 байт с путём
  `packages/svelte/src/compiler/phases/1-parse/utils/entities.js`. С путём
  `src/entities.js` он короче на 4463 × 46 байт: путь стоит в каждом из 4462
  мутантов и в списке файлов. Первоначальный замер дал 418 754 527 байт.
  `list` идёт 36–56 с, пик RSS процесса `mootant list` — 1,4–1,9 ГБ. В
  первоначальном замере было 3,9 ГБ, но это RSS измерительного скрипта: он
  держал в памяти JSON, switched-текст и вывод oxc. `transformWithOxc`
  switched-текста (Vite 8.3.5) занимает 7–9 с под именем `.js` и 10–13 с под
  `.ts` (первоначальный замер шёл под `.ts`), на исходнике — 3 мс.
- `recommended`: только 2231 `number-literal`, удаления отброшены правилом
  `solitary`. `--json --verbose` весит около 0,9 МБ (926 003 байта), но с
  `--skipped` — 205 517 767 байт.
- Весь `packages/svelte/src` под `strict`: 380 файлов, 49 518 мутантов.

Направления исправления. Это выводы по чтению кода, ни одно направление
запуском не проверено:

1. Хостить удаление на уровне элемента: `{ a, ...(check ? {} : { b: 1 }), c }`
   сохраняет порядок ключей, для массива — `[a, ...(check ? [] : [b]), c]`.
   Для части членов это не эквивалентно:
   - spread копирует значение геттера в момент создания объекта, а не
     определяет аксессор; свойство с одним сеттером станет данными со
     значением `undefined`;
   - у метода с `super` HomeObject станет внутренний литерал;
   - `__proto__: x` во внутреннем литерале задаёт прототип внутреннего объекта,
     и spread его не переносит;
   - spread массива вызывает итератор массива
     (`Array.prototype[Symbol.iterator]`), а литерал без spread — нет.

   Это чинит switched-текст, но не `list`.
2. Сузить сам мутант до удаляемого элемента. Тогда линейны и switched-текст, и
   все отчёты. Но нужен новый вид хостинга с новым `kind` в типах, JSON и
   `apply-mutant.ts`, и id этих двух мутаторов сменятся.
3. Сохранить модель мутанта и id, а в отчётах показывать удаляемый элемент:
   например, задать `focus` и строить `before`/`after` по нему. Обычный `--json`
   станет линейным. `--verbose` и `--skipped` останутся квадратичными, пока в
   них печатаются полные тексты, так что для них нужно менять формат.
4. Пропускать удаления в литералах больше K элементов со skip-правилом и
   причиной. Но `--skipped` всё равно печатает полные тексты, и их тоже надо
   укоротить. Кроме того, первая проверка теста шага 1 перестанет выполняться.
   Граница 50× в этом тесте означает, что K должен быть не больше примерно 50:
   switched-текст литерала растёт как K × его размер.
5. Бюджет размера switched-текста на файл действует только в `run`. Отчёт
   `list` он не меняет, а мутанты сверх бюджета получат Error или skip.

Критерий ниже требует линейности и switched-текста, и всех JSON-отчётов. Для
этого нужно одно из двух: сменить id `object-property` и `array-element`
(путь 2) или изменить формат отчёта (пути 3 и 4). В этой задаче разрешено и то,
и другое (см. «Ограничения»).
