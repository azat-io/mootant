# BUG-304: R6 считает константы `return ok` поглощёнными мутантом инициализатора, хотя `ok` читается ещё где-то

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Для булева возвращаемого значения `return-value` выдаёт `true` и `false`, но
пропускает константу по правилу `R6` (категория `subsumed`,
`heuristic: false`, `core/skips/skip-rules.ts:322-325`), если работающий мутант
«двигает» к ней результат или **значение, присвоенное локальной переменной**
(`core/mutators/return-value.ts:202-239`, источники —
`getAssignedValues`, `core/mutators/return-value.ts:508-517`). Субсумпция
`kill(владелец) ⊆ kill(константа)` верна, только если владелец наблюдаем через
этот `return`. Если переменная читается ещё где-то (ветка, вызов), тест убивает
мутант инициализатора через это чтение и не проверяет возвращаемое значение —
константа выжила бы, но её нет в отчёте. В отличие от `solitary`, правило
заявлено как доказательное, и его не возвращает `strict`/`coarseMutants`
(только отключение мутатора-владельца,
`docs/content/mutators/return-value.md:180-183`).

## Воспроизведение

Падающий тест — `test/repros/BUG-304.test.ts` в ветке `experiment/bug-repros`:

```ts
import { describe, expect, it } from 'vitest'

import { listMutantTexts } from '../helpers/list-mutant-texts'
import { listSkipped } from '../helpers/list-skipped'

let validate = [
  'export function validate(input, report) {',
  '  let ok = input.length > 2 && input.length < 10',
  '  if (!ok) {',
  "    report('invalid')",
  '  }',
  '  return ok',
  '}',
]

describe('BUG-304: R6 takes a mutant of a local read elsewhere for a subsumer of the returned constants', () => {
  it('keeps the constants of a returned local that a branch also reads', () => {
    expect(
      listMutantTexts('return-value', validate, { file: 'example.js' }),
    ).toStrictEqual(['ok -> true', 'ok -> false'])
  })

  it('does not skip the constants as subsumed', () => {
    expect(
      listSkipped('return-value', validate.join('\n'), { file: 'example.js' }),
    ).toStrictEqual([])
  })
})
```

Сквозная проверка (фикстура `analysis/data/skips/fx1`, `src/validate.js`,
`test/validate.test.js` — шесть входов, проверяются только вызовы `report`):

```bash
npx mootant run src/validate.js --no-cache   # killed 9, score 100%
# физически заменить `return ok` на `return true` (и на `return false`):
npx vitest --run test/validate.test.js        # оба раза проходит — мутанты выжили
```

## Ожидаемое поведение

Значения, присвоенные локальной переменной, учитываются в `R6`, только если
переменная читается лишь в этом `return` (иначе владелец может убиваться через
другое чтение). В примере выводятся `ok -> true` и `ok -> false`.

## Фактическое поведение

```
return-value 'ok' -> 'true'  [R6/subsumed] by comparison-operator@2:12
  it makes the result true, as comparison-operator does on some inputs
return-value 'ok' -> 'false' [R6/subsumed] by comparison-operator@2:12
```

## Подозреваемые места в коде

- `core/mutators/return-value.ts:219-237` — цикл по `sources` с
  инициализатором и записями.
- `core/mutators/return-value.ts:508-517` (`getAssignedValues`) и
  `core/mutators/return-value.ts:349-365` (`getLocalRanges`) — нет проверки
  других чтений переменной (у `Binding` есть `references`). Та же причина у
  BUG-301 (`solitary`), исправлять лучше одним предикатом «единственное чтение —
  этот return».
