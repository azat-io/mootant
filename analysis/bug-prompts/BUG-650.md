# BUG-650: пункт меню «Agent skill» на сайте ведёт на несуществующую страницу

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Сайт документации собирается Astro из `docs/` (`astro.config.ts`: `srcDir:
'./docs'`, `root: './docs'`). В главном меню на каждой странице четыре пункта
(`docs/components/Header.astro:11-16`), последний — `{ href: '/agent-skill',
title: 'Agent skill' }`. Маршрута `/agent-skill` нет: в `docs/pages/` есть
только `index.astro`, `404.astro`, `mutators/index.astro`,
`mutators/[slug]/index.astro`, `guide/[slug]/index.astro` (страницы из
`docs/content/guide/*.mdx`: `cli`, `compatibility`, `configuration`,
`getting-started`, `report`) и `search-index.json.ts`; в
`docs/public/_redirects` только редирект с `mootant.netlify.app`. Пункт меню
о главном отличии проекта ведёт на 404. Сам skill пока тоже отсутствует (см.
BUG-651).

## Воспроизведение

```bash
grep -rn "agent-skill" docs          # одна ссылка: docs/components/Header.astro:15
find docs/pages -type f              # нет agent-skill
ls docs/content/guide                # нет agent-skill.mdx
cat docs/public/_redirects           # нет редиректа
pnpm docs:build && ls docs/dist | grep -i agent   # (если собирать) — страницы нет
```

## Ожидаемое поведение

Пункт меню ведёт на существующую страницу про skill: как установить (`npx
skills add azat-io/mootant --skill mootant`), что делает skill, пример сессии
(`docs/components/skill-session.ansi`), ограничения (раннеры, требование
зелёных тестов, что агент не меняет исходники).

## Фактическое поведение

Ссылка `/agent-skill` → 404.

## Подозреваемые места в коде

- `docs/components/Header.astro:15` — ссылка.
- `docs/pages/` — нужен маршрут (`docs/pages/agent-skill.astro` или запись в
  коллекции контента и шаблон), либо временно ссылка на
  `/guide/getting-started#let-an-agent-fix-them`.
- `docs/components/Skill.astro` и `skill-session.ansi` — готовые блоки для
  страницы.

## Критерий готовности

- После `pnpm docs:build` в выходном каталоге есть страница, на которую
  ведёт пункт меню (или пункт ведёт на существующий якорь).
- Появляется проверка ссылок меню: тест (например, рядом с другими тестами
  документации, если они есть, или скрипт в `test:astro`), который берёт
  `href` из `links` в `Header.astro` и проверяет, что для каждого есть
  маршрут в `docs/pages` или страница в `docs/content`.
- `pnpm test` полностью зелёный (`test:astro`, `test:css`, `test:format`,
  `test:spelling` проверяют и документацию).

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, строгий ESLint (`@azat-io/eslint-config`),
  `@azat-io/stylelint-config` для `.astro`, cspell, knip.
- Тексты на сайте — английские, в стиле существующих страниц (коротко,
  конкретно).
- Не обещай на странице того, чего ещё нет: если skill (BUG-651) не готов,
  временно веди пункт меню на раздел getting-started.
- Сообщения коммитов — Conventional Commits (commitlint).
