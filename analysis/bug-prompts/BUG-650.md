# BUG-650: пункт меню «Agent skill» на сайте ведёт на несуществующую страницу

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: low (в анализе была medium). Статус:
> подтверждён. Найдено на коммите 170ec52.
>
> Перепроверено независимо: воспроизведено — `pnpm docs:build` на дереве
> 170ec52 (exit 0) не создаёт `/agent-skill`, ссылка стоит на 27 из 29
> HTML-страниц сборки и остаётся единственной битой внутренней ссылкой сайта,
> `astro preview` отдаёт на неё 404; скептик: не опроверг, но снизил до low —
> дефект только в навигации сайта (на CLI, вердикты и score не влияет),
> команда установки и пример сессии есть на главной и в getting-started, а
> настоящий вред — отсутствующий skill (BUG-651).

## Контекст

Сайт документации `https://mootant.org` (`astro.config.ts:24`) собирает Astro
из `docs/`: `srcDir: './docs'`, `root: './docs'` (`astro.config.ts:88-89`),
`build.format: 'file'` (`astro.config.ts:76`), так что маршрут
`docs/pages/x.astro` выходит файлом `x.html`. Сборка пишется в `./dist` в
корне репозитория, а не в `docs/dist`: в логе сборки «sitemap-index.xml
created at `dist`», деплой берёт `publish-dir: './dist'`
(`.github/workflows/docs.yml:42`). Сайт собирается и выкладывается на Netlify
при каждом push в `main` (`docs.yml:3-6`, `:36-42`).

В главном меню четыре пункта (`docs/components/Header.astro:11-16`), последний
— `{ href: '/agent-skill', title: 'Agent skill' }` (`Header.astro:15`).
`Header` стоит в обоих лейаутах с шапкой: `docs/layouts/Home.astro:24`
(главная) и `docs/layouts/Content.astro:38` (страницы guide и мутаторов).
Маршрута `/agent-skill` нет:

- в `docs/pages/` только `index.astro`, `404.astro`, `mutators/index.astro`,
  `mutators/[slug]/index.astro`, `guide/[slug]/index.astro` и
  `search-index.json.ts`. Динамические маршруты вложены в `/guide` и
  `/mutators` и `/agent-skill` не ловят. `guide/[slug]` строит страницы из
  коллекции `guide` (`docs/pages/guide/[slug]/index.astro:14-22`,
  `docs/content.config.ts:6-16`), то есть из `docs/content/guide/*.mdx`:
  `cli`, `compatibility`, `configuration`, `getting-started`, `report`;
- в `astro.config.ts:26-91` нет ключа `redirects`;
- в `docs/public/_redirects:1` только редирект `mootant.netlify.app` →
  `mootant.org`;
- единственная интеграция со своей страницей, `reportDemo`, пишет только
  `report/demo.html` (`docs/plugins/report-demo.ts:122-125`).

Ссылка есть на 27 из 29 HTML-страниц сборки: главная, 5 страниц guide,
`/mutators` и 20 страниц мутаторов. Её нет только в `404.html` (лейаут
`docs/layouts/Blank.astro` без шапки) и в `report/demo.html` (HTML-отчёт CLI).
На ширине меньше 800px на страницах с лейаутом `Content` ссылки меню скрыты:
`Content.astro:38-43` кладёт боковое меню в слот `navigation`, и список
получает класс `desktop-only` (`Header.astro:20`, `:40`, `:231-235`). Поэтому
на мобильных пункт виден только на главной.

Пункт посвящён главному отличию проекта, но и самого skill пока нет: в 170ec52
нет ни одного `SKILL.md` и каталога `skills/` (это BUG-651). При этом главная
(`docs/components/Skill.astro:22-46`, `docs/components/Hero.astro:30`) и
раздел «Let an agent fix them» (`docs/content/guide/getting-started.mdx:136-145`)
пишут, что skill уже в комплекте, и дают команду установки
`npx skills add azat-io/mootant` (`Skill.astro:39`, `getting-started.mdx:142`)
и пример сессии `docs/components/skill-session.ansi`. Пункт без страницы
появился в коммите 6d85816 («docs: add internal pages»): он перевёл меню с
`/docs/*` на нынешние адреса.

Сайт `mootant.org` из песочницы анализа открыть не удалось (прокси отвечал
403), поэтому поведение проверено на локальной сборке. По данным скептика,
прогон `Docs` для 170ec52 прошёл успешно, а upstream `main` в момент анализа
стоял на 170ec52. Значит, на публичном сайте, по всей видимости, та же 404
(напрямую не проверено).

## Воспроизведение

Теста-воспроизведения в ветке `experiment/bug-repros` для этого бага нет. Баг
виден статически (шаг 1), а сборка (шаги 2–3) подтверждает его на выходе.

Собирать пакет mootant и ставить его в фикстуру (`pnpm build` + `pnpm pack`,
установка tarball, `npm i -D vitest@5`) для этого бага не нужно: он только в
сайте. `pnpm docs:build` сам собирает CLI (`vite build`) и прогоняет
`bin/mootant.js run --html` на `docs/demo` в хуке `astro:build:start`
(`docs/plugins/report-demo.ts:126-128`, `:142-155`).

Шаг 0. Клон. На свежем `main` сначала проверь, не исправлено ли уже:
`grep -n agent-skill docs/components/Header.astro`, `ls docs/pages`.

```bash
git clone https://github.com/azat-io/mootant.git
cd mootant
git checkout 170ec52    # исследуемый коммит
```

Шаг 1. Статически, до установки зависимостей:

```bash
grep -rn "agent-skill" docs

# docs/pages/index.astro:12:    'agent-skills',
#   ^ вторая строка — ключевое слово главной (keywords), не ссылка
find docs/pages -type f | sort
# docs/pages/404.astro
# docs/pages/guide/[slug]/index.astro
# docs/pages/index.astro
# docs/pages/mutators/[slug]/index.astro
# docs/pages/mutators/index.astro
# docs/pages/search-index.json.ts
ls docs/content/guide
# cli.mdx  compatibility.mdx  configuration.mdx  getting-started.mdx  report.mdx
cat docs/public/_redirects
# https://mootant.netlify.app/* https://mootant.org/:splat 301!
grep -c redirects astro.config.ts                     # 0: редиректов Astro нет
find . -name SKILL.md -not -path '*/node_modules/*'   # пусто: skill ещё нет (BUG-651)
```

Шаг 2. Сборка сайта. Нужен pnpm 12, как в CI
(`.github/actions/install-tools/action.yml:14`: `version: latest-12`; Node там
24, `:9`), например `npm i -g pnpm@12`. pnpm 10 не читает `configDependencies`
из `pnpm-workspace.yaml:1-2` и, по данным базовой линии анализа, зависает уже
на `pnpm --version` внутри репозитория.

```bash
pnpm --version                                    # 12.x
pnpm install --frozen-lockfile --ignore-scripts   # так ставит CI
pnpm exec astro sync                              # так CI готовит типы перед проверками
pnpm docs:build         # exit 0, «28 page(s) built»; ~2–2,5 мин на машине анализа
ls dist | grep -i agent                           # пусто (exit 1): страницы нет
grep -rl 'href="/agent-skill"' dist --include='*.html' | wc -l
# 27 — все страницы с шапкой (число — по данным перепроверки)
grep -o 'id="let-an-agent-fix-them"' dist/guide/getting-started.html
# id="let-an-agent-fix-them" — якорь запасного варианта (см. ниже) существует
```

Смотри в `dist/`, а не в `docs/dist`. Каталога `docs/dist` нет, и
`ls docs/dist | grep -i agent` «подтвердит» баг по неверной причине. Тот же
`dist/` использует `vite build` пакета (`pnpm build`).

Шаг 3. Как отдаёт сервер. В отдельном терминале запусти
`pnpm exec astro preview --port 4321`, затем:

```bash
for p in /agent-skill /agent-skill/ /guide/getting-started /mutators; do
  printf '%s ' "$p"
  curl -s -o /dev/null -w '%{http_code}\n' "http://localhost:4321$p"
done
```

Команды шагов 2–3 в точно таком виде при подготовке промпта не запускались.
Ожидаемые значения взяты из перепроверки. Она ставила зависимости командой
`pnpm install --frozen-lockfile` без `--ignore-scripts` (с этим флагом, как в
шаге 2, ставит CI, и сборка сайта в CI для 170ec52 прошла), собирала сайт
`pnpm docs:build`, считала ссылки в `dist/` своим скриптом и опрашивала
`pnpm exec astro preview` через `curl`.

## Ожидаемое поведение

Пункт меню «Agent skill» ведёт на существующую цель. Какую именно, зависит от
того, есть ли уже skill (проверка:
`find . -name SKILL.md -not -path '*/node_modules/*'`).

- Skill нет. Так в 170ec52, и сейчас ожидается именно это исправление: пункт
  временно ведёт на раздел «Let an agent fix them»,
  `{ href: '/guide/getting-started#let-an-agent-fix-them', title: 'Agent skill' }`.
  Заголовок стоит в `docs/content/guide/getting-started.mdx:136`, id
  `let-an-agent-fix-them` в собранной `dist/guide/getting-started.html` есть.
  Допустимая альтернатива (её тоже предлагал анализ) — убрать пункт из меню до
  появления skill.
- Skill уже есть (BUG-651 исправлен, например появился
  `skills/mootant/SKILL.md`). Тогда нужна отдельная страница про skill, и
  пункт ведёт на неё. На странице: как установить; что делает skill; пример
  сессии (`docs/components/skill-session.ansi`, готовые блоки —
  `docs/components/Skill.astro:38-46`); ограничения — только те, что
  действительно описаны в `SKILL.md` (например, поддерживаемые раннеры,
  требование зелёных тестов, что агент не меняет исходники). Команда
  установки — как в документации: `npx skills add azat-io/mootant`
  (`Skill.astro:39`, `getting-started.mdx:142`). В прежней версии этого
  промпта стояло `--skill mootant`, но это предложение анализа, а не текущая
  документация. Если вводишь флаг, меняй команду во всех местах сразу.

## Критерий готовности

- Пункт «Agent skill» в `docs/components/Header.astro` ведёт на существующую
  цель по правилу из «Ожидаемого поведения». Пока в репозитории нет
  `SKILL.md` (как в 170ec52), это `/guide/getting-started#let-an-agent-fix-them`
  или пункт убран из `links`. Если skill уже есть — новая страница про него.
- Появляется Vitest-тест на ссылки меню, который падает на 170ec52 (на
  `/agent-skill`) и проходит после исправления. Тест кладётся по пути
  проверяемого файла (правило `contributing.md:191-192`), например
  `test/docs/components/header.test.ts`. Если вынесешь массив `links` в
  `docs/utils/<имя>.ts` (как `pages` в `docs/utils/pages.ts`), то тест —
  `test/docs/utils/<имя>.test.ts`. Сайт тест не собирает (`pnpm docs:build`
  идёт минуты и пересобирает CLI), а проверяет исходники:
  - берёт все `href` из `links`: читает `Header.astro` как текст или
    импортирует вынесенный массив. Модули, которые импортируют
    `astro:content` (как `docs/utils/pages.ts:1`), в Vitest проекта, скорее
    всего, не загрузятся, потому что в `vitest.config.ts` нет плагинов Astro
    (не проверено);
  - отбрасывает `#фрагмент` и ищет исходник страницы по правилам: `/` →
    `docs/pages/index.astro`; `/guide/<id>` → `docs/content/guide/<id>.mdx`;
    `/mutators` → `docs/pages/mutators/index.astro`; `/mutators/<id>` →
    `docs/content/mutators/<id>.md`; любой другой `/<путь>` →
    `docs/pages/<путь>.astro`, `.md`, `.mdx` или
    `docs/pages/<путь>/index.astro`;
  - желательно: для ссылки с `#фрагментом` проверяет, что на странице есть
    заголовок с таким id (`## Let an agent fix them` →
    `let-an-agent-fix-them`).

  Отдельно тест запускается командой `pnpm exec vitest --run <путь>`, без
  `--coverage`: пороги покрытия рассчитаны на полный прогон.
- Ручная проверка сборки: `rm -rf dist && pnpm docs:build` завершается с кодом
  0, и:
  - при варианте с якорем `grep -rl 'href="/agent-skill"' dist --include='*.html'`
    ничего не находит,
    `grep -o 'href="/guide/getting-started#let-an-agent-fix-them"' dist/index.html`
    находит ссылку, а
    `grep -o 'id="let-an-agent-fix-them"' dist/guide/getting-started.html`
    печатает id;
  - при варианте со страницей есть `dist/agent-skill.html` (или
    `dist/guide/agent-skill.html`), и шаг 3 «Воспроизведения» отдаёт на её
    адрес 200.
- Каждый скрипт по отдельности зелёный (почему не одним `pnpm test` — см.
  «Ограничения»): `pnpm test:astro` (после `rm -rf dist`), `pnpm test:css`,
  `pnpm test:format`, `pnpm test:spelling` (они проверяют и `docs/`), а также
  `pnpm test:js`, `pnpm test:types`, `pnpm test:usage`, `pnpm test:packages`,
  `pnpm test:unit`.

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), `@azat-io/stylelint-config` для
  `.astro` (`stylelint.config.ts`), Prettier для `.astro`, `.mdx` и `.ts`
  (`package.json:70`), cspell, knip.
- Тексты на сайте — английские, в стиле существующих страниц (коротко,
  конкретно).
- Не обещай на странице того, чего ещё нет: если skill (BUG-651) не готов,
  веди пункт меню на раздел getting-started. Обещания про skill на главной и в
  getting-started — предмет BUG-651, в этом исправлении их не меняй.
- Проверку ссылок не встраивай в `test:astro`: это `astro check`
  (`package.json:68`), то есть проверка типов. Других тестов сайта в `test/`
  нет: там только `adapters`, `cli`, `core`, `fixtures` и `helpers`, а
  `docs/demo/**` — демо-проект, исключённый из Vitest (`vitest.config.ts:18`).
  Пороги покрытия 100% действуют только на `adapters/**`, `cli/**` и
  `core/**` (`vitest.config.ts:9-15`), так что код и тесты сайта на покрытие
  не влияют.
- Теста-воспроизведения из анализа для этого бага нет. Если по образцу других
  багов захочется положить проверку в `test/repros/`, так нельзя: этот каталог
  не исключён ни из ESLint, ни из knip, cspell или tsc. Исключён только
  `test/fixtures/**` (`eslint.config.ts:15`, `knip.config.ts:5`,
  `cspell.config.ts:44`, `vitest.config.ts:18`, `tsconfig.json:2`). Тест пиши
  в стиле проекта под строгий ESLint: имя файла в kebab-case, как у остальных
  тестов, `describe`/`it`, порядок импортов, JSDoc у констант и функций
  (пример — `test/cli/parse-arguments.test.ts`). Фикстуры, если понадобятся,
  клади в `test/fixtures/**`.
- `pnpm test` после `pnpm build` даёт ложные ошибки `test:astro`: 14 ошибок
  `ts(2322)` в `docs/components/*.astro` (по данным базовой линии анализа).
  Причина: `tsconfig.json:2-4` включает `**/*.ts` и не исключает `dist/`. После
  сборки в программу попадает `dist/types/html/inline-script.d.ts` (копия
  `types/html/inline-script.d.ts`) с `/// <reference types="vite/client" />`,
  и объявления `*.svg` из Vite конфликтуют с SVG-компонентами Astro. В CI
  джоба Astro пакет не собирает, поэтому там она зелёная. `pnpm docs:build`
  тоже пишет в `dist/` и внутри себя вызывает `vite build`. Как собранный сайт
  влияет на `test:astro`, не проверено. Поэтому `test:unit`, `test:js`,
  `test:types` и остальные скрипты проверяй по отдельности, а `test:astro`
  запускай после `rm -rf dist`.
- Известные зависимости `test:unit` от окружения, не связанные с этим багом:
  - 4 теста ждут Unicode-символы и падают при `TERM=linux`
    (`cli/terminal/is-unicode-supported.ts:13`):
    `test/cli/run-list.test.ts:160,180` и
    `test/cli/run-mutation.test.ts:127,194`. Запускай с
    `TERM=xterm-256color`;
  - тест «skips test files it cannot read»
    (`test/adapters/node-test/score-node-test.test.ts:98`) падает под root;
  - при заданном `NODE_OPTIONS` покрытие ветвей не достигает 100% в
    `adapters/node-test/start-node-test-session.ts:119,167`. Запускай с
    `env -u NODE_OPTIONS`.
- Сообщения коммитов — Conventional Commits (commitlint): правка сайта —
  `docs:`, тест — `test:` (`contributing.md:81`, `:84`).
