# BUG-106: регулярное выражение, начинающееся с `<!--`, ломает switched-модуль в Vite 8

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Mootant хостит мутанты в switched-тексте файла: выражение становится
`(check ? (replacement) : (original))`, и каждая ветка всегда берётся в скобки
(`core/instrument/render-mutant-range.ts:91-95`). Vite 8 (rolldown) и Vitest 5
на нём разбирают модули парсером oxc с `sourceType: 'unambiguous'`. В oxc
(проверено 0.156.0 — версия в зависимостях Mootant и Vite 8.3.5/rolldown
1.2.16 — и 0.157.0, последняя на 2026-11-04) есть ошибка лексера: в модуле
(файле с `import`/`export`) скобка, за которой сразу идёт литерал регулярного
выражения, начинающийся с `<!--`, даёт ошибку разбора «HTML comments are not
allowed in modules»:

```text
const a = (/<!--x/g)\nexport {}           -> ERR   (unambiguous)
const a = (c ? (/<!--x/g) : 1)\nexport {} -> ERR
const a = /<!--x/g\nexport {}             -> ok
f(/<!--x/g)\nexport {}                    -> ok
const a = (0, /<!--x/g)\nexport {}        -> ok
const a = (c ? /<!--x/g : 1)\nexport {}   -> ok
const a = (/<!--x/g)\nexport {}  (module) -> ok
```

Исходный код обычно такой конструкции не содержит (`html.replace(/<!--…-->/g, '')`
— аргумент вызова, разбирается нормально), но switched-текст создаёт её для
каждого мутанта, чей диапазон или replacement начинается с такого литерала:
`regex-flag`/`regex-pattern` по регулярному выражению для HTML-комментариев, а
также replacement `regex-pattern`, который удаляет первую альтернативу
(`/^(?:-?>)+|<!--|…/` → `/<!--|…/`, так в `packages/shared/src/escapeHtml.ts`
vuejs/core). Модуль не трансформируется, тест-файлы падают при загрузке в
instrumented dry run, все мутанты файла получают `Error` с диагностикой
`instrumentation-break` («Tests fail with the switched … and pass without
it»); при пустом покрытии упавших тестов срабатывает ещё и BUG-100 — тогда
выбрасываются все файлы прогона. Физически применённый мутант при этом
разбирается нормально.

## Воспроизведение

Юнит-тест `test/repros/BUG-106.test.ts` (ветка `experiment/bug-repros`), оба
кейса падают на 170ec52 (`expected null not to be null`):

```ts
import { describe, expect, it } from 'vitest'

import { getSyntaxFingerprint } from '../helpers/get-syntax-fingerprint'
import { instrumentFile } from '../../core/instrument/instrument-file'
import { generateMutants } from '../helpers/generate-mutants'

describe('BUG-106', () => {
  it.each([
    ['strip.ts', [
      'export function strip(html: string): string {',
      "  return html.replace(/<!--[\\s\\S]*?-->/g, '')",
      '}',
    ]],
    ['escape.ts', [
      'const commentStripRE = /^(?:-?>)+|<!--|-->|--!>|<!-$/g',
      'export function escapeHtmlComment(src: string): string {',
      "  return src.replace(commentStripRE, '')",
      '}',
    ]],
  ])('hosts the mutants of %s in a module that parses', (file, lines) => {
    let source = lines.join('\n')
    let mutants = generateMutants(source, { preset: 'recommended', file })
    let switched = instrumentFile({ mutants, source, file })
    expect(getSyntaxFingerprint(file, source)).not.toBeNull()
    expect(mutants.some(mutant => mutant.mutator === 'regex-pattern')).toBe(true)
    expect(getSyntaxFingerprint(file, switched)).not.toBeNull()
  })
})
```

Сквозное воспроизведение на Vitest 5.0.5 + Vite 8.3.5 —
`test/repros/BUG-106/run.sh` (тест фикстуры лежит как `strip.check.ts`):


## Ожидаемое поведение

Switched-текст любого файла, который разбирается в исходном виде, разбирается
тем же парсером, что использует раннер (oxc в режиме `unambiguous`), и мутанты
регулярных выражений для HTML-комментариев получают вердикты.

## Фактическое поведение

```
plain vitest passes
{"summary":{"totalErrorMutants":9,…,"totalMutants":9,"totalKilled":0,…},
 "diagnostics":["instrumentation-break src/strip.js","instrumentation-break src/strip.ts"]}
```

Ошибка Vitest при загрузке switched-модуля:
`RolldownError: Parse failure: Parse failed with 3 errors: HTML comments are not allowed in modules`.

## Подозреваемые места в коде

- `core/instrument/render-mutant-range.ts:91-95` — replacement и original
  всегда в скобках; для литералов (регулярное выражение, строка, число),
  идентификаторов и выражений уровня вызова/члена скобки в ветках условного
  выражения не нужны — в альтернативе `?:` скобки нужны только
  `SequenceExpression`. Не ставить их хотя бы для литералов регулярных
  выражений и выражений, текст которых начинается с `/`.
- `core/instrument/create-switched-files.ts:74-104` — нет проверки, что
  switched-текст разбирается: ловить такие файлы до dry run дешевле и точнее
  (диагностика по файлу вместо `instrumentation-break` и BUG-100).
- `core/parser/parse-file.ts:77` — тот же `parseSync` с `unambiguous`:
  исходный файл с `(/<!--…/)` Mootant считает непарсящимся и не мутирует,
  хотя Node его выполняет.
- Апстрим: сообщить об ошибке в oxc (лексер в режиме `unambiguous` после `(`).

  (`core/instrument/instrumenter-version.ts:6`), он входит в ключ кэша.
