# BUG-652: подсказки перепроверки печатают `mootant …` без `npx` и не запускаются

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Документация ставит Mootant локально (`npm install -D mootant`) и запускает
через `npx` (`readme.md:77-78`, `docs/content/guide/getting-started.mdx:75-77`,
`:115`). Но все команды, которые Mootant сам печатает для копирования,
начинаются с голого `mootant`: строка `re-check one:` в текстовом отчёте,
поле `recheck` у каждого мутанта в JSON (его читают агенты), блок «Run it
again» и подсказка на обзоре HTML-отчёта. При локальной установке
`node_modules/.bin` не в `PATH`, и скопированная команда даёт `command not
found`. JSDoc `formatCommand` обещает обратное: «Arguments a shell would split
are quoted, so the line can be copied and run» (`cli/report/format-command.ts:62-67`).
Агент из `docs/components/skill-session.ansi` вызывает `mootant run src
--mutant q31p780qv6yk` — в Bash-инструменте агента это тоже не сработает.

## Воспроизведение

```bash
mkdir /tmp/bug-652 && cd /tmp/bug-652
npm init -y >/dev/null && npm pkg set type=module scripts.test="vitest run"
npm install -D vitest@5 /path/to/mootant-0.1.0.tgz   # или mootant после публикации
mkdir -p src test
printf 'export function getDiscount(total: number): number {\n  return total >= 100 ? 10 : 0\n}\n' > src/price.ts
cat > test/price.test.ts <<'TS'
import { expect, it } from 'vitest'
import { getDiscount } from '../src/price'
it('gives large orders 10% off', () => {
  expect(getDiscount(150)).toBe(10)
})
TS
npx mootant run src | tail -1           # re-check one: mootant run src --mutant xxxx
$(npx mootant run src | tail -1 | sed 's/^re-check one: //')   # bash: mootant: command not found
npx mootant run src --json | grep -o '"recheck":"[^"]*"' | head -1
```

## Ожидаемое поведение

Напечатанная команда запускается в той же оболочке, где пользователь запустил
Mootant: `npx mootant run src --mutant xxxx` для npm, `pnpm exec mootant …`
(или `pnpm mootant …`) для pnpm, `yarn mootant …` для Yarn, `bunx mootant …`
для Bun, голое `mootant …` — только когда Mootant вызван не через менеджер
пакетов (глобальная установка, `PATH`).

## Фактическое поведение

```text
re-check one: mootant run src --mutant 69kd
bash: mootant: command not found
"recheck":"mootant run src --mutant 69kd780...."
```

## Подозреваемые места в коде

- `cli/report/format-command.ts:77` — `['mootant', command, …]`, общий источник
  строки.
- `cli/run-mutation.ts:52-58` — `recheck` для отчётов собирается
  `formatCommand('run', …)`.
- `cli/report/format-run-text-report.ts:173` — `re-check one:`.
- `cli/report/build-run-report.ts:101-104` — поле `recheck` в JSON.
- `cli/html/client/unpack-run-report.ts:68-71`,
  `cli/html/client/render-mutant-panel.ts:197`,
  `cli/html/client/render-overview.ts:150-154` — HTML.
- `docs/components/skill-session.ansi`, `docs/components/hero-output.ansi` —
  примеры в документации.

Определить запускатель можно по `process.env.npm_config_user_agent`
(проверено: `npx` и `npm exec` дают `npm/10.9.9 node/v22.23.4 linux x64
workspaces/false`, `pnpm exec` — `pnpm/10.28.0 npm/? node/v22.23.4 linux x64`,
прямой `node` — переменной нет; Yarn и Bun выставляют её так же) с запасным
вариантом по
lockfile корня (`core/cache/find-lockfile.ts` уже знает их порядок). Заголовок
отчёта (`command` — как набрано) менять не нужно, только подсказки.

## Критерий готовности

- Unit-тест функции выбора префикса (новый файл рядом с
  `format-command.ts`): user agent npm/pnpm/yarn/bun, отсутствие user agent,
  неизвестный менеджер.
- Тесты `format-run-text-report`, `build-run-report` и HTML-клиента обновлены:
  при запуске через npm подсказка начинается с `npx mootant`.
- Ручная проверка из «Воспроизведения»: строка после `re-check one:` и поле
  `recheck` запускаются копированием.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- `docs/components/skill-session.ansi` и `hero-output.ansi` показывают те же
  команды, что печатает инструмент.
