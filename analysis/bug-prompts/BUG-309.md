# BUG-309: значения JSX-атрибутов в кавычках, включая `type`, `href` и `aria-*`, всегда пропускаются как шум, и опции, чтобы их мутировать, нет

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: low (запрос на улучшение; в анализе была
> medium). Статус: поведение воспроизведено, как дефект опровергнуто
> (задокументировано и задумано). Найдено на коммите 170ec52.
>
> Перепроверено независимо: воспроизведено (unit-тест падает с `received []`
> в трёх прогонах, один из них на копии 170ec52; на упакованном mootant
> `list src --skipped` даёт три пропуска `noise jsx-attribute`, с
> `--preset strict` то же; слабый тест компонента получает score 100 %, а с
> теми же значениями в `{'…'}` — 0 % и три выживших); скептик: как дефект
> опровергнуто — пропуск всех значений в кавычках задокументирован
> (`docs/content/mutators/string-literal.md:130`, `:147-157`), закреплён
> тестом проекта (`href="x"` в
> `test/core/mutators/string-literal.test.ts:385-391`) и совпадает со
> StrykerJS. Итог — low: нужна opt-in опция для поведенческих атрибутов
> (`type`, `href`, `aria-*`), а не исправление ошибки.

## Контекст

`string-literal` не мутирует строку, если её родитель — `JSXAttribute`
(`core/mutators/string-literal.ts:170-175`): правило `jsx-attribute`,
категория `noise`, `heuristic: false` (`core/skips/skip-rules.ts:250-253`).
Имя атрибута не учитывается. Поэтому под правило попадают не только
оформительские `className="badge"`, но и `type="password"` (маскирование
пароля), `name`, `href="/reset"`, `aria-label="Password"` (по нему элемент
находит `getByLabelText` из Testing Library), `role`, `htmlFor`, `value`,
`method`. Это поведение компонента: тест, который проверяет атрибуты, такие
мутанты убивает (шаг 3). Слабый тест получает 100 %, а `mootant run` о
пропусках не сообщает (наблюдение скептика).

Пропуск задуман и задокументирован, поэтому это запрос на улучшение, а не
ошибка кода:

- Таблица пропусков описывает правило общо: «Quoted value of a JSX attribute»
  (`docs/content/mutators/string-literal.md:130`). В списке «Changes that come
  back» его нет, а дальше сказано «The other changes stay skipped»
  (`:147-157`). Поведенческие атрибуты документация не называет: в обзоре
  пример только `className="badge"` (`:35-37`).
- Тесты закрепляют пропуск именно `href`: `<a href="/home" />` не даёт
  мутантов `string-literal` (`test/core/mutators/string-literal.test.ts:44`), а
  `<a href="x" />` даёт `"x" -> "" (noise jsx-attribute)` (`:385-391`).
- JSDoc мутатора относит «JSX attribute strings» к сознательным пропускам
  (`core/mutators/string-literal.ts:48-62`, `:129-134`). Комментарий фикстуры
  гласит «JSX attribute strings are never mutated»
  (`test/fixtures/list/source/component.tsx:1`).
- StrykerJS делает так же и без опции: `types.isJSXAttribute(parent)` в
  `isValidParent` (`packages/instrumenter/src/mutators/string-literal-mutator.ts`,
  скептик смотрел main от 2026-10-29), тест «should not mutate string JSX
  attributes».

Вернуть эти мутанты нельзя никакой настройкой. У `string-literal` есть только
опция `caseTests` (`docs/content/guide/configuration.mdx:202`,
`docs/content/mutators/string-literal.md:104-117`). Для логов есть настройка
`loggers` (`configuration.mdx:219`, `:224-231`), для атрибутов — ничего.
Граница при этом проходит по синтаксису записи, а не по смыслу: значения в
фигурных скобках уже мутируются (`<a title={'t'} />` даёт `'t' -> ''`,
`test/core/mutators/string-literal.test.ts:68-72`). Дело в том, что
`getContextSlot` (`core/tree/get-context-slot.ts`) пропускает только обёртки
из `core/tree/is-expression-wrapper.ts:26-33`, а `JSXExpressionContainer` к
ним не относится.

Насколько это массово, количественно не проверялось. На демо zustand из
корпуса анализа правило дало 28 пропусков: `className` 11, SVG-атрибуты
(`xmlns`, `viewBox`, `fill`, `stroke`, `strokeLinecap`, `strokeLinejoin`, `d`)
7, `href` на внешние URL 5, `value` 2, `language`, `src` и `alt` по одному.

Одной правкой условия опцию не сделать. Правило `noise` сейчас прикрывает и
техническое ограничение: переключатель мутантов не умеет ставить замену на
место значения в кавычках (см. «Подозреваемые места в коде»).

## Воспроизведение

Нужны Node.js `^20.19.0 || >=22.12.0` (поле `engines` в `package.json`) и
pnpm 12: pnpm 10 не читает `configDependencies` из `pnpm-workspace.yaml` и
зависает.

### Шаг 1. Unit-тест (сборка не нужна)

В анализе тест лежал в `test/repros/BUG-309.test.ts` ветки
`experiment/bug-repros`, которой в чистом клоне нет. Создай этот файл
временно, только чтобы увидеть падение. В таком виде его не коммить (см.
«Ограничения»). Хелпер `test/helpers/list-mutant-texts.ts` есть в 170ec52.
Через `test/helpers/run-mutator.ts` он прогоняет весь конвейер со всеми
встроенными мутаторами, как `mootant list`, и возвращает мутанты одного
мутатора в виде `original -> replacement`. Если какой-то мутатор сообщил об
ошибке, хелпер бросает `Error` (`test/helpers/generate-candidates.ts:78-83`).

## Ожидаемое поведение

Решение перепроверки: поведение по умолчанию остаётся, добавляется opt-in
опция. Исходное предложение анализа (опция
`jsxAttributes: 'presentational' | 'all'` со значением `'presentational'` по
умолчанию) меняло бы поведение по умолчанию и этому решению противоречит.

1. **По умолчанию ничего не меняется.** В `recommended` значение атрибута в
   кавычках по-прежнему пропускается с правилом `jsx-attribute` (`noise`).
   Тесты `test/core/mutators/string-literal.test.ts:44`, `:68-72` и
   `:385-391` проходят без правок. Фикстуры `recommended`
   (`test/fixtures/list/expected-mutants.json`, `expected-skipped.json`) не
   меняются.
2. **Новая опция мутатора `string-literal`**, рабочее имя `jsxAttributes`:
   булева, `false` по умолчанию. С ней значение атрибута в кавычках мутируется
   как обычная строка: `"password"` → `""`, пустое `href=""` → `"mootant"`.
   Остальные проверки `getStringSkip` после JSX-проверки
   (`core/mutators/string-literal.ts:176` и дальше) работают как для любой
   строки. Для снипета шага 1 с опцией ожидается
   `['"password" -> ""', '"Password" -> ""', '"/reset" -> ""']`.
3. **`strict` включает опцию.** Документация обещает, что `strict` включает все
   опции мутаторов: «The options are `false` by default, and `strict` turns all
   of them on» (`docs/content/guide/configuration.mdx:184`), в таблице
   пресетов — «Mutator options … All on» (`:148`). Если решишь не включать,
   исправь оба места и объясни исключение в PR.
4. **Какие атрибуты пропускать и с опцией, реши явно** и закрепи тестами и
   документацией. Рекомендуемый минимум — оформительские `className`, `class`
   и `style` остаются `jsx-attribute`, `noise`. Это предложение анализа, на
   корпусе оно не проверялось. Скептик предупреждает, что деление по имени —
   эвристика: на демо zustand такой список вернул бы 17 строк из 28, из них 7
   SVG-атрибутов. Отдельно реши:
   - `title`, `alt`, `placeholder`: их читают `getByTitle`, `getByAltText`,
     `getByPlaceholderText`;
   - `key`, `id`/`htmlFor`, `data-testid` и прочие `data-*`, атрибуты с
     пространством имён (`JSXNamespacedName`, например `xlink:href`);
   - пропсы компонентов (`<Button variant="primary">`, `className` у
     компонента): смысл по имени не определить;
   - строковый `style`: в React он невалиден, в Preact и Solid допустим;
   - SVG-атрибуты (`viewBox`, `d`, `fill`, `stroke`).
5. **Без поддержки хостинга опции не будет** (механизм — в «Подозреваемых
   местах в коде»). Значение в кавычках должно стать местом, где переключатель
   может включить мутант. Переключённый файл при этом парсится, а исходная
   ветка даёт то же значение, что исходный атрибут.
6. **Документация называет охват правила.** В
   `docs/content/mutators/string-literal.md:35-37` и в строке таблицы `:130`
   прямо сказано, что по умолчанию пропускаются все значения в кавычках, в том
   числе `type`, `href`, `aria-*`, `name`, а значения в `{}` мутируются. У
   опции есть раздел по образцу `### caseTests` (`:104-117`) и строка в
   «Changes that come back» (`:147-155`). Фразы о `strict` (`:40-41`,
   `:101-102`, `:157`) исправлены. В таблицу опций
   `docs/content/guide/configuration.mdx:188-202` добавлена строка.

- Шаг 2 (сокращённая запись верификатора, не дословный вывод CLI):

  ```text

    4:19 string-literal "password" -> ""  noise jsx-attribute
    4:41 string-literal "Password" -> ""  noise jsx-attribute
    5:15 string-literal "/reset" -> ""    noise jsx-attribute
  ```

  С `--preset strict` и для `Login.tsx` то же. В `braces/Variants.jsx`

## Подозреваемые места в коде

- `core/mutators/string-literal.ts:170-175` — условие
  `parent?.type === 'JSXAttribute'` без учёта имени атрибута и опций. Опцию
  проверяй здесь, как `caseTests` на `:158`. Опции мутатора: интерфейс `StringLiteralOptions`
  (`:18-23`), `defaultOptions` (`:109`), пресет `core/presets/strict.ts:26`.
  Отдельных типов опций в `types/` нет. JSDoc — `:48-62`, `:129-134`.
- `core/skips/skip-rules.ts:250-253` — `jsx-attribute`: `noise`,
  `heuristic: false`.
- Где теряется мутант и почему наивная правка ломает конвейер:
  - `core/generate/collect-candidates.ts:278-284` — пропущенная замена
    (`replacement.skip`) записывается в skipped без проверки цели, поэтому
    сейчас ошибки не видно;
  - `:286-303` — непропущенная замена проходит `validateReplacement`. При
    нарушении в диагностику пишется ошибка мутатора, а замена уходит в skipped
    с правилом `invalid-target`;
  - `core/generate/validate-replacement.ts:62-63` — для выражения вне value
    position возвращается «cannot replace a … node in a position where Mootant
    cannot switch a mutant on.»;
  - `core/syntax/is-value-position.ts:109-115` — `isSourceShape`:
    `case 'JSXAttribute': return key === 'value'` (JSDoc `:35-43` и
    `:100-108`: JSX attribute values и JSX children отклоняются);
  - `core/instrument/render-mutant-range.ts:91-95` — хост выражения пишется
    прямо на место текста: `(check ? (r) : (orig))`. После `type=` без `{}`
    это невалидный JSX. Нужен текст вида
    `type={(check ? ("") : ("password"))}`.
- Варианты хостинга предложил верификатор, ни один не проверен. Оговорки к
  ним ниже сделаны по чтению кода.
  - **(а) Обёртка `{…}`.** Разреши значение атрибута в кавычках как цель и
    оборачивай его хост в `{…}`. Учти:
    - `isValuePosition` входит в публичный API плагинов
      (`types/syntax/syntax-helpers.d.ts:193-197`; мутаторам его отдаёт
      `core/syntax/create-syntax-helpers.ts:157`; в ядре его вызывают
      `core/mutators/shared/get-call-target.ts:20`,
      `core/mutators/number-literal.ts:198`,
      `core/mutators/method-call.ts:382`,
      `core/mutators/optional-chaining.ts:133`). Правка `isSourceShape`
      меняет контракт для всех мутаторов. Узкая альтернатива — отдельное
      исключение в `validateReplacement`.
    - `instrumentFile` знает о синтаксисе только начала инструкций
      (`core/instrument/instrument-file.ts:56-57`,
      `core/instrument/find-statement-starts.ts:62`). Хосты группируются по
      `kind` мутанта (`core/instrument/group-mutant-ranges.ts`,
      `types/mutant/mutant-range.d.ts`: `'expression' | 'block'`), а `kind`
      попадает в JSON-отчёт `list --json --verbose` (поле `"kind"` в
      `test/fixtures/list/expected-mutants.json`). Новое значение `kind` —
      изменение публичного формата. Альтернатива — находить значения
      атрибутов разбором файла, по образцу `findStatementStarts`.
    - Строка JSX-атрибута — не JS-литерал: escape-последовательностей в ней
      нет, а HTML-сущности вроде `&amp;` декодируются (так по спецификации
      JSX; как это делают oxc и Vite, не проверено). Если перенести исходный
      текст `pattern="\d+"` или `title="a &amp; b"` в `{…}` как есть,
      значение исходной ветки изменится. Либо не мутируй такие значения (с
      `\`, `&` или переводом строки), либо строй исходную ветку из значения,
      а не из текста.
  - **(б) Цель — объемлющее выражение в value position** (например, внешний
    JSX-элемент) с `focus` на значении атрибута. По
    `types/mutator/replacement.d.ts` `focus` — правка внутри узла, которую
    показывают отчёты, а мутант всё равно заменяет весь узел. Синтаксис
    атрибутов не меняется, но каждая замена — копия всего внешнего элемента
    (`render-mutant-range.ts:85-95` пишет замены целиком). У вложенных
    элементов (`<input>` внутри `<form>`) это всё дерево компонента. Кроме
    того, директивы игнорирования сопоставляются по смещению начала мутанта
    (`core/ignore/create-ignore-rules.ts:18-31`), поэтому
    `mootant-ignore-next-line` над строкой атрибута такой мутант, вероятно,
    не накроет (не проверено).
- Тесты, закрепляющие текущее поведение:

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл»
  (`contributing.md:240`), JSDoc на каждую функцию, `let` вместо `const` там,
  где так принято в проекте, строгий ESLint (`@azat-io/eslint-config`),
  cspell, knip. Новые функции (проверка имени атрибута, поиск значений
  атрибутов для хостинга) — отдельные файлы со своими тестами. Если в
  документации появится якорь вроде `#jsxattributes`, cspell может
  потребовать добавить слово в `words` (`cspell.config.ts`), как уже сделано
  для `coarsemutants`.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига) без явной необходимости; если без этого нельзя — опиши компромисс.
  Новая опция — дополнение к формату конфига. Публичны и
  `SyntaxHelpers.isValuePosition` (`types/syntax/syntax-helpers.d.ts:193-197`),
  и поле `kind` JSON-отчёта; любое их изменение опиши в PR.
- В репозитории нет `changelog.md`: при релизе его собирает changelogen из
  Conventional Commits (`release:version` в `package.json`, типы в
  `changelog.config.ts`). Новая опция — коммит `feat`. Если `strict` её
  включает, напиши в теле коммита и в PR, что у пользователей `strict`
  меняется mutation score: появляются мутанты значений JSX-атрибутов.
- Тест-воспроизведение из анализа нельзя копировать как есть в
  `test/repros/`: перепиши его в стиле проекта. Строгий ESLint
  (`eslint.config.ts`: `@azat-io/eslint-config` с правилами perfectionist и
  vitest) проверяет имена файлов, `describe`/`it`, порядок импортов и
  ключей. По чтению конфигурации (ESLint не запускался) имя
  `BUG-309.test.ts` не проходит `unicorn/filename-case` (нужен kebab-case или
  PascalCase), заголовок `describe('BUG-309: …')` — правило
  `vitest/prefer-lowercase-title`, а perfectionist сортирует ключи объектов и
  импорты по длине строки по убыванию. Проверки BUG-309 добавь в существующие
  `test/core/mutators/string-literal.test.ts` и
  `test/core/instrument/instrument-file.test.ts`, временный
  `test/repros/BUG-309.test.ts` удали. Фикстуры, если понадобятся, клади
  только в `test/fixtures/**`: их игнорируют ESLint (`eslint.config.ts:15`),
  `tsc` (`tsconfig.json:2`) и Vitest (`vitest.config.ts:18`).

  `ts(2322)` в `docs/components/*.astro`). Причина: `tsconfig.json:2-4`

  остальные `test:*`) по отдельности.
