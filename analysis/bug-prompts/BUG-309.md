# BUG-309: все строковые значения JSX-атрибутов пропускаются как шум, включая `type`, `href`, `aria-*`

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

`string-literal` не мутирует строку, если её родитель — `JSXAttribute`
(`core/mutators/string-literal.ts:170-175`, правило `jsx-attribute`,
категория `noise`, `heuristic: false`). Документация приводит безобидный
пример — `className="badge"` (`docs/content/mutators/string-literal.md:35-37`,
`:130`), но правило покрывает **все** атрибуты: `type="password"` (маскирование
пароля), `name="password"` (имя поля формы), `href="/reset"`,
`aria-label="Password"` (по нему находят элемент `getByLabelText` в Testing
Library), `role`, `htmlFor`, `value`, `method`. Это поведение компонента, и
разумный тест компонента такой мутант убивает; если не убивает — это дыра в
тестах, которую Mootant прячет. В React-проекте значительная доля строковых
литералов — атрибуты JSX, и опции, возвращающей их, нет (для `case`-меток есть
`caseTests`, для логгеров — `loggers`).

## Воспроизведение

Падающий тест — `test/repros/BUG-309.test.ts` в ветке `experiment/bug-repros`:

```ts
import { describe, expect, it } from 'vitest'

import { listMutantTexts } from '../helpers/list-mutant-texts'

let login = [
  'export function Login() {',
  '  return (',
  '    <form>',
  '      <input type="password" aria-label="Password" />',
  '      <a href="/reset">Reset</a>',
  '    </form>',
  '  )',
  '}',
]

describe('BUG-309: every JSX attribute value is skipped as noise', () => {
  it('keeps the strings of attributes that change behavior', () => {
    expect(
      listMutantTexts('string-literal', login, { file: 'example.jsx' }),
    ).toStrictEqual([
      '"password" -> ""',
      '"Password" -> ""',
      '"/reset" -> ""',
    ])
  })

  it('still skips a class name', () => {
    expect(
      listMutantTexts(
        'string-literal',
        ['export let badge = <span className="badge">New</span>'],
        { file: 'example.jsx' },
      ),
    ).toStrictEqual([])
  })
})
```

```bash
#   4:57 string-literal "Password" -> ""  noise jsx-attribute
#   ... ни одного мутанта строк атрибутов
```

## Ожидаемое поведение

Шумом считаются только оформительские атрибуты (`className`, `class`,
`style`, `tw`, возможно `data-*` кроме `data-testid`), остальные строковые
значения атрибутов мутируются. Альтернатива с меньшим риском — опция
`string-literal` (например, `jsxAttributes: 'presentational' | 'all'`), по
умолчанию `'presentational'`, и строка в таблице skipped changes с честным
описанием. Решение и его обоснование зафиксировать в тесте и документации.

## Фактическое поведение

Все строки JSX-атрибутов — `jsx-attribute`, `noise`; вернуть их нельзя
никакой настройкой.

## Подозреваемые места в коде

- `core/mutators/string-literal.ts:170-175` — проверка `parent?.type ===
  'JSXAttribute'` без учёта имени атрибута.
- `docs/content/mutators/string-literal.md:35-37, 130` — описание правила.

## Критерий готовности

- Тест `test/repros/BUG-309.test.ts` (перенести в
  `test/core/mutators/string-literal.test.ts`) падает до исправления и
  проходит после; `className` по-прежнему пропускается.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- Документация `string-literal` перечисляет, какие атрибуты считаются шумом;
  если добавлена опция — она описана в `docs/content/guide/configuration.mdx`
  (таблица опций мутаторов) и в типах опций.
