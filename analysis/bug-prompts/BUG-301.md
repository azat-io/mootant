# BUG-301: тонкий мутант инициализатора локальной переменной прячет `return x` → `0` (solitary)

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

`return-value` заменяет возвращаемое значение пустым (`0`, `''`, `[]`,
`undefined`). Для возвращаемой локальной переменной диапазоны `solitary`
включают не только само выражение, но и инициализатор и все записи переменной
в той же функции (`core/mutators/return-value.ts:170-171`, `getLocalRanges`
в `core/mutators/return-value.ts:349-365`). Если внутри любого из них есть
тонкий мутант, `return count` → `return 0` выбрасывается
(`core/generate/apply-solitary-rule.ts:60`).

Предположение «тест, убивающий тонкий мутант, наблюдает удаляемый код» ломается,
когда переменная читается ещё где-то кроме этого `return`: тонкий мутант
инициализатора (`let count = 0` → `1`) или записи (`count++` → `count--`)
убивается через другое чтение (аргумент колбэка, другое `return`, условие), а
возвращаемое значение тест может не проверять вовсе. Документация
(`docs/content/mutators/return-value.md:84-94`) признаёт только случай «пустого
списка» и не упоминает этот, более частый, класс: аккумулятор, который
одновременно передаётся наружу и возвращается.

## Воспроизведение

Падающий тест — `test/repros/BUG-301.test.ts` в ветке `experiment/bug-repros`:

```ts
import { describe, expect, it } from 'vitest'

import { listMutantTexts } from '../helpers/list-mutant-texts'
import { listSkipped } from '../helpers/list-skipped'

let processAll = [
  'export function processAll(items, onItem) {',
  '  let count = 0',
  '  for (let item of items) {',
  '    count++',
  '    onItem(item, count)',
  '  }',
  '  return count',
  '}',
]

describe('BUG-301: a finer mutant of a returned local hides the returned default', () => {
  it('keeps the default of a returned local that is also read elsewhere', () => {
    expect(
      listMutantTexts('return-value', processAll, { file: 'example.js' }),
    ).toStrictEqual(['count -> 0'])
  })

  it('does not drop the default as solitary', () => {
    expect(
      listSkipped('return-value', processAll.join('\n'), {
        file: 'example.js',
      }),
    ).toStrictEqual([])
  })
})
```

Сквозная проверка (фикстура `analysis/data/skips/fx1`, файлы `src/process.js`,
`test/process.test.js`): тест проверяет только аргументы колбэка
(`[['a', 1], ['b', 2]]`).

```bash
npx mootant run src/process.js --no-cache   # killed 3, score 100%
# физически заменить `return count` на `return 0`:
npx vitest --run test/process.test.js        # проходит — мутант выжил
```

## Ожидаемое поведение

Если локальная переменная читается не только в этом `return` (другие чтения в
функции, замыкания, передача в вызов), мутанты её инициализатора и записей не
должны считаться для `solitary` возвращаемого значения; `count -> 0`
выводится как мутант. Если единственное чтение — этот `return`, поведение
прежнее.

## Фактическое поведение

```
return-value 'count' -> '0' [solitary/subsumed/H]
  by number-literal@2:15 (let count = 0 -> 1): a finer number-literal mutant lies inside the code it removes, ...
```

## Подозреваемые места в коде

- `core/mutators/return-value.ts:349-365` (`getLocalRanges`) — включает
  инициализатор и записи без проверки, что других чтений переменной нет.
- `core/mutators/return-value.ts:378-391` (`getLocalBinding`) — здесь доступен
  `Binding` с `references`, по которым можно проверить «единственное чтение».
- `core/generate/apply-solitary-rule.ts:97-115` — поиск тонкого кандидата.
