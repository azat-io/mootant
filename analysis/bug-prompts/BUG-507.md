# BUG-507: под Vitest модули, загруженные через `require()`, не переключаются — ложные NoCoverage

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: high. Статус: подтверждён. Найдено на коммите
> 170ec52.
>
> Перепроверено независимо: воспроизведено (репро-тест падает 3 из 3; на
> фикстуре с нуля с упакованным mootant и Vitest 5.1.0 все 5 мутантов `b.cjs`
> получают NoCoverage, хотя вручную 4 из 5 убиты; та же цепочка под node:test
> совпадает с ручным применением: killed 7, survived 1); скептик: не
> опровергнуто, high на нижней границе — ошибка пессимистичная (ложных Killed
> нет, `never-served` печатается, но с ложной причиной), и затронут только код,
> который под Vitest загружает нативный `require()`.

## Контекст

Vitest-адаптер подменяет текст мутированных файлов только в `transform`-хуке
своего Vite-плагина (`adapters/vitest/create-mootant-plugin.ts:32-50`; там же
`state.served.add` на `:43` и проверка текста `resolveSwitchedText` на `:44`).
Других мест подмены в `adapters/vitest/` нет: `_compile`, `registerHooks` и
`Module.prototype` там не встречаются. Модуль, который исполняет сам Node через
`require()`, Vite не видит. Это проявляется в двух случаях, и теряется в них
разное:

- **А. Цепочка CommonJS** (основной случай этой задачи). Тест импортирует
  `src/a.cjs`, его обслуживает Vite, а `a.cjs` делает `require('./b.cjs')`. Тест
  в dry run выбирается, мутанты `a.cjs` решаются верно. Но `b.cjs` компилирует
  загрузчик CommonJS Node прямо с диска, без подмены. Файл не попадает в
  `served`, mootant печатает предупреждение `never-served`
  (`core/run/run-dry-phase.ts:360-367`) и ставит всем мутантам файла NoCoverage,
  хотя тест их убивает. Проба верификатора: `transform` видит `test/a.check.js`
  и `src/a.cjs`, но ни разу не видит `src/b.cjs`, а в тесте `require.cache`
  содержит `.../src/b.cjs`.
- **Б. Тест сам грузит код через `createRequire` или `require`.** Здесь теряется
  уже отбор тестов. Под Vitest тест-файлы для dry run выбирает сам Vitest:
  `findSpecifications` записывает в `vitest.config.related` все переключённые
  файлы (`core/run/run-dry-phase.ts:156`) и вызывает
  `vitest.getRelevantTestSpecifications()` (`adapters/vitest/run-dry.ts:225-236`).
  Связь через `require()` этот отбор не видит: `vitest related src/a.js src/b.js
  --run` отвечает «No affected test files found». Тест не попадает в dry run, и
  NoCoverage получают все мутанты (`core/run/run-dry-phase.ts:129-130`: «Without
  related tests the dry run is empty»).

Причина в тексте `never-served` в обоих случаях ложная. Это общий текст «no test
imports it, or tests import a built copy, an external or a pre-bundled
dependency» (`core/run/run-dry-phase.ts:365`). Для CommonJS-кодовой базы под
Vitest баг занижает score (на фикстуре ниже 37,5% вместо 87,5%) и прячет
настоящих выживших: мутант `age == 18` на деле Survived, а отчёт показывает его
непокрытым, с `"tests": 0` в JSON. Затронуты только модули, которые под Vitest
загружает нативный `require()`: JS в синтаксисе CommonJS и `createRequire`.
Проекты на TypeScript и ESM не затронуты, их `import` обрабатывает Vite.
Документация обещает для `.cjs` «List and run mutants» без оговорок
(`docs/content/guide/compatibility.mdx:34`), а в списке ограничений Vitest
(`:45-57`) про `require()` ничего нет. При этом авторы знают, что `require()`
обходит Vite: ключи `createRequire(import.meta.url).cache` уже передаются как
зависимости для кэша (`adapters/vitest/runner.ts:1176-1187`, ключи на `:1182`;
JSDoc `adapters/vitest/worker/list-dependencies.ts:17-31`), но сами модули не
переключаются. Адаптер node:test переключает такие модули патчем
`Module.prototype._compile`
(`adapters/node-test/preload/patch-module-compile.ts:14-42`, вызов в
`adapters/node-test/preload/install-module-hooks.ts:76`). На той же цепочке под
node:test вердикты совпадают с ручным применением.

## Воспроизведение

Ветки `experiment/bug-repros` в публичном репозитории нет, файлы ниже создайте
сами. Нужны Node.js 22.12 или новее (этого требует Vitest 5,
`docs/content/guide/compatibility.mdx:23-24`) и pnpm 12. В CI стоит
`latest-12` (`.github/actions/install-tools/action.yml`). pnpm 10 не читает
`configDependencies` из `pnpm-workspace.yaml`, и даже `pnpm --version` внутри
репозитория у него зависает. Команды шагов 2–4 рассчитаны на одну сессию shell:
они используют переменные `TGZ` и `FIX`.

### Шаг 1. Падающий тест на исходниках (сборка не нужна)

Тест фикстуры назван `*.check.js`, чтобы корневой Vitest репозитория его не
подхватывал. Все файлы временные и в коммит не входят (см. «Ограничения»).

```bash
# в корне клона azat-io/mootant
pnpm install
mkdir -p test/repros/BUG-507/src test/repros/BUG-507/test

cat > test/repros/BUG-507/package.json <<'EOF'
{
  "name": "bug-507-fixture",
  "private": true,
  "type": "module",
  "scripts": {
    "test": "vitest --run"
  }
}
EOF

cat > test/repros/BUG-507/vitest.config.ts <<'EOF'
export default {
  test: {
    include: ['test/**/*.check.js'],
  },
}
EOF

cat > test/repros/BUG-507/src/a.cjs <<'EOF'
const { isAdult } = require('./b.cjs')

function canVote(age) {
  return isAdult(age)
}

module.exports = { canVote }
EOF

cat > test/repros/BUG-507/src/b.cjs <<'EOF'
function isAdult(age) {
  return age >= 18
}

module.exports = { isAdult }
EOF

cat > test/repros/BUG-507/test/a.check.js <<'EOF'
import { expect, it } from 'vitest'

import { canVote } from '../src/a.cjs'

it('lets 18-year-olds vote', () => {
  expect(canVote(18)).toBe(true)
  expect(canVote(17)).toBe(false)
})
EOF

cat > test/repros/BUG-507.test.ts <<'EOF'
import { describe, expect, it } from 'vitest'
import path from 'node:path'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

/**
 * Project with CommonJS sources: the test imports `src/a.cjs`, which loads
 * `src/b.cjs` with `require()`.
 */
let root = path.resolve(import.meta.dirname, 'BUG-507')

describe('BUG-507: Vitest and modules loaded with require()', () => {
  it('decides the mutants of a module that a source loads with require()', async () => {
    let result = await runMutants({
      builtIns: createBuiltIns('vitest', vitestAdapter()),
      paths: ['src'],
      concurrency: 1,
      cache: false,
      cwd: root,
    })
    let verdicts = result.results
      .filter(verdict => verdict.mutant.file === 'src/b.cjs')
      .map(verdict => `${verdict.mutant.replacement} ${verdict.status}`)

    /*
     * With `age >= 18` -> `age > 18` applied to `src/b.cjs` by hand, the test
     * fails (`canVote(18)` is false). Vite serves only `src/a.cjs`; Node's own
     * `require()` loads `src/b.cjs` from disk, unswitched, so every mutant of
     * `src/b.cjs` ends as NoCoverage with a `never-served` warning.
     */
    expect(verdicts).toContain('age > 18 Killed')
  }, 60_000)
})
EOF

pnpm exec vitest --run test/repros/BUG-507.test.ts
```

### Шаг 3. Эталон: ручное применение и node:test

Мутанты фикстуры (`npx mootant list src --json`): три в `src/a.cjs` и пять в
`src/b.cjs`. Столбец «Вручную» показывает, что дал `vitest --run` с мутантом,
вписанным в файл руками.

| Место | Мутатор | Было → стало | Вручную |
| --- | --- | --- | --- |
| `src/a.cjs:4` | return-value | `isAdult(age)` → `undefined` | Killed |
| `src/a.cjs:7` | statement-removal | `module.exports = { canVote }` → `;` | Killed |
| `src/a.cjs:7` | object-property | `{ canVote }` → `{}` | Killed |
| `src/b.cjs:2` | comparison-operator | `age >= 18` → `age > 18` | Killed |
| `src/b.cjs:2` | comparison-operator | `age >= 18` → `age == 18` | Survived |
| `src/b.cjs:2` | comparison-operator | `age >= 18` → `age >= 17` | Killed |
| `src/b.cjs:5` | statement-removal | `module.exports = { isAdult }` → `;` | Killed |
| `src/b.cjs:5` | object-property | `{ isAdult }` → `{}` | Killed |

Ручная проверка мутантов `b.cjs` в `$FIX` (GNU sed). Верификатор применял
мутанты по `start`/`end` из `mootant list --json --verbose`. Этот цикл собран
по таблице и запуском не проверялся.

```bash
cd "$FIX"
ORIG="$(mktemp)"
cp src/b.cjs "$ORIG"
for expr in 's/age >= 18/age > 18/' 's/age >= 18/age == 18/' \
  's/age >= 18/age >= 17/' 's/^module\.exports = { isAdult }$/;/' \
  's/= { isAdult }$/= {}/'; do
  cp "$ORIG" src/b.cjs
  sed -i "$expr" src/b.cjs
  if npx vitest --run > /dev/null 2>&1; then
    echo "Survived: $expr"
  else
    echo "Killed: $expr"
  fi
done
cp "$ORIG" src/b.cjs
```

## Ожидаемое поведение

- Случай А. Мутанты `src/b.cjs` переключаются так же, как у модуля, который
  обслуживает Vite, и вердикты совпадают с ручным применением из таблицы шага 3.
  `age > 18`, `age >= 17`, удаление `module.exports = { isAdult }` и `{}` дают
  Killed, `age == 18` даёт Survived. По всей фикстуре: killed 7, survived 1, no
  coverage 0, score 87,5%, как под node:test. Предупреждения `never-served` для
  `src/b.cjs` нет. Если текст `b.cjs` на диске отличается от того, по которому
  составлен список мутантов, выдаётся `instrument-error`, как для файлов,
  которые обслужил Vite (`core/run/run-dry-phase.ts:354-359`).
- Случай Б. В идеале вердикты те же, что вручную: 7 Killed и 1 Survived.
  Минимум, допустимый в рамках этой задачи, указан в «Критерии готовности».

## Фактическое поведение

Шаг 1:

```
AssertionError: expected [ 'age > 18 NoCoverage', …(4) ] to include 'age > 18 Killed'
```

Все пять мутантов `src/b.cjs` получают NoCoverage, все три мутанта `src/a.cjs`
— Killed. В `result.diagnostics` одна диагностика: `never-served` для
`src/b.cjs`, severity `warning`.

Шаг 2 (CLI). Три прогона дали одинаковый результат. От нагрузки и таймингов он
не зависит: решает только то, какой загрузчик исполняет файл.

```
! src/b.cjs: No test loaded src/b.cjs through the test runner's transform: … [never-served]
```

Сводка: killed 3, survived 0, no coverage 5, score 37.5%. Полный текст причины
(`core/run/run-dry-phase.ts:365`): «No test loaded src/b.cjs through the test
runner's transform: no test imports it, or tests import a built copy, an
external or a pre-bundled dependency.» Причина ложная: тест импортирует `a.cjs`,
а тот грузит `b.cjs` через `require()`.

Шаг 3. Вручную убиты 4 из 5 мутантов `b.cjs`, `age == 18` выживает. Под
node:test: killed 7, survived 1, no coverage 0, score 87.5%. Выживший тот же,
`age == 18`.

Шаг 4 (вариант Б). В dry run 0 тестов, `never-served` для `src/a.js` и
`src/b.js`, no coverage 8, score 0%. Вручную 7 из 8 мутантов убиты, `age == 18`
выживает. Значит, неверны все 8 вердиктов: 7 пропущенных убийств и один скрытый
выживший.

Дополнительно, по данным скептика (фикстуры здесь не приводятся). Легаси-проект
с `"type": "commonjs"`: тест импортирует `src/price.js`, а тот делает
`require('./discount')` и `require('./math')`. Там 18 из 24 мутантов получают
NoCoverage, score 25%. Если в том же проекте тесты сами вызывают `require()`
(`globals: true`), в dry run 0 тестов, 24 из 24 NoCoverage, score 0%.

## Подозреваемые места в коде

Где теряется:

- `adapters/vitest/create-mootant-plugin.ts:32-50` — единственная точка
  переключения в адаптере Vitest, хук Vite `transform` (`served.add` на `:43`,
  `resolveSwitchedText` на `:44`, `mismatched` на `:46`). До `require()` хук не
  дотягивается. Настройкой Vite или Vitest это не обойти: Vitest не пропускает
  `require()` через Vite.
- `adapters/vitest/run-dry.ts:225-236` — отбор тест-файлов для dry run (случай
  Б): `vitest.config.related` и `vitest.getRelevantTestSpecifications()`. Патч
  `_compile` эту потерю не исправит: тест-файл в dry run вообще не запускается.
  Для случая Б mootant нужен собственный маппинг «тест → require-зависимости».
  Дизайн не проработан, не проверено.
- `core/run/run-dry-phase.ts:360-367` — `never-served` с общей причиной (`:365`),
  если адаптер не передал свою в `unserved`. node:test передаёт конкретную
  причину (`adapters/node-test/run-dry.ts:17-24` и `:151-154`).

Как чинить случай А (направление по чтению кода, запуском не проверено):

- `adapters/vitest/runner.ts` — раннер воркера. Он загружается до setup-файлов
  и тестов (`:189-193`), так что здесь можно ставить `patchModuleCompile` из
  `adapters/node-test/preload/patch-module-compile.ts:14-42`, как это делает
  `adapters/node-test/preload/install-module-hooks.ts:76`. Хуки
  `module.register()` не видят `require()` (`patch-module-compile.ts:3-8`), а
  `registerHooks` появился только в Node 22.15 и 23.5
  (`install-module-hooks.ts:49-53`). Vitest 5 работает и на 22.12, поэтому
  опирайтесь на `_compile`, как node:test.
- В воркере нет переключённых текстов. Тексты (`VitestSessionState.files`),
  `served`, `mismatched` и флаг `instrumented` живут в главном процессе, в
  состоянии Vite-плагина
  (`adapters/vitest/types/vitest-session-state.d.ts:18-22,45-54,67-70`). У
  воркера есть mutant runtime (`adapters/vitest/runner.ts:253-256`), опции из
  `provide`: `ProvidedContext.mootant: VitestWorkerOptions` с рабочим каталогом
  `directory` (`adapters/vitest/types/vitest-worker.d.ts:193-220,237-247`), и
  планы юнитов `plan/<hash>.json` в этом каталоге (пишет
  `adapters/vitest/write-plan-files.ts`, читает
  `adapters/vitest/worker/read-worker-plan.ts`). Текстов файлов среди этих
  данных нет. Значит, их надо доставить в воркер, например файлом плана подмены
  в рабочем каталоге по образцу `adapters/node-test/write-switch-plan.ts:16-31`.
  Обратно в главный процесс надо вернуть `served` и `mismatched`. Например,
  полем записи конца юнита по аналогии с `dependencies`
  (`adapters/vitest/types/vitest-worker.d.ts:9-18`): запись идёт через
  `adapters/vitest/worker/write-out-record.ts`, чтение — через
  `adapters/vitest/read-out-files.ts`. Затем эти данные нужно объединить с
  данными плагина там, где dry run собирает `served` и `mismatched`
  (`adapters/vitest/run-dry.ts:126-134`).
- Нужна проверка mismatch, аналог цепочки `resolveSwitchedText` → `null` →
  `mismatched` (`core/instrument/resolve-switched-text.ts:19-33`). Образец
  переключателя — `adapters/node-test/preload/create-source-switcher.ts:35-69`.
  Он переключает только файлы плана и отмечает файл как served маркером, который
  срабатывает, только когда переключённый текст действительно исполнился.
- В dry run без подмены (`request.instrumented === false`,
  `adapters/vitest/run-dry.ts:61-64`) патч не должен ничего переключать, как и
  плагин (`create-mootant-plugin.ts:35`).
- Кэш уже учитывает `require.cache` воркера (`adapters/vitest/runner.ts:1182`).
  Видимо, отдельной правки он не требует (не проверено).

Не здесь:

- `core/run/read-test-imports.ts`, `core/run/rank-test-file.ts` тест-файлы для
  dry run не выбирают. Они только ранжируют файлы, которые уже покрыли мутант в
  dry run (`core/run/rank-mutant-files.ts:52`), и подбирают файл, куда
  предложить дописать тест для NoCoverage (`core/run/rank-module-files.ts:43`
  через `core/run/decide-results.ts:52-55`). Импорты для этого читаются в
  `core/run-mutants.ts:465-467`.

Документация и тестовые помощники:

- `docs/content/guide/compatibility.mdx:34,45-57`. После исправления случая А
  строка таблицы на `:34` верна и для цепочек `require()`. Ограничение случая Б
  опишите рядом с `:56-57`.
- `test/helpers/run-reference-mutants.ts`. В режиме по умолчанию эталон
  запускает `vitest related` по изменённому файлу каждой копии (`:130-133`,
  `:160-169`). Верификатор показал, что `vitest related src/b.cjs` тест не
  находит. Значит, такой эталон для мутантов `b.cjs` ничего не запустит и
  запишет их как «не убиты». Это вывод по чтению кода, запуском не проверен.
  Нужен режим `separate: true` (`:145-153`): каждая копия гоняет все свои тесты
  в своём экземпляре Vitest (`:57-73`). Так уже сделано в
  `test/adapters/vitest/index.test.ts:891-912`.
- `test/helpers/classify-verdict.ts:14-16` сводит NoCoverage к `survived`.
  Поэтому `expectAgreement` (`test/adapters/vitest/index.test.ts:196-207`) не
  отличит выжившего `age == 18` от непокрытого. С эталоном по умолчанию такой
  тест прошёл бы и до исправления: эталон дал бы `survived`, и NoCoverage тоже
  считается `survived`.

## Критерий готовности

- Случай А, обязательно. Появляется новый тест в
  `test/adapters/vitest/index.test.ts` по образцу `runAllPaths` и
  `expectAgreement` (`:135-207`). Он работает на новой фикстуре, например
  `test/fixtures/equivalence/require/`: `src/a.cjs` и `src/b.cjs` как в шаге 1,
  тест `test/a.test.ts` импортирует `../src/a.cjs`, свой `vitest.config.ts` с
  `include: ['test/**/*.test.ts']`, как у соседних фикстур. Тест падает до
  исправления, проходит после и проверяет:
  - вердикты совпадают с эталоном `runReferenceMutants(…, { separate: true })`
    (эталон по умолчанию через `vitest related` здесь неверен);
  - у `age >= 18` → `age == 18` статус именно `Survived`, а не `NoCoverage`;
    остальные четыре мутанта `src/b.cjs` и три мутанта `src/a.cjs` дают
    `Killed`; ни одного `NoCoverage` в результате нет;
  - в `diagnostics` нет `never-served` и `instrument-error` для `src/b.cjs`.
- Тестом покрыта ветка mismatch для модулей, загруженных через `require()`:
  текст на диске отличается от списка → `instrument-error`. Без этого не будет и
  100% покрытия.
- Новые модули получают юнит-тесты по соседству (`test/<тот же путь>.test.ts`),
  как принято в проекте.
- Временный тест из шага 1 проходит (`pnpm exec vitest --run
  test/repros/BUG-507.test.ts`). После проверки каталог `test/repros/` удалён.
- Шаг 2, повторённый целиком после исправления (новые `pnpm build` и
  `pnpm pack`, свежий каталог `FIX`, чтобы npm не сверял новый tarball со старым
  lockfile), не печатает `never-served`. Сводка: killed 7, survived 1, no
  coverage 0, score 87.5%, как под node:test в шаге 3.
- Случай Б. Как минимум ограничение описано в
  `docs/content/guide/compatibility.mdx` рядом с `:56-57`: тесты, которые грузят
  исходники только через `require()` или `createRequire`, Vitest-адаптер не
  выбирает, и мутанты таких исходников получают NoCoverage. Полный отбор тестов
  для Б делается по желанию: отдельным коммитом и с отдельным тестом на фикстуре
  шага 4 (ожидание: 7 Killed, 1 Survived).
- Проверки проекта зелёные при запуске по отдельности: `pnpm test:unit` (с
  порогом покрытия 100%), `pnpm test:js`, `pnpm test:types`, `pnpm test:usage`,
  `pnpm test:spelling`, `pnpm test:format` и остальные `test:*`. `pnpm
  test:astro` запускайте без `dist/` (см. «Ограничения»). Падения, которые
  зависят от окружения (см. «Ограничения»), сверьте с прогоном на нетронутом
  коде.

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига) без явной необходимости; если без этого нельзя — опиши компромисс.
- Сообщения коммитов — Conventional Commits (commitlint).
- Тест из шага 1 нельзя копировать в `test/repros/` как есть. Этот каталог не
  исключён ни из ESLint, ни из knip, cspell или tsc. Исключён только
  `test/fixtures/**` (`eslint.config.ts:15`, `knip.config.ts:5`,
  `cspell.config.ts:44`, `vitest.config.ts:18`, `tsconfig.json:2`). Постоянный
  тест перепишите в стиле проекта под строгий ESLint (имена файлов,
  `describe`/`it`, порядок импортов, JSDoc), а фикстуры кладите в
  `test/fixtures/**`. Каталог `test/repros/`, tarball и временные каталоги в
  коммит не входят.
- `pnpm test` после `pnpm build` даёт ложные ошибки `test:astro`: 14 ошибок
  `ts(2322)` в `docs/components/*.astro`. Причина в том, что `tsconfig.json`
  включает `**/*.ts` и не исключает `dist/`. После сборки в программу попадает
  `dist/types/html/inline-script.d.ts` (из `types/html/inline-script.d.ts`) с
  `/// <reference types="vite/client" />`, и объявления `*.svg` из Vite
  конфликтуют с SVG-компонентами Astro. В CI джоба Astro пакет не собирает,
  поэтому там она зелёная. После шага 2 проверяйте `test:unit`, `test:js`,
  `test:types` и остальные скрипты по отдельности, а `test:astro` запускайте
  после `rm -rf dist`.
- Известные зависимости `test:unit` от окружения, не связанные с этим багом:
  - 4 теста в `test/cli/run-list.test.ts` и `test/cli/run-mutation.test.ts`
    ждут Unicode-символы и падают при `TERM=linux`
    (`cli/terminal/is-unicode-supported.ts:13`); запускайте с
    `TERM=xterm-256color`;
  - тест «skips test files it cannot read»
    (`test/adapters/node-test/score-node-test.test.ts:98`) падает под root;
  - при заданном `NODE_OPTIONS` покрытие ветвей не достигает 100% в
    `adapters/node-test/start-node-test-session.ts:119,167`.
