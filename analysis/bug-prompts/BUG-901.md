# BUG-901: crash и load-error без достижения мутанта засчитываются как Killed

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

`readIsolatedUnit` (`core/run/read-isolated-unit.ts:22-107`) решает isolated-
юнит. Две ветки убивают мутанта, не проверяя, причастен ли он:

- `facts.incomplete === 'crash'` → `Killed`, cause `crash`
  (`read-isolated-unit.ts:42-44`). Адаптер Vitest называет crash-ем любой
  захваченный юнит без end-записи, если его не остановил watchdog
  (`adapters/vitest/build-isolated-facts.ts:32-44`): OOM-killer, сигнал, падение
  пула. Кэш сам считает такие убийства зависящими от загрузки машины и не
  хранит их (`core/cache/create-run-cache.ts:143-144,313-318`), но в текущем
  прогоне они без подтверждения дают `Killed`.
- `facts.loadError !== null` → `Killed`, cause `load-error`
  (`read-isolated-unit.ts:75-83`) без проверки `facts.reached`, хотя для
  хук-ошибок проверка есть (`read-isolated-unit.ts:84`), а end-запись юнита
  Vitest сообщает `reached` и при ошибке загрузки
  (`adapters/vitest/runner.ts:933`). Такое убийство кэшируется и
  переиспользуется следующими прогонами.

Для нестатического мутанта загрузка тест-файла с мутантом и без него
одинакова, пока сайт мутанта не вычислен: ошибка загрузки без `reached` вызвана
окружением (например, тест-файл подключается к сервису на верхнем уровне).

## Воспроизведение

Юнит-тест (ветка `experiment/bug-repros`, `test/repros/BUG-901.test.ts`):

```ts
import { describe, expect, it } from 'vitest'

import type { IsolatedResult } from '../../types/adapter/isolated-result'
import type { MutantState } from '../../types/run/mutant-state'
import type { FakeWorld } from '../helpers/create-fake-adapter'

import { runIsolatedRounds } from '../../core/run/run-isolated-rounds'
import { getFinalStatus } from '../../core/run/get-final-status'
import { createTestRun } from '../helpers/create-test-run'

async function runMutant(
  spoil: (facts: IsolatedResult['units'][number]) => IsolatedResult['units'][number],
): Promise<MutantState> {
  let world: FakeWorld = {
    onIsolated: (result: IsolatedResult, _plan, call) =>
      call === 1 ? { units: result.units.map(spoil) } : result,
    tests: [
      { file: '/t/c.test.ts', id: 'c1' },
      { file: '/t/c.test.ts', covers: ['m'], id: 'c2' },
    ],
  }
  let { session, state } = await createTestRun(world, { mutants: ['m'], isolate: true })
  await runIsolatedRounds(session, state)
  return state.mutants.get('m')!
}

describe('BUG-901', () => {
  it('does not kill a mutant whose only covering file lost its worker once, before any test reached the mutant', async () => {
    let mutant = await runMutant(facts => ({ ...facts, incomplete: 'crash', reached: false, tests: [] }))
    expect(mutant.verdict?.cause).not.toBe('crash')
    expect(getFinalStatus(mutant)).toBe('Survived')
  })

  it('does not kill a mutant that is not reached while loading when its test file failed to load once', async () => {
    let mutant = await runMutant(facts => ({
      ...facts,
      loadError: 'connect ECONNREFUSED 127.0.0.1:5432',
      reached: false,
      tests: [],
    }))
    expect(mutant.verdict?.cause).not.toBe('load-error')
    expect(getFinalStatus(mutant)).toBe('Survived')
  })
})
```

```bash
pnpm exec vitest run test/repros/BUG-901.test.ts
# 2 failed: expected 'crash' not to be 'crash'; expected 'load-error' not to be 'load-error'
```

Сквозные фикстуры на реальном Vitest 5.0.5 (`src/math.js`:
`return a + b`, единственный тест `add runs` вызывает `add(1, 1)` без
проверок, т. е. обычный прогон с любым мутантом проходит):

- в том же файле тест `dies once` во 2-м запуске делает
  `process.kill(process.pid, 'SIGKILL')` → `mootant run --no-cache` →
  `killed 1`, в `--json --verbose --all`: `"status":"Killed","cause":"crash"`;
- верхний уровень тест-файла во 2-й загрузке бросает `connect ECONNREFUSED`
  → `killed 1` (load-error); если счётчик запусков лежит вне проекта (как
  внешний сервис — вне входов кэша), второй прогон с кэшем печатает
  `Reused a cached verdict for 1 of 1 mutants` и снова `killed 1`, хотя файл
  уже грузится; `--no-cache` → `survived 1`.

## Ожидаемое поведение

- `load-error` без `reached` у нестатического мутанта не решает ничего: юнит
  повторяется (как юнит без фактов), при повторной ошибке — `Error` с
  диагностикой; такая улика не кэшируется.
- `crash` подтверждается повтором, как timeout с `hang`
  (`core/run/get-unit-evidence.ts:129-135`): `Killed` только если повтор тоже
  падает; одиночный crash без подтверждения — не убийство.
- В сценариях выше мутант `Survived`.

## Фактическое поведение

`Killed` (cause `crash` или `load-error`) с первой попытки; load-error-убийство
переживает следующие прогоны через кэш.

## Подозреваемые места в коде

- `core/run/read-isolated-unit.ts:42-44` — crash без подтверждения.
- `core/run/read-isolated-unit.ts:75-83` — load-error без `facts.reached`/
  `mutant.static`.
- `core/run/get-unit-evidence.ts:122-137` — подтверждение есть только для
  `time-limit`/`hang`.
- `core/cache/create-run-cache.ts:313-318` — что кэшируется.
