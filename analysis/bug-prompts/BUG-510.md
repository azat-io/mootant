# BUG-510: node:test — проба Node падает со стеком, если `NODE_OPTIONS` подгружает печатающий модуль

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён. Найдено на
> коммите 170ec52.
>
> Перепроверено независимо: воспроизведено — данных нет (BUG-510 не попал в
> перепроверку двумя агентами, итогового решения координатора по нему нет,
> поэтому серьёзность оставлена заявленной); скептик: не проводился. Для этой
> версии промпта цитаты кода сверены с 170ec52 только чтением, без запусков.
> Исправлены два утверждения исходной версии: какой `NODE_OPTIONS` видит проба
> и печатает ли `-r dotenv/config` (по умолчанию не печатает).

## Контекст

При старте сессии node:test (`adapters/node-test/start-node-test-session.ts:72`)
mootant узнаёт версию Node и поддержку type stripping. `readNodeRuntime`
(`adapters/node-test/read-node-runtime.ts:18-33`) запускает
`execFile(node, ['-p', PROBE], …)` (скрипт `PROBE` — `:7-8`) без опции `env`,
то есть с окружением самого процесса mootant. `JSON.parse(stdout)` выполняется
прямо в колбэке `execFile` (колбэк — `:22-31`, разбор — `:24`). Если
`NODE_OPTIONS` этого окружения подгружает модуль (например,
`--require ./print.cjs`), который при загрузке пишет в stdout, ответ пробы
начинается не с JSON, и `JSON.parse` бросает `SyntaxError`.

Колбэк вызывается из `ChildProcess.exithandler`, вне промиса, поэтому
исключение не становится его отказом, а остаётся неперехваченным. В главном
процессе mootant `uncaughtException` никто не слушает. Подписки на ошибки
процесса есть только в коде тестовых процессов: в preload node:test
(`adapters/node-test/preload/preload.ts:77-82`) и в раннере воркеров Vitest
(`adapters/vitest/runner.ts:1261-1262`). Node печатает стек и завершает процесс
с кодом 1. `catch` команды `run`, который печатает `Error: …`
(`cli/run-mutation.ts:83-94`), не срабатывает, промис `readNodeRuntime` так и
не завершается. Прогон node:test в таком окружении невозможен.

Что ещё следует из кода (запуском не проверялось):

- Проба видит только `NODE_OPTIONS`, экспортированный в окружение, где
  запущен mootant: оболочку, CI, IDE, direnv. Переменные из самого тест-скрипта
  (`"test": "NODE_OPTIONS=… node --test"`; их собирает в `command.env`
  `adapters/node-test/resolve-command.ts:54-61`) и из `nodeTestAdapter({ env })`
  попадают только в окружение тестовых процессов
  (`start-node-test-session.ts:111-116`). Отсюда обход до исправления: не
  экспортировать печатающий preload в окружение mootant.
- Та же авария будет при любом stdout пробы, который не является JSON, если
  код выхода 0. Например, когда `nodeTestAdapter({ node })` указывает на
  обёртку, которая что-то печатает.
- Рабочий каталог прогона `mootant-XXXXXX` создаётся в TMPDIR до старта
  адаптера (`core/run-mutants.ts:271`, `core/run/create-work-directory.ts:26-32`),
  а удаляется в `finally` (`core/run-mutants.ts:324`). При аварийном выходе
  `finally` не выполняется, и каталог остаётся.

Насколько это распространено. Исходная версия промпта называла вероятным
источником `-r dotenv/config` у dotenv 17. Для настроек по умолчанию это
неверно. В dotenv 17.0.0, 17.2.3, 17.3.1 и 17.4.2 точка входа `dotenv/config`
(`node_modules/dotenv/config.js:1-9`) передаёт в `config()` опции из
`lib/cli-options.js`. Если в argv нет `dotenv_config_quiet=…`, тот ставит
`quiet = 'true'` (`lib/cli-options.js:12-14`). Строку о загрузке `.env`
(`console.log`, то есть stdout) `-r dotenv/config` печатает при
`DOTENV_CONFIG_QUIET=false` или `DOTENV_CONFIG_DEBUG=true`, заданных в
окружении или в самом `.env` (в 17.4.2 — `lib/main.js:248`, `:292-294`).
Проверено чтением исходников этих версий dotenv, запуском с mootant — нет.
Реальный источник проблемы — собственные preload и инструментирование, если
они печатают в stdout при загрузке. Тест ниже имитирует такой preload.

## Воспроизведение

Ветки `experiment/bug-repros` в публичном репозитории нет, все файлы ниже
создайте сами. Нужны:

- Node.js 22.12 или новее. Сам mootant поддерживает `^20.19.0 || >=22.12.0`,
  но Vitest 5 из devDependencies требует `^22.12.0 || ^24.0.0 || >=26.0.0`
  (`docs/content/guide/compatibility.mdx:22-24`).
- pnpm 12 (`contributing.md:98`; в CI стоит `latest-12`,
  `.github/actions/install-tools/action.yml:11-15`). По наблюдению анализа,
  pnpm 10 не читает `configDependencies` из `pnpm-workspace.yaml`, и команды
  pnpm внутри репозитория у него зависают.

### Шаг 1. Падающий unit-тест в клоне (так баг найден)

Тест взят без изменений из локальной ветки анализа
(`test/repros/BUG-510.test.ts`, коммит `6b1e3de`). Положите его временно по
тому же пути: под него написан относительный импорт. Корневой конфиг Vitest
берёт всё из `test/`, кроме `test/fixtures/**` (`vitest.config.ts:18`).
Сборка для этого шага не нужна. В коммит файл не входит, и перед проверками
lint/types его нужно удалить (см. «Ограничения»). Комментарий о dotenv внутри
теста неточен (см. «Контекст»), в новый тест его не переносите.

```bash
# в корне клона azat-io/mootant
pnpm install
pnpm exec vitest --run test/adapters/node-test/read-node-runtime.test.ts   # контроль: 2 существующих теста проходят

mkdir -p test/repros
cat > test/repros/BUG-510.test.ts <<'EOF'
import { afterEach, describe, expect, it } from 'vitest'
import { mkdtemp, writeFile, rm } from 'node:fs/promises'
import { tmpdir } from 'node:os'
import path from 'node:path'

import { readNodeRuntime } from '../../adapters/node-test/read-node-runtime'

/**
 * `NODE_OPTIONS` of the test process before the test changed it.
 */
let originalOptions = process.env['NODE_OPTIONS']

/**
 * Directory of the preload that prints to stdout.
 */
let directory: string | null = null

describe('BUG-510: node:test probe with a preload that prints', () => {
  afterEach(async () => {
    if (originalOptions === undefined) {
      delete process.env['NODE_OPTIONS']
    } else {
      process.env['NODE_OPTIONS'] = originalOptions
    }
    if (directory !== null) {
      await rm(directory, { recursive: true, force: true })
      directory = null
    }
  })

  it('reads the runtime when NODE_OPTIONS preloads a module that prints', async () => {
    directory = await mkdtemp(path.join(tmpdir(), 'mootant-print-'))
    let preload = path.join(directory, 'print.cjs')
    // As `-r dotenv/config` of dotenv 17 prints "[dotenv@17…] injecting env"
    await writeFile(preload, "console.log('[preload] hello')\n")
    process.env['NODE_OPTIONS'] = `--require ${preload}`

    /*
     * `node -p PROBE` prints the preload's line before the JSON; `JSON.parse`
     * of the whole stdout throws inside the `execFile` callback, so the
     * promise never settles and the exception is uncaught: `mootant run`
     * crashes with a stack trace instead of starting the session.
     */
    await expect(readNodeRuntime(process.execPath)).resolves.toMatchObject({
      version: process.version,
    })
  })
})
EOF

pnpm exec vitest --run test/repros/BUG-510.test.ts; echo "exit=$?"   # до исправления: exit=1
```

### Шаг 2. Сквозной прогон упакованного mootant на фикстуре node:test

`bin/mootant.js` импортирует `../dist/cli/index.js` (`bin/mootant.js:3`), а
скрипта `prepack` в `package.json` нет, поэтому перед `pnpm pack` нужен
`pnpm build`. Фикстура повторяет `nt-basic` из анализа. Ставить в неё нужно
только tarball mootant: адаптер node:test выбирается по тест-скрипту
(`adapters/node-test/score-node-test.ts:31-38`), а `vitest` у mootant —
необязательная peer-зависимость. Если для другой фикстуры понадобится Vitest,
ставьте `npm i -D vitest@5`, а не `vitest@5.0.5`: в npm 10.9.9 установка 5.0.5
падает с `Cannot read properties of null (reading 'edgesOut')`, это баг
arborist. `mootant run` без путей завершается ошибкой «mootant run needs
paths» (`core/run-mutants.ts:183-185`), поэтому команда — `mootant run src`.
`--no-cache` не даёт mootant оставить кэш в
`node_modules/.cache/mootant/run-v3.json` фикстуры
(`core/cache/get-cache-path.ts:13-20`, `core/cache/cache-version.ts:6`).
Команды рассчитаны на одну сессию shell: они используют переменные `CLONE`,
`PACK`, `TGZ` и `FIX`.

```bash
# в корне клона, после шага 1 (зависимости стоят)
CLONE="$(pwd)"
pnpm build
pnpm pack
PACK="$(mktemp -d)"
mv mootant-*.tgz "$PACK/"     # *.tgz нет в .gitignore, не оставляйте его в дереве
TGZ="$(ls "$PACK"/mootant-*.tgz)"

FIX="$(mktemp -d)"
cd "$FIX"
mkdir -p src test

cat > package.json <<'EOF'
{
  "name": "nt-basic",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": { "test": "node --test" }
}
EOF

cat > src/math.js <<'EOF'
export function add(a, b) {
  return a + b
}

export function isAdult(age) {
  return age >= 18
}

export function label(n) {
  if (n > 10) {
    return 'big'
  }
  return 'small'
}
EOF

cat > test/math.test.js <<'EOF'
import { it } from 'node:test'
import assert from 'node:assert/strict'

import { add, isAdult, label } from '../src/math.js'

it('adds', () => {
  assert.equal(add(2, 3), 5)
})

it('checks adults', () => {
  assert.equal(isAdult(30), true)
  assert.equal(isAdult(3), false)
})

it('labels', () => {
  assert.equal(label(100), 'big')
})
EOF

# preload, печатающий в stdout при загрузке; под шаблоны тест-файлов
# (adapters/node-test/get-default-patterns.ts:6-13) он не попадает
printf "console.log('[preload] hello')\n" > print.cjs

npm i -D "$TGZ"
node --test                       # без mootant: 3 теста проходят
./node_modules/.bin/mootant run src --no-cache; echo "exit=$?"   # контроль: отчёт без SyntaxError, запомните код выхода
NODE_OPTIONS="--require ./print.cjs" ./node_modules/.bin/mootant run src --no-cache; echo "exit=$?"   # до исправления: стек SyntaxError, exit=1
cd "$CLONE"
```

После исправления пересоберите пакет и переустановите его в ту же фикстуру.
Имя tarball не меняется, поэтому `package-lock.json` с прежним integrity
удалите:

```bash
cd "$CLONE" && pnpm build && pnpm pack && mv mootant-*.tgz "$PACK/"
cd "$FIX" && rm -rf node_modules package-lock.json && npm i -D "$TGZ"
NODE_OPTIONS="--require ./print.cjs" ./node_modules/.bin/mootant run src --no-cache; echo "exit=$?"
cd "$CLONE"
```

## Ожидаемое поведение

- `readNodeRuntime` никогда не бросает вне промиса. Если ответ пробы не
  разобрать, промис отклоняется с `Error`, CLI печатает `Error: …` в stderr и
  выходит с кодом 1 (`cli/run-mutation.ts:83-94`), а рабочий каталог
  удаляется. Сообщение называет бинарник Node и подсказывает причину,
  например показывает начало stdout и упоминает `NODE_OPTIONS`.
- Посторонний вывод preload (целые строки до ответа пробы) не мешает
  прочитать версию и признак type stripping: прогон из шага 2 идёт так же,
  как без `NODE_OPTIONS`. Строка `[preload] hello`, которую печатает сам
  процесс mootant (он тоже получает этот `NODE_OPTIONS`), в stdout
  останется. Это не часть бага.
- Признак `typescript` по-прежнему отражает флаги, с которыми стартуют
  тестовые процессы, включая флаги из `NODE_OPTIONS` (см. «Подозреваемые
  места»).

## Фактическое поведение

Шаг 2, прогон с `NODE_OPTIONS`. Вывод из анализа (Node 22.23.4, упакованный
mootant 170ec52); сырой лог в данных анализа не сохранён:

```
[preload] hello
<anonymous_script>:1
[preload] hello
 ^

SyntaxError: Unexpected token 'p', "[preload] h"... is not valid JSON
    at JSON.parse (<anonymous>)
    at file:///…/node_modules/mootant/dist/adapters/node-test/read-node-runtime.js:6:23
    at ChildProcess.exithandler (node:child_process:410:7)
```

- Первая строка — вывод preload в самом процессе mootant. При запуске через
  `npx` она появится ещё раз: `npx` тоже процесс Node.
- Следующие три строки — фрагмент строки, которую получил `JSON.parse`, то
  есть stdout пробы.
- `:6:23` указывает на `JSON.parse(i)` в собранном
  `dist/adapters/node-test/read-node-runtime.js` коммита 170ec52 (сверено
  чтением сборки).
- Номер строки в `node:child_process` зависит от версии Node.

Строки `Error: …` нет, код выхода 1.

Шаг 1: тест падает по таймауту 5 с с «Unhandled Errors: SyntaxError …» в
отчёте Vitest. Это стандартный `testTimeout` Vitest: `vitest.config.ts` и
`vite.config.ts` его не меняют.

## Подозреваемые места в коде

- `adapters/node-test/read-node-runtime.ts:22-31` — колбэк `execFile`: разбор
  stdout (`:24`) без `try/catch`, исключение уходит мимо промиса.
- `adapters/node-test/read-node-runtime.ts:7-8` — `PROBE` печатает голый JSON,
  и его нельзя отличить от чужого вывода.
- `adapters/node-test/start-node-test-session.ts:72` — единственный вызов
  пробы. Других мест, где stdout дочернего процесса разбирается через
  `JSON.parse` после `execFile`, в `adapters/`, `core/` и `cli/` нет.
- `adapters/node-test/start-node-test-session.ts:80-83` — `strips` зависит от
  `runtime.typescript`. Флаги type stripping явно ищутся только в `execArgv`
  команды, а флаги из `NODE_OPTIONS` учитываются только через пробу.

Направление исправления (по чтению кода; ни один вариант не проверялся
запуском):

- Одного `try/catch` с `reject(new Error(…))` мало. Он убирает стек и
  зависший промис, но прогон в таком окружении по-прежнему не стартует, а
  «Ожидаемое поведение» требует большего.
- Ответ пробы нужно отделить от чужого вывода: например, `PROBE` печатает
  уникальный маркер в начале отдельной строки, а разбор ищет строку с этим
  маркером. Можно и вообще передать ответ не через stdout. Вариант «последняя
  строка stdout» работает, только если чужой вывод состоит из целых строк до
  ответа. Он ломается, если вывод перед ответом не заканчивается переводом
  строки или если что-то печатается после ответа (например, обработчик `exit`
  в preload).
- Запускать пробу без `NODE_OPTIONS` не стоит. По `@types/node`
  (`process.d.ts`, `process.features.typescript`) значение равно `"strip"` по
  умолчанию, `"transform"` с `--experimental-transform-types` и `false` с
  `--no-strip-types`. Тестовые процессы наследуют `NODE_OPTIONS`
  (`start-node-test-session.ts:111-116`, `:164-171`). Если такие флаги приходят
  через `NODE_OPTIONS`, проба без них неверно определит type stripping в
  тестовых процессах. Принимает ли Node эти флаги в `NODE_OPTIONS`, здесь не
  проверялось.

## Критерий готовности

- В `test/adapters/node-test/read-node-runtime.test.ts` появляются тесты в
  стиле соседних. До исправления они падают (таймаут и unhandled
  `SyntaxError`), после проходят:
  - `NODE_OPTIONS` с `--require` preload, печатающего целую строку в stdout:
    `readNodeRuntime(process.execPath)` разрешается с
    `version: process.version` и булевым `typescript`;
  - stdout при коде выхода 0 без ответа пробы: промис отклоняется с `Error`,
    в сообщении есть путь к бинарнику, неперехваченных исключений нет.
    Подойдёт, например, preload с `process.exit(0)` (stdout пуст) или
    исполняемый скрипт, который вместо Node печатает не-JSON. CI гоняет тесты
    только на `ubuntu-latest` (`.github/workflows/test.yml`). Оба варианта
    фикстуры запуском не проверялись.
- Временный `test/repros/BUG-510.test.ts` из шага 1 после исправления проходит
  и в коммит не попадает.
- Шаг 2 после пересборки и переустановки пакета: с
  `NODE_OPTIONS="--require ./print.cjs"` нет `SyntaxError`, прогон доходит до
  отчёта, а код выхода совпадает с контрольным прогоном без `NODE_OPTIONS`.
  По коду результаты тестов mootant читает из out-файла, а не из stdout
  тестовых процессов (`adapters/node-test/run-test-process.ts:99-115`), и их
  stdout уходит только в вывод тестов (`:116-129`). Поэтому печать preload
  внутри тестовых процессов вердиктам мешать не должна. Запуском это не
  проверено.
- По отдельности зелёные `pnpm test:unit` (порог coverage 100%, новые ветки
  разбора покрыты), `pnpm test:js`, `pnpm test:types`, `pnpm test:usage`,
  `pnpm test:spelling` и `pnpm test:format`. `test:unit` запускайте как
  `env -u NODE_OPTIONS TERM=xterm-256color pnpm test:unit`. Если окружение
  совпадает с CI (нет `dist/`, не root, нет `NODE_OPTIONS`, `TERM` не
  `linux`), `pnpm test` зелёный целиком. Падения, которые есть и на
  нетронутом 170ec52 (см. «Ограничения»), исправлению не мешают. Их нужно
  перечислить в отчёте.

## Ограничения

- Соблюдай стиль проекта: TypeScript, ESM, «одна функция — один файл», JSDoc
  на каждую функцию, `let` вместо `const` там, где так принято в проекте,
  строгий ESLint (`@azat-io/eslint-config`), cspell, knip.
- Не ломай публичный API (`exports` в `package.json`, типы в `types/`, формат
  конфига) без явной необходимости; если без этого нельзя — опиши компромисс.
- Сообщения коммитов — Conventional Commits (commitlint).
- Тест-воспроизведение из анализа нельзя копировать как есть в `test/repros/`.
  Его нужно переписать в стиле проекта, потому что строгий ESLint его не
  пропустит:
  - имя `BUG-510.test.ts` нарушает `unicorn/filename-case`: разрешены только
    kebab-case и PascalCase;
  - perfectionist сортирует строки импорта и имена внутри `{ … }` по длине
    строки по убыванию, а в тесте порядок другой.

  В проекте `describe` называют по функции (`describe('readNodeRuntime', …)`),
  а окружение восстанавливают через `process.env = { ...SAVED }`
  (`test/adapters/node-test/start-node-test-session.test.ts`). Сценарий пишите
  в `test/adapters/node-test/read-node-runtime.test.ts`. Статические фикстуры,
  например файл preload, кладите в `test/fixtures/**`. Их исключают Vitest
  (`vitest.config.ts:18`), ESLint (`eslint.config.ts`), `tsc`
  (`tsconfig.json:2`) и knip (`knip.config.ts`). Временные файлы создавайте
  через `mkdtemp(tmpdir())` и удаляйте в `afterEach`. Перед `test:js`,
  `test:types` и `test:spelling` удалите временный `test/repros/`.
- `pnpm test` после `pnpm build` даёт ложные ошибки `test:astro`: по базовой
  линии анализа это 14 ошибок `ts(2322)` в `docs/components/*.astro`.
  Причина — `tsconfig.json:2-4` не исключает `dist/`, и в программу попадает
  `dist/types/html/inline-script.d.ts` с
  `/// <reference types="vite/client" />`. В CI джоба Astro пакет не собирает,
  поэтому она зелёная. После сборки проверяйте `test:unit`, `test:js`,
  `test:types` и остальные `test:*` по отдельности, а `test:astro` запускайте
  только после `rm -rf dist`.
- По базовой линии анализа есть тесты, которые зависят от окружения и падают
  и без исправления:
  - 4 теста CLI в `test/cli/run-list.test.ts` и
    `test/cli/run-mutation.test.ts` ждут Unicode-символов, а при `TERM=linux`
