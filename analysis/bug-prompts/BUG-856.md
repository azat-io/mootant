# BUG-856: тесты `core/git` не защищают разбор диффа для `--since`

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

`--since <ref>` оставляет только мутантов на изменённых строках. Строки
читаются из `git diff --unified=0` (`core/git/parse-unified-diff.ts`), список
бинарных для git файлов — из `git diff --numstat -z`
(`core/git/parse-binary-paths.ts`, `core/git/read-changed-lines.ts:76-77`).
Ошибка в этом разборе молча теряет мутантов в CI-сценарии «только изменения
PR». Покрытие строк и веток у модуля 100 %, но мутационный прогон
`mootant run core/git` оставляет 37 выживших, и 14 из них — настоящие
непроверенные поведения.

Главное: тест `test/core/git/parse-unified-diff.test.ts:81-94` («never reads
changed lines as headers») не может упасть по своей причине. Он должен
проверять, что строки ханка пропускаются по счётчику
(`parse-unified-diff.ts:29-33,44-47`), но его «коварные» строки (`'---- a/x'`,
`'-@@ -1 +1 @@'`, `'++++ b/other.ts'`, `'+@@ -7 +7 @@'`) разборщик не принял бы
за заголовки и без пропуска. `^@@` не совпадает с `-@@`/`+@@`, а
`'++++ b/other.ts'.startsWith('+++ ')` ложно: четвёртый символ `+`, а не
пробел. Двусмысленна только добавленная строка с текстом `++ …`: в диффе она
выглядит как `+++ …`.

## Воспроизведение

```bash
# 1. Логика пропуска не защищена: удалить её — тесты зелёные
sed -i 's/^    remaining = Number(removed) + count$/    \/\/ removed/' core/git/parse-unified-diff.ts
pnpm exec vitest --run test/core/git/parse-unified-diff.test.ts   # 6 passed
git checkout core/git/parse-unified-diff.ts

# 2. Выжившие мутанты модуля
pnpm run build
node bin/mootant.js run core/git --concurrency 2 --json --all > git.json
# 238 мутантов: Killed 199, Timeout 2, Survived 37 (score 84,45 %)
```

Выжившие, которые закрываются тестами ниже: `parse-unified-diff.ts:47`
(удаление `remaining = …` и `+` → `-`), `:29` (`> 0` → `> 1`), `:30` (×2,
обработка `\ No newline`), `:31` (`-= 1` → `-= 2`), `:44` (`'1'` → `''`), `:8`
(×3, `\d+` → `[^]+` в группах `HUNK_PATTERN`), `read-changed-lines.ts:77`
(`--numstat` без `base`), `run-git.ts:47` (удалён `maxBuffer`), `run-git.ts:57`
(у неуспешной команды пропал `stdout`), `unquote-git-path.ts:39`
(`index + 4` → `index + 5`).

## Ожидаемое поведение

Тесты падают, если:

- строка ханка, похожая на заголовок `+++ `, не пропущена по счётчику (в
  том числе последняя строка ханка, строка после `\ No newline` и ханк с
  опущенным числом удалённых строк);
- после ханка `-N,0` теряется следующий ханк того же файла или контекст
  функции после `@@` ломает разбор заголовка;
- бинарный для git файл, изменённый **коммитом** на ветке (а не только в
  рабочем дереве), выпал из `--since`;
- вывод git больше 1 МиБ (дефолтный `maxBuffer` у `execFile`) ломает `runGit`;
- октальный escape в кавычках пути, за которым идёт цифра, читается неверно.

## Фактическое поведение

Все перечисленные изменения кода проходят существующие тесты (см.
воспроизведение).

## Подозреваемые места в коде

Код верен. Неполны тесты:

- `test/core/git/parse-unified-diff.test.ts:81-94`;
- `test/core/git/read-changed-lines.test.ts:66-120`: `src/binary.ts` и
  `src/vendor.js` меняются только в рабочем дереве;
- `test/core/git/run-git.test.ts:43-57` (не проверены `stdout` неуспешной
  команды и большой вывод), `:59-76` (в `objectContaining` нет `maxBuffer`);
- `test/core/git/unquote-git-path.test.ts:6-17`.

- Новые тесты проходят на текущем коде (проверено на 170ec52: 25/25 в
  `test/core/git/`).
- Повторный `node bin/mootant.js run core/git --mutant <id> …` по 37
  выжившим даёт 14 убитых. Остаются только эквивалентные (`code !== 0` →
  `> 0` ×6, `split('\t', 2)` → `3`, `'utf8'` → `''`, `?? → ||` в
  `unquote-git-path.ts:42`, инварианты формата git), шумовые (`256 * 1024 *
  1024`) и `stderr.trim()` в текстах ошибок. Последние можно закрыть
  точным сравнением сообщения (`toThrow(new Error('…'))` вместо подстроки)
  или явно принять.
- Если удалить `remaining = Number(removed) + count`, новый тест падает.
- `pnpm test` полностью зелёный (включая 100 % coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
