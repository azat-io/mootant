# BUG-850: порог coverage 100 % падает на машине с `NODE_OPTIONS`

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

`pnpm test:unit` запускает `vitest --run --coverage` с порогом 100 % по
statements, branches, functions и lines (`vitest.config.ts:9-14`). На этот же
скрипт опирается `release:check` (`package.json`, `pnpm test && pnpm run
build`). В адаптере node:test есть две ветки, которые зависят от переменной
окружения **машины, где идут тесты**:

- `adapters/node-test/start-node-test-session.ts:119` —
  `...(environment['NODE_OPTIONS'] ?? '').split(/\s+/u)`;
- `adapters/node-test/start-node-test-session.ts:167` —
  `placePreload(preload, execArgv, environment['NODE_OPTIONS'] ?? '')`.

`environment` собирается из `process.env` (`:111-116`). Если у разработчика
или в CI задан `NODE_OPTIONS`, правая сторона `?? ''` не выполняется ни в одном
тесте, branch coverage падает ниже 100 %, и `test:unit` завершается с ошибкой
при **полностью зелёных тестах**. `NODE_OPTIONS` задают часто: отладчик
VS Code (auto-attach, «JavaScript Debug Terminal»), `--max-old-space-size` в
CI, `--use-openssl-ca` за корпоративным прокси.

## Воспроизведение

```bash
pnpm install --frozen-lockfile --ignore-scripts
NODE_OPTIONS=--use-openssl-ca pnpm exec vitest --run --coverage \
  --coverage.include=adapters/node-test/start-node-test-session.ts \
  test/adapters/node-test/start-node-test-session.test.ts
# Branch 94.11% (32/34), Uncovered Line #s 119,167; 12/12 тестов зелёные

env -u NODE_OPTIONS pnpm exec vitest --run --coverage \
  --coverage.include=adapters/node-test/start-node-test-session.ts \
  test/adapters/node-test/start-node-test-session.test.ts
# Branch 100% (34/34)

NODE_OPTIONS=--use-openssl-ca pnpm test:unit
# ERROR: Coverage for branches (99.98%) does not meet global threshold (100%)
```

## Ожидаемое поведение

Результат `pnpm test:unit` не зависит от того, задан ли `NODE_OPTIONS` в
окружении: обе ветки `?? ''` покрыты тестами, которые сами задают нужное
состояние переменной.

## Фактическое поведение

С `NODE_OPTIONS` в окружении порог branches не выполняется (99,98 % < 100 %),
без него — выполняется.

## Подозреваемые места в коде

- `test/adapters/node-test/start-node-test-session.test.ts` — ни один тест не
  фиксирует `NODE_OPTIONS`, все берут его из окружения процесса.
- `adapters/node-test/start-node-test-session.ts:119,167` — ветки, которые
  покрываются только при «пустом» окружении.
- Проверить также `adapters/node-test/get-node-cache-inputs.ts:69`
  (`input.env['NODE_OPTIONS'] ?? null`) и другие чтения `process.env` в
  адаптерах: `grep -rn "NODE_OPTIONS" adapters core cli`.

## Критерий готовности

- В `test/adapters/node-test/start-node-test-session.test.ts` есть тесты,
  которые явно задают оба состояния: `vi.stubEnv('NODE_OPTIONS', undefined)`
  и непустое значение, например `--max-old-space-size=4096`. Они проверяют
  итоговые `execArgv`/`NODE_OPTIONS` дочернего процесса. В `afterEach` —
  `vi.unstubAllEnvs()`.
- `NODE_OPTIONS=--use-openssl-ca pnpm test:unit` и `env -u NODE_OPTIONS pnpm
  test:unit` оба зелёные, включая порог 100 %.
- `pnpm test` полностью зелёный (включая `test:js`, `test:types`,
  `test:usage`, `test:spelling`).
- Желательно: общий `test.setupFiles` (или `test.env` в `vitest.config.ts`),
  который нормализует переменные окружения, влияющие на код: `NODE_OPTIONS`,
  `TERM`, `CI`, `NO_COLOR`, `FORCE_COLOR`. Тогда такие зависимости не
  вернутся с новым кодом. Тесты, которые проверяют сами переменные, и так
  стабят их явно (`test/cli/terminal/*.test.ts`).
