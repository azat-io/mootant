# BUG-410: изменения в `node_modules` без смены lockfile дают устаревшие вердикты

> Самодостаточный промпт для отдельной сессии Claude Code в репозитории
> azat-io/mootant. Серьёзность: medium. Статус: подтверждён.
> Найдено на коммите 170ec52.

## Контекст

Из зависимостей тестового файла исключается всё под `node_modules`, «which the
lockfile stands for»: модули — в `getModuleFile`
(`adapters/vitest/get-module-file.ts:17-20`), чтения через `node:fs` — в
`trackInputs` (`adapters/shared/track-inputs.ts:33`), для `node:test` — в
`collectNodeDependencies` (`adapters/node-test/collect-node-dependencies.ts:49-55`).
Взамен в ключ окружения входит первый lockfile, найденный от root вверх
(`core/cache/find-lockfile.ts:23-38`, `core/cache/prepare-run-cache.ts:120-124`).
Допущение «lockfile описывает содержимое `node_modules`» нигде не проверяется
и в документации не упомянуто. Оно ломается, когда код зависимости меняется
без lockfile: `patch-package` (патчи в `patches/` применяет `postinstall`),
ручной патч в `node_modules`, проект без lockfile (`package-lock=false` в
`.npmrc`, lockfile в `.gitignore` — в библиотеках так бывает), `node_modules`,
не переустановленные после смены ветки. Тогда кэш возвращает старые вердикты в
обе стороны (ложный `Survived` и ложный `Killed`) без предупреждения.

## Воспроизведение

Создай `test/repros/BUG-410.test.ts` и запусти
`pnpm vitest run test/repros/BUG-410.test.ts --coverage.enabled=false` (падает
на 170ec52):

```ts
import { writeFile, realpath, mkdtemp, symlink, mkdir, rm } from 'node:fs/promises'
import { afterEach, expect, it } from 'vitest'
import { setTimeout } from 'node:timers/promises'
import { tmpdir } from 'node:os'
import path from 'node:path'

import type { RunResult } from '../../types/run/run-result'

import { createBuiltIns } from '../helpers/create-built-ins'
import { vitestAdapter } from '../../adapters/vitest/index'
import { runMutants } from '../../core/run-mutants'

let roots: string[] = []

async function write(root: string, files: Record<string, string>): Promise<void> {
  for (let [file, text] of Object.entries(files)) {
    await mkdir(path.dirname(path.join(root, file)), { recursive: true })
    await writeFile(path.join(root, file), text)
  }
  // Files modified in the millisecond a run starts count as changed during it.
  await setTimeout(5)
}

function run(root: string, cache = true): Promise<RunResult> {
  return runMutants({
    builtIns: createBuiltIns('vitest', vitestAdapter()),
    paths: ['src'],
    concurrency: 1,
    cwd: root,
    cache,
  })
}

function verdicts(result: RunResult): Record<string, string> {
  return Object.fromEntries(
    result.results.map(entry => [entry.mutant.replacement, entry.status]),
  )
}

afterEach(async () => {
  await Promise.all(roots.splice(0).map(root => rm(root, { recursive: true, force: true })))
})

it('runs the mutants again when a dependency is patched in place', async () => {
  let root = await realpath(await mkdtemp(path.join(tmpdir(), 'mootant-bug-')))
  roots.push(root)
  await mkdir(path.join(root, 'node_modules'))
  await symlink(
    await realpath(path.resolve(import.meta.dirname, '../../node_modules/vitest')),
    path.join(root, 'node_modules/vitest'),
  )
  await write(root, {
    'node_modules/limits-pkg/package.json':
      '{ "name": "limits-pkg", "type": "module", "main": "index.js" }',
    'node_modules/limits-pkg/index.js': 'export default { age: 30 }\n',
    'package-lock.json': '{ "lockfileVersion": 3, "packages": {} }\n',
    'vitest.config.ts': "export default { test: { include: ['test/**/*.test.ts'] } }\n",
    'test/math.test.ts': [
      "import { expect, it } from 'vitest'",
      "import limits from 'limits-pkg'",
      "import { isAdult } from '../src/math'",
      "it('isAdult', () => {",
      '  expect(isAdult(limits.age)).toBe(true)',
      '  expect(isAdult(5)).toBe(false)',
      '})',
    ].join('\n'),
    'src/math.ts': 'export function isAdult(age: number): boolean {\n  return age >= 18\n}\n',
    'package.json': '{ "type": "module" }',
  })
  await run(root)
  // As patch-package or a manual fix does: the lockfile stays the same.
  await write(root, { 'node_modules/limits-pkg/index.js': 'export default { age: 18 }\n' })

  let cached = await run(root)
  let fresh = await run(root, false)

  expect(verdicts(cached)).toStrictEqual(verdicts(fresh))
}, 120_000)
```

С `node:test` — то же (сценарий `nt_node_modules_patch` в

## Ожидаемое поведение

После правки кода зависимости вердикты пересчитываются: второй прогон
совпадает с прогоном без кэша (`age > 18` — `Killed`, `age == 18` —
`Survived`).

## Фактическое поведение

```
- Expected
+ Received
  {
-   "age == 18": "Survived",
-   "age > 18": "Killed",
+   "age == 18": "Killed",
+   "age > 18": "Survived",
    "age >= 17": "Survived",
  }
```

## Подозреваемые места в коде

- `adapters/vitest/get-module-file.ts:17-20`,
  `adapters/node-test/collect-node-dependencies.ts:49-55` — файлы из
  `node_modules` отбрасываются до хэширования. Вариант исправления: хэшировать
  файлы `node_modules`, которые тесты реально загрузили (они общие для многих
  тестов, а `hashFiles` хэширует каждый путь один раз за прогон), в ключе
  окружения или ключах тестов; дешёвый частичный вариант — добавить в файлы
  окружения «установленный» lockfile (`node_modules/.package-lock.json`,
  `node_modules/.pnpm/lock.yaml`, `node_modules/.modules.yaml`,
  `node_modules/.yarn-state.yml`) и каталог `patches/`, но он не ловит ручную
  правку.
- `core/cache/find-lockfile.ts:23-38` — без lockfile в проекте ищется любой
  lockfile выше по дереву, вплоть до корня ФС; в проекте без lockfile ключ не
  описывает зависимости вообще.
- `docs/content/guide/configuration.mdx:350-359` — допущение и способ
  обойти его (`--no-cache` не обновляет кэш, нужно удалить каталог) стоит
  описать.

## Критерий готовности

- Появляется тест (интеграционный в `test/adapters/vitest/index.test.ts` по
  образцу теста выше и unit в `test/core/cache/` или
  `test/adapters/vitest/collect-dependencies.test.ts` для выбранного
  механизма), который падает до исправления и проходит после.
- `pnpm test` полностью зелёный (включая 100% coverage, `test:js`,
  `test:types`, `test:usage`, `test:spelling`).
- Повторный прогон неизменённого проекта по-прежнему берёт все вердикты из
  кэша; время подготовки кэша на самом mootant (`mootant run core/regex`)
  растёт не больше чем на несколько процентов — замерь до и после.
