Mootant makes small changes to your code, called mutants, and runs the tests
that should notice them. **A mutant that survives points to a test that is
missing or too weak.**

## Requirements

Mootant needs Node.js and tests on [Vitest](https://vitest.dev),
[Jest](https://jestjs.io) or [Node Test](https://nodejs.org/api/test.html), the
test runner built into Node.js. The tests have to pass as they are: Mootant runs
them without mutants first.

## Installation

Add Mootant to the development dependencies of your project:

```sh
npm install -D mootant
```

## First run

Point Mootant at your source code:

```sh
npx mootant run src
```

Mootant finds Vitest, Jest or Node Test and uses your existing configuration.
The mutants are compiled into your code in memory, so your files stay untouched,
and each mutant runs only the test files that reach it.

<Terminal output={heroOutput} />

The report lists the mutants that survived, the ones no test reached and the
ones that caused an error, file by file. Each mutant comes with:

- `comparison-operator`: the [mutator](/mutators/comparison-operator) that made
  it
- <DemoLink route="#/mutant/q31p">`q31p`</DemoLink>: its short id
- The `-` and `+` lines: the change
- `test:`: the test file to extend

`re-check one:` at the end of the report is the command that runs the first
survivor again.

## Fix a surviving mutant

This mutant is `total >= 100` → `total > 100`. The two versions differ only for
an order of exactly 100, and no test uses one. Move the slider to find it:

<DiscountProbe />

Write a test with that value:

```ts
it('gives orders of exactly 100 10% off', () => {
  expect(getDiscount(100, false)).toBe(10)
})
```

Then run the mutant again by its id:

```sh
npx mootant run src --mutant q31p
```

<Terminal output={recheckOutput} />

Verdicts are cached, so the next full run reuses them for mutants whose file and
tests did not change.

## Run in CI

Check only the lines a pull request changed, and fail the build when the
mutation score drops below a threshold:

```sh
npx mootant run src --since origin/main --threshold 80
```

The ref must exist locally: in CI, fetch the base branch with enough history to
find its merge base. The [CLI reference](/guide/cli#shared-options) lists the
other options.

## Let an agent fix them

Mootant ships with an agent skill. It reads the report, writes the missing tests
and asks Mootant to confirm each kill:

```sh
npx skills add azat-io/mootant
```
