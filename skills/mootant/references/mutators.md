# Mutators

How to write a test that kills a surviving mutant of each built-in mutator. The
page of each mutator has examples: `https://mootant.org/mutators/<id>`.

| Mutator               | Kill it with                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `arithmetic-operator` | A right side other than 0 for `+` and `-`; for `*` and `/`, a left side other than 0 and a right side other than 1 and -1; a pair the two operators treat differently, such as 5 and 2 for `%` → `*` (1 against 10) or 3 and 2 for `**` → `*` (9 against 6); for a dropped right side of a `+`, a non-empty string or a number other than 0 there, and a check of the whole result. |
| `array-element`       | Inputs where every element makes a difference, and the whole array checked with `toEqual`; for `[]` → `[undefined]`, its length, since Jest's `toEqual([])` accepts `[undefined]`; for a hook dependency, a rerender with a new value of it.                                                                                                                                        |
| `assignment-operator` | The value after the assignment: a target such as 10 with 3 on the right; for a logical assignment, a target it keeps, one it overwrites, and a falsy one other than `null`, `undefined` and the default, such as `''` or `0`.                                                                                                                                                       |
| `bitwise-operator`    | Flags that lack a bit of the mask, or have it for `^`; a shift from 1 to 31; a negative number for `>>>`; a quotient with a fraction where the code cuts it off.                                                                                                                                                                                                                    |
| `boolean-literal`     | A case where the literal decides the result, such as a call that relies on a default.                                                                                                                                                                                                                                                                                               |
| `comparison-operator` | The boundary and one step on each side, also for `===` and `!==` with a number; for other `===`, `in` and `instanceof`, one true and one false case.                                                                                                                                                                                                                                |
| `condition`           | One input for each outcome, and a check of a result that depends on the condition.                                                                                                                                                                                                                                                                                                  |
| `logical-operator`    | A case where the dropped side decides the result, or where a condition made `true` or `false` has the other value; for a swap of `??` and the logical or, a falsy value other than `null`, `undefined` and the default, such as `''`, `0` or `false`.                                                                                                                               |
| `method-call`         | A value the call changes, such as `' 42 '` for `trim()`; a list where some items pass the check and others do not, for `every`, `some` and `filter`; a value the two methods of a pair treat differently.                                                                                                                                                                           |
| `missing-await`       | A check of what the code does with the awaited value, a falsy awaited value where it is a condition, or an awaited call that fails; for the order of effects, a promise the test resolves itself, without real delays.                                                                                                                                                              |
| `number-literal`      | An input for which the old and the new number give different results, such as an amount over a cap.                                                                                                                                                                                                                                                                                 |
| `object-property`     | A check of the removed property or of a value the removed spread copies; `toHaveBeenCalledWith` for an object passed to another module.                                                                                                                                                                                                                                             |
| `optional-chaining`   | `null` or `undefined` right before the `?.`, and a check of the result.                                                                                                                                                                                                                                                                                                             |
| `regex-flag`          | Text for which the flag changes the result, such as letters in the other case for `i` or a second match for `g`.                                                                                                                                                                                                                                                                    |
| `regex-pattern`       | Text the pattern must reject; for a removed alternative, a test for each alternative; for an optional part made required, text without that part.                                                                                                                                                                                                                                   |
| `return-value`        | An exact check of the result, with an input for which the function returns something else; where a call becomes `undefined`, a check of what that call does.                                                                                                                                                                                                                        |
| `statement-removal`   | The effect of the statement: state it changes, an error it throws, or a call into another module.                                                                                                                                                                                                                                                                                   |
| `string-literal`      | The whole result with `toBe`, for an input that makes the string appear in it.                                                                                                                                                                                                                                                                                                      |
| `unary-operator`      | A value the operator changes: a total other than 0 for `-`, a string such as `'3'` for `+`, a flag set in the value for `~`, a quotient with a fraction for `~~`.                                                                                                                                                                                                                   |
| `update-operator`     | An input that reaches the update, and a check of the counter or of the value the update gives; for a postfix update whose value is used, the second value too.                                                                                                                                                                                                                      |

A mutator whose id has a `/` comes from a plugin and has no row here. Read its
description in `<mootant> list <file> --json --verbose`, the changed source and
the mutant's entry in the report.

These mutants often have no test that can catch them. Check the whole input
domain before you propose an ignore comment:

- `optional-chaining` when the value before `?.` is never `null` or `undefined`.
- `regex-flag` without `i` when the code first converts the text to the letter
  case of the pattern, as `toLowerCase()` before `/^save\d+$/i`.
- `unary-operator` without `+` when `*`, `/`, `%` or a subtraction converts the
  value anyway, as in `+input * 2`, and the value is never a BigInt: `+x` throws
  for one.
- `update-operator` with prefix and postfix swapped when nothing reads the
  value, as in `setTimeout(() => attempts++)`.
